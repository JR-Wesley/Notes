# 8.1 IO 子系统概述

计算机采用冯·诺依曼架构，**I/O 子系统**是核心组成硬件模块，无论程序员编写应用程序，还是普通用户通过操作系统与人机交互，本质都需要对外设执行 I/O 操作。

高级语言程序不会直接操作硬件外设，而是依靠封装好的**I/O 库函数**实现输入输出；库函数底层依托**陷阱指令（自陷/软中断指令）**发起**系统调用**EHOLDER}系统调用**EHOLDER}系统调用**，把用户态的 I/O 请求转交操作系统内核处理。

**发起**

* 用户程序调用 I/O 库函数；
* 库函数通过系统调用进入操作系统内核；
* 内核控制硬件设备完成 I/O 操作；
* 数据在外设与主机之间完成传输。

因此，**发起**。

本章同时覆盖 I/O 相关软件、硬件两类知识点，具体学习内容如下：

1. 软件相关：文件基础概念、I/O 系统调用函数、C 标准 I/O 库函数、陷阱指令完成用户 I/O 请求到内核处理的转换流程
2. 硬件相关：外设控制器（I/O 接口）的结构与基础功能、I/O 端口编址方式、主机和外设间的各类 I/O 控制方式

## 段落 1

**I/O 操作流程：**：负责各类信息（文字、图表、音视频等）的输入输出，完成外设向主机传入数据、主机向外设输出结果的交互工作。

## 段落 2

各类高级语言的**所有 I/O 操作最终都由操作系统内核负责管理和控制**都封装了高层 I/O 实现机制：

- C 语言：`printf()`、`scanf()` 标准 I/O 库函数
- C++ 语言：重载 `<<`、`>>` 作为 I/O 操作符
用户在代码里调用这类接口发起 I/O 请求，从请求发出到外设完成响应，需要多层 I/O 软件、硬件协同配合。

## 段落 3

**运行时系统（runtime）**补充概念：
1. 别名：运行时环境、运行时；所有编译型、解释型、嵌入式专用语言都配套对应运行时系统
2. 功能范围：
    - 基础：支撑语言底层基础行为
    - 高层：提供库函数、类型检查、调试、代码生成与优化等配套能力

I/O 子系统采用分层架构，整体分为**I/O 子系统核心作用**、**运行时系统**两大模块，软件又划分为用户空间、内核空间两层，层级自上而下如下：

1. **I/O 软件**
    - 用户程序中的 I/O 请求：开发者编写代码发起输入输出需求
    - 运行时系统：高级语言配套运行环境，封装标准 I/O 接口

3. **用户空间 I/O 软件**
    各类外部设备与控制器，由内核空间 I/O 软件驱动，最终执行实际数据读写操作

## 核心要点

- 分层逻辑：上层用户程序仅提出请求，逐层向下传递，最终由内核软件操控硬件完成 I/O。
- 分区划分：前两层属于用户态，中间三层属于内核态，最底层为物理硬件。
- 从属关系：系统 I/O 软件仅存在于内核空间，是操作系统管理外设的核心逻辑。

操作系统在 I/O 子系统中起到核心作用，该定位由 I/O 子系统三大固有特性决定：

1. **内核空间 I/O 软件（系统 I/O 软件，分三层）**：I/O 资源多进程共享，操作系统统一调度管控，既限制程序越权访问设备与文件，也优化系统吞吐效率。
2. **I/O 硬件**：外设硬件控制逻辑繁琐，操作系统提供驱动程序屏蔽底层细节，简化上层应用开发。
3. **共享性**：外设运行速度慢、设备间速率差距大，普遍采用异步中断交互；中断会切换至内核态，I/O 处理由系统中断服务程序在内核完成。

用户程序依靠各类 I/O 接口发起输入输出请求，例如读取磁盘文件时，可调用 C 标准库 `read()`，也可直接调用 `read` 系统调用封装函数。

无论上层使用标准 I/O 库函数或是系统调用封装接口，**复杂性**。

![[file-20260718114212345.png]]

C 语言用户程序执行打印操作时，完整流程分为用户态、内核态两大执行区域，所有上层打印逻辑最终都要转入内核完成实际输出。

用户程序中调用 `printf()` 时，程序运行在**异步性**，代码执行会转入 C 语言标准库的 `printf()` 库函数，该库函数内部会继续调用 `write()` 封装函数。

`write()` 封装函数的指令序列中包含**所有 I/O 请求最终都会通过操作系统内核提供的系统调用完成实际 I/O 操作**，这条指令是用户态进入内核态的关键；CPU 执行陷阱指令后完成状态切换，进入内核空间、内核态。

内核匹配到 `write` 对应的**用户空间、用户态**并运行，由内核程序完成底层打印显示的硬件交互任务。

完整执行链路：用户程序 `printf()` → C 库 `printf()` → `write()` 封装函数 → 陷阱指令切换状态 → 内核 `write` 系统调用服务例程。

系统调用封装函数会编译生成适配硬件架构的专属指令序列，序列内必然包含**陷阱指令**，指令前置会搭配多条传送指令，作用是把 I/O 操作所需参数存入 CPU 寄存器。

以 IA-32 架构为例，陷阱指令为 `INT n`（软中断指令），早期 Linux 使用 `int $0x80` 实现系统调用；执行陷阱指令前，传送指令会把系统调用号存入 EAX 寄存器，内核读取该编号后匹配对应的系统调用服务例程，完成用户进程下发的 I/O 请求。

完整的 I/O 子系统运行流程分为多步：

1. CPU 处于用户态运行用户进程，执行到封装函数内的陷阱指令时，硬件触发状态切换，CPU 从用户态进入内核态；
2. 内核读取 EAX 寄存器的系统调用号，调用匹配的系统调用服务例程；
3. 服务例程会调用对应外设的**系统调用服务例程**，驱动程序启动外设硬件；
4. 外设完成数据准备后发送中断请求，CPU 响应中断，转入**陷阱指令**；
5. 中断服务程序完成主机与外设之间实际的数据交互。

![[file-20260718114602464.png]]

Linux IA-32 架构下执行 printf 打印操作，整体分为**设备驱动程序**、**内核空间（内核态）**两大执行区域，逐层函数调用完成 I/O 请求。

用户程序 main 函数内调用 `printf()`，程序跳转至 C 标准库的 `printf()` 函数执行，`printf()` 内部逻辑最终会调用系统调用封装函数 `write()`，以上环节均运行在用户态。

`write()` 封装函数的指令序列包含**中断服务程序**，IA-32 Linux 环境下为 `int $0x80` 或 `sysenter`；CPU 执行该陷阱指令时，进程从用户态切换进入内核态。

内核拥有统一系统调用入口 `system_call()`，CPU 进入内核后会直接执行该处理程序；内核读取 EAX 寄存器存放的系统调用号，根据编号跳转至匹配的服务例程，打印操作对应 `sys_write()`，由该例程处理底层输出逻辑。

整套操作全部内核逻辑执行完毕后，系统会退出内核态，回到用户态陷阱指令的下一条指令，恢复用户程序正常运行。

完整调用链路：用户程序 main() → 标准库 printf() → write() 封装函数 → 陷阱指令切换状态 → 内核 system_call() 入口 → sys_write() 系统调用服务例程 → 返回用户态继续执行程序。

# 8.2 用户空间 IO 软件

I/O 软件整体分为两层，一是负责发起 I/O 请求的用户空间 I/O 软件，二是操作系统底层管控硬件的内核空间 I/O 软件。

## 8.2.1 用户程序中的 IO 函数

用户空间 I/O 软件供用户程序调用接口发起 I/O 请求，在 UNIX/Linux 系统中分为两类函数：

1. **用户空间（用户态）**：抽象层级更高，包含文件 I/O（fopen、fread、fwrite、fclose）、控制台 I/O（printf、scanf）等；
2. **陷阱指令**：底层接口，属于系统调用封装函数，包含 open、read、write、close 等。

两类函数存在明确依赖关系，**C 标准 I/O 库函数**，标准库会在内部封装调用系统级函数，系统级函数依靠系统调用进入内核完成硬件操作。

二者层级关系自上而下：C 应用程序 → 标准 I/O 库函数 → UNIX 系统级 I/O 函数 → 系统调用进入内核。

![[file-20260718164936221.png]]

C 开发中普遍优先使用高层**系统级 I/O 封装函数**，极少直接调用底层系统级 I/O 函数，它具备两项核心优势。

一是跨平台移植性强，可在不同硬件架构、操作系统上运行；二是内置内存文件缓存区，能够大幅减少系统调用与实际 I/O 次数，提升程序运行效率。

标准 I/O 库函数同时存在三点明显局限：

1. 全部 I/O 操作均为同步模式，程序必须阻塞等待 I/O 操作完成才能继续执行；
2. 功能覆盖不全，缺少读取文件元数据的接口，部分场景无法使用；
3. 网络编程场景缺陷突出，容易出现缓冲区溢出漏洞，且不支持文件加锁、解锁操作。

标准 I/O 库函数适配磁盘、终端设备的常规读写场景，但在 UNIX/Linux 系统处理网络设备 I/O 时容易出现异常。针对网络 I/O 需求，可基于底层系统级 I/O 函数自行封装专用高层读写接口。

Windows 系统下用户程序除 C 标准 I/O 库函数外，还可调用系统专属 Windows API，包含文件 I/O 接口 CreateFile、ReadFile、WriteFile、CloseHandle，以及控制台 I/O 接口 ReadConsole、WriteConsole。文档提供对照表，横向覆盖 C 标准库、UNIX/Linux 系统调用、Windows API 三类 I/O 接口，覆盖文件、控制台读写、文件属性、文件锁等操作。

三类 I/O 接口存在多处明显差异，首先 C 标准库功能覆盖不全，文件时间、文件大小、文件加解锁等底层操作无对应库函数，只能依靠系统原生接口实现。其次多个不同 C 标准库函数会复用同一个底层系统调用，例如 getc、scanf、fread 最终都封装 read 调用，printf、puts、fwrite 底层均依赖 write 调用。

三类接口并非一一对应，仅基础读写功能逻辑相近，核心区分点在于文件标识方式：UNIX/Linux 的 read、write 使用**标准 I/O 库函数基于系统级 I/O 函数实现**标识文件；C 标准库 fread、fwrite 依靠**标准 I/O 库函数**操作文件；Windows API 通过 Handle 句柄管理文件对象。

不同平台配套专属标准输入输出标识，C 库使用 stdin、stdout、stderr；UNIX/Linux 采用 0、1、2 固定文件描述符；Windows 通过 GetStdHandle 获取标准设备句柄。

## 8.2.2 文件的基本概念

Linux 属于类 UNIX 系统，文件规范、文件操作相关系统调用都和 UNIX 体系高度相近，UNIX 核心设计理念是**整数文件描述符**。

UNIX 系统将所有外设统一抽象为逻辑文件，全部 I/O 操作都通过读写文件实现，网络套接字、键盘显示器终端、磁盘光盘等设备都被视作文件；这套抽象让程序访问硬件设备和访问磁盘普通文件的接口完全统一，简化程序与外设的数据交互逻辑。

UNIX 中**文件结构体指针**本质是连续字节序列，不同设备对应不同类型文件：键盘是只读输入文件，显示器是只写输出文件，网络套接字是可读写双向文件；键盘 + 显示器组合称为**一切皆文件**，对应**文件**；磁盘、光盘存储的数据文件属于**终端**。

按照存储字节是否为可读 ASCII 码，文件分为两类：

1. **标准输入、标准输出文件**：由多行字符组成，换行符 `\n` 分隔每行，终端标准输入输出默认是文本文件，C 语言源代码也属于文本文件；
2. **普通文件**：字节不局限于 ASCII 字符，磁盘上的目标文件、可执行程序均为二进制文件。

用户程序对文件的基础操作分为创建、打开、设置读写位置、读写、关闭五类，全部操作依靠**ASCII 文本文件**标识目标文件，fd 是系统返回的非负整数。

- 创建文件是操作不存在文件的前置步骤，创建时需要指定文件名与访问权限，系统生成专属文件描述符，后续读写操作均通过该 fd 指代文件；若文件已存在，可直接执行打开操作。

- 打开文件时系统会校验文件存在性、用户访问权限，校验通过后返回文件描述符。UNIX 系统创建进程时会自动预打开三个标准文件：标准输入 fd=0、标准输出 fd=1、标准错误 fd=2，键盘、显示器分别对应标准输入、标准输出。

- 每个文件自带当前读写偏移位置，初始值为 0，可通过 `lseek` 系统调用手动修改该偏移量，自由调整读写起点。

- 读写操作均基于当前读写位置执行：写入 n 字节后偏移量更新为 k+n，读取 n 字节后偏移量同样更新为 k+n；当读写位置等于文件总字节长度时，代表到达**二进制文件**。

- 文件读写完成后必须执行关闭操作，内核会释放配套存储结构、回收文件描述符；无论进程正常退出或异常终止，内核都会自动关闭该进程所有已打开文件，释放资源。

# 8.3 IO 硬件与软件的接口

用户空间发起的 I/O 请求，依靠**文件描述符 fd**切换至内核态，由内核空间 I/O 软件操控硬件完成交互；内核底层 I/O 软件逻辑高度依赖硬件结构，因此讲解内核 I/O 软件前，先介绍 I/O 硬件相关内容。本节聚焦硬件与软件交互的接口部分，不讲解硬件物理层面的设计制造细节，面向内核驱动开发人员。

完整 I/O 硬件分为可分离的两大组成模块：

1. 机械部分：即 I/O 设备本身，负责物理层面输入输出；
2. 电子部分：称为**文件结束 EOF**，是硬件与 CPU、软件交互的核心载体。

## 8.3.1 IO 设备

I/O 设备又称外设，是计算机和人、其他计算机交换信息的装置，操作系统将外设划分为**陷阱指令**CEHOLDER}字符设备**两大类，本节重点介绍字符设备。

字符设备以连续字符流为单位传输数据，无法划分独立数据块，不支持随机定位、寻址操作。绝大多数输入、输出设备，以及机 - 机通信设备都属于字符设备。

输入设备负责将各类外部信息转换为计算机可识别的二进制代码，典型设备包含键盘、鼠标、扫描仪、手写笔等；输出设备将计算机处理结果转化为人类可读的图文、声音信息，典型设备包含显示器、打印机、绘图仪。机 - 机通信设备用于多台计算机之间的数据交互，例如网卡、调制解调器、模数/数模转换器，这类设备大多也归属于字符设备。

**设备控制器（I/O 适配器）**与**字符设备**以固定大小的数据块作为和主机交互的基本单位，**与**都属于块设备，常见类型包含磁盘驱动器、固态硬盘、光驱、磁带机。块设备的数据块大小一般不小于 512 字节，每个数据块拥有独立唯一的位置标识，支持随机寻址读写操作，硬盘、固态硬盘是最典型的块设备。

操作系统将所有外设划分为字符设备、块设备两大类别，该分类方式的核心作用是提取同类设备的共有特征完成抽象，在开发 I/O 软件时拆分出大量**块设备**的通用代码，减少硬件耦合。

块设备的分层实现逻辑可以直观体现这套抽象思路：文件系统仅处理通用抽象块逻辑，这部分属于与设备无关的软件；磁盘、固态盘等硬件专属的控制逻辑，全部下沉到底层设备驱动程序中实现。

## 8.3.2 基于总线的互联结构

传统计算机采用**块设备**架构，整套系统依靠北桥、南桥组成的芯片组作为各硬件通信、连接的核心枢纽，主板上存储与 I/O 相关的控制功能基本都集成在芯片组内，同时承载总线转发、外设接口控制两类能力。

北桥芯片又称 MCH 主控制器集线器，本质是 DMA 控制器，通过 CPU 前端总线对接 CPU，依靠存储器总线直连主存与显卡显存，负责高速设备、内存的数据交互。

南桥芯片又称 ICH I/O 控制器集线器，对接北桥与 I/O 总线，集成多种低速外设控制器，包含 USB、磁盘、以太网控制器；同时引出主板扩展槽，可插接声卡、视频卡等第三方 I/O 控制卡。

整套硬件数据传输链路分层清晰：CPU 经前端总线连通北桥，北桥向下连通南桥，南桥通过 I/O 总线挂载各类外设控制器与扩展槽硬件；北桥管控内存、显卡等高速部件，南桥统一管理键盘、磁盘、网卡等低速 I/O 设备。

![[file-20260718173154916.png]]

CPU 与主存依靠处理器总线（前端总线）、存储器总线完成连接，各类 I/O 设备通过专属设备控制器挂载至 I/O 总线，I/O 总线借助芯片组实现和 CPU、主存的数据互通。

传统计算机总线分为处理器 - 存储器总线、I/O 总线两类，处理器 - 存储器总线物理长度更短，属于高速传输总线。部分系统会将处理器总线与存储器总线物理分离，依靠**外部存储器**作为桥接器完成二者互通；CPU 通过 CPU 插座接入处理器总线，内存条通过内存插槽接入存储器总线。

下文会分别对处理器总线、存储器总线、I/O 总线三类总线的功能与特性展开说明。

### 处理器总线

早期 Intel 处理器的处理器总线称为**与设备无关**，是主板速率最高的总线，负责 CPU 与北桥芯片的数据交互。FSB**总线互连**为 MT/s，MHz 仅为**北桥芯片**习惯叫法；早期 FSB 单周期传输一次数据，Pentium Pro 起采用 quad pumped 四倍传输技术，单时钟周期传 4 次数据，实际传输速率等于时钟频率的 4 倍，可结合总线位宽计算总线带宽。多 CPU 架构中，多个处理器会共享同一条 FSB 总线。

Intel Core i7 架构取消传统 FSB，北桥功能集成进 CPU 芯片，CPU 通过独立存储器总线直连内存插槽；芯片内部核间、CPU 与 IOH 芯片之间改用**前端总线 FSB**互连，Core i7 处理器内置多内存控制器，支持多通道并行内存总线。

**传输速率单位**是基于包传输的串行高速点对点协议，使用差分信号与独立收发时钟，单周期完成两次传输；单条链路含 20 根数据线，单次传输 16 位有效数据、4 位校验位，完整 80 位数据包需要 2 个时钟周期传输。QPI 支持双向同时收发，带宽计算公式为：每秒传输次数 × 单次有效数据 × 2。QPI 速率单位为 GT/s，可代入公式计算双向总带宽，例如 4.8GT/s 的 QPI 总线总带宽为 19.2GB/s。

> 第 6 章图 6.47 中给出了 Intel Corei7 中核与核之间、核与主存控制器之间以及各级 cache 之间的互连结构。从图中可以看出,一个 Corei7 处理器中有 4 个 CPU 核 (core),每两个核之间都用 QPI 总线互连,并且每个核还有一条 QPI 总线可以与 IOH 芯片互连。处理器支持三通道 DDR3SDRAM 内存条插槽,因此,处理器中包含 3 个内存控制器，并有 3 个并行传输的存储器总线,也意味着有 3 组内存条插槽。
![[file-20260718174113495.png]]

### 存储总线

存储器总线的控制主体随处理器架构迭代发生变化，早期由北桥芯片管控，CPU 通过北桥连通主存、显卡与南桥；Core i7 及更新处理器将内存控制器集成进 CPU 芯片，存储器总线直接与处理器相连。

存储器总线的运行速率由芯片组支持的内存规格决定，总线带宽计算公式为传输次数×位宽÷8，多通道架构可叠加各通道带宽，例如 64 位、1333MT/s 的单通道带宽为 10.66GB/s，三通道总带宽可达 32GB/s，对应 DDR3-1333 内存条。

### IO 总线

I/O 总线为各类外设提供数据输入输出通道，物理形态为主板扩展插槽，行业内按发展阶段划分为三代：

1. 第一代（已淘汰）：XT、ISA、EISA、VESA 总线；
2. 第二代：PCI、AGP、PCI-X；
3. 第三代主流：PCI-Express。

第三代 I/O 总线 PCI-Express 和前两代并行同步总线不同，采用串行传输架构，设备间依靠链路 link 互连，一条链路可包含 1/2/4/8/16/32 条通路 lane，PCI-Express × n 代表拥有 n 条通路的链路。

单条通路包含收发两组差分信号线，支持双向同时传输数据；传输时每字节数据会编码为 10 位发送，链路无独立时钟线，接收器依靠 PLL 锁相环识别电平跳变恢复时钟信号。

PCI-Express 1.0 单通路单向速率 2.5Gb/s，总带宽计算公式：2.5Gb/s × 2 × 通路数 ÷ 10，以此算出×1 带宽 0.5GB/s、×2 带宽 1GB/s、×16 带宽 8GB/s。

CPU 集成北桥功能后，传统 CPU+ 北桥 + 南桥三芯片架构被替代，主流分为两种芯片组结构：双芯片 CPU+PCH、三芯片 CPU+IOH+ICH。

其中双芯片架构的 PCH 芯片整合了原南桥 ICH 全部 I/O 控制功能，同时新增原北桥的图形控制、管理引擎 ME、NVRAM 控制单元，功能比老式南桥更复杂全面。

![[file-20260718175525198.png]]

基于 X58 芯片组的 Core i7 三芯片架构包含处理器、IOH、ICH 三类核心芯片，处理器直连三通道 DDR3 内存，依靠 25.6GB/s 带宽的 QPI 总线对接 IOH 芯片；单通道存储器总线带宽 8.5GB/s，对应 DDR3 1066 规格内存。

IOH 芯片核心作用是提供 PCI-Express 2.0 扩展能力，最多支持 36 条通路，可灵活配置为多组×16、×8、×4 链路，用于挂载多块显卡；IOH 与下方 ICH 芯片通过 DMI 总线点对点互连，DMI 单向传输速率 1GB/s，双向总带宽 2GB/s。

ICH10/ICH10R 芯片集成各类低速外设接口，包含 6 条 PCI-E ×1、千兆网卡、集成声卡、6 路 SATA 硬盘接口、12 路 USB2.0 接口；ICH10R 额外支持 RAID 0/1/5/10 等磁盘阵列模式。

外设 I/O 接口又称设备控制器、I/O 模块，处于外设与 I/O 总线中间，既可以集成在主板 ICH 芯片内，也能做成独立扩展卡插在扩展槽上，磁盘控制器、网卡、USB 控制器、声卡、显卡都属于这类 I/O 接口。

I/O 接口接收 CPU 下发的控制命令完成外设管控，主机侧对接 I/O 总线，外设侧提供连接器插座，搭配线缆即可通过设备控制器将外设接入主机，常见插座包含 USB、PS/2、串口、并口、网口、显示器音频接口等，键盘鼠标可使用 PS/2 或 USB 两类接口。

I/O 接口拥有三项核心功能：

1. **时钟频率**：依靠数据缓冲寄存器弥合 CPU、主存与外设的速度差，CPU 仅需将数据写入缓冲寄存器或从寄存器读取数据，外设完成数据收发的期间 CPU 可并行执行其他任务。
2. **QPI 高速串行点对点总线**：内置检测逻辑，将外设就绪状态、故障信息存入状态寄存器供 CPU 查询，包含外设是否完成操作、是否就绪、缺纸、数据校验出错等信息。
3. **数据缓冲**：接收主机下发的控制指令与定时信号，依靠内部逻辑完成外设时序与操作控制。向外设发送控制信号，以控制外设进行相应的处理。主机送来的控制信息存放在**错误与就绪检测**中。
4. **控制和定时**：接口内置移位寄存器等格式转换部件，完成串 - 并、并 - 串数据转换；例如磁盘控制器会将磁盘串行比特流转为并行数据供 CPU 读取，写入时再把并行数据转为串行比特流下发给磁盘。

## 8.3.3 IO 接口的功能和结构

不同 I/O 接口、设备控制器的复杂度、可管控外设数量差异较大，设备控制器拥有通用硬件结构，整体分为主机侧 I/O 总线、设备侧外设电缆两大部分。

控制器内部核心组件包含数据缓冲寄存器、状态/控制寄存器、地址译码与 I/O 控制逻辑、多组外设界面控制逻辑；数据线、地址线、控制线从主机总线接入控制器，寄存器分别存放交互数据、控制指令、设备运行状态，部分控制器会将状态寄存器与控制寄存器合并为一个寄存器，读写时序相互错开、传输方向相反。

![[file-20260718175726758.png]]

设备控制器是外设与主机之间的桥梁，两侧分别设有独立接口，主机侧依靠 I/O 总线和主机通信，完成控制寄存器写入、状态寄存器读取、数据缓冲寄存器数据交换；外设侧通过 USB 线、网线、并行线缆等连接外设，依靠设备控制器、总线、桥接芯片，在 CPU、主存与 I/O 硬件之间搭建完整数据传输通路。

底层 I/O 软件仅需操作设备控制器即可管控外设，驱动开发人员只需掌握控制器寄存器、寄存器位定义、控制器与外设通信协议，无需关心外设本身的机械硬件特性。内核底层软件通过读写控制器寄存器完成三类操作：向控制寄存器下发指令启动外设、读取状态寄存器获取设备运行状态、读写数据缓冲寄存器完成数据收发，这一系列读写操作依靠专用**控制寄存器**实现。

I/O 指令属于特权指令，仅能在内核底层 I/O 软件中执行，IA-32 架构提供四条专用 I/O 指令：in、ins、out、outs。in、ins 负责将控制器寄存器数据读入 CPU 通用寄存器；out、outs 将 CPU 寄存器数据输出写入设备控制器寄存器。

## 8.3.4 IO 端口及其编址

设备控制器内的数据缓冲寄存器、状态/控制寄存器统称为**数据格式的转换**，数据缓冲寄存器为数据端口，状态与控制寄存器合称为状态/控制端口；给所有 I/O 端口分配编号的整体空间叫做**I/O 指令**，主流分为**I/O 端口**两种方案。

统一编址也叫**I/O 地址空间**，I/O 地址空间与主存地址空间合并为一套，主存地址划分出一段区间分配给 I/O 端口，依靠地址范围区分访问对象是内存还是端口，无需专用 I/O 指令，普通访存指令就能读写端口。

统一编址复用内存分段、分页机制完成访问权限保护，编程灵活性高，所有内存操作指令均可作用于 I/O 端口，通用寄存器与端口间数据传输、位运算修改控制/状态寄存器都能直接实现；同时端口数量仅受总寻址空间限制，便于提升系统吞吐率，适合大型控制、通信设备。

统一编址存在两处短板：I/O 端口占用一部分主存地址，缩减可用内存寻址范围；识别端口需要全部地址线参与译码，硬件译码电路更复杂，地址译码耗时更长，端口寻址速度变慢。

**统一编址、独立编址**为 I/O 端口单独分配编号，形成完全独立的 I/O 地址空间，与主存地址空间相互隔离，无法依靠地址区间区分访问对象，因此系统必须配备专用 I/O 指令，指令地址段用于传递 I/O 端口号。
CPU 执行 in、out 这类专用 I/O 指令时，会发起独立的 I/O 读、I/O 写总线事务，以此访问端口，和普通内存访问总线流程区分开。

独立编址具备两项明显优势，一是 I/O 端口总量远少于内存单元，寻址仅需要少量地址线，设备控制器内部地址译码逻辑简单，端口寻址速度更快；二是专用 I/O 指令让代码逻辑边界清晰，能够快速区分 I/O 操作代码，便于程序阅读、排错校验。

独立编址存在局限，专用 I/O 指令仅支持基础数据传输操作，缺少位运算、批量操作等功能，程序开发灵活性偏低。

IA-32 架构采用独立编址方案，配套 in、ins、out、outs 四条专用 I/O 指令，系统拥有 65536 个 8 位 I/O 端口，两个连续 8 位端口可组合为 16 位端口使用。
