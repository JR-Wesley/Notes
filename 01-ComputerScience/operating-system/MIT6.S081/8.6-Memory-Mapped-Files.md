# 8.6 Memory Mapped Files

## 本节知识点

内存映射文件（memory-mapped file）把文件的某个区间放进进程的虚拟地址空间。通常程序通过 `read()`、`write()` 和 `lseek()` 按文件偏移操作字节；映射后，程序可以对映射地址使用普通的 load/store 指令，地址在映射区间内的位移决定所访问的文件位置。`mmap()` 负责建立这种关联，它返回或指定一段可访问的虚拟地址；这并不意味着调用时必须把整个文件读入物理内存。

文件映射可以沿用上一节的按需分页机制：内核先记录映射的地址范围、文件、起始偏移和访问权限，暂不装入每个页面。进程首次访问尚未驻留的映射页时产生 page fault；内核根据故障地址算出对应的文件偏移，读取内容、建立页表映射，再重试原指令。因此，页表负责把内存访问接到文件内容，page fault 负责延迟实际载入。

讲义特别提醒：文件映射中没有文件内容覆盖的空洞必须呈现为零填充页面，不能让进程读到旧物理页的残留数据。这既是正确的读取语义，也是进程隔离所需的边界。映射的访问权限同样需要落实到页表；例如只读映射不能因为页已被载入就允许写入。

## 关键解读

**映射是地址与文件区间的关系，不是一次性复制文件。** 例如文件偏移 `offset` 对应映射起点 `base`，那么访问 `base + n` 对应文件的 `offset + n`。实际实现还要按页对齐并处理页内偏移，但核心转换就是这两个区间的相对位移。由此也可理解为什么随机访问时不必先用 `lseek()` 改动文件描述符的位置。

**文件页能否回写，取决于映射语义。** 作为机制上的延伸，支持可写文件映射的系统通常还要区分共享映射与私有映射：共享映射的修改可能需要写回文件，私有映射的写入则可通过写时复制保持为进程私有。脏页跟踪、解除映射时的处理及多个进程的一致性都属于实现问题，不能仅凭“有了页表”就认为已经解决。课程讲义此页只提出文件映射的基本用法，没有展开这些接口细节。

**它与按需载入可执行文件使用同一种故障恢复思路，但对象不同。** 8.5 讨论的是 `exec()` 启动程序后按需读取代码或数据页；这里是应用通过 `mmap()` 把普通文件区间纳入自身地址空间。两者都需要记录页的后备来源，并在访问时判断故障地址是否合法。
