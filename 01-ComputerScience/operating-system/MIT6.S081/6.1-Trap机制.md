# 6.1 Trap 机制

> 原页面：[MIT 6.S081 中文翻译：6.1 Trap 机制](https://mit-public-courses-cn-translatio.gitbook.io/mit6-s081/lec06-isolation-and-system-call-entry-exit-robert/6.1-trap)。补充说明依据 [RISC-V 特权架构规范：Supervisor-Level ISA](https://docs.riscv.org/reference/isa/priv/supervisor.html)与 [xv6 book：Traps](https://pdos.csail.mit.edu/6.1810/2025/xv6/book-riscv-rev5.pdf)。本节先建立用户态进入内核的整体图景，具体入口指令和 xv6 实现留待后续小节。

## 本页知识点

用户程序执行系统调用、发生异常（例如缺页），或者设备发出中断时，处理器需要把控制权交给内核。这类控制转移统称为 trap。课程以 Shell 调用 `write` 为例：程序原本在 user mode 执行，trap 之后内核要在 supervisor mode 处理请求。由于系统调用和某些异常发生频繁，入口过程既要保证隔离，也要控制开销。

切换前，处理器的状态适合继续执行用户程序：通用寄存器中可能有参数、临时值和栈指针，程序计数器指向用户指令，`satp` 对应当前地址转换设置。课程还点名了几个与 trap 相关的监督模式控制寄存器：`stvec` 给出 trap 入口位置，`sepc` 保存需要恢复的程序位置，`sscratch` 为入口汇编提供临时状态。原页的 `SSRATCH` 是 `sscratch` 的笔误。

进入内核 C 代码前，必须妥善保存用户程序之后还需要的执行状态，取得 supervisor 权限，将地址转换切换到内核使用的页表，并把栈指针转到内核栈，最后才能按内核的调用约定运行 C 函数。尤其对于异步中断，用户程序并未主动准备调用内核；内核处理完毕后，应让程序能够从正确位置继续，并保持应保留的寄存器值。

trap 入口还承担安全边界的职责。用户寄存器里的值可能由不可信程序控制，入口代码必须把它们当作数据保存，不能把未经验证的值直接当作可信的内核栈、页表或跳转目标。与此同时，安全的切换过程只保证了入口边界；`write` 等系统调用的内核实现仍须检查来自用户空间的参数。

## 关键解读

**trap 不是普通的函数调用。** 普通调用发生在既定的执行环境中，遵循调用约定即可；trap 可能在任意用户指令处发生。进入内核时，权限、地址空间、栈和可用寄存器都需要安排，因此不能直接把用户程序的当前栈和寄存器当成内核 C 函数的运行环境。

**权限提升与地址映射是两件事。** supervisor mode 允许操作受限的控制寄存器并访问满足权限检查的监督模式页，但不会使任意物理地址自动可读写。内核访问内存仍要经过当前页表的虚拟地址转换。原页说监督模式不能使用 `PTE_U=1` 的页面，是对本课通常配置的简化叙述；精确行为还取决于 RISC-V 的访问权限规则及 `sstatus.SUM` 等状态，不能将其当作无条件禁令。

**先记住要保存什么，再研究谁来保存。** 本节列的是完成切换所需的状态与目标，并不表示硬件会自动保存全部 32 个通用寄存器、切换页表和栈。后续阅读 trap 入口汇编时，应逐项追踪硬件完成的步骤、软件保存用户寄存器的位置，以及何时开始安全地执行内核 C 代码。
