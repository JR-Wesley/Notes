# 3.9 xv6 启动过程

> 来源：[MIT 6.S081 中文翻译：3.9 xv6 启动过程](https://mit-public-courses-cn-translatio.gitbook.io/mit6-s081/lec03-os-organization-and-system-calls/3.9-xv6-qi-dong-guo-cheng)。本节沿课堂 gdb 演示梳理启动主线；地址、函数名和构建产物以该版 xv6 为上下文，本文未在本地复现实验。

## 本页知识点

课堂启动带调试接口的 QEMU，再连接 RISC-V gdb，沿内核入口、`main`、首个用户进程和系统调用一路观察。页面中的内核起始地址为 `0x80000000`，由链接脚本 `kernel.ld` 配置；断点命中 `0x8000000a` 表明执行已经越过入口处的几条指令。对照 `kernel.asm` 和 gdb 可把地址、机器码及汇编指令对应起来。课程演示只模拟一个 CPU 核，以简化单步调试。

| 阶段 | 页面展示的关键动作 | 作用 |
| --- | --- | --- |
| 早期入口 | 从 `entry.S` 开始，初期处于 Machine mode，尚未启用分页；随后转入 Supervisor mode。 | 为运行 C 语言内核初始化代码建立基本环境。 |
| `main` 初始化 | 初始化 console、物理页分配器、内核页表、进程表、trap、中断控制器、缓冲缓存、文件系统和磁盘等。 | 让后续进程与设备服务具备运行条件；部分初始化有顺序依赖。 |
| 创建首个用户进程 | `userinit` 建立初始进程，并让它运行简短的 `initcode`。 | 从只有内核代码执行的状态过渡到用户空间。 |
| 首次 `exec` | `initcode` 把程序路径和参数放入约定寄存器，以 `ecall` 请求 `exec`，装入 `init`。 | 展示第一个用户态系统调用如何进入内核分派。 |
| 启动 Shell | `init` 配置 console，`fork` 子进程并在子进程中 `exec` Shell。 | 最终在 QEMU 中看到可交互的 Shell。 |

系统调用跟踪中，`initcode` 将 `init` 路径放在 `a0`、参数数组放在 `a1`、`SYS_exec` 编号放在 `a7`，然后执行 `ecall`。内核的 `syscall` 分派代码从当前进程的 trapframe 读取 `a7`；在页面所用版本中，编号 `7` 对应 `exec`，于是分派到 `sys_exec`。后者从用户空间取得程序路径，页面调试时看到的值是 `init`。之后 `init` 再启动 Shell。

## 关键解读

**启动是一串前提关系。** console 就绪后才能可靠输出；内存、进程和 trap 等基础设施就绪后，内核才适合创建用户进程并处理它发出的系统调用。初始化函数的顺序不是任意排列，某一步依赖的状态必须先建立。

**首个系统调用把“启动”和“接口”接起来。** `userinit` 先为用户态指令创造运行条件，`initcode` 再用与普通应用相同的系统调用入口请求 `exec`。这说明内核完成自身初始化后，也是通过受控的用户／内核边界逐步启动上层程序，而非直接把 Shell 当作内核函数调用。

**区分观察到的轨迹与完整机制。** 本页利用断点证明了 `a7` 中的调用号如何到达分派函数，并追踪 `init`、Shell 的出现；`ecall` 后如何保存寄存器、切换页表和安全返回用户态仍待后续课程。页面把 `kinit` 说成“页表分配器”，此处按其实际职责理解为物理页分配器；页表初始化由 `kvminit` 等步骤承担。
