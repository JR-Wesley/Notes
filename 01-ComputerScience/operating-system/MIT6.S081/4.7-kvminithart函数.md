## 本页知识点

`kvminit` 在内存中创建内核页表；`kvminithart` 则让当前 CPU 开始使用它。函数把 `kernel_pagetable` 经过 `MAKE_SATP` 编码后写入当前 CPU 的 `satp` 寄存器。`satp` 保存分页模式及根页表的物理页号，处理器随后依据该根页表转换虚拟地址。每个 CPU 都有自己的 `satp`，所以函数名中的 `hart` 指向当前硬件线程，而不是再次构建一张新的内核页表。

课程对应的 xv6 源码在写 `satp` 前后各执行一次 `sfence_vma()`。写入前的栅栏确保此前对页表内存的写入已经完成；写入后的栅栏使当前 CPU 不再使用旧的地址转换缓存。这里的 C 函数名 `sfence_vma()` 封装了 RISC-V 指令 `sfence.vma`。页表本身、`satp` 中的选择状态和 TLB 中缓存的转换结果，是三个需要分别理解的对象。

启用分页时还有一个连续执行的问题：写 `satp` 后，下一条指令的地址也要按新页表翻译。xv6 内核页表将内核代码等关键区域直接映射到相同数值的物理地址，因此切换前后，当前代码仍能从正确位置继续执行。若新页表未映射当前执行地址或栈，启用页表就可能立即出错。

## 关键解读

**建立页表、选用页表、清理旧转换是连续的三个环节。** `kvminit` 填好 PTE；`kvminithart` 写 `satp` 选中根页表；`sfence.vma` 使处理器按规定同步页表写入并处理旧缓存。只完成第一步，普通访存不会自动改用新页表。

**`satp` 装的不是整个页表。** 页表树位于物理内存，寄存器只提供模式及根页表的位置。`MAKE_SATP` 的作用是把根页表地址转换为寄存器需要的格式，而非复制页表内容。处理器读取寄存器后，仍要通过 MMU 和页表项完成地址转换。

**这一步发生在每个 CPU 上。** 内核页表可以共享，但每个 CPU 的 `satp` 和 TLB 状态属于该 CPU。理解这一点，才能解释为什么启动时会有面向各 hart 的初始化，以及为什么一次本地 `sfence.vma` 不能直接等同于所有 CPU 的缓存都已更新。
