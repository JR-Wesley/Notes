# 1.8 fork 系统调用

> 原页面：[MIT 6.S081 中文翻译：1.8 fork 系统调用](https://mit-public-courses-cn-translatio.gitbook.io/mit6-s081/lec01-introduction-and-examples/1.8-fork)。本次原页面正文未能直接读取；以下依据[按章节整理的课程笔记](https://www.cnblogs.com/looking-for-zihuatanejo/p/17564124.html#18-fork拷贝当前进程的内存)，并与本课程前后章节交叉核对，记录可确认的核心内容。

## 本页知识点

`fork` 创建一个新的进程。课程用“复制当前进程”来建立直观模型：调用后有父进程和子进程，两者各自从 `fork` 返回后的代码继续执行。子进程开始时具有父进程的程序指令和数据副本，但它是独立的进程，而不是父进程中的另一条普通函数调用路径。

两条执行路径可以通过返回值区分：在父进程中，`fork` 返回子进程的 PID（正整数）；在子进程中，同一次 `fork` 返回 `0`。因此程序只需调用一次 `fork`，随后便能按返回值让父子进程执行不同分支。若要编写健壮程序，还需要处理创建失败的情况；该页的入门讲解主要关注父子两条成功路径。

Shell 执行命令时需要一个新进程承载命令，例如用户输入 `ls`，Shell 可以先通过 `fork` 创建子进程。仅有 `fork` 仍会得到一个运行 Shell 代码的子进程；要把它变成运行 `ls` 的进程，还需要下一节介绍的 `exec`。

## 关键解读

**一次调用产生两处返回。** 父子进程都从同一代码位置继续，但观察到不同的 `fork` 返回值。理解示例代码时，先画出“父进程：返回子 PID”和“子进程：返回 0”两条路径，再分别追踪它们后续执行的语句，比把 `fork` 当作普通函数更清楚。

**复制的是初始状态，不意味着之后的状态永远同步。** 父子进程有各自的执行流程；一方改变自己的普通内存变量，不应据此推断另一方变量也改变。与此同时，课程前面指出子进程能够继续使用父进程在 `fork` 前打开的文件描述符。因而要区分普通进程内存的独立性与已打开资源的继承关系，具体共享哪些内核对象留待后续实现章节核实。

**`fork` 解决“产生进程”，`exec` 才解决“运行另一个程序”。** 这也是 Shell 不必用新命令覆盖自身的基础：它创建子进程，再由子进程装入目标程序。下一节可继续检查 `exec` 如何影响进程身份、内存和文件描述符。
