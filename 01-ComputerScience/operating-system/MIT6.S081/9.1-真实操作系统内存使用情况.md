# 9.1 真实操作系统内存使用情况

> 章节入口：[MIT 6.S081 中文翻译：9.1 真实操作系统内存使用情况](https://mit-public-courses-cn-translatio.gitbook.io/mit6-s081/lec09-interrupts/9.1-memory-in-real-os)。原站本次无法直接读取；以下依据对该段课程内容的[转载整理](https://cloud.tencent.com/developer/article/2337456)归纳。文中的数值属于课堂展示的某台 Athena 机器的快照，不代表所有系统的固定比例。

## 本节知识点

课程先用一台 MIT Athena 机器的 `top` 输出回顾上一讲的虚拟内存。物理内存统计中，空闲的 `free` 只占一小部分，而相当多的内存处于 `buff/cache`：操作系统利用暂时不用的 RAM 缓存文件或块数据，使后续访问有机会避开较慢的存储设备。因此，“空闲内存少”不能单独推断为内存紧张；还要看有多少缓存能够回收，以及应用接下来的内存需求。

这也解释了内存分配为什么可能牵涉额外工作。若现有空闲页不足，内核可能要回收缓存页；若需要回收正在使用的进程页，则还要考虑其内容是否需要保存及之后如何恢复。课堂借这张快照强调：真实系统常把物理内存充分利用起来，申请新页时并不保证总有完全闲置的 RAM 可立即交付。

`top` 的进程列还显示 `VIRT` 与 `RES` 的区别。`VIRT` 反映进程拥有的虚拟地址空间范围，`RES` 反映其当前驻留在物理内存中的部分；课堂示例中许多进程的 `RES` 明显小于 `VIRT`。这种差距与上一讲的按需分页相呼应：进程可以先拥有一段合法虚拟地址，只有访问到某些页时才需要分配或载入对应的物理页。

## 关键解读

**缓存占用与进程驻留要分开看。** `buff/cache` 是系统为加速 I/O 使用的一类物理内存；`RES` 是从进程视角观察驻留页。两组数字的统计口径不同，不能把所有缓存都算成某个进程的实际占用，也不能把低 `free` 直接等同于无法分配新内存。

**`VIRT` 大于 `RES` 说明虚拟地址与物理驻留并非一一对应，但不能仅凭这一点确定原因。** 未触及的按需分配页、尚未载入的文件映射页等都可能造成差距。判断某个进程的具体内存来源，还需要结合其映射和更细的内存统计；课堂在此主要用这组数字说明虚拟内存机制在实际系统中的效果。

**这段是从 page fault 过渡到设备中断的背景。** 页面载入、缓存回收和文件 I/O 都可能涉及磁盘等设备，而设备完成工作后怎样通知内核，是接下来中断与设备驱动课程要解决的问题。
