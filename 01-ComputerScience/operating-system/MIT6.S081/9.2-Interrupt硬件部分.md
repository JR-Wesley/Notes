## 本节知识点

中断是硬件设备主动请求 CPU 关注的机制。以 UART 收到字符或发送完字符为例，设备不必等当前进程主动调用某个函数；它发出中断请求，处理器暂停原来的执行流，转入内核的 trap 路径，内核处理完事件后再恢复执行。RISC-V 对中断、系统调用和 page fault 复用 trap 的基本入口机制，但中断的到来时机由外部事件决定。

这带来三项特征。第一，中断是异步的：当前正在运行的进程不一定与产生中断的设备操作有关。第二，设备与 CPU 并行工作，驱动和中断处理代码必须面对并发。第三，内核需要理解设备的寄存器与中断协议，才能正确配置设备、确认事件并启动后续操作。仅知道 CPU 会跳到处理程序，并不足以完成设备交互。

外设中断通常先送到 PLIC（Platform-Level Interrupt Controller）。设备有对应的中断源编号；PLIC 接收请求，按配置将待处理的外部中断送往某个处理器核心。核心处理时需要领取（claim）中断源，并在处理完成后通知 PLIC（complete），使控制器更新该请求的状态。PLIC 负责分发和记录待处理中断；具体该怎样读写 UART 或其他设备，仍由相应驱动负责。

RISC-V 还区分外部中断、软件中断和定时器中断。就 supervisor 模式而言，`sie` 中的相应位控制各类中断是否允许，`sstatus.SIE` 是当前核心的总开关，`sip` 可反映等待处理的中断，`scause` 记录 trap 原因，`stvec` 指向内核入口。中断发生时，硬件保存可供恢复的执行位置等状态；内核随后还要保存其他上下文并识别具体中断源。

## 关键解读

**中断源、PLIC 和 CPU 是三个不同层次。** 设备负责报告事件，PLIC 负责把外部请求分发给核心，CPU 的 trap 机制负责切换执行流。区分这三层，才能理解为什么既要配置设备本身的中断使能，也要配置 PLIC 和处理器侧的使能位。

**“异步”意味着不能假设处理程序属于当前进程。** 例如某进程启动了 UART 输出，设备稍后完成发送时，CPU 可能已经在运行另一进程或内核代码。中断处理必须依据设备状态和驱动维护的数据结构工作，而不能依赖被打断进程恰好就是请求者。

**中断可延后响应，但不能把等待与丢失混为一谈。** 若当前核心暂时关闭中断，或者 PLIC 尚未把请求交给核心，请求可保持待处理状态；恢复允许后再进入处理流程。实际能否保持事件及保持多少事件仍受设备和控制器协议约束，驱动需要按硬件文档处理。
