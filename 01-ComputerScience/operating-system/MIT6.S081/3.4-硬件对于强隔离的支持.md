## 本页知识点

前一节提出，内核要防御不可信应用，必须有应用无法自行绕开的隔离机制。本节把硬件支持分成两个互补部分：处理器的权限模式限制哪些指令与操作可以由应用执行；页表支持的虚拟内存限制程序能够访问哪些内存。只靠软件约定要求应用“不要越界”，无法对恶意程序形成强隔离。

| 硬件机制 | 要回答的问题 | 在课程中的位置 |
| --- | --- | --- |
| User mode 与 Supervisor mode | 当前运行的代码是否有权执行特权操作？ | 为应用与内核划出执行权限边界。后续 3.5 节讨论如何跨越边界请求内核服务。 |
| 页表与虚拟内存 | 当前进程的地址可以映射到哪些物理内存，以及能否访问？ | 为进程间和用户／内核间的内存保护提供基础；后续页表课程再展开。 |
| RISC-V Machine mode | 处理器是否还有比 Supervisor mode 更高的运行模式？ | RISC-V 还定义 Machine mode；本节只需知道不能把“user/kernel”误当作该架构的全部模式。 |

## 关键解读

**权限模式保护“能做什么”，页表保护“能碰哪里”。** 普通程序即使知道内核代码地址，也不应因此获得执行特权指令的能力；即使会构造某个内存地址，也不应因此读取或覆盖任意物理内存。两类硬件机制共同使操作系统的隔离策略能够被强制执行。

**硬件提供能力，内核负责配置与使用。** 处理器可以区分运行模式、检查地址转换权限，但哪些进程可访问哪些页面、何时进入内核服务仍取决于操作系统的设计与实现。因此学习时应分别问：硬件拒绝了什么？内核设置了什么？应用通过什么受控接口请求服务？

**不要把三种模式和后续细节混在一起。** 课程此处建立 User、Supervisor、Machine mode 的层级意识，以及页表的保护作用；系统调用怎样从 User mode 转入 Supervisor mode、页表项如何表示权限，会在后续章节更具体地讨论。由于原页未能直接读取，这里的范围划分是基于相邻章节的学习性整理。
