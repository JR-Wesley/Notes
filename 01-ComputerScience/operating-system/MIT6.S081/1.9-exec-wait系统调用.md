# 1.9 exec、wait 系统调用

> 原页面：[MIT 6.S081 中文翻译：1.9 exec, wait 系统调用](https://mit-public-courses-cn-translatio.gitbook.io/mit6-s081/lec01-introduction-and-examples/1.9-exec-and-wait-systemcall)。本次原页面正文未能直接读取；以下依据[按章节整理的课程笔记](https://www.cnblogs.com/looking-for-zihuatanejo/p/17564124.html#19-exec执行指令-wait等待子进程退出)及前后章节核对。本文概括接口语义，不代表已验证 xv6 实验代码。

## 本页知识点

`fork` 产生子进程，但子进程起初仍执行与父进程相同的程序。`exec` 接收目标程序路径和参数，读取程序文件，用它替换**当前进程**的程序映像，并开始执行新程序。它不额外创建进程。成功的 `exec` 不会回到原程序中紧随调用的语句；如果加载失败，才会返回，使程序有机会处理错误。

课程示例让 Shell 先 `fork`，再由子进程调用 `exec` 运行如 `echo` 这样的命令。Shell 自身保留为父进程，所以命令运行完后还可以继续接收输入。`exec` 后，新程序仍可使用调用前已打开的文件描述符；这为继承标准输入输出及后续的 I/O 重定向提供了基础。

父进程可以调用 `wait` 等待子进程退出。示例中，`wait` 返回已退出子进程的 PID，并通过传入的状态地址把退出状态交给父进程；若父进程不关心状态，可以传入空指针。页面用 `exit(0)` 表示成功，用非零值表示错误，这是该示例采用的约定。

| 操作 | 对进程的作用 | 对 Shell 执行命令的意义 |
| --- | --- | --- |
| `fork` | 创建子进程，父子进程分别继续执行。 | 为命令准备独立的执行进程。 |
| `exec` | 在当前进程中装入新程序；成功时不返回旧代码。 | 让子进程运行用户指定的命令。 |
| `wait` | 等待子进程结束并获取其结果。 | 让父进程知道命令何时完成。 |

## 关键解读

**“新进程”和“新程序”是两件事。** `fork` 改变进程数量；`exec` 改变某个既有进程执行的程序。把二者连起来，Shell 才能既启动命令，又保持自身继续工作。`exec` 替换的是当前进程的程序映像，不能理解为进程身份本身消失。

**文件描述符跨越 `exec` 是有意设计的接口组合。** 子进程可以先准备好输入输出连接，再装入目标程序；目标程序只需遵循标准描述符约定，无需知道 Shell 如何设置它们。下一节的重定向正是利用这一点。

**等待与退出状态让父进程获得结果。** Shell 不仅要启动命令，还需知道命令是否结束及其退出状态。阅读示例时，可沿“父进程等待—子进程执行—子进程退出—父进程恢复”顺序追踪控制流。页面提到 `fork` 后立即 `exec` 会使前者复制的许多内存很快被替换；copy-on-write 是后续讨论的优化，本节不展开其实现。
