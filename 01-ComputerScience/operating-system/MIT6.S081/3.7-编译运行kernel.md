# 3.7 编译运行 kernel

> 来源：[MIT 6.S081 中文翻译：3.7 编译运行 kernel](https://mit-public-courses-cn-translatio.gitbook.io/mit6-s081/lec03-os-organization-and-system-calls/3.7-bian-yi-yun-xing-kernel)。本文整理页面展示的构建与启动路径；未在本地编译或运行 xv6。

## 本页知识点

xv6 代码可先按用途看成三个部分：`kernel` 目录放内核代码，宏内核中的各模块最终链接成一个内核可执行文件并以特权模式运行；`user` 目录放用户态程序；`mkfs` 工具创建用于启动的文件系统镜像。这样的目录划分把上一节的内核组织方式落实到了构建产物。

页面用 `proc.c`、`pipe.c` 展示编译链：C 源码经编译器成为 RISC-V 汇编，再经汇编器成为 `.o` 目标文件，最后由**链接器**把多个目标文件组合成内核文件。原文把汇集 `.o` 的环节称为“Loader”，按通常工具链术语，这一步应理解为链接；启动时把内核装入虚拟机是另一件事。页面所示的 `.s` 中间文件是解释编译过程的视角，实际生成哪些中间文件应以所用 xv6 版本的 Makefile 为准。

| 产物或参数 | 在本页中的作用 |
| --- | --- |
| `.o` 目标文件 | 各源文件编译、汇编后的机器代码与待链接信息。 |
| 内核可执行文件 | 链接后的整体内核，作为 QEMU 的 `-kernel` 输入。 |
| `kernel.asm` | 包含内核反汇编，便于将地址、机器码与汇编指令对照，用于调试。 |
| `fs.img` | 由文件系统构建流程准备的磁盘镜像，经 `-drive` 提供给虚拟机。 |
| QEMU 的 `-m`、`-smp` | 分别指定虚拟机内存规模与可用 CPU 核数。 |

页面举出 `kernel.asm` 中地址 `0x80000000` 附近的 RISC-V 指令，并说明旁边的十六进制数是指令的机器编码。随后由 Makefile 启动 `qemu-system-riscv64`，通过 `-kernel`、`-m`、`-smp`、`-drive` 等参数提供内核、虚拟硬件规模和磁盘镜像。

## 关键解读

**从源码到运行中的内核有两次不同的组合。** 编译与链接把许多内核源文件变成一个程序；QEMU 再把这个程序和模拟的处理器、内存、磁盘放到同一运行环境中。理解构建错误时看编译／链接阶段，理解启动或运行错误时再看模拟硬件与内核执行阶段。

**`kernel.asm` 连接源码理解与机器执行。** 调试器给出地址或当前指令时，可以用反汇编找到其所属代码位置，核对真实执行的指令。源码、汇编助记符和十六进制机器码是同一程序的不同表示，不能把机器码列当作另一个独立步骤。

**构建产物依赖具体版本。** 页面展示的是当次课程使用的 xv6 构建方式。自行复现实验时，应检查对应仓库的 Makefile、交叉编译工具链和 QEMU 参数，不能仅凭这页的概念描述假定本机已有相同环境。
