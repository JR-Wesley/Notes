# 5.1 C 程序到汇编程序的转换

> 原页面：[MIT 6.S081 中文翻译：5.1 C程序到汇编程序的转换](https://mit-public-courses-cn-translatio.gitbook.io/mit6-s081/lec05-calling-conventions-and-stack-frames-risc-v/5.1-introduction-to-lecture05)。本文按该小节整理；其中关于 `.o`、`.asm` 和处理器执行内容的表述作了必要的技术澄清。

## 本页知识点

第 5 讲转向 RISC-V 汇编语言、处理器和调用约定（calling convention）。课程指出，这些知识对后续 traps 实验尤其重要：阅读 trapframe、栈以及用户态与内核态之间的切换代码时，必须看懂寄存器和汇编指令如何配合。本节只是建立从 C 程序到处理器指令的基本路径，具体寄存器约定和栈帧在后续小节展开。

C 源码不能直接由处理器执行。编译器把 C 程序转换为目标架构的机器指令；汇编文本是这些指令的可读表示，汇编器负责将汇编文本编码为机器码。目标文件（如 `.o`）保存机器码及供链接使用的信息，链接器再把所需目标文件组合成可加载的程序。课程为说明主线省略了部分编译、汇编和链接细节，重点是：最终执行的指令必须符合处理器支持的指令集架构（ISA）。

RISC-V 是 ISA 的一种。ISA 规定处理器可识别的指令、寄存器和相关行为；指令有相应的二进制编码。`add` 等汇编助记符方便人阅读，但硬件实际取指、解码的是机器码。C 中的表达式、分支、循环和函数调用，最终都需要通过较低层的指令序列实现。

原页提示可以在 xv6 的构建目录中观察 `.o` 和 `.asm` 文件。阅读 `.asm` 有助于把 C 函数与实际指令对应起来，但 `.asm` 的具体生成方式取决于构建脚本：它可能是编译器输出的汇编文本，也可能是对已生成机器码做的反汇编。不能仅凭扩展名推断它必然是编译器直接产生的文件。

## 关键解读

**把“语言形式”和“执行形式”分开。** C 是程序员常用的高级语言，汇编是贴近 ISA 的文本表示，机器码是处理器执行的编码。处理器理解 RISC-V 指令编码，并不是直接读取 C 源码或汇编助记符。

**C 的结构在汇编中会被展开。** 汇编通常以顺序指令、条件分支、跳转和标号表达控制流；循环仍能实现，只是不再保留 C 语言的 `for` 或 `while` 语法。函数也仍能调用，但参数传递、返回地址和寄存器保存要遵守调用约定。后面的小节会逐步解释这些约定。

**学习目标是能追踪行为。** 阅读 xv6 的 trap 相关代码时，先确认当前指令使用哪些寄存器、修改了哪些状态，再追踪它如何转移到下一段代码。无需把本节当成完整的编译器或链接器教程。
