# 6.5 `uservec` 函数

> 原页面：[MIT 6.S081 中文翻译：6.5 uservec 函数](https://mit-public-courses-cn-translatio.gitbook.io/mit6-s081/lec06-isolation-and-system-call-entry-exit-robert/6.5-uservec)。实现细节对照课程使用的 [2020 xv6 book，第 4 章](https://pdos.csail.mit.edu/6.828/2020/xv6/book-riscv-rev1.pdf)；后续版本的 xv6 可能调整函数名、参数和汇编细节。

## 本页知识点

`uservec` 是用户态 trap 进入 xv6 后首先执行的汇编入口。刚开始时仍使用用户页表，所有通用寄存器都保存用户程序状态，内核既没有可随意使用的通用寄存器，也不能依赖用户栈。xv6 通过每进程 trapframe 与 `sscratch` 共同打破这个困局。

内核把每个进程的 trapframe 映射到用户页表中的固定虚拟地址 `TRAPFRAME`，但不设置 `PTE_U`，所以用户代码不能访问。trapframe 一部分槽位用于保存用户寄存器，另一部分由内核预先写入进入内核所需的信息，包括内核页表的 `satp` 值、进程内核栈顶、`usertrap` 地址以及当前 hart 的编号。这使入口代码在尚未切换页表时就能取得可信的内核状态。

进入用户态前，内核让 `sscratch` 保存 trapframe 地址。`uservec` 首先执行 `csrrw a0, sscratch, a0`，交换 `a0` 与 `sscratch`：用户的 `a0` 暂存进 `sscratch`，而 `a0` 获得 trapframe 地址。随后一系列 `sd` 指令以 `a0` 为基址保存用户寄存器，最后再把 `sscratch` 中原来的用户 `a0` 保存到对应槽位。

寄存器保存完成后，`uservec` 从 trapframe 取出 `kernel_sp` 写入 `sp`，取出 hart ID 写入 `tp`，把 `usertrap` 地址和内核页表对应的 `satp` 值装入临时寄存器。接着写 `satp` 切换至内核页表，并按实现需要使用 `sfence.vma` 处理地址转换缓存，最后通过间接跳转进入 `usertrap`。到这里，处理器才拥有内核栈、内核页表和可供 C 代码使用的寄存器环境。

页表切换不会令当前代码失效，因为 trampoline 页面以相同虚拟地址映射到用户页表和内核页表，并指向同一物理页面。程序计数器在切换前后指向同一虚拟地址，取到的仍是同一段 `uservec` 指令，这正是 “trampoline” 名称所表达的过渡作用。

## 关键解读

**trapframe 是受内核控制、但在入口阶段可寻址的桥接区。** 它出现在用户页表中不代表属于用户可访问内存；`PTE_U=0` 阻止用户态访问，而固定映射让 supervisor mode 的入口汇编能在用户页表仍生效时保存上下文。内核不能把寄存器直接压到用户栈，因为用户 `sp` 可能无效、恶意，或者指向内核不了解的语言运行时结构。

**入口所需信息必须在返回用户态前准备好。** 第一次运行用户进程也不例外：机器从内核启动，进入用户态只能经过内核构造好的返回路径。该路径预置 `stvec`、`sscratch` 和 trapframe 中的内核状态，之后执行 `sret`；因此进程第一次触发 trap 时，`uservec` 已具备全部入口条件。

**课程中“交换 `satp` 和 `t1`”是口头简化。** 关键动作是把预先编码好的内核页表值写入 `satp`，旧 `satp` 是否保留在该临时寄存器取决于具体指令与课程版本。阅读源码时应以实际的 CSR 指令以及紧邻的 `sfence.vma` 为准，不要把描述理解成固定的双向交换协议。
