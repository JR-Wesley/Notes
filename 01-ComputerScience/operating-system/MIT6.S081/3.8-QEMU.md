# 3.8 QEMU

> 来源：[MIT 6.S081 中文翻译：3.8 QEMU](https://mit-public-courses-cn-translatio.gitbook.io/mit6-s081/lec03-os-organization-and-system-calls/3.8-qemu)。页面用概念模型解释模拟器；涉及 RISC-V 指令长度和寄存器名称时，以[RISC-V ISA 规范](https://docs.riscv.org/reference/isa/v20240411/unpriv/intro.html)与[ABI 规范](https://docs.riscv.org/reference/application-software/abi/_attachments/riscv-abi.pdf)校正。

## 本页知识点

运行 xv6 时，可以把 QEMU 提供的环境想成一台 RISC-V 计算机：它有处理器、内存以及供操作系统访问的设备。页面借一块实际主板说明这幅心智模型，列举 CPU 核、缓存、DRAM 控制器、UART 和时钟等部件。QEMU 在宿主机的软件中模拟这些部件，使 xv6 可以像面对硬件那样启动和运行。

页面把处理器模拟概括为循环取出客体指令、识别操作并推进客体状态。模拟器需要保存客体寄存器等状态；执行一条加法指令后，目标寄存器的值应随之改变。它不仅要处理普通指令，也要呈现 xv6 所依赖的特权行为。授课者还说明，课程使用的 QEMU 在模拟多个 CPU 核时可借助宿主机线程并行运行。

## 关键解读

**区分宿主机与客体机。** QEMU 是在宿主操作系统上运行的程序；xv6 看到的是 QEMU 提供的 RISC-V 处理器和设备。调试时应先判断问题位于宿主工具链、模拟硬件配置，还是客体 xv6 代码，不能把两层环境混为一谈。

**“取指—译码—执行”是理解模型，不是对 QEMU 全部实现的精确描述。** 它说明为什么客体代码能影响模拟寄存器与设备状态；无需据此推断 QEMU 的每条指令都只能由一个简单循环逐条解释执行。对学习 xv6 而言，关键是客体程序观察到符合目标机器接口的结果。

**校正页面中的两处细节。** 原文把 RISC-V 指令说成“4 字节或者 8 字节”，并在例子中把 `a0` 与 `x0` 混用。基础 RISC-V 指令是 32 位；启用压缩扩展时常见的还有 16 位指令，不能概括为“4 或 8 字节”。`x0` 是不可修改的零寄存器，`a0` 对应 `x10`。这些事实来自上述 RISC-V 规范；不影响本页关于模拟器维护客体状态的主旨。
