# 1.1 课程内容简介

> 来源：[MIT 6.S081 中文翻译：1.1 课程内容简介](https://mit-public-courses-cn-translatio.gitbook.io/mit6-s081/lec01-introduction-and-examples/1.1-ke-cheng-jian-jie)。本文概括该页内容；“关键解读”是基于原文目标所作的学习性解释，不代表课程在本页已经讲解了具体实现。

## 本页知识点

MIT 6.S081 希望学生同时理解操作系统的**设计**与**实现**：设计关注系统整体如何组织，实现关注代码如何落实这些设计。课程以教学操作系统 xv6 为实践对象，通过阅读系统、完成实验和使用操作系统接口编写系统软件，建立从抽象概念到代码行为的联系。

原文列出的操作系统目标可以按它们所回答的问题来理解：

| 目标 | 要解决的问题 | 本页举例或含义 |
| --- | --- | --- |
| 硬件抽象（abstraction） | 应用如何避免直接面对 CPU、内存等低层资源？ | 提供进程、文件系统等更易用、较便于移植的接口。 |
| 资源复用（multiplexing） | 多个应用如何共同使用有限硬件？ | 编辑器、编译器和数据库可以在同一系统中运行。 |
| 隔离（isolation） | 一个程序故障时，如何避免干扰其他程序？ | 不同活动需要相互隔离。 |
| 共享（sharing） | 相互隔离的活动如何在需要时协作？ | 编辑器写出的文件可供编译器读取。 |
| 安全与权限（security / access control） | 哪些共享应当被禁止？ | 公共计算机上的其他用户不应随意读取自己的文件。 |
| 性能（performance） | 操作系统提供服务时如何避免妨碍应用发挥硬件性能？ | OS 的开销不应成为应用性能的无谓障碍。 |
| 通用性 | 同一系统如何服务不同场景？ | 桌面程序、游戏、数据库服务器与云计算等工作负载。 |

## 关键解读

**抽象与复用是理解 OS 的入口。** 进程和文件等抽象让应用以稳定接口使用硬件；当多个应用同时使用这些抽象时，操作系统还要协调底层资源。因而学习时要分别追问：“应用看到了什么接口？”以及“系统如何在有限资源上实现这个接口？”本页提出了这些目标，并未展开具体调度或文件系统机制。

**隔离、共享与权限必须一起考虑。** 隔离降低故障和相互干扰的范围，但应用仍需交换数据。文件共享的例子说明，目标不是让活动永远互不可见，而是让数据在被允许时流动。权限控制进一步决定谁可以访问什么资源；能够共享，不等于对所有人开放。

**性能与通用性使设计成为权衡。** 操作系统既要提供上述服务，又要让不同类型的应用获得合理性能。某一种机制是否合适，需要同时看它提供了哪些能力、增加了多少开销，以及面向哪些工作负载。这里是从课程目标得出的学习视角；本页没有给出具体方案或性能数据。

后续阅读 xv6 时，可用三个问题检查理解：该功能向应用提供什么抽象？它如何实现复用、隔离或受控共享？实现代价和适用场景是什么？
