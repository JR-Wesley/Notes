# 5.3 gdb 和汇编代码执行

> 原页面：[MIT 6.S081 中文翻译：5.3 gdb和汇编代码执行](https://mit-public-courses-cn-translatio.gitbook.io/mit6-s081/lec05-calling-conventions-and-stack-frames-risc-v/5.3-gdb-he-hui-bian-dai-ma-zhi-hang)。调试命令另以 [GDB 官方手册：TUI](https://sourceware.org/gdb/current/onlinedocs/gdb.html/TUI.html)与[单步执行](https://www.sourceware.org/gdb/current/onlinedocs/gdb.html/Continuing-and-Stepping.html)核对。

## 本页知识点

本节用一个求 `1` 到 `n` 之和的 `sum_to` 函数练习阅读 RISC-V 汇编。示例先把输入参数从 `a0` 复制到 `t0`，再将 `a0` 清零作为累加器；循环中把当前计数加到 `a0`，递减 `t0`，直到计数为零。对应的 C 逻辑可能很短，但实际汇编由编译器和优化设置决定，自己编译得到的指令顺序、寄存器选择与课件示例不一定相同。

汇编文件中，`.section` 用于指定后续内容所属的节，`.text` 表示代码节，`.globl` 或 `.global` 声明可供链接器从其他目标文件引用的全局符号。函数名通常作为标号出现。xv6 编译后的 `kernel.asm` 可用于查看内核反汇编：指令前的地址能与 GDB 中的程序计数器（PC）对应，标号则帮助定位函数。`.s` 通常用于汇编源文本，`.asm` 在这个仓库中用于带地址和注释的反汇编清单；扩展名本身并非通用语义，实际生成方式应查当前 Makefile。

原页通过 QEMU 与 GDB 调试 `sum_to`：在函数处设置断点，程序停下后比对 PC 与 `kernel.asm` 的地址，再打开汇编和寄存器窗口，观察 `a0`、`t0` 随单条指令变化。TUI 中发生变化的寄存器会高亮，便于把“当前指令做了什么”与“程序状态如何改变”连起来看。如果函数完全由汇编编写，GDB 不会凭空提供对应的 C 源码窗口；调试 C 编译出的代码时则可选择源码与汇编并排显示。

| GDB 命令 | 本节中的用途 |
| --- | --- |
| `tui enable`、`layout asm`、`layout regs` | 打开 TUI，并查看反汇编和寄存器 |
| `layout split`、`layout src` | 同时查看源码与汇编，或只查看源码；需有可用的源码信息 |
| `break sum_to`、`continue` | 在函数入口停下，再继续运行至断点 |
| `stepi`、`nexti` | 按机器指令单步；前者进入调用，后者跨过调用 |
| `info registers`、`info breakpoints` | 查看寄存器状态或已设置的断点 |

## 关键解读

**把 PC、反汇编地址和寄存器放在同一条观察链中。** PC 告诉你下一条将执行的指令位于哪里；`kernel.asm` 告诉你该地址对应什么指令；寄存器窗口告诉你执行前后的状态。三者结合，比只盯着 C 源码更适合分析 trap 入口等汇编路径。

**按指令单步与按源码行单步不同。** 一行 C 代码可能对应多条机器指令，也可能因优化而没有直接对应的指令。要验证循环跳转、参数传递或寄存器保存，就用 `stepi` / `nexti` 逐条看；阅读高层控制流时再使用源码级单步。

**调试信息有边界。** 编译器优化可能使某个 C 变量只存在于寄存器、被合并，或完全消失。此时 GDB 显示“optimized out”并不等于程序未执行相关逻辑，应回到实际指令和寄存器状态判断。文中的 PC 数值是课堂运行示例，不应当作所有构建的固定地址。
