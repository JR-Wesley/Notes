## 本页知识点

寄存器是处理器内部用于保存当前运算值的存储位置。RISC-V 的整数算术通常以寄存器为操作数：先用加载指令把内存中的值取入寄存器，在寄存器中计算，再在需要时把结果写回内存。前一节的 `sum_to` 正是用 `t0` 保存计数、用 `a0` 保存累加结果。本节把这些名字放进函数调用约定中理解。

RISC-V 有 32 个整数寄存器，硬件编号是 `x0`～`x31`；汇编代码常用其 ABI 名称，例如 `x1` 叫 `ra`，`x2` 叫 `sp`，`x10`～`x17` 叫 `a0`～`a7`。在课程使用的 RV64 环境中，整数寄存器宽度为 64 位。`a0`～`a7` 用于传递可放进寄存器的整数或指针参数，`a0`、必要时连同 `a1` 用于返回值；参数超出可用寄存器容量时，额外部分按 ABI 放在栈上。

| 寄存器 | 常见作用 | 跨函数调用的约定 |
| --- | --- | --- |
| `zero` (`x0`) | 固定为零 | 无需保存 |
| `ra` (`x1`) | 保存返回地址 | caller saved；再次调用函数会改写它 |
| `sp` (`x2`) | 指向当前栈顶 | callee 必须按约定恢复 |
| `t0`～`t6` | 临时计算值 | caller saved |
| `a0`～`a7` | 参数；`a0`、`a1` 还可承载返回值 | caller saved |
| `s0`～`s11` | 需跨调用保留的值；`s0` 可作 `fp` | callee saved；callee 若使用须恢复 |
| `gp`、`tp` | 全局指针、线程指针 | 有专门用途，不当作普通临时寄存器 |

“Caller saved”指调用方若还需要原值，必须在调用前自行保存；它并不表示每次调用都会自动保存。“Callee saved”指被调用方若修改该寄存器，返回前必须恢复原值。`ra` 是理解这一区别的好例子：函数 A 调用 B 时，新调用会改写 `ra`；如果 A 随后仍需用原返回地址返回自己的调用者，就要事先妥善保存。下一节的栈帧将展示这种保存如何发生。

原页还提到压缩指令和多寄存器返回值。这里应分清三种宽度：RV64 整数寄存器为 64 位；常规基础指令编码为 32 位，C 压缩扩展提供 16 位编码；在 RV64 C ABI 中，`long long` 仍是 64 位，而更宽且符合 ABI 规则的返回值才可能用 `a0`、`a1` 两个寄存器表示。并非所有压缩指令都只使用 `x8`～`x15`，应以具体指令格式为准。

## 关键解读

**ABI 名称体现的是约定。** `x10` 是硬件编号，`a0` 提示它在函数入口可能装参数、在函数出口可能装返回值。读汇编时先根据 ABI 名称判断寄存器角色，再看当前指令如何改变它；不要把“通常用途”误解为硬件强制限制。

**保存责任取决于谁需要保留值。** 调用方只需保存调用后仍要使用的 caller saved 值；被调用方只需恢复自己实际修改过的 callee saved 值。因此函数入口不必机械地保存整张寄存器表，具体保存哪些寄存器由函数行为和编译结果决定。

**寄存器宽度不等于指令长度或 C 类型宽度。** 把这三者分开，才能正确理解 RV64、压缩指令与返回值布局，也能避免把课堂示意中的口头简化当作 ABI 规则。
