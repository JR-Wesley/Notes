# 4.2 地址空间（Address Spaces）

> 原页面：[MIT 6.S081 中文翻译：4.2 地址空间](https://mit-public-courses-cn-translatio.gitbook.io/mit6-s081/lec04-page-tables-frans/4.2-di-zhi-kong-jian-address-spaces)。本文按该小节内容整理；页表的具体结构留待 4.3。

## 本页知识点

本节从内存隔离的目标引入地址空间：Shell、cat 等用户程序应彼此隔离，也应与内核隔离。若程序直接用同一套物理地址访问 DRAM，一个出错的 cat 程序就可能把数据写进 Shell 所在的物理内存，破坏后者的代码或数据。课程用“Shell 占据物理地址 1000～2000，而 cat 向地址 1000 写入”的简化例子说明风险。

地址空间使每个进程拥有自己可使用的一套地址；内核也有自己的地址空间。因此，cat 和 Shell 都可以使用数值为 1000 的地址，但两次访问应分别作用于各自被映射的内存。进程不能仅凭猜出另一个进程的地址数值，就读写对方的内存。要在同一组 DRAM 上实现这种效果，操作系统需要正确设置并管理页表；页表怎样完成地址映射是下一节的主题。

虚拟地址空间的大小不必等于机器的物理内存容量，也不必因有多个进程而简单地按进程数平分物理内存。不过，实际使用的物理页和页表仍会消耗有限的内存，进程过多或分配过大时可能耗尽。课程以 xv6 的 `kalloc` 为例：空闲物理页用尽时，分配可能返回空指针，内核需要处理失败并向应用报告错误，而不能假定分配必然成功。

## 关键解读

**相同的地址数值不等于相同的物理位置。** 地址 1000 对 cat 和 Shell 各有意义，最终访问哪一处物理内存取决于当前地址空间的映射。课程中的 1000 只是演示数字；理解时应分别追踪“进程看到的地址”和“DRAM 中实际存放数据的位置”。

**隔离取决于映射是否正确。** 给进程命名一个“专属地址空间”还不足以保证安全；若页表错误地允许 cat 访问 Shell 或内核的物理页，隔离仍会失效。课程明确把正确设置与管理页表作为实现强隔离的前提。

**地址空间容量和已分配物理内存是两回事。** 虚拟地址范围可以很大，但只有实际建立并使用的映射才对应相应资源。由此可以理解“虚拟空间比物理内存大”与“物理内存仍可能耗尽”并不矛盾。下一节需要进一步看地址如何经页表转换，以及哪些访问会被允许或拒绝。
