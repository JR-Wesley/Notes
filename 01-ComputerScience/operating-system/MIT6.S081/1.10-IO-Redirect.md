# 1.10 I/O Redirect

> 来源：[MIT 6.S081 中文翻译：1.10 I/O Redirect](https://mit-public-courses-cn-translatio.gitbook.io/mit6-s081/lec01-introduction-and-examples/1.10-io-redirect)。本页用输出重定向串起 Lec01 介绍的进程与文件接口。

## 本页知识点

Shell 中的 `echo hello > out` 把 `echo` 的标准输出送入文件 `out`；`cat < out` 则把该文件作为 `cat` 的标准输入。本页重点解释输出重定向：Shell 先 `fork`，让子进程调整自己的文件描述符，再用 `exec` 运行目标程序。父进程的标准输出不受子进程的调整影响，因此 Shell 仍可正常显示提示符。

示例的关键步骤是：在子进程中调用 `close(1)`，释放原先指向 console 的标准输出描述符；随后用适当标志 `open("output.txt", ...)`。在该示例中，描述符 `0` 仍被占用，`1` 是最小的空闲编号，因此 `open` 返回 `1`，使它指向输出文件。接着执行 `exec("echo", ...)`；`exec` 保留已设置的文件描述符，`echo` 按惯例向 `1` 写数据，于是输出进入文件。父进程可以等待子进程结束，再继续工作。

| 阶段 | 子进程中的描述符 `1` | 执行的程序 |
| --- | --- | --- |
| `fork` 刚返回 | 指向原来的 console 输出 | 仍执行 Shell 的代码 |
| `close(1)` 后 | 空闲 | 仍执行 Shell 的代码 |
| `open` 输出文件后 | 指向输出文件 | 仍执行 Shell 的代码 |
| `exec` 成功后 | 继续指向输出文件 | 执行 `echo` |

## 关键解读

**重定向改变的是描述符连接，而非命令程序本身。** `echo` 不需要识别 `>`，也不需要知道输出文件名；它只向标准输出写入。Shell 负责解释用户输入，并在启动命令前准备好描述符。这样同一个程序既可向终端输出，也可向文件输出。

**`fork` 与 `exec` 之间的间隔提供了配置机会。** `fork` 后，子进程暂时仍运行 Shell 的指令，因而可以先 `close`、`open`，再用 `exec` 装入命令。改变发生在子进程的描述符空间内；父 Shell 的描述符 `1` 保持原状。这里展示了几个简单系统调用如何组合出更高层的 Shell 功能。

**`open` 返回 `1` 依赖示例的描述符状态。** 先释放 `1`，并确认更小的编号仍被占用，才能推出下一次 `open` 会选到 `1`。阅读类似代码时，应明确哪些描述符已经打开，而不能把“`open` 总返回 `1`”当作普遍规则。
