# 6.3 ECALL 指令之前的状态

> 原页面：[MIT 6.S081 中文翻译：6.3 ECALL 指令之前的状态](https://mit-public-courses-cn-translatio.gitbook.io/mit6-s081/lec06-isolation-and-system-call-entry-exit-robert/6.3-before-ecall)。本节通过 GDB 和 QEMU 观察 Shell 执行 `write` 时、`ecall` 尚未执行前的处理器状态。

## 本页知识点

Shell 使用 `write(2, "$ ", 2)` 输出提示符。用户态的 `write` 包装函数位于 `usys.S`：它先把系统调用号 `SYS_write`（课程版本中为 16）装入 `a7`，再执行 `ecall`；内核处理结束后，从 `ecall` 后面的 `ret` 继续，最终返回 Shell。这里同时使用了两套约定：`a0`、`a1`、`a2` 依次携带文件描述符、缓冲区地址和字节数，`a7` 携带系统调用号。

课程在 `sh.asm` 中找到 `ecall` 的地址并设置断点。停下后，程序计数器仍指向用户空间中的 `ecall`，通用寄存器仍保存用户程序状态；检查 `a1` 指向的内存，可以看到准备输出的美元符号和空格。此时 `pc`、`sp` 都位于较低的用户虚拟地址，表明处理器尚未进入 trap 入口。

当前 `satp` 对应 Shell 的用户页表。QEMU 的 `info mem` 显示，该页表主要映射 Shell 的代码、数据和栈，还包含靠近虚拟地址顶端的 `TRAPFRAME` 与 `TRAMPOLINE` 页面。两者没有设置 `PTE_U`，所以用户态不能访问；它们却必须出现在用户页表中，因为 trap 刚发生时硬件不会自动换页表，入口代码需要在原页表下先执行并保存状态。

页表项的 `R`、`W`、`X` 表示读、写、执行权限，`U` 控制用户态访问，`A`（Accessed）记录页面是否被访问，`D`（Dirty）记录页面是否被写入。较完整的操作系统可利用 `A`、`D` 判断页面活跃程度及换出时是否需要回写；xv6 本身没有实现这类页面置换策略。

## 关键解读

**断点展示的是切换前的基线。** 在执行 `ecall` 前，寄存器、程序计数器、栈和页表都属于用户进程。下一节观察 `ecall` 后的状态时，应逐项与此基线比较，才能分清硬件自动改变了什么，以及入口汇编还必须完成什么。

**系统调用参数没有被单独复制到特殊硬件区域。** 它们最初只是普通参数寄存器中的值。trap 入口必须先保存寄存器，内核随后才能从 trapframe 中可靠地取得系统调用号和参数；其中的指针仍是用户虚拟地址，内核使用前还必须检查并安全访问。

**高地址映射是 trap 得以启动的桥梁。** 用户页表不包含普通内核代码与数据映射，但包含不可由用户访问的 trampoline 和 trapframe。这样既保持用户与内核的隔离，又让处理器在尚未切换 `satp` 时有一小段可信入口代码和保存状态的空间可用。
