# 1.2 操作系统结构

> 来源：[MIT 6.S081 中文翻译：1.2 操作系统结构](https://mit-public-courses-cn-translatio.gitbook.io/mit6-s081/lec01-introduction-and-examples/1.2-cao-zuo-xi-tong-jie-gou)。本文按该页内容整理；“关键解读”补充概念之间的联系。

## 本页知识点

这一节用分层视角介绍计算机系统：底层是 CPU、内存、磁盘和网卡等硬件；上层是编辑器、编译器、Shell 等用户空间程序；内核（kernel）位于两者之间，管理资源并向程序提供服务。课程后续主要关注内核、内核内部的组织，以及用户程序进入内核的接口。

| 层次或机制 | 本页强调的职责 |
| --- | --- |
| 用户空间与进程 | 应用程序作为进程运行，各自需要内存并共享 CPU 时间。 |
| 内核 | 保存管理进程和硬件资源所需的数据结构，提供文件系统、进程管理、内存分配等服务。 |
| 文件系统 | 管理文件内容在磁盘上的位置，以及文件名和层级目录构成的命名空间。 |
| 访问控制 | 判定进程能否使用内存、读取数据等资源；多用户系统还需考虑不同用户的访问规则。 |
| 系统调用 | 构成用户程序访问内核服务的接口。调用形式类似函数，但会进入内核执行对应实现。 |

页面用三个系统调用快速展示这一接口。`open` 接收文件名和打开方式，成功后返回文件描述符（file descriptor，`fd`）；应用随后以 `fd` 指明要操作的已打开文件。`write` 接收 `fd`、待写数据的内存地址和字节数，内核据此将指定字节写入相应文件。`fork` 用来创建新进程；页面只给出直观预览，具体返回值与实现细节留待后文。

## 关键解读

**系统调用是分层结构的连接点。** 应用只需提供文件名、数据地址等参数；内核负责解释请求、管理文件和底层设备，并返回结果。因此，理解一个系统调用时应同时看应用侧的参数与返回值，以及内核侧为实现它必须维护的状态。`fd` 是应用后续引用已打开文件的句柄，并非磁盘上文件内容本身。

**不同内核服务共同支撑同一次操作。** 一次文件写入表面上属于文件系统操作，但进程需要先获得访问权限，内核还要从进程提供的内存地址取得数据，并处理文件到存储设备的映射。这说明“进程管理、内存管理、文件系统、访问控制”是帮助理解职责的划分，实际请求会跨越这些职责。此处是对页面结构的解释，尚非 xv6 具体代码路径。

**本节先建立接口与职责地图。** 页面把 `open`、`write`、`fork` 作为例子，并未完整讲解系统调用入口、文件描述符的内部表示或 `fork` 的精确语义。后续读 xv6 时，可分别追踪：用户程序发起了什么请求，内核检查和修改了哪些状态，结果如何返回用户程序。
