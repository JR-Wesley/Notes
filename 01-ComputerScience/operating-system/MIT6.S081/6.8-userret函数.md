# 6.8 `userret` 函数

> 原页面：[MIT 6.S081 中文翻译：6.8 userret 函数](https://mit-public-courses-cn-translatio.gitbook.io/mit6-s081/lec06-isolation-and-system-call-entry-exit-robert/6.8-userret)。本节完成 Lec06 的系统调用往返路径，具体寄存器偏移对应课程使用的 xv6 版本。

## 本页知识点

`usertrapret` 配置好控制寄存器并跳入 trampoline 后，`userret` 接管最后的返回工作。它首先把作为参数传入的用户页表值写入 `satp`，并通过 `sfence.vma` 处理地址转换缓存。切换后，普通内核映射不再可用，但 trampoline 在内核页表和用户页表中具有相同的虚拟地址映射，所以当前汇编指令仍能继续执行。

课程版本中，`a0` 保存固定的 trapframe 虚拟地址。`userret` 先从 trapframe 的 `a0` 槽位取出用户应看到的值，并暂存进 `sscratch`。对于本页的 `write` 示例，这个槽位已经被 `syscall()` 改写为返回值 2。随后汇编以 trapframe 为基址，把先前保存的用户寄存器逐一恢复；此时 `a0` 暂时仍要充当 trapframe 指针，所以留到最后处理。

大部分寄存器恢复后，用户的 `sp`、参数寄存器及其他执行状态已经重新出现。最后一条 `csrrw` 交换 `a0` 与 `sscratch`：`a0` 获得系统调用返回值，`sscratch` 再次保存 trapframe 地址，为下一次 trap 的 `uservec` 入口做好准备。这样同一条交换指令在进入和返回方向上形成对称协议。

最后执行 `sret`。此前 `usertrapret` 已把 `sstatus.SPP` 清零、把 `SPIE` 置位，并将恢复地址写入 `sepc`；因此 `sret` 将权限降回 U-mode，把 `sepc` 复制到程序计数器，并按 `SPIE` 恢复中断使能状态。程序从 `ecall` 后面的 `ret` 继续，先返回用户态 `write` 包装函数，再返回 Shell。

## 关键解读

**页表必须在 trampoline 内切换。** 一旦装入用户页表，普通内核 C 代码和内核栈通常无法再按原虚拟地址访问。只有同时映射在两套页表中的 trampoline 可以跨越这一瞬间，继续完成寄存器恢复和 `sret`。

**`a0` 承担了三种连续角色。** 进入系统调用前它是第一个参数；处理期间 trapframe 的 `a0` 槽位被改写为返回值；返回汇编开始时真实 `a0` 又暂作 trapframe 指针。最后与 `sscratch` 交换，才让真实 `a0` 变成用户应收到的返回值，并为下一次入口保留 trapframe 地址。

**`sret` 的效果由预先配置的控制状态决定。** 原页把它概括为返回用户态、跳到 `sepc` 并打开中断；更准确地说，目标权限由 `SPP` 决定，中断状态从 `SPIE` 恢复。`sret` 并不自行判断应该回到哪个进程，也不负责恢复通用寄存器，这些条件都必须由前面的 C 代码和 `userret` 汇编准备好。

本讲展示了完整闭环：`ecall → uservec → usertrap → syscall → usertrapret → userret → sret`。系统调用表面上像普通函数调用，背后却需要硬件与软件共同保存状态、切换权限和地址空间，并始终把用户提供的状态视为不可信数据。
