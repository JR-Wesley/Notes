# 1.4 课程结构和资源

> 来源：[MIT 6.S081 中文翻译：1.4 课程结构和资源](https://mit-public-courses-cn-translatio.gitbook.io/mit6-s081/lec01-introduction-and-examples/1.4-ke-cheng-zi-yuan)。页面描述的是当次授课的安排与评分方式，具体比例、平台及实验要求不应当作当前课程政策。

## 本页知识点

这门课由课前阅读、课堂讲授和编程实验构成。课堂既讲操作系统基本概念，也阅读和演示 xv6 代码；部分课程补充实验所需的 C 语言与 RISC-V 知识，后期还会讨论操作系统论文。课前阅读 xv6 教材或指定论文，并提出问题，是参与课堂讨论的准备。

| 环节或资源 | 页面中的作用 |
| --- | --- |
| 课程网站 | 发布课程计划、实验内容和课程安排。 |
| Piazza | 讨论实验问题与发布课程通知。 |
| 课前阅读与提问 | 先了解 xv6 的运行与设计，或阅读指定论文，再带着问题参与课堂。 |
| 课堂 | 理解概念、追踪 xv6 代码，并学习实验需要的基础知识。 |
| Lab | 从编写使用系统调用的应用程序起步，逐渐实现或扩展操作系统功能，积累实际经验。 |

页面强调实验是课程的主体。原授课安排中，实验代码测试占成绩 70%，实验理解核查占 20%，其余 10% 来自作业与参与；当次课程没有考试和测验。这些数字说明该版课程重视动手能力与对实现的解释能力，不能直接用于判断其他年份的评分规则。页面还要求学生独立编写实验代码，讨论思路时不分享或查看彼此的实现。

## 关键解读

**阅读、听课与实验形成一条学习链。** 课前先建立代码与概念的背景，课堂用讲解和演示澄清理解，实验再检验能否把接口与机制落实到程序中。若只记住概念而无法解释代码如何运行，就难以完成本页所描述的学习目标。

**实验验证包含“能运行”和“能解释”。** 页面中的测试检验实现的外部行为，助教核查则检验学生是否理解自己的实现。因此，自学时也可保留两个检查点：运行课程提供的测试，并用自己的话说明关键代码路径、状态变化和边界条件。这是根据课程评价方式提出的学习建议，并非原页新增的评分要求。

**后续学习应以正在使用的课程版本为准。** 本页的 Piazza、截止时间、网络实验和成绩比例都属于授课时的具体安排；若实际跟做实验，应再查对应版本的课程网站与实验说明。
