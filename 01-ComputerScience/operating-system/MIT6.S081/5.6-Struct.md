# 5.6 结构体（Struct）

> 原页面：[MIT 6.S081 中文翻译：5.6 Struct](https://mit-public-courses-cn-translatio.gitbook.io/mit6-s081/lec05-calling-conventions-and-stack-frames-risc-v/5.6-struct)。本笔记按该页内容整理；关于字段偏移的说明是帮助理解内存访问的补充，不代表原页给出了具体汇编指令。

## 本页知识点

`struct` 把多个有名字的字段组织为一个 C 类型。课程用 `f1`、`f2`、`f3` 说明：一个结构体对象占用连续的内存区域，字段按照声明顺序排列，字段的类型可以不同。因此可以把它粗略理解为“元素类型可以不同的数组”，但访问时使用字段名，而不是数组下标。

原页随后展示 `struct Person`，将其交给 `printPerson` 打印。调试器在 `printPerson` 的栈帧中显示参数 `p`：`p` 是指向 `Person` 的指针，对 `p` 解引用才能查看所指结构体的字段值。这一演示连接了前三节的参数传递、栈帧与调试方法：先确定当前函数收到的是对象还是地址，再解释调试器显示的内容。

页面末尾的问答提到，GCC 与 LLVM 等编译器负责把 C 程序编译到不同的指令集；新架构的编译器支持通常需要架构与编译器社区协作。这是课堂上的概括性回答，并非对某个编译器项目贡献来源的精确历史描述。

## 关键解读

**连续存放不等于字段之间没有空隙。** 编译器会按目标平台的布局规则为字段确定偏移，可能插入填充字节以满足对齐要求。读取结构体对应的汇编时，应根据字段的实际偏移理解基址加偏移的访存，而不能假定后一个字段紧贴前一个字段的最后一个字节。课程在本页只介绍结构体的基本直观模型，没有展开对齐与填充规则。

**区分“传结构体”与“传指向结构体的指针”。** 原页先说结构体可以作为函数参数，具体的 `printPerson` 演示中 `p` 则是指针。指针参数传递的是对象地址，调试器打印 `p` 得到地址，解引用 `*p` 才能看到对象；若参数类型本身是 `struct Person`，那是另一种按值传参的接口，不能从这个示例推断两者的调用开销或寄存器布局相同。

读 xv6 中的结构体时，可依次检查字段声明、变量或参数的实际类型，再看访问表达式中的 `.` 与 `->`：前者访问结构体对象的字段，后者经由指针访问所指对象的字段。这样能把 C 层面的数据组织与先前学习的寄存器、地址和栈帧对应起来。
