# 8.5 Demand Paging

## 本节知识点

按需分页（demand paging）利用 page fault 把页面的物理内存分配和内容载入推迟到实际访问时。课程版 xv6 的 `exec` 会先为可执行文件的 text、data 分配物理页并装入内容，然后才开始运行进程。若程序只执行少数代码路径，未用到的页面也被读入，启动时会产生不必要的 I/O 和内存占用。按需载入可以先记录虚拟地址区间、文件来源、文件偏移和访问权限，等首次取指或读写触发故障时，再分配物理页、从文件读取相应内容、建立映射，并重试故障指令。

同一机制也能处理内存不足后的换出（eviction）。内核选择暂时不活跃的物理页，必要时把内容写到磁盘，撤销其有效映射并记录后备存储位置。进程再次访问该虚拟页时，硬件产生 page fault；内核查明它是已换出页，分配可用物理页、从磁盘读回内容、恢复 PTE，然后从原指令继续。若没有空闲页，还可能先换出另一页为这次换入腾出空间。

这两种故障都表现为当前虚拟页不可访问，但内容来源不同：首次访问可执行文件页面时，后备来源是程序文件；访问被换出的已修改页面时，来源是保存其最新内容的交换空间或其他后备存储。处理程序必须根据地址空间元数据区分它们与非法地址、延迟分配的零页及 COW 写故障，不能看到无效 PTE 就直接从磁盘读取。

按需分页的效果依赖局部性：程序在一段时间内只访问其地址空间的一小部分时，物理内存只需容纳活跃页面，启动时也不必读入所有代码和数据。代价是首次访问或换入可能等待慢速磁盘 I/O；如果工作集持续大于物理内存，频繁换入换出会显著拖慢执行。

## 关键解读

**“按需”描述载入时机，“换页”描述内存压力下的去留。** 两者共用 page fault 的恢复路径，但无需等到 RAM 耗尽才能在 `exec` 时按需载入；反过来，换出需要额外的页面选择、脏页回写与后备位置管理。把两者区分开，才能解释页第一次进入内存与后来重新进入内存的不同来源。

**无效 PTE 不是页面状态的全部信息。** 硬件只知道这次访问不能按当前页表完成，内核还须维护该虚拟页是否合法、应从哪里重建、原本允许哪些访问等元数据。磁盘读入期间进程可能睡眠，其他进程仍可运行；恢复时还必须保持页表和缓存的地址转换一致。

**透明性有适用前提。** 如果内核能找到页面内容、可用物理空间并建立合适权限，原指令重试后应用程序无需修改；若后备数据不可用、地址非法或资源无法回收，就不能把故障当作可恢复的按需载入。原始 xv6 没有实现这里讨论的完整换出与换入机制。
