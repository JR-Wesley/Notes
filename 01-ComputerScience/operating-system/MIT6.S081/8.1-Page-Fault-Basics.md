# 8.1 Page Fault Basics

> 原页面：[MIT 6.S081 中文翻译：8.1 Page Fault Basics](https://mit-public-courses-cn-translatio.gitbook.io/mit6-s081/lec08-page-faults-frans/8.1-page-fault-basics)。本节介绍机制与设计空间，后续小节再分别讨论具体用途。

## 本页知识点

Page fault 是由地址转换或页面权限检查失败引发的同步异常。本讲将用它实现或解释多种虚拟内存功能，包括 lazy allocation、copy-on-write fork、demand paging 和 memory-mapped files。课程所用的原始 xv6 遇到用户 page fault 时通常直接终止进程，而现代操作系统会先判断故障是否代表可修复的按需操作。

虚拟内存提供两个基础能力：一是隔离，每个进程拥有受页表约束的地址空间；二是间接层，程序使用虚拟地址，内核决定虚拟页与物理页的映射。Trampoline 的共享映射与栈下方的 guard page 已经展示了这种间接层的用途，而 page fault 使内核能够在程序访问发生时动态建立、复制或加载映射。

内核处理 page fault 时需要三类信息：

1. `stval` 给出导致页面异常的虚拟地址，使内核知道要检查或修复哪个虚拟页。
2. `scause` 给出异常类型。课程使用的 RISC-V 编码中，12 是 instruction page fault，13 是 load page fault，15 是 store/AMO page fault；不同类型可能需要不同权限和处理策略。
3. `sepc` 保存触发异常的指令地址，xv6 随后把它转存到 trapframe 的 `epc`。修复映射后，内核通常需要重新执行这条尚未成功完成的指令。

Page fault 沿用 Lec06 的 trap 路径进入内核，但与系统调用的恢复语义不同。`ecall` 已经完成，系统调用路径把保存的 PC 加 4，从下一条指令继续；page fault 对应的访存或取指没有成功，若内核修复了页表，应保持原 PC，让同一条指令重试。若地址超出进程合法范围、权限不允许且没有特殊机制可处理，内核则应把它视为程序错误。

## 关键解读

**Page fault 是控制流信号，不只是崩溃。** 硬件只报告“当前映射无法完成这次访问”，真正的含义由内核结合进程地址布局、PTE 状态和访问类型判断。未映射地址可能表示非法指针，也可能表示尚未分配的堆页、尚未载入的文件页或需要复制的只读页。

**动态映射的关键是可重试性。** 内核根据 `stval` 找到目标页，根据 `scause` 确认访问性质，更新页表并处理必要的 TLB 状态，再从 `sepc` 重试指令。只要处理建立了满足访问条件的映射，用户程序便无需显式感知此次故障。

**“此前映射是静态的”是相对表述。** xv6 在 `exec`、进程扩容和退出等操作中本来就会修改页表；本讲强调的是，它通常在系统调用中主动、立即地建立映射。Page fault 则允许把修改推迟到首次访问时，从而形成按需分配、加载或复制的策略。
