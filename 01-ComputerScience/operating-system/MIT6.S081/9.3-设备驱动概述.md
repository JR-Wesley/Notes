# 9.3 设备驱动概述

> 章节入口：[MIT 6.S081 中文翻译：Lec09 Interrupts](https://mit-public-courses-cn-translatio.gitbook.io/mit6-s081/lec09-interrupts)。原站 9.3 正文此次无法直接读取；以下依据课程指定的 [2020 xv6 book，第 5 章](https://pdos.csail.mit.edu/6.828/2020/xv6/book-riscv-rev1.pdf)及 [MIT 6.S081《Interrupts》讲义](https://pdos.csail.mit.edu/6.828/2022/slides/6s081-lec-interrupts.pdf)归纳。

## 本节知识点

设备驱动（device driver）是内核中管理某类具体设备的代码。它要配置硬件、要求设备执行操作、处理设备随后发出的中断，并与等待 I/O 的进程交互。设备有各自的寄存器和操作协议，因此驱动把硬件细节封装在内核内部，让应用通过 `read()`、`write()` 等接口使用设备。xv6 的 UART 与 console 是本讲后续分析的例子。

课程将驱动的执行分为两个上下文。**Top half** 在发起 I/O 的进程的内核执行流中运行：系统调用进入内核后，它接收请求、把数据放入队列或要求设备启动操作，必要时等待完成。**Bottom half** 在设备中断到达时运行：中断处理程序确认完成了什么操作，推进队列，适时唤醒等待的进程，也可能让设备开始下一项工作。这里的 top/bottom 是课程及 xv6 book 对这两个执行位置的称呼。

两个部分通过缓冲区或队列衔接。以串口输出为例，进程可以先把待发送字符放进驱动缓冲区；UART 以自己的速度取走字符，完成一次发送后通过中断通知内核继续。队列让进程产生数据的速度与设备消耗数据的速度不必完全一致，但队列满时仍需等待或采取其他限流办法。

## 关键解读

**驱动是跨越同步调用与异步完成的桥梁。** 进程调用 `write()` 是有明确调用者的同步入口；设备完成发送并产生中断时，CPU 可能正在执行其他代码。驱动保存未完成操作的状态，才有办法在中断到来后找到对应工作并通知等待者。

**中断处理程序不能假定拥有原请求进程的上下文。** 它应主要依据设备状态和驱动共享的数据结构处理事件。若需要访问某个进程的用户地址或让进程等待，通常交由在进程上下文中运行的路径完成；这也是 top half 与 bottom half 分工的重要原因。

**并发不是附带问题。** 设备、进程中的驱动代码，以及其他 CPU 上的中断处理可能同时接触队列状态。驱动必须协调这些访问，并正确处理缓冲区空、满及唤醒时机，否则会出现数据丢失或进程一直等待。具体的锁和 UART 代码将在本讲后续小节展开。
