# 5.5 栈（Stack）

> 原页面：[MIT 6.S081 中文翻译：5.5 Stack](https://mit-public-courses-cn-translatio.gitbook.io/mit6-s081/lec05-calling-conventions-and-stack-frames-risc-v/5.5-stack)。栈指针对齐与寄存器保存责任按课程指定的 [RISC-V Calling Convention](https://pdos.csail.mit.edu/6.828/2020/readings/riscv-calling.pdf)核对；调试命令参照 [GDB 手册：Stack Frames](https://sourceware.org/gdb/current/onlinedocs/gdb.html/Stack.html)。原页示意中的固定布局只适用于其示例。

## 本页知识点

函数调用把控制流交给被调用函数，返回时还要找回调用处继续执行。栈为调用过程提供保存状态和临时数据的空间；一个调用对应的相关状态称为栈帧（stack frame）。在本课的 RISC-V 环境中，栈向低地址增长，函数需要栈空间时减小 `sp`，释放时再增大 `sp`。栈帧大小取决于需要保存的寄存器、局部数据和无法放入参数寄存器的参数，并非每个函数都相同。

原页对比了两个函数：`sum_to` 不再调用别的函数，是叶子函数（leaf function），示例只用寄存器完成计算，因此不必建立保存 `ra` 的栈帧；`sum_then_double` 会调用 `sum_to`，所以要保留自己收到的返回地址。示例中的函数序言（prologue）先把 `sp` 减 16，为栈帧留出空间，再把 `ra` 存入栈；函数尾声（epilogue）从栈中恢复 `ra`、把 `sp` 加回 16，最后执行 `ret`。

为什么不能直接省掉这两段代码？当调用者进入 `sum_then_double` 时，`ra` 指向它应返回的位置；随后 `sum_then_double` 调用 `sum_to`，调用指令会将 `ra` 改为 `sum_to` 返回到 `sum_then_double` 的位置。若前一个返回地址没有预先保存，`sum_then_double` 自己执行 `ret` 时就会跳错，课程示例表现为反复回到函数内部。这个过程具体说明了 `ra` 为 caller saved：函数若还要在调用后使用原值，就要自行保存。

`sp` 标记当前栈顶；`s0/fp` 可作为帧指针，帮助以稳定基址定位帧内数据和上一帧。使用帧指针是编译器和函数实现的选择，并非所有函数都必须建立它。RISC-V 标准调用约定还要求调用边界处 `sp` 保持 16 字节对齐，所以示例即使只存一个 8 字节的 `ra`，仍把栈指针移动 16 字节。不能据此推断每个函数都会在这 16 字节中同时存放 `ra` 和旧 `fp`。

原页最后演示 GDB 调试：`backtrace`（`bt`）列出从当前函数向调用者延伸的调用栈，`info frame` 显示选中帧的地址、保存的返回位置和寄存器等信息。GDB 中 `frame 0` 是当前最内层的帧，不是最早调用的“栈底”帧。编译器优化可能改变变量的存放方式、内联函数或省略帧指针，因此调试器显示的帧和源码中的每次调用不一定一一对应。

## 关键解读

**先追踪 `ra` 的两次含义。** 进入非叶子函数时，它指向该函数的调用者；非叶子函数再次执行调用后，它改为指向本函数内的下一条执行位置。函数序言保存旧值，尾声恢复旧值，才能让最后的 `ret` 返回真正的调用者。

**栈帧是组织调用状态的手段，不是固定模板。** 叶子函数可能不需要栈帧，非叶子函数可能需要保存 `ra`，使用 `s` 寄存器的函数还须恢复相应值。`ra` 或旧 `fp` 在栈中的具体偏移由生成的汇编决定，读代码时应看实际的 `sd`、`ld` 和 `sp` 调整，而不是把课堂示意图当成 ABI 的统一布局。

**调试时把帧信息与实际指令对应。** `bt` 帮助确认调用路径，`info frame` 提供选中帧的细节；若返回地址异常，再回到函数序言、调用指令和尾声检查 `ra` 是否被正确保存与恢复。这样能把“无限循环”之类的表象追到具体的调用约定错误。
