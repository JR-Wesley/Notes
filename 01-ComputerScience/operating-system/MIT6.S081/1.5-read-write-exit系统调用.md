# 1.5 read、write、exit 系统调用

> 来源：[MIT 6.S081 中文翻译：1.5 read, write, exit 系统调用](https://mit-public-courses-cn-translatio.gitbook.io/mit6-s081/lec01-introduction-and-examples/1.5-some-systemcalls)。本页通过一个 `copy` 程序介绍系统调用的应用侧接口；以下没有把示例演示当作已运行的本地实验。

## 本页知识点

xv6 是用于教学的简化 Unix 风格操作系统。课程在 QEMU 中模拟 RISC-V 计算机运行它；`make qemu` 会构建 xv6 内核和用户程序，再启动模拟器。页面随后展示一个简短的 `copy` 程序：循环从输入读取字节，把读到的字节写到输出，最后退出。这个例子让系统调用的参数和返回值比内核实现更先进入视野。

| 调用或约定 | 在本页示例中的作用 |
| --- | --- |
| 文件描述符 `0`、`1` | 程序启动时由 Shell 设置；分别连接标准输入与标准输出。在示例中，它们连接到 console。 |
| `read(fd, buf, n)` | 从 `fd` 所指对象最多读取 `n` 字节，放入 `buf` 指向的内存。返回实际读取的字节数；到文件末尾返回 `0`，出错可能返回 `-1`。 |
| `write(fd, buf, n)` | 把 `buf` 指向的 `n` 字节送往 `fd` 所指对象。示例使用它把输入原样写到输出；本页未详细讨论其返回值。 |
| `exit` | 示例使用的第三个系统调用，用于结束程序；本页没有展开其参数或内部流程。 |

示例在栈上准备了 64 字节缓冲区，传入 `sizeof(buf)` 作为 `read` 的最大读取长度。这个长度必须与可用缓冲区匹配：若告诉内核可写入 65 字节，却只提供 64 字节空间，就可能覆盖相邻内存，造成错误或崩溃。页面还提醒检查系统调用返回值；演示代码为了简短，并未处处处理错误。

## 关键解读

**文件描述符把程序与具体输入输出来源解耦。** `copy` 只需约定从 `0` 读、向 `1` 写；它不必在程序中指定“键盘”或“屏幕”。本页示例由 Shell 预先配置这两个描述符，因此代码可以直接使用它们。后续学习重定向时，可再追问 Shell 如何改变这些连接。

**`read` 的返回值决定下一步操作。** 请求最多读取 64 字节，不代表每次必然得到 64 字节；应按实际返回的字节数处理数据。返回 `0` 表示文件输入到达末尾，错误返回值则应单独处理。将“缓冲区容量”“请求长度”和“实际读取长度”混为一谈，容易导致越界或输出无效数据。

**读写接口处理字节，数据意义由应用决定。** `copy` 不解析输入是文本、程序还是其他内容，只搬运字节流。内核提供通用读写能力，应用再决定如何解释字节。这也是同一接口能够服务不同程序的原因。
