# 6.7 `usertrapret` 函数

> 原页面：[MIT 6.S081 中文翻译：6.7 usertrapret 函数](https://mit-public-courses-cn-translatio.gitbook.io/mit6-s081/lec06-isolation-and-system-call-entry-exit-robert/6.7-usertrapret)。本节对应课程使用的 2020 版 xv6；新版源码已可能重构为 `prepare_return` 等函数，阅读时应以所用版本为准。

## 本页知识点

`usertrap` 处理完系统调用、异常或中断后，调用 `usertrapret` 准备返回用户态。它首先关闭中断，因为接下来要把 `stvec` 从内核 trap 入口 `kernelvec` 改回 trampoline 中的 `uservec`。在配置转换尚未完成时若发生内核中断，处理器却跳入面向用户态的入口，会在错误的页表、栈和上下文假设下运行，因此这段过渡区必须保持不可中断。

随后函数把 `stvec` 设置为 `uservec`，并为下一次用户态 trap 填充 trapframe 中的入口数据：内核页表的 `satp` 值、当前进程的内核栈顶、`usertrap` 地址以及当前 hart ID。这些字段不是为了本次返回恢复用户寄存器，而是让进程下一次进入 `uservec` 时能够重新建立内核执行环境。

接下来，`usertrapret` 配置 `sstatus`：清除 `SPP`，使之后的 `sret` 返回 U-mode；设置 `SPIE`，使 `sret` 把中断使能状态恢复为开启。它还把此前保存在 trapframe `epc` 字段中的用户程序计数器写回 `sepc`，因为 `sret` 会从 `sepc` 指定的位置恢复执行。

普通内核 C 代码不能在切换为用户页表后继续执行，因为用户页表没有映射一般内核代码。因此函数先计算用户页表对应的 `satp` 值，以及 trampoline 中 `userret` 的虚拟地址，再像调用函数一样进入 `userret`。课程版本把 trapframe 地址和用户 `satp` 值作为参数放入 `a0`、`a1`；余下的页表切换和寄存器恢复由 trampoline 汇编完成。

## 关键解读

**返回路径也在为下一次进入内核做准备。** `kernel_satp`、`kernel_sp`、`kernel_trap` 和 hart ID 在本次 `userret` 中不一定立即使用，但下一次 `uservec` 依赖它们。trap 的进入与返回因此形成一个闭环：返回阶段预置下一次入口需要的可信状态。

**关闭中断保护的是一个配置不一致窗口。** 当 `stvec` 已指向 `uservec`、CPU 却仍在内核态运行时，系统暂时不满足任一完整入口协议。关中断避免异步设备中断落入这个窗口；完成 `sstatus` 配置并执行 `sret` 后，再由硬件按 `SPIE` 恢复用户态的中断使能状态。

**`sepc` 可以在汇编或 C 中保存，但通用寄存器必须先由汇编保存。** 编译后的 C 函数会使用并覆盖通用寄存器，所以 `uservec` 必须在调用 C 代码前保存它们。`sepc` 是控制寄存器，只要在可能被覆盖或进程切换前转存即可；xv6 选择在 `usertrap` 中完成，是实现选择而非硬件强制。
