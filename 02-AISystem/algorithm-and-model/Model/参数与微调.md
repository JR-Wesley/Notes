# LLM 可调参数

在当前（2025 年）的大语言模型（LLM）领域，**Decoder-Only** 架构结合 **混合专家模型（Mixture of Experts, MoE）** 已成为构建高性能、高效率模型的主流范式。这类模型在保持强大生成能力的同时，通过 MoE 机制实现了“更大容量、更小计算开销”的目标。

这类模型的超参数设置非常复杂，通常分为**架构级超参数**和**训练级超参数**两大类。以下是关键超参数的详细说明：

---

## 一、 架构级超参数 (Architecture Hyperparameters)

这些参数定义了模型的基本结构和规模。

1.  **模型维度 (`d_model`)**:
    *   **定义**: 模型中每个 token 的嵌入向量维度，也是 Transformer 层内部表示的维度。
    *   **典型值**: 4096, 8192, 12288 等。
    *   **影响**: 直接影响模型的表达能力和参数量。`d_model` 越大，模型理论上能捕捉更复杂的模式，但计算和内存开销也呈平方级增长。

2.  **层数 (`n_layer`)**:
    *   **定义**: Transformer 解码器堆叠的层数。
    *   **典型值**: 32, 64, 96 等。
    *   **影响**: 更深的网络可以学习更复杂的层次化特征，但也更容易出现梯度消失/爆炸问题，训练难度增加。

3.  **专家数量 (`n_experts`)**:
    *   **定义**: 在 MoE 层中并行存在的专家子网络的数量。
    *   **典型值**: 8, 16, 32, 64, 128 甚至更多。
    *   **影响**: 专家越多，模型的总容量（总参数量）越大，可以学习更细粒度的知识。但专家数量过多可能导致路由不稳定或稀疏性不足。

4.  **每层激活专家数 (`n_experts_per_token` 或 `top_k`)**:
    *   **定义**: 在每个 MoE 层中，路由器（Router）为每个输入 token 选择并激活的专家数量。
    *   **典型值**: 通常为 1 或 2。`top_k=2` 是最常见的选择，因为它在性能和稳定性之间取得了良好平衡。
    *   **影响**: `k` 越大，每个 token 的计算量越大（但利用了更多知识）；`k` 越小，计算越高效，但可能损失信息。`k=1` 时，模型退化为“路由到单个专家”，可能不稳定。

5.  **专家前馈网络维度 (`d_ff_expert`)**:
    *   **定义**: 每个专家子网络内部前馈层的隐藏维度。
    *   **典型值**: 通常是 `d_model` 的 4 倍（如 `d_model=8192`, `d_ff_expert=32768`），但也可以独立设置。
    *   **影响**: 决定了每个专家的容量。更大的 `d_ff_expert` 意味着每个专家更“博学”，但总参数量也会增加。

6.  **注意力头数 (`n_head`)** 和 **注意力头维度 (`d_head`)**:
    *   **定义**: 多头注意力机制中的头数。`d_head = d_attn / n_head`，通常 `d_attn = d_model`。
    *   **典型值**: `n_head` 从 32 到 96 不等。
    *   **影响**: 更多的头可以让模型从不同子空间学习不同的注意力模式，提升模型的表征能力。

7.  **上下文长度 (`n_ctx` 或 `max_seq_len`)**:
    *   **定义**: 模型一次能处理的最大 token 数量。
    *   **典型值**: 8192, 16384, 32768, 甚至 100K+。
    *   **影响**: 更长的上下文使模型能处理更长的文档、进行更复杂的推理。需要结合 **旋转位置编码（RoPE）** 或 **ALiBi** 等技术来支持。

8.  **分组查询注意力 (GQA)**:
    *   **定义**: 一种优化注意力机制的技术，将 `n_head` 分组，每组共享 Key 和 Value，减少 KV Cache 的内存占用。
    *   **超参数**: `n_kv_groups`（KV 组数）。
    *   **影响**: 显著降低推理时的显存消耗，加速长文本生成。

9.  **词汇表大小 (`vocab_size`)**:
    *   **定义**: 模型词表的大小。
    *   **典型值**: 32K, 64K, 128K（如 LLaMA-3）。
    *   **影响**: 更大的词表可以减少文本的 token 化长度，提高编码效率，但也增加嵌入层的参数量。

---

## 二、 训练级超参数 (Training Hyperparameters)

这些参数控制模型的训练过程。

1.  **批量大小 (`batch_size`)**:
    *   **定义**: 一次前向/反向传播中处理的 token 总数（通常指 `total_batch_size`，即 `micro_batch_size * gradient_accumulation_steps * num_gpus`）。
    *   **典型值**: 数百万（如 2M, 4M）。
    *   **影响**: 更大的批量大小通常能带来更稳定的梯度和更快的收敛，但对硬件内存要求极高。

2.  **学习率 (`learning_rate`)**:
    *   **定义**: 优化器更新参数的步长。
    *   **典型值**: 通常在 `1e-4` 到 `5e-4` 之间。
    *   **调度**: 通常使用 **余弦退火（Cosine Decay）** 或 **线性预热 + 余弦衰减** 的学习率调度策略。

3.  **预热步数 (`warmup_steps`)**:
    *   **定义**: 学习率从 0 线性增加到目标值的训练步数。
    *   **典型值**: 几千到几万步。
    *   **影响**: 防止训练初期梯度爆炸，稳定训练。

4.  **优化器 (Optimizer)**:
    *   **常用**: `AdamW`（Adam with Weight Decay）是最主流的选择。
    *   **变体**: `Adafactor`（节省内存）、`Lion`（Google 提出，计算更高效）等也被探索。

5.  **权重衰减 (`weight_decay`)**:
    *   **定义**: L2 正则化系数，防止过拟合。
    *   **典型值**: `0.1`。
    *   **注意**: 通常不对 LayerNorm 和偏置项进行权重衰减。

6.  **Dropout**:
    *   **定义**: 一种正则化技术，随机丢弃部分神经元。
    *   **典型值**: 在大型 LLM 中，dropout 率通常很低（如 `0.0` 或 `0.1`），因为大规模数据本身提供了足够的正则化。

7.  **MoE 路由相关超参数**:
    *   **路由器初始化**: 路由器的初始化方式对训练稳定性至关重要。
    *   **负载均衡损失 (Load Balancing Loss)**:
        *   **定义**: 一个辅助损失项（如 `router_z_loss`, `expert_capacity_loss`），用于惩罚专家负载不均衡。
        *   **系数 (`auxiliary_loss_coeff`)**: 控制该损失项的权重，通常很小（如 `1e-2` 或 `1e-3`）。
    *   **专家容量 (`expert_capacity`)**: 限制每个专家在一批次中能处理的 token 数，防止过载。

8.  **训练步数 (`training_steps`)**:
    *   **定义**: 整个预训练过程的总迭代次数。
    *   **典型值**: 数十万到上百万步。
    *   **原则**: 遵循 **Chinchilla Scaling Law**，即在给定计算预算下，数据量和模型参数量应按 1:1 的比例扩展。

## 三、 典型配置示例（假设）

一个典型的 **Decoder-Only MoE LLM** 可能如下配置：

*   **`d_model`**: 8192
*   **`n_layer`**: 64
*   **`n_experts`**: 16
*   **`n_experts_per_token`**: 2
*   **`d_ff_expert`**: 32768
*   **`n_head`**: 64
*   **`n_kv_groups`**: 8 (GQA)
*   **`max_seq_len`**: 32768
*   **`vocab_size`**: 128000

*   **`total_batch_size`**: 4,000,000 tokens
*   **`learning_rate`**: 2e-4 (cosine decay)
*   **`warmup_steps`**: 10,000
*   **`optimizer`**: AdamW
*   **`weight_decay`**: 0.1
*   **`auxiliary_loss_coeff`**: 0.01
*   **`training_steps`**: 500,000

---

## 总结

设计一个 Decoder-Only MoE LLM 是一个复杂的系统工程。核心在于：

1.  **平衡 MoE 的稀疏性与容量**: 通过 `n_experts` 和 `top_k` 控制总参数量和实际计算量。
2.  **优化长上下文处理**: 利用 GQA、RoPE 等技术。
3.  **稳定 MoE 训练**: 通过负载均衡损失和合理的初始化。
4.  **遵循规模定律**: 合理分配计算预算给模型大小和数据量。

这些超参数的选择需要大量的实验和调优，通常由拥有强大算力的团队完成。对于使用者而言，理解这些参数的含义有助于更好地选择和应用现有的开源 MoE 模型（如 Mixtral, DeepSeek-MoE 等）。
