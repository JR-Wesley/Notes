# Inside NVIDIA GPUs：高性能矩阵乘法（matmul）内核解析网页总结

## 一、文章概述

本文围绕 NVIDIA GPU（以 Hopper H100 为核心案例）高性能矩阵乘法（matmul）内核展开，从硬件架构、编程模型到内核设计逐步深入，旨在帮助读者理解支撑顶尖（SOTA）matmul 内核的核心技术，同时提及后续系列计划覆盖的内容，如 Blackwell GPU 的 SOTA matmul 内核设计、多 GPU 内核设计等。

## 二、GPU 硬件架构基础

### 1. 核心任务与架构划分

- GPU 核心任务分为数据移动存储（内存系统）和数据计算（计算流水线），H100 GPU 框图中蓝色组件代表内存/数据移动相关，红色为计算单元。
- 重点聚焦 Hopper H100 GPU，理解其架构可轻松适配其他代际 GPU（如 Blackwell、Ampere 等），Hopper 和 Ampere 白皮书是重要参考资料。

### 2. 内存系统（层级结构）

| 内存层级 | 特点 | 关键信息 |
| ---- | ---- | ---- |
| 设备内存（VRAM） | 片外 DRAM，HBM 实现 | 包含全局内存（GMEM）、线程本地内存（寄存器溢出空间）等 |
| L2 缓存 | 大型 k 路组相联 SRAM 缓存 | 物理分为两部分，每个 SM 直接连接一个分区，通过交叉开关间接连接另一个 |
| 分布式共享内存（DSMEM） | 物理上靠近的 SM 组（GPC）的共享内存池 | 支持 SM 间直接通信 |
| L1 缓存与共享内存（SMEM） | 均为 SM 私有，共享物理存储 | L1 是硬件管理缓存，SMEM 是程序员管理片上内存，二者比例可软件配置 |
| 寄存器文件（RMEM） | 速度最快，位于计算单元旁 | 线程私有，GPU 寄存器数量远多于 CPU，总容量与 L1/SMEM 总和相当 |

- 额外重要组件：张量内存加速器（TMA，Hopper 引入），支持 GMEM 与 SMEM 间、SMEM 与 SMEM 间异步数据传输，还能通过交错访问减少银行冲突。
- 内存层级趋势：从设备内存到寄存器，带宽大幅提升，延迟和容量显著降低，因此需将频繁访问数据放在靠近计算单元处，减少低层级内存（尤其是 GMEM）访问。

### 3. 计算单元

- 流多处理器（SM）：H100（SXM5）共 132 个 SM，按图形处理集群（GPC）分组，每个 GPC 含 18 个 SM，8 个 GPC 分两组连接 L2 缓存分区。实际产品中部分 SM 会被屏蔽，影响内核集群配置。
- SM 内部关键组件：
  - 张量核心（Tensor Cores）：专门执行小矩阵块乘法，是实现峰值性能的关键
  - CUDA 核心与 SFU：CUDA 核心执行 FMA 等标准浮点运算，SFU 处理超越函数和代数函数
  - 加载/存储（LD/ST）单元：处理加载存储指令，与 TMA 引擎互补
  -  warp 调度器：每个 SM 含多个，每周期可向 32 线程组（warp）下发一条指令
- 并行性与并发性：SM 每周期最多同时执行 4 个 warp（128 线程）的指令（并行），但可容纳 2048 个并发线程（64 个 warp），通过调度隐藏内存/流水线延迟（并发）。

### 4. 光速性能（SoL）与功耗限制

- 峰值吞吐量计算：`perf = freq_clk_max * num_tc * flop_per_tc_per_clk`，不同数据类型（如 bf16、fp8）峰值不同，LLM 训练中 bf16 为主流。
- 功耗限制影响：实际时钟频率受功耗或热节流影响，会降低有效 SoL 性能。

## 三、CUDA 编程模型

### 1. 核心抽象（层级从低到高）

- 线程（thread）：最基本执行单元
- Warp（32 线程）：SM 调度的基本指令下发单元
- 线程块（thread block）：驻留在单个 SM 上，含至少 4 个 warp（128 线程）以充分利用 SM 的 4 个 warp 调度器
- 线程块集群（thread block cluster）：跨 SM 的线程块组，基于 GPC 硬件单元
- 网格（grid）：由线程块或集群组成
- 线程通过 `gridDim`、`blockIdx`、`blockDim`、`threadIdx` 等变量感知自身在层级中的位置，便于任务分配，如处理图像时计算像素坐标。

### 2. GMEM 与 SMEM 模型

- GMEM（全局内存）：HBM 实现，由 DRAM 单元构成，访问模式关键。线程访问连续内存地址可实现 GMEM 合并，减少 DRAM 行访问次数，提升效率；列优先存储矩阵需调整内循环遍历方式以避免性能损失。
- SMEM（共享内存）：SRAM 构成，含 32 个存储体（每体 32 位宽），单周期可从所有存储体读取 128B 数据，但同一 warp 线程访问同一存储体不同地址会导致银行冲突，序列化请求；访问同一地址则可广播数据。

### 3. L1 缓存模型

- 与 SMEM 共享物理存储，逻辑流程：warp 发起内存请求→进入 MIO 流水线并分发到 LSUIN 路由器→SMEM 请求直接处理，GMEM 请求进入标签比较阶段→命中则从数据阵列读取，未命中则转发到 L2 及更高层级，数据返回后缓存到 L1 并返回给 warp。
- L2 缓存与 L1 类似，但全局共享、容量更大、关联性更高，分为两个切片通过交叉开关连接，支持更精细的持久化和缓存策略。

### 4. GPU 代际差异

- Ampere→Hopper 关键升级：DSMEM、TMA、线程块集群、异步事务屏障
- Ampere 关键特性：张量核心支持 tf32 和 bf16、GMEM 到 SMEM 异步复制、异步屏障、CUDA 任务图、warp 级归约指令

## 四、GPU 汇编语言（PTX 与 SASS）

### 1. 基本概念

- SASS：NVIDIA GPU 原生 ISA，文档有限，不同代际差异大，是硬件直接执行的指令集。
- PTX：虚拟 ISA，不直接执行，由 `ptxas` 编译为 SASS，优势是向前兼容，旧 PTX 代码可在新 GPU 上 JIT 编译运行。
- 重要性：优化核心内核性能（如 LLM 训练）时，PTX/SASS 层面的优化能带来显著收益，例如调整 SASS 避免银行冲突可提升性能，部分指令需通过内联 PTX 实现。

### 2. 编译流程

CUDA C++ 代码→PTX 代码→SASS 代码，CUDA 二进制文件中同时包含 PTX 和对应架构的 SASS，运行时若无匹配 SASS 则 JIT 编译 PTX。

### 3. 朴素 Matmul 内核分析

- 代码逻辑：以 GEMM（`C = alpha * A @ B + beta * C`）为例，每个线程计算 `C` 中一个元素，通过线程和块索引确定元素坐标，处理矩阵非 32 倍数时的边界线程。
- 线程组织：采用 32×32 线程块（1024 线程）划分输出矩阵，存在瓦片量化（tile quantization）现象，矩阵尺寸非 32 倍数时部分线程无效。
- 资源限制与并发：寄存器、SMEM、线程数限制 SM 上并发块数量，例如 H100 上该朴素内核每 SM 最多 2 个并发块，总需多轮（wave）执行完成计算，存在波量化（wave quantization）现象，轮次少且块数非 SM 倍数时资源利用率低。
- 编译器优化：PTX 代码中可见早期退出、循环展开、主循环与尾循环拆分、流水线负载均衡等优化；SASS 代码循环展开程度更高（如×16），调整加载指令位置重叠计算与数据加载，但也存在冗余初始化、无用指令等低效问题。

## 五、近 SOTA 同步 Matmul 内核设计（warp-tiling 方法）

### 1. 约束条件

不使用 TMA、异步内存指令、张量核心，仅支持 fp32，适用于 Pre-Volta GPU，在 Volta/Ampere 上接近 SOTA。

### 2. 关键优化思路

- 循环重排：将 `K` 作为外层循环，把 matmul 视为部分外积之和，减少 GMEM 访问次数，例如 `A` 的加载次数从 `N^3` 降至 `N^2`。
- 分块计算：将大矩阵拆分为 SMEM 可容纳的小块，通过块 matmul 计算部分点积，减少 GMEM 通信，提升算术强度（AI，每字节 GMEM 加载执行的 FLOP 数）。
- 瓦片形状：输出瓦片尽量接近正方形，每个线程计算多个输出元素，以提高算术强度。

### 3. 算法流程

1. 加载数据：将 `A` 的 `Bm×Bk` 块和 `B` 的 `Bk×Bn` 块分别加载到 SMEM 的 `As`（转置，便于后续向量加载）和 `Bs`（非转置），加载过程通过向量指令优化，`As` 存储因转置无法向量化但优先保证计算时快速加载。
2. 线程块同步：确保数据完全加载到 SMEM。
3. 计算阶段：以 warp 为单位，通过线程级外积实现块 matmul，每个线程维护私有结果寄存器，累积部分乘积。
4. 再次同步：避免后续数据写入覆盖当前计算数据。
5. 循环推进：`A` 和 `B` 指针分别推进 `Bk` 列和 `Bk` 行，重复上述步骤直至所有块处理完成。
6. 结果写入：线程将私有寄存器中的最终结果写入 `C` 的对应输出瓦片。

### 4. 性能影响因素

- GMEM 访问模式：错误的线程坐标计算（如交换 `%` 和 `/` 操作）会导致 GMEM 访问非合并，性能大幅下降（如 H100 上从 3171 GFLOP/s 降至 243 GFLOP/s）。
- 屋顶线模型（Roofline Model）：朴素内核处于内存带宽受限区域，warp-tiling 通过提升算术强度推动内核向计算受限区域靠近，H100 需 AI 超过~410 才能进入计算受限 regime。

## 六、Hopper 上 SOTA 异步 Matmul 内核设计

### 1. 核心硬件特性利用

- TMA（张量内存加速器）：简化数据加载，支持 GMEM 与 SMEM 间异步传输，自动实现交错访问（swizzling）减少银行冲突，仅需构造张量映射、单线程触发 TMA 操作、通过共享内存屏障同步。
- 张量核心（Tensor Cores）：使用 `wgmma.mma_async`（Hopper 引入，4 个 warp 协同的异步指令），支持 `m64nNk16`（`N` 为特定值）形状矩阵乘法，bf16 精度，大幅提升计算效率，抽象掉手动 warp/线程调度复杂度。

### 2. 关键技术细节

- 交错访问（Swizzling）：TMA 自动应用，通过 XOR 特定掩码实现，使矩阵行、列在 SMEM 中均可单周期加载（无银行冲突），不同带宽模式（128B/64B/32B）对应不同掩码生成规则，数据从 SMEM 写回 GMEM 时 TMA 自动取消交错。
- 异步同步机制：使用共享内存屏障（如 `barA`、`barB`），TMA 操作发起后，通过 `barrier_arrive_tx` 关联字节计数，线程调用 `bar.wait` 等待所有线程到达且异步传输完成，确保数据就绪。
- 流水线优化：将 SMEM 数据块组织为队列，分生产者（1 个 warp 组，通过 TMA 向队列填充数据）和消费者（1 个或多个 warp 组，从队列取数据用张量核心计算），通过 `full`/`empty` 屏障对同步，重叠数据加载与计算，减少空闲周期。

### 3. 性能优化策略

| 优化策略 | 具体措施 | 性能提升效果（参考数据） |
| ---- | ---- | ---- |
| 增大输出瓦片 | 从 128×128 扩展到 128×256，拆分 accumulator 到 2 个消费者 warp 组避免寄存器溢出 | 从 498 TFLOP/s 提升至 610 TFLOP/s |
| 持久化内核 | 每个 SM 启动一个长生命周期块，循环处理多个瓦片，重叠输出存储与输入加载 | 从 610 TFLOP/s 提升至 660 TFLOP/s |
| 更快 PTX 屏障 | 优化屏障 `arrive/wait` 调用，移除冗余信号（如消费者无需在 `full[qidx]` 信号到达） | 从 660 TFLOP/s 提升至 704 TFLOP/s |
| 集群与 TMA 多播 | 利用 Hopper 线程块集群，SM 间共享 SMEM（DSMEM），减少 L2/GMEM 加载次数 | 从 704 TFLOP/s 提升至 734 TFLOP/s |
| 微优化 | 寄存器重分配（向消费者 warp 组倾斜）、异步存储（寄存器→SMEM→GMEM，TMA 异步写回）、跳过冗余初始化（首轮 MMA 不累积） | 从 734 TFLOP/s 逐步提升至 758 TFLOP/s |
| Hilbert 曲线调度 | 采用空间填充曲线（Hilbert 曲线）调度输出瓦片，最大化缓存局部性 | 从 758 TFLOP/s 提升至 764 TFLOP/s |

### 4. 代码结构与关键指令

- 张量映射构造：使用 `cuTensorMapEncodeTiled` 指定数据类型、维度、指针、形状、步幅、SMEM 目标形状和交错模式。
- TMA 数据加载：单线程调用 `cde::cp_async_bulk_tensor_2d_global_to_shared` 发起异步传输，关联屏障与字节计数。
- 张量核心计算：通过内联 PTX 或封装函数（如 `wgmma64`）调用 `wgmma.mma_async`，配合 `wgmma.fence`、`wgmma.commit_group`、`wgmma.wait_group` 等指令保证执行顺序和结果正确性。
- 多 warp 组协作：生产者 warp 组填充数据队列，消费者 warp 组并行计算，多消费者组拆分大瓦片避免寄存器溢出，集群模式下跨 SM 共享数据。
