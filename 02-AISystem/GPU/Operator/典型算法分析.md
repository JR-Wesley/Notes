# 前缀和

实现高效的 CUDA 前缀和（Prefix Sum，又称 Scan）算法是一个经典的并行计算问题，它完美地展示了如何将算法设计与底层硬件特性（如内存层次结构、线程调度、共享内存等）紧密结合，以达到极致性能。下面我们从算法思想到硬件优化，系统性地讲解如何实现一个高性能的 CUDA 前缀和。

---

## 一、前缀和的定义与应用

前缀和是将一个输入数组 `A[0..n-1]` 转换为输出数组 `B[0..n-1]`，其中：

- **B[i] = A[0] + A[1] + ... + A[i]**（对于加法操作，可推广到任意结合律操作）

**应用**：排序（如基数排序）、流处理、直方图、内存分配、并行搜索等。

---

## 二、串行 Vs 并行

- **串行实现**：简单，时间复杂度 O(n)
- **目标**：利用 GPU 的数千个核心并行计算，将时间压缩到 O(log n)

---

## 三、并行前缀和算法：Blelloch Scan（分治策略）

Blelloch 算法是一种经典的并行前缀和算法，分为两个阶段：

### 1. **上行（Reduce）阶段**

- 自底向上进行归约（Reduction），但保留中间结果
- 每一步合并相邻元素，生成部分和
- 时间复杂度：O(log n)，但需要存储中间状态

### 2. **下行（Propagate）阶段**

- 自顶向下将“偏移量”传递回每个子树
- 利用上行阶段的结果，为每个节点加上“左侧兄弟”的总和
- 最终得到完整的前缀和

> **特点**：步骤少，但访存不规则，适合 small-to-medium 数据集

---

## 四、Hillis-Steele Scan（直观并行）

每一步计算所有元素与 `2^k` 步之前的元素之和：

```cpp
for k = 0 to log2(n)-1:
    for i = 2^k to n-1 in parallel:
        B[i] = A[i - 2^k] + A[i]
    A = B
```

- **优点**：每步都是规则访存，易于 GPU 实现
- **缺点**：O(n log n) 时间复杂度，不适合大数据

> **适用**：小数组或教学演示

---

## 五、CUDA 实现策略：分块 + 共享内存 + 合并访问

实际高性能实现通常采用 **分块（Block-wise）Blelloch Scan**，结合全局归约与局部扫描。

### 1. **整体架构**

- 将大数组划分为多个 block，每个 block 用一个 CUDA block 处理
- 每个 block 内部执行 **intra-block scan**（使用共享内存）
- 计算每个 block 的总和，形成一个“偏移数组”
- 对偏移数组递归或迭代执行 scan
- 最后将偏移量加回到各个 block 的输出中

### 2. **关键步骤**

#### (1) Kernel 1: 分块扫描 + 块和计算

```cpp
__global__ void block_scan_kernel(int *input, int *output, int *block_sums, int n) {
    extern __shared__ int s_data[]; // 动态共享内存
    int tid = threadIdx.x;
    int bid = blockIdx.x;
    int i = bid * blockDim.x + tid;

    // Load data into shared memory
    s_data[tid] = (i < n) ? input[i] : 0;
    __syncthreads();

    // Blelloch Scan in shared memory (up-sweep)
    for (int stride = 1; stride < blockDim.x; stride *= 2) {
        int index = (tid + 1) * stride * 2 - 1;
        if (index < blockDim.x)
            s_data[index] += s_data[index - stride];
        __syncthreads();
    }

    // Down-sweep: build exclusive scan
    for (int stride = blockDim.x / 2; stride > 0; stride /= 2) {
        int index = (tid + 1) * stride * 2 - 1;
        if (index < blockDim.x) {
            int temp = s_data[index - stride];
            s_data[index - stride] = s_data[index];
            s_data[index] += temp;
        }
        __syncthreads();
    }

    // Write back scan result
    if (i < n) output[i] = s_data[tid];

    // Save block sum (last element of inclusive scan)
    if (tid == 0) block_sums[bid] = s_data[blockDim.x - 1];
}
```

#### (2) Kernel 2: 扫描 block_sums 数组（偏移量）

- 递归调用 `block_scan_kernel` 或使用 Hillis-Steele 处理 `block_sums`
- 得到每个 block 应加的偏移量

#### (3) Kernel 3: 偏移量加回去

```cpp
__global__ void add_offset(int *output, int *offsets, int block_size, int n_blocks) {
    int bid = blockIdx.x;
    int tid = threadIdx.x;
    int i = bid * blockDim.x + tid;

    if (bid > 0 && i < n)
        output[i] += offsets[bid - 1]; // 前面所有块的和
}
```

---

## 六、硬件优化技巧

### 1. **共享内存（Shared Memory）**

- 将 block 内数据加载到 shared memory，避免重复 global memory 访问
- shared memory 带宽远高于 global memory（~1TB/s vs ~800GB/s）

### 2. **合并内存访问（Coalesced Access）**

- 确保连续线程访问连续内存地址
- 使用 `blockIdx.x * blockDim.x + threadIdx.x` 索引

### 3. **减少 Bank Conflict**

- shared memory 被划分为 32 个 bank
- 避免多个线程同时访问同一 bank
- 使用 padding 或调整数据布局（如 `__shared__ int s_data[256 + 8];`）

### 4. **使用 Warp-Level Primitives（CUDA 9+）**

- 对于小规模 scan（≤32 线程），可用 warp shuffle 指令减少同步开销

```cpp
// Warp-level inclusive prefix sum
int warp_scan(int val) {
    for (int offset = 1; offset < 32; offset *= 2) {
        int temp = __shfl_up_sync(0xFFFFFFFF, val, offset);
        if (threadIdx.x >= offset) val += temp;
    }
    return val;
}
```

### 5. **流水线与异步传输**

- 使用多个 stream 实现数据传输与计算重叠
- `cudaMemcpyAsync` + `cudaMemPrefetchAsync`

### 6. **Occupancy 优化**

- 增加每个 SM 的活跃 warp 数量
- 调整 block size（如 256 或 512）以最大化利用率

---

## 七、完整流程（递归或迭代）

对于大数组（如 2^20）：

1. 第一层：用 4096 个 block，每个 block 处理 512 元素 → 生成 4096 个 block sum
2. 第二层：用 1 个 block 扫描 4096 个 block sum → 得到偏移数组
3. 第三层：将偏移加回各 block 输出

---

## 八、使用 CUDA SDK：CUB 库

实际项目中，推荐使用 NVIDIA 提供的 **CUB** 库，它已高度优化：

```cpp
#include <cub/cub.cuh>

int *d_in, *d_out;
int num_items = 1000000;
size_t temp_storage_bytes = 0;

// 第一次调用：获取临时存储大小
cub::DeviceScan::InclusiveSum(nullptr, temp_storage_bytes, d_in, d_out, num_items);

// 分配临时存储
void *d_temp_storage;
cudaMalloc(&d_temp_storage, temp_storage_bytes);

// 执行扫描
cub::DeviceScan::InclusiveSum(d_temp_storage, temp_storage_bytes, d_in, d_out, num_items);
```

CUB 内部使用了：

- 分块策略
- warp-specialized scan
- 内存预取
- 自动调优

---

## 九、性能对比（示例）

|方法|时间复杂度|适用规模|是否推荐|
|---|---|---|---|
|串行 CPU|O(n)|小|❌|
|Hillis-Steele GPU|O(n log n)|小|⚠️ 教学|
|Blelloch GPU|O(log n)|中小|✅|
|分块 + CUB|O(n) 并行|大|✅✅✅|

---

## 十、总结

实现高性能 CUDA 前缀和的关键在于：

1. **算法选择**：中小数组用 Blelloch，大数组用分块 + 递归
2. **硬件利用**：
    - 共享内存加速 block 内 scan
    - 合并访存减少 global memory 延迟
    - 减少 bank conflict
3. **分层处理**：先 block 内 scan，再 block 间 scan，最后加偏移
4. **使用库**：生产环境优先使用 **CUB** 或 **Thrust**

> **最终建议**：学习原理用自实现，工程实现用 `cub::DeviceScan`。

---

通过将算法设计与 GPU 的内存模型、线程层次、执行模型深度融合，我们才能真正发挥 CUDA 的并行威力。前缀和是一个绝佳的范例。

# Topk

实现高效的 CUDA Top-K 算法是一个典型的并行选择问题，它要求从大规模数据集中找出最大的（或最小的）K 个元素。与前缀和不同，Top-K 更加复杂，因为它涉及排序、选择、堆操作等，并且对内存访问模式和分支效率高度敏感。

下面我们从**算法设计思想**到**GPU 硬件特性优化**，系统性地讲解如何实现一个高性能的 CUDA Top-K 算法。

---

## 一、Top-K 问题定义

给定一个大小为 `N` 的数组 `A`，找出其中最大的 `K` 个元素，并可选择是否排序输出。

- **输出形式**：
    - 无序 Top-K：仅返回 K 个最大值
    - 有序 Top-K：返回按降序排列的 K 个最大值

> 示例：`A = [3, 1, 4, 1, 5, 9, 2], K=3` → 输出 `[9,5,4]`

---

## 二、串行解法回顾（作为对比基准）

|方法|时间复杂度|说明|
|---|---|---|
|排序后取前 K|O(N log N)|简单但浪费，尤其当 K << N|
|堆（最小堆维护 K 个元素）|O(N log K)|最常用串行方法|
|快速选择（QuickSelect）|平均 O(N)，最坏 O(N²)|找第 K 大元素，再遍历一次|

目标：利用 GPU 的数千核心并行化这些策略，达到接近 O(N) 的实际运行时间。

---

## 三、并行 Top-K 的挑战

1. **数据规模大**：N 可达百万甚至亿级
2. **K 的范围不确定**：
    - K 很小（如 K=10）：适合堆法
    - K 中等（K ~ 1k~10k）：适合分块 + 归并
    - K 很大（K ~ N/2）：接近排序，可用并行排序后截取
3. **内存带宽瓶颈**：频繁比较和交换操作易受限于 global memory 带宽
4. **负载不均衡**：某些线程处理更多数据

---

## 四、CUDA 实现策略（按 K 大小分类）

### ✅ 策略 1：小 K（K ≤ 1024）—— 并行堆法（Parallel Heap / Tile-based）

#### 思路

- 将输入划分为多个 tile（块），每个 block 处理一个 tile
- 每个 block 维护一个 **共享内存中的最小堆**（大小为 K）
- 扫描本地数据，更新堆
- 最后将所有 block 的堆结果合并

#### 实现步骤

```cpp
__global__ void topk_small_kernel(float* input, float* output, int N, int K) {
    extern __shared__ float s_heap[]; // shared memory heap (size K)
    int tid = threadIdx.x;
    int bid = blockIdx.x;
    int start = bid * blockDim.x;
    
    // 初始化堆为空（负无穷）
    if (tid < K) s_heap[tid] = -INFINITY;
    __syncthreads();

    // 插入本地元素（每个线程处理一个）
    int idx = start + tid;
    if (idx < N) {
        float val = input[idx];
        if (val > s_heap[0]) { // 比堆顶大
            s_heap[0] = val;
            // 下滤调整堆
            int i = 0;
            while (true) {
                int left = 2*i + 1, right = 2*i + 2;
                int smallest = i;
                if (left < K && s_heap[left] < s_heap[smallest]) smallest = left;
                if (right < K && s_heap[right] < s_heap[smallest]) smallest = right;
                if (smallest == i) break;
                swap(s_heap[i], s_heap[smallest]);
                i = smallest;
            }
        }
    }
    __syncthreads();

    // Block 最后将本地堆写回 global memory（用于后续归并）
    if (tid < K) {
        output[bid * K + tid] = s_heap[tid];
    }
}
```

> **后续步骤**：
>
> - 调用 `thrust::sort` 或递归合并所有 block 的 K 个候选
> - 取最终前 K 个

#### 优点

- 每个 block 独立，可扩展
- 利用 shared memory 高速缓存堆

#### 缺点

- 若 block 数多，归并开销大
- 不适合 K 很大

---

### ✅ 策略 2：中等 K（K ~ 1k ~ 100k）—— 分块排序 + 归并选择

#### 思路

1. 将数组分成 B 个 block，每个 block 内部用 **并行排序**（如 bitonic sort 或 cub::BlockSort）
2. 每个 block 排序后取前 K 个元素
3. 将所有 block 的前 K 个合并成一个大小为 B*K 的数组
4. 在 host 或 device 上用快速选择或排序取最终 Top-K

#### 优化点

- 使用 `cub::BlockRadixSort` 或 `cub::BlockMergeSort` 实现 block 内排序
- 合并阶段可用多路归并或堆归并（k-way merge）

```cpp
#include <cub/cub.cuh>

template<int BLOCK_THREADS = 256, int K = 1024>
__global__ void topk_sort_kernel(float* d_in, float* d_candidates, int N) {
    typedef cub::BlockRadixSort<float, BLOCK_THREADS, K> BlockRadixSort;
    __shared__ typename BlockRadixSort::TempStorage temp_storage;
    __shared__ float s_data[K];

    int bid = blockIdx.x;
    int tid = threadIdx.x;
    int start = bid * K;

    // Load up to K elements
    if (tid < K && (start + tid) < N)
        s_data[tid] = d_in[start + tid];
    else if (tid < K)
        s_data[tid] = -INFINITY;
    __syncthreads();

    // Sort in shared memory
    BlockRadixSort(temp_storage).Sort(s_data);

    // Write top-K (descending order)
    if (tid < K) {
        d_candidates[bid * K + tid] = s_data[K - 1 - tid]; // 降序
    }
}
```

> 后续调用 `thrust::sort(d_candidates, d_candidates + total_candidates)` 并取前 K

#### 优点

- 充分利用 shared memory 和 warp 指令
- 访存合并，适合中等 K

---

### ✅ 策略 3：大 K（K > 100k）—— 并行排序截取

当 K 接近 N 时，最有效的方法是直接使用 **高性能并行排序**，然后取前 K。

#### 推荐工具

- `cub::DeviceRadixSort::SortDescending`
- `thrust::sort` + `thrust::reverse`

```cpp
#include <cub/cub.cuh>

size_t temp_storage_bytes = 0;
float *d_temp_storage = nullptr;

// 获取临时空间大小
cub::DeviceRadixSort::SortDescending(
    d_temp_storage, temp_storage_bytes, d_keys, d_sorted, N);

// 分配并执行
cudaMalloc(&d_temp_storage, temp_storage_bytes);
cub::DeviceRadixSort::SortDescending(
    d_temp_storage, temp_storage_bytes, d_keys, d_sorted, N);

// Top-K 即 d_sorted[0:K]
```

#### 优点

- CUB 的 radix sort 高度优化，接近内存带宽极限
- 对大 K 最稳定高效

---

## 五、硬件优化技巧（关键！）

### 1. **共享内存（Shared Memory）**

- 用于 block 内堆或排序，避免频繁 global memory 访问
- 定义 `extern __shared__` 动态分配，或固定大小模板

### 2. **合并内存访问（Coalescing）**

- 确保连续线程访问连续地址
- 使用 `blockIdx.x * blockDim.x + threadIdx.x` 索引

### 3. **减少 Bank Conflict**

- Shared memory 有 32 个 bank
- 若使用 `float s_data[32][1024]`，同一列访问会导致冲突
- 解决：加 padding，如 `float s_data[32][1024 + 7]`

### 4. **Warp-Level Primitives**

- 对于小规模操作（如 warp 内找最大值），使用 `__shfl_xor_sync` 或 `__reduce_max_sync`
- 减少同步和分支

```cpp
float warp_max(float val) {
    for (int offset = 16; offset > 0; offset /= 2)
        val = fmaxf(val, __shfl_xor_sync(0xFFFFFFFF, val, offset));
    return val;
}
```

### 5. **Occupancy 优化**

- 增加每个 SM 的活跃 warp 数
- 调整 block size（256 或 512）和 shared memory 使用量
- 使用 `cudaOccupancyMaxPotentialBlockSize` 自动调优

### 6. **异步执行与流水线**

- 使用多个 stream 实现数据传输与计算重叠
- `cudaMemcpyAsync` + kernel pipeline

---


>

> - 中 K：分块排序 + 归并

# Flashattention

你已经理解了 **Flash Attention v1**，这是非常重要的基础。Flash Attention 系列的目标是**在保持注意力机制数学等价的前提下，极大提升其计算效率、降低内存占用，并适配现代 GPU 硬件特性**。

下面我们系统地讲解 **Flash Attention v2、v3、v4** 的演进路径，重点突出每一版相比前一版的**核心改进、性能提升原因、以及硬件优化思想**。

---

## 🔁 回顾：Flash Attention v1（2022）

### ✅ 解决了什么问题？

传统注意力（如 PyTorch 实现）：

- 时间复杂度：O(N²)
- 空间复杂度：O(N²)（显式存储 QK^T 和 Softmax 输出）
- 计算不高效：多次 global memory 访问

### ✅ Flash Attention V1 的核心思想

1. **I/O 感知算法设计（Tiling + Blocking）**
    - 将 Q, K, V 分块（tile），只加载必要数据到 on-chip memory（SRAM）
2. **在线 Softmax（Online Softmax）**
    - 不显式存储完整的 S = QK^T 和 P = softmax(S)
    - 边计算边归一化，避免 O(N²) 中间缓存
3. **重计算（Recomputation）**
    - 反向传播时不保存中间矩阵，而是重新计算部分前向结果
    - 节省显存，换取少量计算

### ✅ 效果

- 显存占用从 O(N²) → O(N)
- 训练速度提升 2~4x
- 支持更长序列（如 4K → 8K）

### ❌ 局限性

- 未充分利用 GPU 的 **Tensor Cores**（尤其是 FP16/BF16 + TF32）
- 对 **长序列 + 小 batch** 优化不够
- 向量化和 warp-level 并行仍有提升空间
- 不支持 **masking、causal、alibi** 等复杂 attention 形式高效处理

---

## 🚀 Flash Attention v2（2023）

> 论文：[FlashAttention-2: Faster Attention with Better Parallelism](https://arxiv.org/abs/2307.08691)

### ✅ 核心目标

**进一步减少 global memory 访问，提升 GPU 利用率（尤其是 SM occupancy 和 warp 并行度）**

### ✅ 主要改进

### 1. **更细粒度的并行策略（Reverse Blocking）**

- v1 是“列优先”处理 K/V 块
- v2 改为“行优先”处理 Q 块，并行化更多线程块（blocks）
- 提高 **GPU occupancy**（活跃 SM 数量）

> 结果：kernel 吞吐提升 2x

### 2. **减少 Redundant Memory reads**

- v1 中每个 K/V 块被多个 Q 块重复读取
- v2 优化数据布局和调度，减少重复加载
- 使用 **register blocking**，更多数据驻留在寄存器中

### 3. **Warp-level 优化**

- 使用 warp-level primitives（如 `__shfl_sync`）进行局部归约
- 减少 shared memory 冲突和同步开销

### 4. **支持多种 Attention 形式**

- 高效支持 causal（上三角）、padding mask、prefix attention
- 通过编译时条件判断，避免 runtime 分支

### 5. **自动调优（Kernel Autotuning）**

- 根据序列长度 N、head_dim、batch_size 动态选择最优 tile size
- 类似 CUTLASS 的策略

### ✅ 性能提升（相比 v1）

- **训练速度提升 1.5~2x**
- 在 Llama-2、PaLM 等模型上实测 **端到端训练加速 15~30%**
- 尤其在 **长序列（>2K）和小 batch** 场景下优势明显

### 📈 举例

|模型|序列长度|加速比（vs v1）|
|---|---|---|
|Llama-2-7B|4K|~1.8x|
|PaLM-62B|2K|~1.6x|

## ⚡ Flash Attention v3（2024）

> 论文：[FlashAttention-3: Efficient Transformers with Long Contexts](https://arxiv.org/abs/2405.04574)

### ✅ 核心目标

**为超长上下文（100K+ tokens）和多模态场景优化，支持稀疏、分块、混合精度计算**

### ✅ 主要改进

### 1. **支持 Hopper 架构（H100）的 Tensor Cores（FP8, TF32）**

- 利用 H100 的 **FP8 Tensor Core** 进行 QK^T 计算
- 使用 **TF32** 进行高精度累加
- 显存带宽利用率接近理论峰值

### 2. **混合精度分块计算（Mixed-Precision Tiling）**

- QK^T 使用低精度（FP8/FP16）计算
- Softmax 归一化使用高精度（FP32）
- 最终输出使用 BF16 存储
- 平衡速度与数值稳定性

### 3. **稀疏注意力支持（Sparse Attention）**

- 高效实现 **local + global + random** attention（类似 Longformer）
- 使用 bitmask + warp-level scatter/gather
- 避免对零块进行无效计算

### 4. **多查询注意力（MQA）和分组查询注意力（GQA）优化**

- v3 对 GQA 做了专门优化：
    - 共享 K/V 的 tile 缓存
    - 减少重复 K/V 加载
- 在 Llama-3、Gemini 等模型中显著提速

### 5. **动态序列长度支持（Variable-Length Sequences）**

- 支持一个 batch 内不同 sequence length
- 使用 **padding-free** 处理，避免无效计算
- 通过 **segmented attention** 实现

### 6. **Kernel Fusion 增强**

- 更深度融合 LayerNorm、Residual、RoPE 等操作
- 减少 kernel launch 次数和 memory 往返

### ✅ 性能提升（相比 v2）

- **长序列（32K~~100K）下速度提升 2~~3x**
- GQA 场景下比 v2 快 1.8x
- 支持 FP8 推理，吞吐提升 2x（H100）

## 🔮 Flash Attention v4（2025，最新进展）

> 目前尚未有正式论文，但基于 NVIDIA GTC 2025 发布和社区实现（如 `flash-attn 2.5+`），可总结出 v4 的方向。

### ✅ 核心目标

**极致优化推理性能，支持超大规模 MoE 模型、流式 attention、硬件感知编译**

### ✅ 预期/已实现改进

### 1. **MoE（Mixture Of Experts）原生支持**

- 每个 token 只激活部分 attention head
- 使用 **conditional computation**，跳过非激活 head 的计算
- 结合 Top-K routing，实现稀疏 attention + MoE 联合优化

### 2. **流式 attention（Streaming Attention）**

- 支持无限长上下文（>1M tokens）
- 使用 **chunked attention + cache compression**
- 类似 **Ring Attention** 或 **Blockwise Attention** 思想
- 自动管理 KV Cache 生命周期

### 3. **硬件感知编译（Hardware-Aware Compilation）**

- 使用 **Triton** 或 **CUDA Graph + Autotuning** 生成最优 kernel
- 针对不同 GPU（A100, H100, B100, Blackwell）生成定制代码
- 支持 **dynamic shape** 和 **runtime tuning**

### 4. **极致低延迟推理优化**

- **PagedAttention++**：改进 KV Cache 内存管理
- **Prefetching**：预加载下一块 K/V
- **Quantization-aware kernel**：支持 INT4、FP4 计算

### 5. **支持新型 Attention 变体**

- **MQA-GQA Hybrid**
- **Band + Sparse + Causal** 混合 mask
- **Learned sparse patterns**

### ✅ 预期性能

- 推理延迟降低 40~60%
- MoE 模型吞吐提升 2~4x
- 支持 1M+ 上下文实时处理

## 🔚 总结

Flash Attention 从 v1 到 v4 的演进，是 **“算法 + 系统 + 硬件” 协同设计** 的典范：

- **v1**：算法突破，解决内存瓶颈
- **v2**：系统优化，提升计算效率
- **v3**：硬件适配，拥抱新架构（H100 + Tensor Cores）
- **v4**：场景扩展，面向未来（MoE、流式、无限上下文）

> **一句话总结**：
> Flash Attention 不再只是一个“注意力 kernel”，而是**一个面向现代 AI 硬件的、可扩展的、高性能 attention 运行时系统**。

掌握其演进逻辑，有助于你设计其他高效 CUDA kernel，甚至为未来模型架构（如 1M context、MoE、Agent）做好准备。
