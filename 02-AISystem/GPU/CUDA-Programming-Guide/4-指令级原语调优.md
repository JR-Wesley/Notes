# Overview

- Learning about multiple classes of CUDA instructions and their impact on application behavior
- Observing the relative accuracy of single- and double-precision floating-point values
- Experimenting with the performance and accuracy of standard and intrinsic functions
- Uncovering undefined behavior from unsafe memory accesses
- Understanding the significance of arithmetic instructions and the consequences of using them improperly

本章聚焦于 **compute-bound（计算受限）** 工作负载的指令级调优。决定使用 CUDA 通常是为了 GPU 的计算吞吐，但正如书中所言：

> "However, not all instructions are created equal."

并非所有指令生而平等。理解不同底层原语（primitive）在 **性能、数值精度、线程安全** 上的差异，并知道内核代码何时被编译成哪一种指令，才能反过来调控编译器的代码生成。

贯穿全章的一个核心思想是 **tradeoff（权衡）**：书里用 MAD（乘加融合）举例——`double value = in1 * in2 + in3;` 现代架构支持把"乘+加"融合成单条 MAD 指令，周期数减半，但数值精度往往略低于分开的乘、加两条指令。**本章所有主题都是在两种 desirable 行为之间做取舍。**

# Ch.7 指令级原语调优

> 本章把"指令"作为调优的最小旋钮：浮点精度、标准/内建函数、原子操作，三类都各自在 性能 / 精度 / 正确性 上权衡。

## INTRODUCING CUDA INSTRUCTIONS（CUDA 指令概览）

指令是处理器中最小的逻辑单元。虽然很少直接手写指令，但理解**何时生成哪种指令**、高层语言特性如何映射到指令至关重要。两个功能等价的指令选择，会影响性能、精度、正确性——在做有严格数值校验要求的 CPU→GPU 迁移时尤其重要。

本章三类显著影响指令生成的话题：**浮点运算、内建/标准函数、原子操作**。

### 1. Floating-Point Instructions（浮点指令）

**IEEE 754 基础**
- 二进制浮点由三个字段编码：1 位符号 `sign`、若干位指数 `exponent`、若干位尾数 `significand/fraction`。
- 标准定义 32-bit（`float`）与 64-bit（`double`），对应 C 的 `float` / `double`。
- 一个 32-bit float（符号位 s、8 位指数 e、23 位尾数 v）的值：
  `(-1)^s × (1.υ22υ21...υ0) × 2^(e-127)`
- 浮点能表示的值比整数更细粒度，但仍是**离散且有限的集合**。

**精度粒度（granularity）与舍入**
- 例：`float a = 3.1415927f; float b = 3.1415928f;` 在 IEEE-754 下会打印 `a is equal to b`——两者都无法精确存储，都被舍入到同一个可表示值。
- 舍入模式：默认 `round-to-nearest`（就近舍入）；另有 `round-to-zero`、`round-up`、`round-down`。
- 可表示浮点值之间的间隔随绝对值增大而变宽（FIGURE 7-4）。可用 C 标准库 `nextafterf` 求下一个可表示 float。Table 7-1 显示间隔随数值剧增：

  | x | nextafterf(x) - x |
  |---|---|
  | 3.14 | 2.384186e-07 |
  | 314,159.28 | 0.03125 |
  | 314,159,275,180,032.00 | 3.355443e+07 |

**Single vs Double**
- double 用两倍位 → 粒度更细、范围更广。对应 double 版本 `a != b` 为真（存储的最近可表示值不同）。
- 所有计算能力 GPU 支持单精度；双精度需 compute capability ≥ 1.3。

### 2. Intrinsic and Standard Functions（内建函数 vs 标准函数）

- **Standard functions**：主机与设备通用、标准化，如 `sqrt`、`exp`、`sin` 等 C 标准数学库函数；单指令的乘加也算标准函数。
- **Intrinsic functions（内建/固有函数）**：仅设备代码可用；编译器对其有特殊认知，能做更激进优化、生成专用指令。许多三角函数因图形应用需求在 GPU 硬件直接实现。
- 关联：标准函数常有对应内建版本。例如双精度 `sqrt` ↔ `__dsqrt_rn`；单精度除法 `__fdividef`。
- 关键结论：

  > "Intrinsic functions decompose into fewer instructions than their equivalent standard functions. As a result, intrinsic functions are faster than their equivalent standard functions but less numerically precise."

  **内建函数 = 更少指令 = 更快但精度更低**，可作为逐操作（operation-by-operation）的细粒度旋钮。

### 3. Atomic Instructions（原子指令）

- 原子指令在**单一不可打断**的操作中完成数学运算，不受其它线程干扰；保证 read-modify-write 在多线程共享数据上的正确性（读当前值→改→写回）。
- compute capability ≥ 1.1 支持；Kepler 的全局原子比 Fermi 快得多、吞吐显著提升。
- **Data race / unsafe access（数据竞争/不安全访问）**：两个及以上独立线程访问同一位置且至少一个在写 → 结果未定义。

  ```c
  __global__ void incr(int *ptr) {
      int temp = *ptr;      // 所有线程读同一地址
      temp = temp + 1;
      *ptr = temp;          // 所有线程写同一地址 → 未定义结果
  }
  ```

  32 线程启动，结果**未定义**。改用 `atomicAdd`：

  ```c
  __global__ void incr(int *ptr) {
      int temp = atomicAdd(ptr, 1);   // 原子加 1，返回旧值
  }
  ```

  32 线程 → `*ptr` 必为 32。

- 原子函数分三类：**arithmetic**（add/sub/max/min/inc/dec）、**bitwise**（and/or/xor）、**swap**（`atomicExch` 无条件替换；`atomicCAS` 条件替换——仅当当前值等于期望值时才替换，始终返回目标地址原值）。
- 注意 `check_threshold` 例：仅把全局 flag 置 1，用 unsafe 访问也能功能正确（至少一个线程写成功），但 `atomicExch` 不改变行为且可能显著降低性能。必须谨慎确认操作"真的不依赖每个线程结果都可见"，否则不安全访问是**不推荐的编程实践**。

## OPTIMIZING INSTRUCTIONS FOR YOUR APPLICATION（为应用优化指令）

每类选择都在 **性能 / 精度 / 正确性** 上权衡，没有对所有应用都最优的单一选择，取决于需求。

### 1. Single-Precision vs Double-Precision（单精度 vs 双精度）

- `floating-point-accuracy.cu`：把 12.1 存到单/双精度并输出 20 位小数：
  - 单精度主机/设备 = `12.10000038146972656250`
  - 双精度主机/设备 = `12.09999999999999964473`
  - 都不精确，双精度略接近真值。
- `floating-point-perf.cu` 实测（单 vs 双精度，通信+计算）：

  | | Copy to device | Kernel | Copy from device |
  |---|---|---|---|
  | 单精度 | 129 ms | 574 ms | 201 ms |
  | 双精度 | 258 ms (2.00x) | 890 ms (1.55x) | 401 ms (2.00x) |

  - 通信时间**正好翻倍**（双精度长度翻倍）；计算时间也增（全局内存 I/O 与每指令操作位数都增）。整体近 2x 慢。
- **迭代应用**误差会累积（不精确输出作为下一轮输入）→ 更可能需要双精度。
- **寄存器代价**：double 占寄存器空间是 float 两倍 → 线程块可用寄存器更少 → 可能寄存器溢出到全局内存、占用率下降。
- ⚠️ **常见陷阱**：`float pi = 3.14;`（漏写末尾 `f`）会被 nvcc 自动提升为 double！务必写 `3.14f`。
- Table 7-2 总结：单精度性能更好、精度"够用"、正确性无变化；双精度性能较差（通信/位宽代价）、精度更好、正确性无变化。

### 2. Standard vs. Intrinsic Functions

**用 PTX 可视化差异**
- `nvcc --ptx -o foo.ptx foo.cu` 生成 PTX（Parallel Thread Execution ISA，类 x86 汇编的中间表示），用于洞察内核底层执行路径。
- 对比 `__powf` 与 `powf`：`__powf` 约 7 条指令（`lg2.approx` + `mul` + `ex2.approx` …）；标准 `powf` 在 CUDA 5.0 下长达 344 行。行数≠指令/周期，但性能差距显著。

**实测 `intrinsic-standard-comp.cu`**

| | 结果 |
|---|---|
| Host（基线） | 66932852.000000 |
| Standard `powf` | 66932848.000000（差 4） |
| Intrinsic `__powf` | 66932804.000000（差 48 vs 主机） |
| 耗时 powf | 47 ms |
| 耗时 __powf | 2 ms（约 **24x 加速**） |

内建函数结果偏离基线一个数量级——性能换精度。

### 3. PORTING FROM CPU TO GPU（CPU→GPU 迁移注意）

- 两步：① 把 legacy CPU 应用 port 到 CUDA；② 用 legacy 结果校验 CUDA 版数值精度。
- 即使使用数值稳定函数，GPU 结果仍可能与 CPU 不同（浮点固有误差，难说谁更"正确"）。迁移计划必须**预设数值差异容忍度**。

### 4. Manipulating Instruction Generation（指导指令生成）

多数情况编译器在幕后完成指令翻译，但可用两种方式调控：**编译器 flag** 与 **内建/标准函数调用**。

**编译器 flag（Table 7-3）**

| Flag | 作用 | 默认 | 性能影响 | 精度影响 |
|---|---|---|---|---|
| `--ftz=[true,false]` | 单精度非规格化数 flush to zero | false | true 可能提升 | false 可能提升 |
| `--prec-div=[true,false]` | 单精度除法/倒数数值精度 | true | true 可能降性能 | true 更 IEEE 兼容 |
| `--prec-sqrt=[true,false]` | 更精确 sqrt | true | true 可能降性能 | true 更 IEEE 兼容 |
| `--fmad=[true,false]` | 是否允许乘加融合为 FMAD | true | 启用提升 | 启用可能降精度 |
| `--use_fast_math` | 全部标准函数替换为内建；并设 `--ftz=true --prec-div=false --prec-sqrt=false` | false | 提升 | 可能降 |

**FMAD 示例**
- 默认 `--fmad=true`。`*ptr = (*ptr)*(*ptr) + (*ptr);` → PTX 单条 `mad.f32 %f2, %f1, %f1, %f1;`
- `--fmad=false` → 拆成 `mul.rn.f32` + `add.rn.f32` 两条。
- 控制 FMAD 的内建函数：`__fmul`（float）、`__dmul`（double）乘法。调用它们**阻止 nvcc 把该乘法用于 MAD 优化，且不受 `--fmad` 影响** → 可在全局启用 FMAD 的同时，用 `__fmul`/`__dmul` 对个别计算提升数值稳健性。

**舍入模式后缀（Table 7-4）**
- `__fmul_rn` / `__fadd` / `__fsub` / `__fmul` 等用两字符后缀指明舍入：
  - `rn`：round to nearest（默认）
  - `rz`：round toward zero
  - `ru`：round toward +∞
  - `rd`：round toward -∞

**`fmad.cu` 实测**
- `--fmad=true`：device 与 host 不同，`diff=8.881784e-16`（小误差）
- `--fmad=false`：device 与 host 完全相同，代价是更多指令。

### 5. Understanding Atomic Instructions

**From the Ground Up：用 `atomicCAS` 实现自定义原子**
- CAS 输入：内存地址、期望旧值、期望新值；相等才写入，无论如何返回读取到的旧值（返回==期望即成功）。
- 用 `atomicCAS` 实现 32-bit int 加法 `myAtomicAdd`：

  ```c
  __device__ int myAtomicAdd(int *address, int incr) {
      int expected = *address;                              // 初猜旧值
      int oldValue = atomicCAS(address, expected, expected + incr);
      while (oldValue != expected) {                        // CAS 失败则重试
          expected = oldValue;
          oldValue = atomicCAS(address, expected, expected + incr);
      }
      return oldValue;                                      // 返回被替换的旧值（语义对齐内建）
  }
  ```

  因地址被多线程共享，首次 CAS 可能被中途改写而失败 → 循环重试直到成功。

**Built-In CUDA Atomic Functions（Table 7-6）**

| 操作 | 函数 | 支持类型 |
|---|---|---|
| 加 | `atomicAdd` | int, unsigned int, unsigned long long int, **float** |
| 减 | `atomicSub` | int, unsigned int |
| 无条件交换 | `atomicExch` | int, unsigned int, unsigned long long int, **float** |
| 最小/最大 | `atomicMin` / `atomicMax` | int, unsigned int, unsigned long long int |
| 自增/自减 | `atomicInc` / `atomicDec` | unsigned int |
| 比较交换 | `atomicCAS` | int, unsigned int, unsigned long long int |
| 位与/或/异或 | `atomicAnd` / `atomicOr` / `atomicXor` | int, unsigned int, unsigned long long int |

- 支持：≥1.1 全局内存 32-bit；≥1.2 共享内存 32-bit + 全局 64-bit；≥2.0 共享内存 64-bit。

**The Cost of Atomic Operations（原子代价）**
- ① 原子保证变化立即对所有线程可见 → 至少一次全局/共享内存读写，**无缓存**。
- ② 冲突访问需重试（类似 `myAtomicAdd` 循环），带来 I/O 开销。
- ③ warp 内线程执行不同指令 → 串行化；同一 warp 多线程对同一地址原子操作 → 仅一个成功、其余重试，t 线程 × n 周期，且整个 warp 停顿等待。
- `atomic-ordering.cu` 实测：atomics 30 次共 3704 ms（结果正确 6400064）；unsafe 11 ms（结果 100001，大量被覆盖）。**原子版慢 300+ 倍！**

**Limiting the Performance Cost（降低原子代价）**
- 思路：先用线程块内低延迟资源（**shuffle 指令或共享内存**）做局部归约得到部分结果（要求操作**可交换 commutative**），再用原子操作把部分结果合并到全局（FIGURE 7-5）。

**Atomic Floating-Point Support（浮点原子支持）**
- 内建原子多为整数类型；仅 `atomicExch` 与 `atomicAdd` 支持单精度 float；**无内建支持双精度**。
- 自定义浮点原子：把 float 原始位 reinterpret 成支持的类型（`unsigned int`），对其做 `atomicCAS`：

  ```c
  __device__ float myAtomicAdd(float *address, float incr) {
      unsigned int *typedAddress = (unsigned int *)address;
      float currentVal = *address;
      unsigned int expected = __float2uint_rn(currentVal);
      unsigned int desired  = __float2uint_rn(currentVal + incr);
      int oldIntValue = atomicCAS(typedAddress, expected, desired);
      while (oldIntValue != expected) {
          expected = oldIntValue;
          desired  = __float2uint_rn(__uint2float_rn(oldIntValue) + incr);
          oldIntValue = atomicCAS(typedAddress, expected, desired);
      }
      return __uint2float_rn(oldIntValue);
  }
  ```

- 类型转换工具：`__float2uint_rn`、`__uint2float_rn`、`__double_as_longlong`、`__longlong_as_double`、`__double2float_rn` 等，是实现自定义浮点原子的关键。

**Table 7-7：原子 vs 不安全访问**

| | 性能 | 精度 | 正确性 |
|---|---|---|---|
| 原子操作 | 差（大开销） | 无影响（内建少支持浮点） | 多线冲突访问保证正确 |
| 不安全访问 | 好（等同普通全局访问） | 无影响 | 无保证 |

### 6. Bringing It All Together：NBody 示例

- NBody：粒子间互相施力，迭代更新速度/位置。
- 两个全局统计：① 是否有粒子超出某半径 → 只需 boolean flag → **可用 unsafe 访问**；② 超阈值速度粒子计数 → 需精确 → **必须 atomic**。
- 编译期选精度：`-DSINGLE_PREC` / `-DDOUBLE_PREC`（默认单精度）。
- 实测：单精度 10569 ms，Error 5.48；双精度 60688 ms（约 **6x 慢**），Error 3.66。
  双精度代价来源：① 通信翻倍 ② 设备 I/O 翻倍 ③ 寄存器更少→可能溢出 ④ 双位计算开销。
- `-DVALIDATE` 与 host 实现比对，打印位置平均误差。
- 编译器 flag 实测（单精度，Table 7-8）：

  | 配置 | --ftz | --prec-div | --prec-sqrt | --fmad | --use_fast_math | 时间(ms) | Error |
  |---|---|---|---|---|---|---|---|
  | 全性能 | true | false | false | true | true | 5336 | 4.6946 |
  | 全精度 | false | true | true | false | false | 12042 | 0.0000 |

  - 全性能总执行时间提升 **2.25x**；全精度与 host **零偏差**。

## SUMMARY（本章总结）

- 构建 CUDA 应用须关注：浮点操作、标准/内建函数、原子操作 对 **性能与数值精度** 的影响。
- 编译器/库通常隐藏底层细节 → 双刃剑：自动优化减负，但导致对 kernel 变换的**可见性/意识缺失** → 难调试数值问题、可能错过优化机会。
- NBody 示例展示显著收益来自：单/双精度、内建/标准函数、原子/不安全访问 的合理选择——在**不牺牲正确性**的前提下充分榨取 GPU 算力。
