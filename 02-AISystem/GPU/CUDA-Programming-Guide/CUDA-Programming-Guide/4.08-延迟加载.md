## 4.8. Lazy Loading（延迟加载）

来源：[CUDA Programming Guide — Lazy Loading](https://docs.nvidia.com/cuda/cuda-programming-guide/04-special-topics/lazy-loading.html)。

### 4.8.1. Introduction（简介）

> Lazy loading reduces program initialization time by waiting to load CUDA modules until they are needed. Lazy loading is particularly effective for programs that only use a small number of the kernels they include, as is common when using libraries. Lazy loading is designed to be invisible to the user when the CUDA programming model is followed. [Potential Hazards](https://docs.nvidia.com/cuda/cuda-programming-guide/04-special-topics/lazy-loading.html#lazy-loading-potential-hazards) explains this in detail.

Lazy loading（延迟加载）通过等到需要时才加载 CUDA module，缩短程序初始化时间。对于包含许多 kernel、实际只使用其中少数的程序，这种方式尤其有效；使用库时常见这种情况。遵循 CUDA 编程模型的程序通常无需感知这一机制。关于潜在问题，见下文 Potential Hazards。

> As of CUDA 12.3 lazy Loading is enabled by default on all platforms, but can be controlled via the `CUDA_MODULE_LOADING` environment variable.

从 CUDA 12.3 起，所有平台默认启用 lazy loading；也可以通过环境变量 `CUDA_MODULE_LOADING` 控制。

**解读：** 延迟加载将部分 module 加载工作从启动阶段移到首次需要它们的时刻。启动可能更快，但首次使用某个 kernel 的耗时可能包含加载开销；测量性能时要区分这两段时间。

### 4.8.3. Requirements for Lazy Loading（使用要求）

> Lazy loading is a joint feature of both the CUDA runtime and driver. Lazy loading is only available when the runtime and driver version requirements are satisfied.

Lazy loading 由 CUDA runtime 与 driver 共同支持；两者都满足相应版本要求时才能使用。

#### 4.8.3.1. CUDA Runtime Version Requirement（CUDA Runtime 版本要求）

> Lazy loading is available starting in CUDA runtime version 11.7. As CUDA runtime is usually linked statically into programs and libraries, only programs and libraries from or compiled with CUDA 11.7+ toolkit will benefit from lazy loading. Libraries compiled using older CUDA runtime versions will load all modules eagerly.

从 CUDA runtime 11.7 开始可以使用 lazy loading。由于 CUDA runtime 通常静态链接进程序和库，只有来自 CUDA 11.7 或更高版本 toolkit、或使用其编译的程序和库，才能受益于 lazy loading。使用更旧 CUDA runtime 编译的库会立即加载所有 module。

#### 4.8.3.2. CUDA Driver Version Requirement（CUDA Driver 版本要求）

> Lazy loading requires driver version 515 or newer. Lazy loading is not available for driver versions older than 515, even when using CUDA toolkit 11.7 or newer.

Lazy loading 要求 driver 版本不低于 515。即使用 CUDA 11.7 或更新的 toolkit，driver 低于 515 时仍无法使用 lazy loading。

**解读：** 判断是否可用，不能只看编译所用 toolkit；还要看程序或库所链接的 runtime，以及运行机器上的 driver。不同库若链接了不同版本的 CUDA runtime，其 module 加载行为也可能不同。

#### 4.8.3.3. Compiler Requirements（编译器要求）

> Lazy loading does not require any compiler support. Both SASS and PTX compiled with pre-11.7 compilers can be loaded with lazy loading enabled, and will see full benefits of the feature. However, the version 11.7+ CUDA runtime is still required, as described above.

Lazy loading 不要求编译器提供专门支持。由 11.7 以前的编译器生成的 SASS 和 PTX 也可在启用 lazy loading 时加载，并获得该功能的完整收益；但仍须满足上述 CUDA runtime 11.7 或更高版本的要求。

#### 4.8.3.4. Kernel Requirements（Kernel 要求）

> Lazy loading does not affect modules containing managed variables, which will still be loaded eagerly.

Lazy loading 不作用于包含 managed variable 的 module；这些 module 仍会立即加载。

### 4.8.4. Usage（使用方法）

#### 4.8.4.1. Enabling & Disabling（启用与关闭）

> Lazy loading is enabled by setting the `CUDA_MODULE_LOADING` environment variable to `LAZY`. Lazy loading can be disabled by setting the `CUDA_MODULE_LOADING` environment variable to `EAGER`. As of CUDA 12.3, lazy loading is enabled by default on all platforms.

将环境变量 `CUDA_MODULE_LOADING` 设为 `LAZY` 可启用 lazy loading；设为 `EAGER` 可关闭。自 CUDA 12.3 起，所有平台默认启用。

#### 4.8.4.2. Checking if Lazy Loading is Enabled at Runtime（运行时检查加载模式）

> The `cuModuleGetLoadingMode` API in the CUDA driver API can be used to determine if lazy loading is enabled. Note that CUDA must be initialized before running this function. Sample usage is shown in the snippet below.

可调用 CUDA Driver API 的 `cuModuleGetLoadingMode` 判断是否启用了 lazy loading。调用前必须先初始化 CUDA。下面是使用示例。

```cpp
#include "<cuda.h>"
#include "<assert.h>"
#include "<iostream>"

int main() {
        CUmoduleLoadingMode mode;

        assert(CUDA_SUCCESS == cuInit(0));
        assert(CUDA_SUCCESS == cuModuleGetLoadingMode(&mode));
        std::cout << "CUDA Module Loading Mode is " << ((mode == CU_MODULE_LAZY_LOADING) ? "lazy" : "eager") << std::endl;

        return 0;
}
```

**解读：** `cuInit(0)` 先初始化 CUDA，随后 `cuModuleGetLoadingMode` 返回当前加载模式。示例把 API 调用放在 `assert` 表达式中；若编译时定义了 `NDEBUG`，这些表达式可能被移除。因此实际程序应在 `assert` 外调用 API，再检查返回值。

#### 4.8.4.3. Forcing a Module to Load Eagerly at Runtime（运行时主动加载 Module）

> Loading kernels and variables happens automatically, without any need for explicit loading. Kernels can be loaded explicitly even without executing them by doing the following:

Kernel 和变量会自动加载，无需显式操作。不过，也可以在不执行 kernel 的情况下，通过以下方式主动触发加载：

> - The `cuModuleGetFunction()` function will cause a module to be loaded into device memory
> - The `cudaFuncGetAttributes()` function will cause a kernel to be loaded into device memory

- 调用 `cuModuleGetFunction()` 会使 module 加载到 device memory。
- 调用 `cudaFuncGetAttributes()` 会使 kernel 加载到 device memory。

> **Note:** `cuModuleLoad()` does not guarantee that a module will be loaded immediately.

**注意：** `cuModuleLoad()` 并不保证 module 会立即加载。

**解读：** 需要在计时或并发启动前预加载时，应使用文中明确会触发加载的函数。仅调用 `cuModuleLoad()` 不能据此断定加载成本已经发生。

### 4.8.5. Potential Hazards（潜在问题）

> Lazy loading is designed so that it should not require any modifications to applications to use it. That said, there are some caveats, especially when applications are not fully compliant with the CUDA programming model, as described below.

Lazy loading 的设计目标是让应用无需修改即可使用。不过，如果应用没有完全遵循 CUDA 编程模型，仍须注意下列情况。

#### 4.8.5.1. Impact on Concurrent Kernel Execution（对 Kernel 并发执行的影响）

> Some programs incorrectly assume that concurrent kernel execution is guaranteed. A deadlock can occur if cross-kernel synchronization is required, but kernel execution has been serialized. To minimize the impact of lazy loading on concurrent kernel execution, do the following:

有些程序错误地假定 kernel 一定并发执行。如果两个 kernel 需要相互同步，而实际执行被串行化，可能出现死锁。为减少 lazy loading 对 kernel 并发执行的影响，可以：

> - preload all kernels that you hope to execute concurrently prior to launching them or
> - run application with `CUDA_MODULE_LOADING` = `EAGER` to force loading data eagerly without forcing each function to load eagerly

- 在启动之前预加载所有希望并发执行的 kernel；或者
- 使用 `CUDA_MODULE_LOADING=EAGER` 运行应用，使数据立即加载，但不强制每个 function 都立即加载。

**解读：** 并发执行不是可依赖的同步保证。跨 kernel 的等待若只有在两者同时运行时才能结束，就存在死锁风险；预加载可减少首次加载造成的串行化影响，但程序仍应避免依赖“必定并发”这一假设。

#### 4.8.5.2. Large Memory Allocations（大容量内存分配）

> Lazy loading delays memory allocation for CUDA modules from program initialization until closer to execution time. If an application allocates the entire VRAM on startup, CUDA can fail to allocate memory for modules at runtime. Possible solutions:

Lazy loading 将 CUDA module 所需的内存分配从程序初始化阶段推迟到更接近执行的时刻。如果应用在启动时分配了全部 VRAM，CUDA 可能在运行时无法再为 module 分配内存。可采取以下措施：

> - use `cudaMallocAsync()` instead of an allocator that allocates the entire VRAM on startup
> - add some buffer to compensate for the delayed loading of kernels
> - preload all kernels that will be used in the program before trying to initialize the allocator

- 使用 `cudaMallocAsync()`，避免分配器在启动时占满全部 VRAM；
- 预留一部分 VRAM，以容纳延迟加载的 kernel；
- 在初始化分配器之前，预加载程序将使用的所有 kernel。

**解读：** 延迟加载不会消除 module 的显存需求，只是改变分配发生的时间。若分配器在程序启动时占尽 VRAM，后续首次加载可能失败，因此需要预留空间或调整初始化顺序。

#### 4.8.5.3. Impact on Performance Measurements（对性能测量的影响）

> Lazy loading may skew performance measurements by moving CUDA module initialization into the measured execution window. To avoid this:

Lazy loading 可能把 CUDA module 初始化移入被测执行区间，从而影响性能测量。避免这种情况可采用：

> - do at least one warmup iteration prior to measurement
> - preload the benchmarked kernel prior to launching it

- 测量前至少执行一次预热迭代；
- 启动被测 kernel 前先预加载它。

**解读：** 若目标是测量稳定运行时的 kernel 性能，应先完成预热或预加载；若目标是测量首次调用延迟，则应保留加载成本，并在结果中说明测量范围。
