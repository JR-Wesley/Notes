## 4.10. Asynchronous Barriers（异步屏障）

来源：[CUDA Programming Guide — Asynchronous Barriers](https://docs.nvidia.com/cuda/cuda-programming-guide/04-special-topics/async-barriers.html)

> Asynchronous barriers, introduced in Advanced Synchronization Primitives, extend CUDA synchronization beyond `__syncthreads()` and `__syncwarp()`, enabling fine-grained, non-blocking coordination and better overlap of communication and computation.

Advanced Synchronization Primitives 一节介绍的 asynchronous barrier，将 CUDA 同步能力扩展到 `__syncthreads()` 和 `__syncwarp()` 之外，支持更细粒度、非阻塞的协调，从而更好地重叠通信与计算。

> This section provides details on how to use asynchronous barriers mainly via the `cuda::barrier` API (with pointers to `cuda::ptx` and primitives where applicable).

本节主要通过 `cuda::barrier` API 详细说明 asynchronous barrier 的用法，并在适用处介绍 `cuda::ptx` 和底层 primitive 接口。

**解读：** “异步”主要体现在 arrive 与 wait 可以分开：线程先报告到达，再执行不依赖同步结果的工作，最后等待 phase 完成。Wait 本身仍可能阻塞，barrier 也不会自动识别所有内存传输；异步操作需要按相应 API 的规则关联到它。

### 4.10.1. Initialization（初始化）

> Initialization must happen before any thread begins participating in a barrier.

任何线程开始参与 barrier 之前，都必须先完成初始化。

> **CUDA C++ `cuda::barrier`**

**CUDA C++：`cuda::barrier`**

```cpp
#include <cuda/barrier>
#include <cooperative_groups.h>

__global__ void init_barrier()
{
  __shared__ cuda::barrier<cuda::thread_scope_block> bar;
  auto block = cooperative_groups::this_thread_block();

  if (block.thread_rank() == 0)
  {
    // A single thread initializes the total expected arrival count.
    init(&bar, block.size());
  }
  block.sync();
}
```

> **CUDA C primitives**

**整理说明：** 粘贴内容保留了多个代码选项卡标签，但没有提供其中 `cuda::ptx` 或 CUDA C primitives 选项卡的代码。以下仅整理实际提供的代码，保留这些标签并注明缺失，不把其他来源的示例补作用户原文。

> Before any thread can participate in a barrier, the barrier must be initialized using the `cuda::barrier::init()` friend function. This must happen before any thread arrives on the barrier. This poses a bootstrapping challenge in that threads must synchronize before participating in the barrier, but threads are creating a barrier in order to synchronize. In this example, threads that will participate are part of a cooperative group and use `block.sync()` to bootstrap initialization. Since a whole thread block is participating in the barrier, `__syncthreads()` could also be used.

任何线程参与 barrier 之前，必须使用 `cuda::barrier::init()` 这个 friend function 初始化 barrier，而且初始化必须早于任何线程的 arrive。这带来一个自举问题：线程为了使用 barrier，需要先同步；但创建 barrier 的目的正是同步。本例中的参与线程属于一个 cooperative group，因此使用 `block.sync()` 完成初始化后的首次同步。由于整个 thread block 都参与，也可以使用 `__syncthreads()`。

> The second parameter of `init()` is the expected arrival count, i.e., the number of times `bar.arrive()` will be called by participating threads before a participating thread is unblocked from its call to `bar.wait(std::move(token))`. In this and the previous examples, the barrier is initialized with the number of threads in the thread block i.e., `cooperative_groups::this_thread_block().size()`, so that all threads within the thread block can participate in the barrier.

`init()` 的第二个参数是 expected arrival count，即参与线程在某个线程能够从 `bar.wait(std::move(token))` 解除阻塞前，需要调用 `bar.arrive()` 的次数。本例及前面的例子都将计数初始化为 thread block 的线程数，也就是 `cooperative_groups::this_thread_block().size()`，使 block 内所有线程都能参与 barrier。

> Asynchronous barriers are flexible in specifying how threads participate (split arrive/`wait`) and which threads participate. In contrast, `this_thread_block.sync()` or `__syncthreads()` is applicable to the whole thread-block and `__syncwarp(mask)` to a specified subset of a warp. Nonetheless, if the intention of the user is to synchronize a full thread block or a full warp, we recommend using `__syncthreads()` and `__syncwarp()` respectively for better performance.

Asynchronous barrier 可以灵活指定线程如何参与，例如将 arrive 与 `wait` 分开，以及哪些线程参与。相比之下，`this_thread_block.sync()` 或 `__syncthreads()` 适用于整个 thread block，`__syncwarp(mask)` 适用于 warp 中指定的线程子集。不过，如果只是要同步完整的 thread block 或完整 warp，原文建议分别使用 `__syncthreads()` 和 `__syncwarp()`，以获得更好的性能。

**解读：** 初始化要解决两个问题：只由约定线程设置计数，以及让全部参与线程在首次 arrive 前看见初始化完成。不能用尚未初始化的 barrier 来完成自身的初始化同步。原文的 `init` 是 friend function；实际调用形式以示例中的 `init(&bar, count)` 为准，不是 `bar.init(...)`。Expected arrival count 统计到达义务，并不总等于 block 线程数；本例之所以相等，是因为每个 block 线程都在每个 phase 到达一次。

### 4.10.2. A Barrier’s Phase: Arrival, Countdown, Completion, and Reset（Barrier 的 Phase：Arrival、倒计数、完成与重置）

> An asynchronous barrier counts down from the expected arrival count to zero as participating threads call `bar.arrive()`. When the countdown reaches zero, the barrier is complete for the current phase. When the last call to `bar.arrive()` causes the countdown to reach zero, the countdown is automatically and atomically reset. The reset assigns the countdown to the expected arrival count, and moves the barrier to the next phase.

参与线程调用 `bar.arrive()` 时，asynchronous barrier 从 expected arrival count 开始倒计数，直至零。倒计数达到零，当前 phase 就完成。最后一次 `bar.arrive()` 使计数归零时，计数会自动且原子地重置为 expected arrival count，barrier 随之进入下一个 phase。

> A token object of class `cuda::barrier::arrival_token`, as returned from `token=bar.arrive()`, is associated with the current phase of the barrier. A call to `bar.wait(std::move(token))` blocks the calling thread while the barrier is in the current phase, i.e., while the phase associated with the token matches the phase of the barrier. If the phase is advanced (because the countdown reaches zero) before the call to `bar.wait(std::move(token))` then the thread does not block; if the phase is advanced while the thread is blocked in `bar.wait(std::move(token))`, the thread is unblocked.

`token=bar.arrive()` 返回的 `cuda::barrier::arrival_token` 对象，与 barrier 的当前 phase 关联。只要 barrier 仍处于该 phase，即 token 对应的 phase 与 barrier 当前 phase 相同，`bar.wait(std::move(token))` 就会阻塞调用线程。如果调用 `wait` 前，phase 已因计数归零而推进，线程就不会阻塞；如果在线程被 `wait` 阻塞期间 phase 推进，线程就会解除阻塞。

> It is essential to know when a reset could or could not occur, especially in non-trivial arrive/`wait` synchronization patterns.

必须清楚 reset 何时可能发生、何时不可能发生，尤其是在较复杂的 arrive/`wait` 同步模式中。

- > A thread’s calls to `token=bar.arrive()` and `bar.wait(std::move(token))` must be sequenced such that `token=bar.arrive()` occurs during the barrier’s current phase, and `bar.wait(std::move(token))` occurs during the same or next phase.

  线程调用 `token=bar.arrive()` 与 `bar.wait(std::move(token))` 时，必须保证 arrive 发生在 barrier 的当前 phase，而对应 `wait` 发生在同一 phase 或紧接着的下一个 phase。

- > A thread’s call to `bar.arrive()` must occur when the barrier’s counter is non-zero. After barrier initialization, if a thread’s call to `bar.arrive()` causes the countdown to reach zero then a call to `bar.wait(std::move(token))` must happen before the barrier can be reused for a subsequent call to `bar.arrive()`.

  线程必须在 barrier counter 非零时调用 `bar.arrive()`。初始化后，如果某次 arrive 使计数归零，则在复用 barrier、再次调用 arrive 之前，必须先执行一次 `bar.wait(std::move(token))`。

- > `bar.wait()` must only be called using a token object of the current phase or the immediately preceding phase. For any other values of the token object, the behavior is undefined.

  `bar.wait()` 只能使用当前 phase 或紧邻的前一个 phase 的 token；使用其他 token 值会导致未定义行为。

> For simple arrive/`wait` synchronization patterns, compliance with these usage rules is straightforward.

对于简单的 arrive/`wait` 同步模式，遵守这些规则并不困难。

**解读：** Token 标识一次 phase，不能保存若干轮后再用，也不能复用同一 token 等待不同轮。这里的计数归零说明针对普通 arrival barrier；加入异步 transaction 后，还需满足 4.10.6 节的完成条件。复杂的单向通知模式也不能仅凭“我已经 arrive”就认为上一轮已完成，必须由整体协议保证安全复用。

#### 4.10.2.1. Warp Entanglement（Warp Entanglement）

> Warp-divergence affects the number of times an arrive on operation updates the barrier. If the invoking warp is fully converged, then the barrier is updated once. If the invoking warp is fully diverged, then 32 individual updates are applied to the barrier.

Warp divergence 会影响 arrive-on 操作更新 barrier 的次数。如果调用 warp 完全 converged，barrier 更新一次；如果 warp 完全 diverged，则会对 barrier 进行 32 次独立更新。

> **Note**

**注意：**

> It is recommended that `arrive-on(bar)` invocations are used by converged threads to minimize updates to the barrier object. When code preceding these operations diverges threads, then the warp should be re-converged, via `__syncwarp` before invoking arrive-on operations.

原文建议由 converged 线程调用 `arrive-on(bar)`，以减少 barrier 对象的更新次数。如果之前的代码使线程发生 divergence，应在执行 arrive-on 之前通过 `__syncwarp` 让 warp 重新 converged。

**解读：** 此处讨论的是异步操作关联中的 arrive-on 更新及 warp divergence 带来的更新放大，不应据此把前例的 expected arrival count 随意由线程数改成 warp 数。减少底层更新次数与履行多少逻辑到达义务是不同问题；计数必须与所用 API 的语义匹配。

### 4.10.3. Explicit Phase Tracking（显式跟踪 Phase）

> An asynchronous barrier can have multiple phases depending on how many times it is used to synchronize threads and memory operations. Instead of using tokens to track barrier phase flips, we can directly track a phase using the `mbarrier_try_wait_parity()` family of functions available through the `cuda::ptx` and primitives APIs.

Asynchronous barrier 可以经历多个 phase，具体取决于它被用于同步线程和内存操作的次数。除了用 token 跟踪 phase 切换，还可以通过 `cuda::ptx` 和 primitive API 中的 `mbarrier_try_wait_parity()` 系列函数直接跟踪 phase。

> In its simplest form, the `cuda::ptx::mbarrier_try_wait_parity(uint64_t* bar, const uint32_t& phaseParity)` function waits for a phase with a particular parity. The `phaseParity` operand is the integer parity of either the current phase or the immediately preceding phase of the barrier object. An even phase has integer parity 0 and an odd phase has integer parity 1. When we initialize a barrier, its phase has parity 0. So the valid values of `phaseParity` are 0 and 1. Explicit phase tracking can be useful when tracking asynchronous memory operations, as it allows only a single thread to arrive on the barrier and set the transaction count, while other threads only `wait` for a parity-based phase flip. This can be more efficient than having all threads arrive on the barrier and use tokens. This functionality is only available for shared-memory barriers at thread-block and cluster scope.

在最简单的形式中，`cuda::ptx::mbarrier_try_wait_parity(uint64_t* bar, const uint32_t& phaseParity)` 用于等待指定 parity 的 phase。`phaseParity` 表示 barrier 当前 phase 或紧邻前一个 phase 的整数奇偶性：偶数 phase 为 0，奇数 phase 为 1。初始化后 phase 的 parity 为 0，因此 `phaseParity` 的有效值是 0 和 1。显式 phase 跟踪对于异步内存操作很有用：可以只让一个线程 arrive 并设置 transaction count，其他线程仅等待 parity 对应的 phase 完成并切换。这可能比所有线程都 arrive 并使用 token 更高效。该功能仅适用于位于 shared memory、scope 为 thread block 或 cluster 的 barrier。

**解读：** 等待 parity 为 0 的 phase，含义是确认该偶数 phase 已完成，而不是等待 barrier“变成 0”。成功后本地 parity 才翻转，准备下一轮。Parity 只有一位，不能唯一标识任意久远的 phase；协议必须防止线程落后多轮而把另一轮的相同 parity 当作目标轮。

> **CUDA C++ `cuda::barrier`**

**CUDA C++：`cuda::barrier`**

```cpp
#include <cuda/ptx>
#include <cooperative_groups.h>

__device__ void compute(float *data, int iteration);

__global__ void split_arrive_wait(int iteration_count, float *data)
{
  using barrier_t = cuda::barrier<cuda::thread_scope_block>;
  __shared__ barrier_t bar;
  int parity = 0; // Initial phase parity is 0.
  auto block = cooperative_groups::this_thread_block();

  if (block.thread_rank() == 0)
  {
    // Initialize barrier with expected arrival count.
    init(&bar, block.size());
  }
  block.sync();

  for (int i = 0; i < iteration_count; ++i)
  {
    /* code before arrive */

    // This thread arrives. Arrival does not block a thread.
    // Get a handle to the native barrier to use with cuda::ptx API.
    (void)cuda::ptx::mbarrier_arrive(cuda::device::barrier_native_handle(bar));

    compute(data, i);

    // Wait for all threads participating in the barrier to complete mbarrier_arrive().
    // Get a handle to the native barrier to use with cuda::ptx API.
    while (!cuda::ptx::mbarrier_try_wait_parity(cuda::device::barrier_native_handle(bar), parity)) {}
    // Flip parity.
    parity ^= 1;

    /* code after wait */
  }
}
```

**解读与示例边界：** 本例仍让全部 block 线程执行 `mbarrier_arrive`，并非上一段所述的单线程 arrive 模式。`compute(data, i)` 位于 arrive 与 wait 之间，不能访问仍依赖其他线程到达前写入的数据，也不能假定 wait 会等待所有线程的 compute 完成。代码使用 `cuda::barrier` 却未直接包含 `<cuda/barrier>`，实际工程应显式包含所使用类型的头文件，并核对目标架构对 PTX 指令的支持；原代码保留。

### 4.10.4. Early Exit（提前退出）

> When a thread that is participating in a sequence of synchronizations must exit early from that sequence, that thread must explicitly drop out of participation before exiting. The remaining participating threads can proceed normally with subsequent arrive and `wait` operations.

如果参与一系列同步的线程必须提前退出，它必须在退出之前显式注销参与。其余线程随后就能正常继续执行 arrive 和 `wait`。

> **CUDA C++ `cuda::barrier`**

**CUDA C++：`cuda::barrier`**

```cpp
#include <cuda/barrier>
#include <cooperative_groups.h>

__device__ bool condition_check();

__global__ void early_exit_kernel(int N)
{
  __shared__ cuda::barrier<cuda::thread_scope_block> bar;
  auto block = cooperative_groups::this_thread_block();

  if (block.thread_rank() == 0)
  {
    init(&bar, block.size());
  }
  block.sync();

  for (int i = 0; i < N; ++i)
  {
    if (condition_check())
    {
      bar.arrive_and_drop();
      return;
    }
    // Other threads can proceed normally.
    auto token = bar.arrive();

    /* code between arrive and wait */

    // Wait for all threads to arrive.
    bar.wait(std::move(token));

    /* code after wait */
  }
}
```

> **CUDA C primitives**

**CUDA C 底层原语**（粘贴文本仅提供此选项卡标签，未提供对应代码。）

> The `bar.arrive_and_drop()` operation arrives on the barrier to fulfill the participating thread’s obligation to arrive in the current phase, and then decrements the expected arrival count for the next phase so that this thread is no longer expected to arrive on the barrier.

`bar.arrive_and_drop()` 首先 arrive，履行线程在当前 phase 的到达义务，然后减小下一 phase 的 expected arrival count，使 barrier 之后不再等待该线程 arrive。

**解读：** `arrive_and_drop()` 同时处理当前轮和未来轮：当前轮补足一次到达，后续轮永久少等一个参与者。因此必须在尚欠当前轮 arrive 时调用，不能先 arrive 再用 drop 重复计数。它也不会取消后续其他同步原语的参与要求；退出线程若仍被其他 barrier 等待，程序依然可能卡住。

### 4.10.5. Completion Function（Completion Function）

> The `cuda::barrier` API supports an optional completion function. A `CompletionFunction` of `cuda::barrier<Scope, CompletionFunction>` is executed once per phase, after the last thread arrives and before any thread is unblocked from the `wait`. Memory operations performed by the threads that arrived at the barrier during the phase are visible to the thread executing the `CompletionFunction`, and all memory operations performed within the `CompletionFunction` are visible to all threads waiting at the barrier once they are unblocked from the `wait`.

`cuda::barrier` 支持可选的 completion function。`cuda::barrier<Scope, CompletionFunction>` 中的 `CompletionFunction` 在每个 phase 执行一次，时机是在最后一个线程 arrive 之后、任何线程从 `wait` 解除阻塞之前。该 phase 中已经 arrive 的线程所执行的内存操作，对执行 `CompletionFunction` 的线程可见；`CompletionFunction` 内执行的全部内存操作，在等待线程解除阻塞后对它们可见。

**解读：** Completion function 为各线程到达前的工作与 wait 之后的工作建立阶段交接。内存保证的关键界限是 arrive：线程在 arrive 之后执行的独立工作，不会仅因位于“同一个循环迭代”就自动受本次 completion 保护。参见 [C++ barrier phase completion guarantees](https://www.open-std.org/JTC1/SC22/WG21/docs/papers/2022/p2588r2.html)。

> **CUDA C++ `cuda::barrier`**

**CUDA C++：`cuda::barrier`**

```cpp
#include <cuda/barrier>
#include <cooperative_groups.h>
#include <functional>
namespace cg = cooperative_groups;

__device__ int divergent_compute(int *, int);
__device__ int independent_computation(int *, int);

__global__ void psum(int *data, int n, int *acc)
{
  auto block = cg::this_thread_block();

  constexpr int BlockSize = 128;
  __shared__ int smem[BlockSize];
  assert(BlockSize == block.size());
  assert(n % BlockSize == 0);

  auto completion_fn = [&]
  {
    int sum = 0;
    for (int i = 0; i < BlockSize; ++i)
    {
      sum += smem[i];
    }
    *acc += sum;
  };

  /* Barrier storage.
     Note: the barrier is not default-constructible because
           completion_fn is not default-constructible due
           to the capture. */
  using completion_fn_t = decltype(completion_fn);
  using barrier_t = cuda::barrier<cuda::thread_scope_block,
                                  completion_fn_t>;
  __shared__ std::aligned_storage<sizeof(barrier_t),
                                  alignof(barrier_t)>
      bar_storage;

  // Initialize barrier.
  barrier_t *bar = (barrier_t *)&bar_storage;
  if (block.thread_rank() == 0)
  {
    assert(*acc == 0);
    assert(blockDim.x == blockDim.y == blockDim.y == 1);
    new (bar) barrier_t{block.size(), completion_fn};
    /* equivalent to: init(bar, block.size(), completion_fn); */
  }
  block.sync();

  // Main loop.
  for (int i = 0; i < n; i += block.size())
  {
    smem[block.thread_rank()] = data[i] + *acc;
    auto token = bar->arrive();
    // We can do independent computation here.
    bar->wait(std::move(token));
    // Shared-memory is safe to re-use in the next iteration
    // since all threads are done with it, including the one
    // that did the reduction.
  }
}
```

**原文代码勘误与解读：** 这个示例有几处需要单独核对。`std::aligned_storage<...>` 应取其 `::type` 成员，或使用等价的正确对齐原始存储，才能作为 placement new 的存储区域；相关声明与 placement new 还应显式包含对应头文件。`assert(blockDim.x == blockDim.y == blockDim.y == 1)` 使用了 C++ 连等比较、重复了 y，并未正确表达三维尺寸约束；结合 128 线程 block 的前提，无法把它直接当作有效的配置检查。所有线程当前都读取同一个 `data[i]`；若意图对不同输入元素求和，还需补充线程索引。多个 block 若共享同一 `acc`，block-scope barrier 也不能消除跨 block 写入竞争。原文全部保留，不猜测作者希望采用的 launch 配置或算法。正确理解其演示意图时，completion 在本轮所有共享数据提交后集中处理，wait 返回后才允许下一轮复用该数据。参见 [C++ aligned_storage 定义](https://eel.is/c++draft/depr.meta.types)。

### 4.10.6. Tracking Asynchronous Memory Operations（跟踪异步内存操作）

> Asynchronous barriers can be used to track asynchronous memory copies. When an asynchronous copy operation is bound to a barrier, the copy operation automatically increments the expected count of the current barrier phase upon initiation and decrements it upon completion. This mechanism ensures that the barrier’s `wait()` operation will block until all associated asynchronous memory copies have completed, providing a convenient way to synchronize multiple concurrent memory operations.

Asynchronous barrier 可以跟踪异步内存复制。当异步 copy 与 barrier 绑定时，copy 在发起时自动增加当前 phase 的 expected count，完成时再减少。这使 barrier 的 `wait()` 会阻塞到所有关联异步复制完成，便于同步多个并发内存操作。

> Starting with compute capability 9.0, asynchronous barriers in shared memory with thread-block or cluster scope can explicitly track asynchronous memory operations. We refer to these barriers as asynchronous transaction barriers. In addition to the expected arrival count, a barrier object can accept a transaction count, which can be used for tracking the completion of asynchronous transactions. The transaction count tracks the number of asynchronous transactions that are outstanding and yet to be complete, in units specified by the asynchronous memory operation (typically bytes). The transaction count to be tracked by the current phase can be set on arrival with `cuda::device::barrier_arrive_tx()` or directly with `cuda::device::barrier_expect_tx()`. When a barrier uses a transaction count, it blocks threads at the `wait` operation until all the producer threads have performed an arrive and the sum of all the transaction counts reaches an expected value.

从 compute capability 9.0 开始，位于 shared memory、scope 为 thread block 或 cluster 的 asynchronous barrier 可以显式跟踪异步内存操作，称为 asynchronous transaction barrier。除 expected arrival count 外，barrier 还可以接收用于跟踪异步 transaction 完成情况的 transaction count。该计数记录尚未完成的异步 transaction，单位由具体异步内存操作决定，通常为字节。可以通过 `cuda::device::barrier_arrive_tx()` 在 arrive 时设置当前 phase 要跟踪的 transaction count，也可以直接用 `cuda::device::barrier_expect_tx()` 设置。使用 transaction count 时，barrier 会在 `wait` 处阻塞线程，直到全部 producer 线程完成 arrive，并且所有 transaction count 的累计结果达到预期值。

**解读（两类计数）：** Arrival count 追踪参与者的到达义务，transaction count 追踪尚未完成的异步工作，常以字节计。Phase 完成要求两者都归零；原文“达到预期值”应理解为预期工作已全部完成，不能只增加预期计数而没有对应完成通知。另需区分底层 cluster-scope 能力与 C++ 类型：当前 libcu++ 文档不允许直接实例化 `cuda::barrier<cuda::thread_scope_cluster>`。参见 [libcu++：cuda::barrier](https://nvidia.github.io/cccl/unstable/libcudacxx/extended_api/synchronization_primitives/barrier.html)。

> **CUDA C++ `cuda::barrier`**

**CUDA C++：`cuda::barrier`**

```cpp
#include <cuda/barrier>
#include <cooperative_groups.h>

__global__ void track_kernel()
{
  __shared__ cuda::barrier<cuda::thread_scope_block> bar;
  auto block = cooperative_groups::this_thread_block();

  if (block.thread_rank() == 0)
  {
    init(&bar, block.size());
  }
  block.sync();

  auto token = cuda::device::barrier_arrive_tx(bar, 1, 0);

  bar.wait(cuda::std::move(token));
}
```

> In this example, the `cuda::device::barrier_arrive_tx()` operation constructs an arrival token object associated with the phase synchronization point for the current phase. Then, decrements the arrival count by 1 and increments the expected transaction count by 0. Since the transaction count update is 0, the barrier is not tracking any transactions. The subsequent section on Using the Tensor Memory Accelerator (TMA) includes examples of tracking asynchronous memory operations.

本例中的 `cuda::device::barrier_arrive_tx()` 构造一个与当前 phase 同步点关联的 arrival token，然后将 arrival count 减 1，将 expected transaction count 加 0。由于 transaction count 的增量为 0，这个 barrier 实际没有跟踪任何 transaction。后续 Using the Tensor Memory Accelerator（TMA）一节提供了跟踪异步内存操作的示例。

**解读：** `barrier_arrive_tx(bar, 1, 0)` 表示本线程履行一次到达义务，但新增待跟踪字节数为零；它没有发起 copy，也不证明存在数据传输。使用非零 tx-count 时，应使声明的总量与实际关联操作的计量单位和完成量一致。参见 [barrier_arrive_tx](https://nvidia.github.io/cccl/unstable/libcudacxx/extended_api/synchronization_primitives/barrier/barrier_arrive_tx.html)。

### 4.10.7. Producer-Consumer Pattern Using Barriers（使用 Barrier 实现 Producer–Consumer 模式）

> A thread block can be spatially partitioned to allow different threads to perform independent operations. This is most commonly done by assigning threads from different warps within the thread block to specific tasks. This technique is referred to as warp specialization.

可以将 thread block 中的线程按空间划分，让不同线程独立执行不同操作。最常见的方法，是把同一个 block 中不同 warp 的线程分配给特定任务，这称为 warp specialization。

> This section shows an example of spatial partitioning in a producer-consumer pattern, where one subset of threads produces data that is concurrently consumed by the other (disjoint) subset of threads. A producer-consumer spatial partitioning pattern requires two one-sided synchronizations to manage a data buffer between the producer and consumer.

本节展示 producer–consumer 模式的空间划分示例：一部分线程产生数据，另一部分与其不重叠的线程并发消费数据。要管理 producer 与 consumer 之间的一个数据 buffer，需要两次 one-sided synchronization。

> | Producer | Consumer |
> | --- | --- |
> | wait for buffer to be ready to be filled | signal buffer is ready to be filled |
> | produce data and fill the buffer |  |
> | signal buffer is filled | wait for buffer to be filled |
> |  | consume data in filled buffer |

| Producer（生产者） | Consumer（消费者） |
| --- | --- |
| 等待 buffer 可以填充 | 通知 buffer 可以填充 |
| 产生数据并填充 buffer |  |
| 通知 buffer 已填满 | 等待 buffer 填满 |
|  | 消费已填满 buffer 中的数据 |

> Producer threads `wait` for consumer threads to signal that the buffer is ready to be filled; however, consumer threads do not `wait` for this signal. Consumer threads `wait` for producer threads to signal that the buffer is filled; however, producer threads do not `wait` for this signal. For full producer/consumer concurrency this pattern has (at least) double buffering where each buffer requires two barriers.

Producer 线程等待 consumer 发出“buffer 可以填充”的信号，而 consumer 不等待这个信号；consumer 线程等待 producer 发出“buffer 已填满”的信号，而 producer 不等待这个信号。为了让生产与消费充分并发，这种模式至少需要 double buffering，且每个 buffer 需要两个 barrier。

**解读：** 每个 buffer 都有两种独立的交接：ready 表示 consumer 已结束上一轮读取，producer 可以覆盖；filled 表示 producer 已完成本轮写入，consumer 可以读取。两块 buffer 各需要 ready、filled 两个 barrier，所以代码总共使用四个。Double buffering 允许 producer 填一块时 consumer 读另一块，但不保证两端耗时不匹配时始终没有等待。

| Barrier | 等待方 | 完成所允许的操作 |
| --- | --- | --- |
| `ready[k]` | Producer | 重新填充 buffer k |
| `filled[k]` | Consumer | 读取 buffer k 的本轮数据 |

两侧都须贡献相应 arrival；“单向”指只有其中一侧在该 barrier 上等待。

> **CUDA C++ `cuda::barrier`**

**CUDA C++：`cuda::barrier`**

```cpp
#include <cuda/barrier>

using barrier_t = cuda::barrier<cuda::thread_scope_block>;

__device__ void produce(barrier_t ready[], barrier_t filled[], float *buffer, int buffer_len, float *in, int N)
{
  for (int i = 0; i < N / buffer_len; ++i)
  {
    ready[i % 2].arrive_and_wait(); /* wait for buffer_(i%2) to be ready to be filled */
    /* produce, i.e., fill in, buffer_(i%2)  */
    barrier_t::arrival_token token = filled[i % 2].arrive(); /* buffer_(i%2) is filled */
  }
}

__device__ void consume(barrier_t ready[], barrier_t filled[], float *buffer, int buffer_len, float *out, int N)
{
  barrier_t::arrival_token token1 = ready[0].arrive(); /* buffer_0 is ready for initial fill */
  barrier_t::arrival_token token2 = ready[1].arrive(); /* buffer_1 is ready for initial fill */
  for (int i = 0; i < N / buffer_len; ++i)
  {
    filled[i % 2].arrive_and_wait(); /* wait for buffer_(i%2) to be filled */
    /* consume buffer_(i%2) */
    barrier_t::arrival_token token3 = ready[i % 2].arrive(); /* buffer_(i%2) is ready to be re-filled */
  }
}

__global__ void producer_consumer_pattern(int N, float *in, float *out, int buffer_len)
{
  constexpr int warpSize = 32;

  /* Shared memory buffer declared below is of size 2 * buffer_len
     so that we can alternatively work between two buffers.
     buffer_0 = buffer and buffer_1 = buffer + buffer_len */
  __shared__ extern float buffer[];

  /* bar[0] and bar[1] track if buffers buffer_0 and buffer_1 are ready to be filled,
     while bar[2] and bar[3] track if buffers buffer_0 and buffer_1 are filled-in respectively */
  #pragma nv_diag_suppress static_var_with_dynamic_init
  __shared__ barrier_t bar[4];

  if (threadIdx.x < 4)
  {
    init(bar + threadIdx.x, blockDim.x);
  }
  __syncthreads();

  if (threadIdx.x < warpSize)
  { produce(bar, bar + 2, buffer, buffer_len, in, N); }
  else
  { consume(bar, bar + 2, buffer, buffer_len, out, N); }
}
```

**示例边界：** `produce` 和 `consume` 中的实际数据处理仍是注释占位，不能把该片段当作完整复制程序。代码按 `threadIdx.x` 分工并用 `blockDim.x` 初始化计数，因此假定一维 block，且要有 producer 与 consumer 两侧的线程；要按注释分成完整 warp，还应选择整 warp 的 block 尺寸。Launch 需提供至少 `2 * buffer_len * sizeof(float)` 字节的动态 shared memory。循环只处理 `N / buffer_len` 个完整分块，要求 `buffer_len > 0`，余数应由外围代码处理或另行约束。

> **CUDA C primitives**

**CUDA C 底层原语**（粘贴文本仅提供此选项卡标签，未提供对应代码。）

> In this example, the first warp is specialized as the producer and the remaining warps are specialized as consumers. All producer and consumer threads participate (call `bar.arrive()` or `bar.arrive_and_wait()`) in each of the four barriers so the expected arrival counts are equal to `block.size()`.

本例把第一个 warp 专门用作 producer，其余 warp 专门用作 consumer。所有 producer 和 consumer 线程都会通过 `bar.arrive()` 或 `bar.arrive_and_wait()` 参与四个 barrier，因此每个 barrier 的 expected arrival count 都等于 `block.size()`。

> A producer thread waits for the consumer threads to signal that the shared memory buffer can be filled. In order to `wait` for a barrier, a producer thread must first arrive on that `ready[i%2].arrive()` to get a token and then `ready[i%2].wait(token)` with that token. For simplicity, `ready[i%2].arrive_and_wait()` combines these operations.

Producer 线程等待 consumer 通知 shared memory buffer 可以填充。为了等待 barrier，producer 必须先通过 `ready[i%2].arrive()` 获取 token，再用该 token 调用 `ready[i%2].wait(token)`。为简化代码，`ready[i%2].arrive_and_wait()` 将这两个操作合并。

```cpp
bar.arrive_and_wait();
/* is equivalent to */
bar.wait(bar.arrive());
```

**解读：** `arrive_and_wait()` 合并当前线程的 arrive 与对应 wait。若将其拆成具名 token，C++ 调用通常需要 `bar.wait(std::move(token))`；原文段落中的 `wait(token)` 是流程说明，而下方 `bar.wait(bar.arrive())` 直接传临时 token。

> Producer threads compute and fill the ready buffer, they then signal that the buffer is filled by arriving on the filled barrier, `filled[i%2].arrive()`. A producer thread does not `wait` at this point, instead it waits until the next iteration’s buffer (double buffering) is ready to be filled.

Producer 线程计算并填充 ready buffer，然后通过 `filled[i%2].arrive()` 通知 buffer 已填满。Producer 此时不等待，而是转去等待下一次迭代的 buffer 就绪，以实现 double buffering。

> A consumer thread begins by signaling that both buffers are ready to be filled. A consumer thread does not `wait` at this point, instead it waits for this iteration’s buffer to be filled, `filled[i%2].arrive_and_wait()`. After the consumer threads consume the buffer they signal that the buffer is ready to be filled again, `ready[i%2].arrive()`, and then `wait` for the next iteration’s buffer to be filled.

Consumer 线程首先通知两个 buffer 都可以填充，此时不等待，而是通过 `filled[i%2].arrive_and_wait()` 等待当前迭代的 buffer 填满。消费完数据后，consumer 通过 `ready[i%2].arrive()` 通知 buffer 可以再次填充，然后等待下一次迭代的 buffer 填满。

**解读：** Consumer 开始时先为两个 ready barrier 各贡献一次 arrival，建立“两个 buffer 初始为空”的状态。Producer 等 ready、只通知 filled；consumer 等 filled、只通知 ready。未用于 wait 的 token 并不意味着漏同步，关键是另一侧确实等待相应 phase，且 ready/filled 交替关系阻止过早覆盖和读取。本章代码仅作整理与静态核对，未编译或运行。
