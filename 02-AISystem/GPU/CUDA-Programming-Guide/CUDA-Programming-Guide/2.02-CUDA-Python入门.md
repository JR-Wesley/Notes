## 2.2. Intro to CUDA Python（CUDA Python 入门）

> This chapter introduces CUDA kernel programming in Python. The CUDA Python ecosystem encapsulates a large and actively evolving ecosystem of tools and libraries. This chapter will start by introducing some of these components and then use a few of them to illustrate methods for writing and executing GPU code in Python.

本章介绍如何使用 Python 编写 CUDA kernel。CUDA Python 包含一个规模庞大、持续演进的工具与库生态。本章先介绍其中的一些组件，再利用部分组件展示在 Python 中编写和执行 GPU 代码的方法。

> There are a large number of ways to leverage GPU computing in Python, many of which do not require writing GPU kernels explicitly. Some components of the CUDA Python Ecosystem provide functions which do their operations on the GPU without the developer needing to do any specific GPU control or coding. The NVIDIA Accelerated Computing Hub has an Accelerated Python User’s Guide, which introduces and discusses many of the different libraries and tools which enable GPU-accelerated computing in Python. This resource is a good starting point for users looking to use GPUs in Python as quickly and easily as possible without necessarily writing GPU code directly.

在 Python 中利用 GPU 计算有许多方式，其中很多不需要显式编写 GPU kernel。CUDA Python 生态中的某些组件提供直接在 GPU 上完成操作的函数，开发者无需专门控制 GPU 或编写 GPU 代码。NVIDIA Accelerated Computing Hub 中的 Accelerated Python User’s Guide 介绍了多种支持 Python GPU 加速计算的库和工具。对于希望尽快、便捷地在 Python 中使用 GPU，而不一定直接编写 GPU 代码的用户，这是一份合适的入门资料。

> This chapter, on the other hand, focuses on direct control of the GPU and writing kernels in Python that execute on the GPU. This chapter focuses on CUDA Single Instruction Multiple Thread (SIMT) programming in Python.

本章则侧重直接控制 GPU，以及用 Python 编写在 GPU 上执行的 kernel，重点介绍 Python 中的 CUDA Single Instruction Multiple Thread（SIMT，单指令多线程）编程。

### 2.2.1. CUDA Python Ecosystem（CUDA Python 生态）

> CUDA Python is an ecosystem of tools and libraries enabling GPU computing in Python. The following list introduces the main pieces of CUDA Python, not all of which are required for the content covered here. This list is adapted from the complete list found at the CUDA Python github repository.

CUDA Python 是由多种工具与库组成的生态，用于支持 Python 中的 GPU 计算。下面介绍其中的主要组件；学习本章并不需要全部使用它们。此列表改编自 CUDA Python GitHub 仓库中的完整列表。

**Main Components - For GPU control and running library-provided GPU code**

主要组件：用于控制 GPU，以及运行库提供的 GPU 代码。

- > `cuda.core` - Pythonic interface for CUDA controls such as memory and device management. Provides for Python what the CUDA Runtime provides for CUDA C++.

  `cuda.core`：采用 Python 风格的 CUDA 控制接口，涵盖内存与设备管理等功能；它在 Python 中承担类似 CUDA runtime 在 CUDA C++ 中的角色。

- > `cuda.compute` - A Python module which provides GPU-accelerated functions provided by the CUDA Core Compute Library (CCCL).

  `cuda.compute`：提供 CUDA Core Compute Library（CCCL）中的 GPU 加速函数的 Python 模块。

- > CuPy - A Python library which provides GPU-accelerated versions of Numpy routines, and also a GPU-accelerated version of the `ndarray` data container.

  CuPy：提供 NumPy 例程的 GPU 加速版本，以及 GPU 加速的 `ndarray` 数据容器的 Python 库。

**Kernel Authoring Components**

kernel 编写组件。

- > `cuda.lang` - A Python Domain-specific language (DSL) for writing CUDA kernels and device functions in the SIMT programming model using a subset the of Python language.

  `cuda.lang`：使用 Python 语言子集、按照 SIMT 编程模型编写 CUDA kernel 和 device function 的领域特定语言（DSL）。

- > `cuda.coop` - A Python module providing device-callable (using `cuda.lang`) primitives of the CUDA Core Compute Library (CCCL).

  `cuda.coop`：提供 CCCL 中可由 device 代码调用的原语的 Python 模块，与 `cuda.lang` 配合使用。

- > `cuda.tile` - A Python Domain-specific language (DSL) for writing CUDA kernels and device functions in the Tile programming model.

  `cuda.tile`：按照 Tile 编程模型编写 CUDA kernel 和 device function 的 Python DSL。

**Other Components**

其他组件。

- > `cuda.pathfinder` - A utility for locating CUDA components installed in the Python environment

  `cuda.pathfinder`：用于定位 Python 环境中已安装 CUDA 组件的工具。

- > `cuda.bindings` - Low level Python bindings for CUDA libraries and utilities including the CUDA Driver API, CUDA Runtime API, NVRTC, NVVM, and others. `cuda.bindings` provides the same functionality available in `cuda.core` via the CUDA Driver and CUDA Runtime components. However, `cuda.bindings` provides these as Python wrappers on the C-language APIs, not native Pythonic interfaces.

  `cuda.bindings`：为 CUDA 库与工具提供底层 Python 绑定，包括 CUDA Driver API、CUDA Runtime API、NVRTC、NVVM 等。通过 CUDA Driver 与 Runtime 组件，它可以提供 `cuda.core` 所提供的同类功能；但这些接口是 C 语言 API 的 Python 包装，而不是原生的 Python 风格接口。

**解读：** 本节列表涵盖设备控制、库函数调用和 kernel 编写等不同层次。后文示例实际采用 `numba.cuda` 编译 kernel，并使用 CuPy 创建和传输数组；阅读时应按照具体包的接口理解代码，不能把生态组件的名称直接互换。

#### 2.2.1.1. Using CUDA Libraries in Python（在 Python 中使用 CUDA 库）

> CUDA C++ has a rich ecosystem of libraries which allow for GPU acceleration without the need to write kernel or GPU code directly. When CUDA C++ was introduced in 2006, there were few libraries and developers largely had to write GPU kernel code themselves. Since then, a large number of libraries have been developed which allow developers to take advantage of GPU computing in C++ without writing much, if any, GPU code.

CUDA C++ 拥有丰富的库生态，可在不直接编写 kernel 或 GPU 代码的情况下实现 GPU 加速。2006 年 CUDA C++ 刚推出时，相关库还很少，开发者大多需要自己编写 GPU kernel。此后，大量库陆续出现，使 C++ 开发者只需编写少量 GPU 代码，甚至完全不写 GPU 代码，就能利用 GPU 计算。

> The CUDA Python ecosystem has evolved from the other direction: Python libraries such as CuPy provided GPU-accelerated implementations of computations and algorithms to Python developers before the ability to write custom kernels directly using Python syntax and semantics became available. Many of these libraries provided Python bindings to GPU code implemented in CUDA C++.

CUDA Python 生态的演进方向有所不同：在开发者能够直接用 Python 语法和语义编写自定义 kernel 之前，CuPy 等 Python 库就已经提供了计算与算法的 GPU 加速实现。这些库中有许多是为 CUDA C++ 实现的 GPU 代码提供 Python 绑定。

> In the modern era of CUDA, it is almost always advisable to use GPU-accelerated libraries if they provide the necessary expressiveness for your needs. Many of these libraries provide implementations tuned by GPU computing experts. When libraries are not available or sufficient, writing GPU kernels and device functions directly is available in Python as in C++.

在如今的 CUDA 开发生态中，只要 GPU 加速库能够满足所需的表达能力，通常都建议优先使用这些库。其中很多实现经过 GPU 计算专家调优。当没有合适的库，或者库的能力不足时，也可以像使用 C++ 一样，在 Python 中直接编写 GPU kernel 和 device function。

**解读：** 库已经实现所需计算时，直接调用库能复用已有优化；自定义 kernel 则用于表达库尚未提供或无法满足的计算。两种方式可以在同一 Python 应用中结合使用。

#### 2.2.1.2. Scope of This Chapter（本章范围）

This chapter covers writing and running custom Python code on the GPU in the same fashion as Section 2.1 does for C++, starting with how to specify a GPU kernel and then how to use the GPU-accelerated `ndarray` provided by cuPy to allocate memory on the GPU and provide communication between the CPU and GPU.

虽然应尽可能优先使用库，本章后续内容将介绍需要自定义 GPU 代码时如何在 Python 中实现。介绍顺序与 Section 2.1 的 C++ 内容相似：先说明如何定义 GPU kernel，再利用 CuPy 提供的 GPU 加速 `ndarray` 分配 GPU 内存，并实现 CPU 与 GPU 之间的数据交换。

### 2.2.2. SIMT Kernels in Python（Python 中的 SIMT kernel）

> As mentioned in the introduction to the CUDA Programming Model, functions which execute on the GPU which can be invoked from the host are called kernels. CUDA provides two different models: Single Instruction Multiple Thread (SIMT), and CUDA tile. SIMT kernels are written to be run by many parallel threads simultaneously. This notion is the same in CUDA Python and CUDA C++. This chapter introduces CUDA Python using SIMT kernels.

如 CUDA Programming Model 的介绍所述，在 GPU 上执行、可从 host 调用的函数称为 kernel。CUDA 提供 SIMT 和 CUDA tile 两种模型。SIMT kernel 由大量并行线程同时执行，这一点在 CUDA Python 与 CUDA C++ 中相同。本章通过 SIMT kernel 介绍 CUDA Python。

#### 2.2.2.1. Specifying Kernels（定义 kernel）

> Before specifying kernels in CUDA Python, the package `numba.cuda` must be imported. This is commonly done as shown below.

在 CUDA Python 中定义 kernel 之前，需要导入 `numba.cuda` 包，常见写法如下。

```python
from numba import cuda
```

> This imports the `numba.cuda` package and allows us to use the components of the cuda namespace provided by that package.

这样会导入 `numba.cuda`，并允许通过该包提供的 `cuda` 命名空间使用其组件。

> To specify a function as a kernel in CUDA Python, place the decorator `@cuda.jit` on the line above the function definition as shown below.

要在 CUDA Python 中把函数指定为 kernel，应在函数定义上一行添加 `@cuda.jit` 装饰器，如下所示。

```python
from numba import cuda

@cuda.jit
def function(input_array, output_array):
    ...
```

> This will cause the kernel to be JIT compiled for the active GPU the first time it is launched. The default CUDA device is used when no other GPU is specified, as is the case for the examples shown in this section.

这样，kernel 会在首次启动时针对当前活动 GPU 进行 JIT 编译。若未指定其他 GPU，就使用默认 CUDA 设备，本节示例均采用这一方式。

**解读：** `@cuda.jit` 将受支持的 Python 函数编译为 GPU kernel。调用脚本的仍是 Python，但 kernel 的执行遵循 GPU 的 SIMT 模型；首次启动还可能包含 JIT 编译成本。

#### 2.2.2.2. Launching Kernels（启动 kernel）

> The number of threads that will execute a kernel are specified as part of the kernel launch. This is called the execution configuration. Each invocation of a kernel can have a unique execution configuration, such as a different block size or number of thread blocks.

执行 kernel 的线程数在 kernel launch 时指定，称为 execution configuration（执行配置）。每次调用可以使用不同配置，例如不同的 block 大小或 thread block 数量。

##### 2.2.2.2.1. Kernel Launch（kernel 启动语法）

> To launch a kernel, the execution configuration is placed in square braces [ ] after the kernel name but before the function arguments. The order of arguments is the same as in the triple chevron notation in C++ introduced in Section 2.1.2.2.1, specifically:

启动 kernel 时，将执行配置放在 kernel 名称之后、函数实参之前的方括号 `[ ]` 中。参数顺序与 Section 2.1.2.2.1 介绍的 C++ 三重尖括号语法相同，具体如下。

```python
kernel_name[number_of_thread_blocks, threads_per_block](arguments, ...)
```

> The code snippet below shows how a kernel is defined and then invoked in a Python source file.

下面的代码片段展示在 Python 源文件中定义并调用 kernel 的方式。

```python
from numba import cuda

@cuda.jit
def my_kernel(input, output):
    ...

## launch the kernel
my_kernel[num_thread_blocks, threads_per_block](in_array, out_array)
```

> There is a limit to the number of threads per block, since all threads of a block reside on the same streaming multiprocessor (SM) and must share the resources of the SM. On current GPUs, a thread block may contain up to 1024 threads. If resources allow, more than one thread block can be scheduled on an SM simultaneously.

每个 block 的线程数有上限，因为块内所有线程都驻留在同一个 SM 上，并共享该 SM 的资源。当前 GPU 的单个 thread block 最多可包含 1024 个线程；若资源允许，一个 SM 可以同时调度多个 block。

##### 2.2.2.2.2. Multi-Dimension Grids and Thread Blocks（多维 grid 与 thread block）

> Thread blocks and the grid of thread blocks can be 1, 2, or 3-dimensional in CUDA. When the grid or thread block is one dimensional, an integer can be used when specifying the execution configuration of a kernel launch. When the thread block or grid is 2 or 3-dimensional, a two or three dimensional tuple is used as shown below for a 2D grid and thread block launch, where gridX and gridY are the x and y dimensions of the grid, and blockX and blockY are the x and y dimensions of each thread block within the grid.

CUDA 的 thread block 和由 block 组成的 grid 都可以是一维、二维或三维。使用一维结构时，可以在启动配置中直接用整数表示维度；使用二维或三维结构时，则使用包含两个或三个元素的 tuple（元组）。下例展示二维 grid 和 block 的启动方式，其中 `gridX`、`gridY` 是 grid 的 x、y 维大小，`blockX`、`blockY` 是每个 block 的 x、y 维大小。

```python
from numba import cuda

@cuda.jit
def function(input, output):
    ...

## launch the kernel
function[(gridX, gridY), (blockX, blockY)](in_array, out_array)
```

**解读：** 方括号描述启动规模，圆括号传递数据参数。一维启动使用整数，二维、三维启动使用 tuple；改变语法不会改变 grid、block、thread 的层次关系。

#### 2.2.2.3. Thread and Grid Index Intrinsics（线程与 grid 索引内置变量）

> Section 1.2.2.1 introduced threads and grids, and Section 2.2.2.2 showed how to specify the grid and thread block size for a kernel launch. Within a kernel, each thread can access the parameters of the execution configuration as well as the thread’s index and thread block index within the grid.

Section 1.2.2.1 介绍了线程与 grid，Section 2.2.2.2 介绍了如何在 kernel launch 时指定 grid 和 thread block 大小。在 kernel 内部，每个线程都能访问执行配置参数，以及自身在线程块中的索引和所属 block 在 grid 中的索引。

> The following variables can be accessed from within a kernel function to determine a thread’s identity:

在 kernel 函数内部，可以访问以下变量来确定线程的身份：

- > `cuda.threadIdx.[xyz]` gives the index of a thread within its thread block. Each thread in a thread block will have a different index.

  `cuda.threadIdx.[xyz]` 表示线程在所属 block 内的索引；同一 block 内每个线程的索引都不同。

- > `cuda.blockDim.[xyz]` gives the dimensions of the thread block, which was specified in the execution configuration of the kernel launch.

  `cuda.blockDim.[xyz]` 表示 thread block 的维度，由 kernel launch 的执行配置指定。

- > `cuda.blockIdx.[xyz]` gives the index of a thread block within the grid. Each thread block will have a different index.

  `cuda.blockIdx.[xyz]` 表示 block 在 grid 内的索引；各 block 的索引不同。

- > `cuda.gridDim.[xyz]` gives the dimensions of the grid, which was specified in the execution configuration when the kernel was launched.

  `cuda.gridDim.[xyz]` 表示 grid 的维度，由 kernel 启动时的执行配置指定。

> Each of these variables is a 3-component vector with a .x, .y, and .z member. If a dimension is not specified in the execution configuration at kernel launch, it defaults to a value of 1 for dimensions and 0 for indices.

这些变量都是具有 `.x`、`.y` 和 `.z` 成员的三分量向量。若启动配置中没有指定某个维度，该维度的大小默认为 1，对应索引默认为 0。

> `cuda.threadIdx` and `cuda.blockIdx` are zero indexed. That is, `cuda.threadIdx.x` will take on values from 0 up to and including `cuda.blockDim.x` - 1. .y and .z operate the same in their respective dimensions.

`cuda.threadIdx` 和 `cuda.blockIdx` 的索引从 0 开始。例如，`cuda.threadIdx.x` 的取值范围为 0 到 `cuda.blockDim.x - 1`，包含两端；`.y`、`.z` 在各自维度上遵循相同规则。

**解读：** 文中的 `.[xyz]` 是“选择 `.x`、`.y` 或 `.z` 成员”的说明性写法，不是可以原样执行的 Python 语法。例如，访问线程的 x 索引应写成 `cuda.threadIdx.x`。

> The code for a simple vector addition kernel, which adds two vectors together element-wise, is shown below. This function takes three arrays, A, B, and C to implement an element-wise vector addition C = A + B

下面展示一个将两个向量逐元素相加的简单 kernel。函数接收 A、B、C 三个数组，实现逐元素向量加法 `C = A + B`。

```python
# C = A + B vector addition
@cuda.jit
def vecadd(A, B, C):
    idx = cuda.threadIdx.x + cuda.blockIdx.x * cuda.blockDim.x
    C[idx] = A[idx] + B[idx]
```

> The kernel begins by calculating the unique index of the thread in the grid. This kernel assumes it is being launched with 1-dimensional thread blocks in a 1-dimensional grid. The idx variable is a unique index from 0 to N-1, where N is the total number of threads in the grid, that is, N = `cuda.gridDim.x` * `cuda.blockDim.x`.

kernel 首先计算线程在整个 grid 中的唯一索引。这里假定使用一维 grid 和一维 block；变量 `idx` 是从 0 到 N−1 的唯一索引，其中 N 为 grid 的线程总数，即 `N = cuda.gridDim.x * cuda.blockDim.x`。

> The pattern for computing the thread index as shown in the code block above is so common, Numba provides a shorthand syntax for this operation: `cuda.grid(n)`, where n is the number of dimensions. In the example above, the line

上面的线程索引计算模式非常常见，因此 Numba 提供简写 `cuda.grid(n)`，其中 n 是维度数。在上述示例中，下面这一行：

```python
idx = cuda.threadIdx.x + cuda.blockIdx.x * cuda.blockDim.x
```

> can be replaced by the much simpler

可以替换为更简洁的：

```python
idx = cuda.grid(1)
```

> One notable aspect of this kernel is that it does not check for out-of-bounds access to A, B, or C. In this chapter, we assume that these are ndarrays created by cuPy, which will be introduced shortly in Section 2.2.3.3. When using cuPy ndarrays, bounds checking is implicitly implemented by the array type.

这个 kernel 有一个值得注意的地方：它没有检查对 A、B、C 的访问是否越界。本章假定这些数组都是由 CuPy 创建的 `ndarray`，将在 Section 2.2.3.3 介绍。使用 CuPy `ndarray` 时，数组类型会隐式实施边界检查。

**解读（边界检查核对）：** 原文关于“CuPy 数组会隐式实施边界检查”的说法不适用于这里的 Numba kernel。Numba 官方教程明确要求在启动规模超过数组范围时自行检查边界；CuPy 通过 CUDA Array Interface 提供设备数组，并不会自动替这段 kernel 屏蔽越界线程。参见 [Numba 线程索引与边界检查](https://nvidia.github.io/numba-cuda/user/kernels.html#thread-positioning)和 [CuPy 与 Numba 互操作](https://docs.cupy.dev/en/stable/user_guide/interoperability.html#numba)。假定 A、B、C 为等长的一维数组，可将原文 kernel 修正如下；这是补充代码，不是原文：

```python
@cuda.jit
def vecadd(A, B, C):
    idx = cuda.grid(1)
    if idx < C.size:
        C[idx] = A[idx] + B[idx]
```

### 2.2.3. Memory in GPU computing（GPU 计算中的内存）

> Note: Python packages like cuPy and others perform GPU memory management by directly using CUDA C++ APIs, such as those covered in Section 2.1.3.2. Multiple Python packages provide wrappers and utilities for controlling GPU memory allocation. In this guide, only cuPy will be covered. The concepts are similar for most packages, and most behave in similar fashion to their C++ counterparts except where noted.

注意：CuPy 等 Python 包通过直接使用 Section 2.1.3.2 所述的 CUDA C++ API 管理 GPU 内存。有多种 Python 包提供控制 GPU 内存分配的包装接口与工具，本指南只介绍 CuPy。大多数包的概念相近，除特别说明的情况外，其行为也大体类似于对应的 C++ 接口。

> As introduced in Section 1.2.3, the GPU has an attached DRAM. Data arrays which will be used in kernels generally need to be in the GPU’s DRAM before they are accessed from the kernel. In Python, controlling the location of data in memory, i.e. moving data between the CPU and GPU, is the responsibility of the programmer. This is the same situation as explicit memory management in C++, as introduced in Section 2.1.3.2.

如 Section 1.2.3 所述，GPU 有直接连接的 DRAM。kernel 要访问的数据数组通常需要事先放入 GPU DRAM。在 Python 中，控制数据存放位置，也就是在 CPU 与 GPU 之间移动数据，是程序员的职责；这与 Section 2.1.3.2 介绍的 C++ 显式内存管理相同。

#### 2.2.3.1. Instantiating arrays on the GPU（在 GPU 上创建数组）

> CuPy provides functions to create `ndarray` objects of a specified type and dimension on the GPU and also to copy data between the CPU and GPU. Many of the functions in cuPy have similar function signatures to functions for creating ndarrays in Numpy. The following shows a few examples of how to create and fill arrays in GPU memory using CuPy.

CuPy 提供在 GPU 上创建指定类型和维度的 `ndarray`，以及在 CPU、GPU 之间复制数据的函数。许多函数的签名与 NumPy 创建 `ndarray` 的函数相似。下面展示使用 CuPy 在 GPU 内存中创建和填充数组的几个例子。

```python
import cupy as cp
import numpy as np

## create a matrix of zeros on the GPU
## when a datatype is not specified, float32 is used by default
A_device = cp.zeros((1024, 1024))

## create an array of 2^20 random doubles on the GPU
B_device = cp.rand.random((2**20), dtype=np.double)

## create an array of zeroes with the same shape and datatype as an existing array
C_device = cp.zeros_like(A)
```

**解读（API 与类型核对）：** 这段原始示例有三处需要修正，原代码已保留在上方：

| 原文写法或说明 | 核对结果 | 对应修正 |
| --- | --- | --- |
| `cp.zeros` 不指定类型时默认 `float32` | 默认 `dtype=float`，对应 `float64` | 需要单精度时使用 `cp.zeros((1024, 1024), dtype=cp.float32)` |
| `cp.rand.random(...)` | 正确接口位于 `cp.random` 命名空间 | `cp.random.random(2**20, dtype=np.double)` |
| `cp.zeros_like(A)` | 片段中没有定义 `A`，已定义的是 `A_device` | 若要匹配前面的矩阵，使用 `cp.zeros_like(A_device)` |

依据：[CuPy `zeros`](https://docs.cupy.dev/en/stable/reference/generated/cupy.zeros.html)、[CuPy `random.random`](https://docs.cupy.dev/en/stable/reference/generated/cupy.random.random.html)。

#### 2.2.3.2. Copying Arrays between the Host and GPU memory（在 host 与 GPU 内存之间复制数组）

> CuPy can also be used to copy data from Numpy ndarrays which reside in CPU memory to CuPy arrays which reside in GPU memory.

CuPy 也可以把位于 CPU 内存中的 NumPy `ndarray` 复制为位于 GPU 内存中的 CuPy 数组。

```python
import cupy as cp
import numpy as np

## Create an array in host memory
A_host = np.zeros((1024, 1024))
## Copy the array to the GPU
A_device = cp.array(A_host)

## Create an array in GPU memory
B_device = cp.rand.random((1024, 1024))
## copy the array to host memory
B_host = cp.asnumpy(B_device)
```

**解读：** `cp.array(A_host)` 将 NumPy 数组的数据复制到 GPU，`cp.asnumpy(B_device)` 将 CuPy 数组的数据复制到 host。原文这一段的 `cp.rand.random` 也应改为 `cp.random.random`，与上一节相同。

#### 2.2.3.3. The ndarray object type（ndarray 对象类型）

> The `ndarray` objects shown in the previous section exist either in the host memory or in the GPU memory, but not both. Passing arrays which reside on the host as arguments to kernels will result in an error. Passing arrays which reside in GPU memory to normal Python functions, i.e. not kernels, will also result in an error. CuPy does not implicitly perform the copies between CPU and GPU because they can be expensive and excessive data copying can hurt performance. As a result, CuPy requires the programmer to be intentional about when data is copied between CPU and GPU.

上一节中的 `ndarray` 对象或者位于 host memory，或者位于 GPU memory，不会同时位于两者。将 host 数组作为 kernel 参数会报错；将 GPU 数组传给普通 Python 函数，也就是非 kernel 函数，也会报错。CuPy 不会隐式执行 CPU 与 GPU 之间的复制，因为这些操作可能开销很大，过度复制会损害性能；因此，它要求程序员明确决定数据何时在 CPU 与 GPU 之间移动。

**解读（参数传递核对）：** 原文把数组的数据位置与 Python 对象的使用方式混在了一起。Numba kernel 可以接受 NumPy host 数组，并自动执行数据传输，不过官方建议显式管理以避免低效复制；普通 Python 函数也可以接收 CuPy 对象并对其调用 GPU 操作，不会仅因它是 GPU 数组就报错。能否执行取决于函数内部是否支持该对象，不能概括为“非 kernel 一律报错”。参见 [Numba Kernel Arguments](https://nvidia.github.io/numba-cuda/reference/kernel.html#kernel-arguments)和 [CuPy 互操作说明](https://docs.cupy.dev/en/stable/user_guide/interoperability.html)。

> One advantage of using the `ndarray` type in GPU kernels is that the array carries with it the extents of its dimensions. As shown in Section 2.2.2.3, boundary checking is done automatically and the kernel code does not need to check for out-of-bounds access when the total number of threads needed is slightly less than the total size of the execution block or grid.

在 GPU kernel 中使用 `ndarray` 的一个优点是，数组携带了各个维度的大小。如 Section 2.2.2.3 所示，边界检查会自动完成，因此当实际需要的线程总数略小于启动的 block 或 grid 所包含的线程总数时，kernel 代码无需显式检查越界访问。

**解读：** 数组携带 shape、size 等元数据，使 kernel 能够方便地编写边界判断，但不代表访问会自动受保护。这里应采用 2.2.2.3 解读中带 `if idx < C.size` 的写法。

### 2.2.4. Synchronizing the CPU and the GPU（同步 CPU 与 GPU）

> Like C++, kernel launches in CUDA Python are asynchronous with respect to the host thread. That is, the host code proceeds executing on the CPU after a kernel launch without any guarantee that the kernel has completed or even started executing. In order to guarantee that GPU kernels have completed executing, the host thread must perform some form of synchronization with the GPU.

与 C++ 一样，CUDA Python 的 kernel launch 相对于 host 线程是异步的。启动后，host 代码会继续在 CPU 上执行，不能保证 kernel 已经完成，甚至不能保证它已经开始执行。要保证 GPU kernel 已完成，host 线程必须进行某种 CPU-GPU 同步。

> The simplest form of synchronization is to synchronize the entire GPU. This device-wide synchronization is an operation provided by the CUDA driver and is exposed to Python by both cuPy and `numba.cuda` as the method synchronize().

最简单的同步方式是同步整个 GPU。设备范围同步由 CUDA driver 提供，CuPy 和 `numba.cuda` 都通过名为 `synchronize()` 的方法向 Python 暴露这一操作。

```python
import cupy as cp
from numba import cuda

..

## Wait on host thread for all pending GPU work to complete
## this uses the interface provided by cupy
cp.synchronize()

## Wait on host thread for all pending GPU work to complete
## this uses the interface provided by numba.cuda
cuda.synchronize()
```

**解读（同步接口核对）：** CuPy 的设备同步应写为 `cp.cuda.Device().synchronize()`，而不是原文中的 `cp.synchronize()`；`cuda.synchronize()` 则是 `numba.cuda` 的接口。代码中的 `..` 也不是合法 Python 语法，运行时需要移除这一省略行。CuPy 接口依据见 [`cupy.cuda.Device.synchronize`](https://docs.cupy.dev/en/stable/reference/generated/cupy.cuda.Device.html#cupy.cuda.Device.synchronize)。

> Device-wide synchronization waits on the host thread until all previously issued work on the GPU has completed. Finer-grain synchronization is available using CUDA streams as described in Section 2.5. In Python, when using streams, recommended practice is to use `cuda.core` to create CUDA streams and perform synchronization only with specific streams as needed.

设备范围同步会使 host 线程等待，直到 GPU 上此前提交的所有工作完成。也可以通过 Section 2.5 介绍的 CUDA stream 实现更细粒度的同步。在 Python 中使用 stream 时，建议通过 `cuda.core` 创建 CUDA stream，并根据需要只同步特定 stream。

### 2.2.5. Putting it All Together（完整示例）

> The ubiquitous first GPU kernel to perform parallel vector addition is shown in its Python form in the source listing below.

并行向量加法是最常见的 GPU kernel 入门示例之一，下面给出它的 Python 代码。

```python
import numpy as np
from numba import cuda
import cupy as cp


## Defines a CUDA kernel to perform C = A + B vector addition
@cuda.jit
def vecadd(A, B, C):
    work_index = cuda.grid(1)
    C[work_index] = A[work_index] + B[work_index]


# note that vector size is not a power of 2 nor a multiple of the block_size defined below
vector_size = 2**24 + 11

device = cp.cuda.Device()
## Create device arrays of uniform random float32 values as input, and an array of zeros
## as the result vector
a = cp.random.uniform(-1, 1, vector_size)
b = cp.random.uniform(-1, 1, vector_size)
c = cp.zeros_like(a)

block_size = 256
grid_size = int(np.ceil(vector_size/block_size))
vecadd[grid_size, block_size](a, b, c)

## synchronize the CPU thread and the GPU to ensure that the kernel has completed
## this is included to illustrate good practices, even though the copy below would implicitly wait for
## the kernel to complete
device.synchronize()

## Copy all 3 arrays to the CPU as ndarrays
a_np = cp.asnumpy(a)
b_np = cp.asnumpy(b)
c_np = cp.asnumpy(c)

## Perform the copy on the CPU to verify the answer
expected = a_np + b_np

## Test that the answer is correct, within floating point epsilon
np.testing.assert_array_almost_equal(c_np, expected)

## The assert will print diagnostics and abort
## so this only prints if the assertion passes
print("Test succeeded")
```

**解读（完整示例核对）：** `vector_size = 2**24 + 11` 不是 256 的整数倍；向上取整后，最后一个 block 只有前 11 个线程对应有效元素，其余 245 个线程必须通过边界判断跳过访问。因此运行前应采用 2.2.2.3 中的修正 kernel。此外，原注释称输入为 `float32`，但 `cp.random.uniform` 默认生成 `float64`；若要与注释一致，应在创建 a、b 时分别指定 `dtype=cp.float32`，c 会通过 `zeros_like` 继承类型。接口依据见 [CuPy `random.uniform`](https://docs.cupy.dev/en/stable/reference/generated/cupy.random.uniform.html)。

**解读：** CPU 端相加和断言用于验证 GPU 结果，不属于 GPU 计算必需的数据传输。性能测量时，应区分 kernel 执行、数据复制和结果校验的成本。

> In this example, the A and B input arrays are created and initialized to random values on the GPU by CuPy. They are copied to the CPU at the end of the code only so that the CPU can perform the vector addition as well and verify that the CPU and GPU answers match.

本例的输入数组 A 和 B 由 CuPy 直接在 GPU 上创建并初始化为随机值。代码末尾将它们复制到 CPU，只是为了在 CPU 上也执行一次向量加法，从而验证 CPU 与 GPU 的结果是否一致。

### 2.2.6. Error Checking in CUDA Python（CUDA Python 错误检查）

> Any operation that affects the GPU, from memory allocation and copies to kernel launches can potentially cause an error condition to arise. As illustrated in Section 2.1.7 for C++, making sure that errors have not occurred in the course of interacting with the GPU is best practice.

任何影响 GPU 的操作，从内存分配、数据复制到 kernel launch，都可能产生错误。如 Section 2.1.7 的 C++ 内容所示，检查与 GPU 交互期间是否发生错误是一项良好实践。

> In Python, CUDA errors throw exceptions which will terminate the program if they are not caught. The exceptions can be caught using normal Python syntax. The example below shows the same vector add as above, but with an error intentionally added: the number of threads per block, 2048, is larger than any current GPU can run. This will cause the kernel to fail to launch, and throw an exception, which this code will catch.

在 Python 中，CUDA 错误会抛出异常；若未捕获，程序就会终止。可以使用标准 Python 语法捕获这些异常。下例使用与前文相同的向量加法，但故意加入一个错误：每个 block 包含 2048 个线程，超过当前所有 GPU 支持的上限。这会导致 kernel 启动失败并抛出异常，代码会捕获该异常。

```python
import numpy as np
from numba import cuda
import cupy as cp


## Defines a CUDA kernel to perform C = A + B vector addition
@cuda.jit
def vecadd(A, B, C):
    work_index = cuda.grid(1)
    C[work_index] = A[work_index] + B[work_index]


try:
    vector_size = 2**24 + 11

    device = cp.cuda.Device()
    a = cp.random.uniform(-1, 1, vector_size)
    b = cp.random.uniform(-1, 1, vector_size)
    c = cp.zeros_like(a)

    ## this block size is too large for any current GPUs
    block_size = 2048
    grid_size = int(np.ceil(vector_size/block_size))
    # Error: launching kernel with invalid block size
    vecadd[grid_size, block_size](a, b, c)

    device.synchronize()
    print("Test did not encounter any errors")

except Exception as e:
    print(f"Exception occurred: {e}")
```

**解读：** 这个例子故意使用非法 block 大小，目的是展示启动错误如何进入 `except` 分支。即使把 2048 改回合法值，kernel 中缺少边界检查的问题仍需修正。同步调用也放在 `try` 中，有助于捕获在等待 GPU 完成时才报告的执行错误。

运行这段代码后，错误会被捕获并显示，如下所示：
