## 4.5. Programmatic Dependent Launch and Synchronization（可编程依赖启动与同步）

来源：[CUDA Programming Guide — Programmatic Dependent Launch and Synchronization](https://docs.nvidia.com/cuda/cuda-programming-guide/04-special-topics/programmatic-dependent-launch.html)。

> The Programmatic Dependent Launch mechanism allows for a dependent secondary kernel to launch before the primary kernel it depends on in the same CUDA stream has finished executing. Available starting with devices of compute capability 9.0, this technique can provide performance benefits when the secondary kernel can complete significant work that does not depend on the results of the primary kernel.

Programmatic Dependent Launch（可编程依赖启动，PDL）允许同一个 CUDA stream 中的 secondary kernel，在它所依赖的 primary kernel 完成之前开始执行。该机制从 compute capability 9.0 的设备起可用。如果 secondary kernel 有较多不依赖 primary kernel 结果的工作可先完成，就可能获得性能收益。

**解读：** PDL 放宽了同一 stream 内相邻 kernel 必须等前一个 kernel 完全结束才能开始的启动限制。它适合 secondary kernel 具有足够长的独立准备工作；能否实际重叠，还取决于设备资源和运行时调度。

Programmatic Dependent Launch 会改变 kernel launch API 的使用方式，下一节将介绍。要使这些 API 提供重叠执行，设备至少需要 compute capability 9.0。

### 4.5.2. API Description（API 说明）

> In Programmatic Dependent Launch, a primary and a secondary kernel are launched in the same CUDA stream. The primary kernel should execute `cudaTriggerProgrammaticLaunchCompletion` with all thread blocks when it’s ready for the secondary kernel to launch. The secondary kernel must be launched using the extensible launch API as shown.

使用 Programmatic Dependent Launch 时，primary kernel 和 secondary kernel 在同一个 CUDA stream 中启动。Primary kernel 准备好让 secondary kernel 开始时，其所有 thread block 都应执行 `cudaTriggerProgrammaticLaunchCompletion`；secondary kernel 则必须通过下文的可扩展 launch API 启动。

```cpp
__global__ void primary_kernel() {
   // Initial work that should finish before starting secondary kernel

   // Trigger the secondary kernel
   cudaTriggerProgrammaticLaunchCompletion();

   // Work that can coincide with the secondary kernel
}

__global__ void secondary_kernel()
{
   // Independent work

   // Will block until all primary kernels the secondary kernel is dependent on have completed and flushed results to global memory
   cudaGridDependencySynchronize();

   // Dependent work
}

cudaLaunchAttribute attribute[1];
attribute[0].id = cudaLaunchAttributeProgrammaticStreamSerialization;
attribute[0].val.programmaticStreamSerializationAllowed = 1;
configSecondary.attrs = attribute;
configSecondary.numAttrs = 1;

primary_kernel<<<grid_dim, block_dim, 0, stream>>>();
cudaLaunchKernelEx(&configSecondary, secondary_kernel);
```

**解读（示例边界）：** `cudaTriggerProgrammaticLaunchCompletion()` 是允许下游 kernel 提前启动的信号，`cudaGridDependencySynchronize()` 是下游在读取依赖数据前的等待点，作用不同。原文中的 `configSecondary`、`grid_dim`、`block_dim` 与 `stream` 未给出定义和初始化；这些语句用于说明 API 关系，并非完整可编译程序。须确保 `configSecondary.stream` 与 primary launch 使用同一 stream。

> When the secondary kernel is launched using the `cudaLaunchAttributeProgrammaticStreamSerialization` attribute, the CUDA driver is safe to launch the secondary kernel early and not wait on the completion and memory flush of the primary before launching the secondary.

使用 `cudaLaunchAttributeProgrammaticStreamSerialization` 属性启动 secondary kernel 后，CUDA driver 可以在 primary kernel 完成并将内存写入对后续 kernel 可见之前，提前启动 secondary kernel。

> The CUDA driver can launch the secondary kernel when all primary thread blocks have launched and executed `cudaTriggerProgrammaticLaunchCompletion`. If the primary kernel doesn’t execute the trigger, it implicitly occurs after all thread blocks in the primary kernel exit.

当 primary kernel 的所有 thread block 都已启动并执行 `cudaTriggerProgrammaticLaunchCompletion` 时，CUDA driver 可以启动 secondary kernel。如果 primary kernel 没有执行该 trigger，则会在 primary kernel 的全部 thread block 退出后隐式触发。

> In either case, the secondary thread blocks might launch before data written by the primary kernel is visible. As such, when the secondary kernel is configured with Programmatic Dependent Launch, it must always use `cudaGridDependencySynchronize` or other means to verify that the result data from the primary is available.

无论哪种情况，secondary kernel 的 thread block 都可能在 primary kernel 写入的数据可见之前开始运行。因此，配置了 Programmatic Dependent Launch 的 secondary kernel，在使用依赖数据之前，必须调用 `cudaGridDependencySynchronize`，或通过其他机制确认 primary kernel 的结果已可用。

**解读（数据可见性）：** 所有 primary block 都触发 launch completion，只表示 CUDA 可以提前启动 secondary；不保证 primary 的写入已经完成或可见。Secondary 可以先执行独立部分，但涉及这些结果的读写必须安排在同步之后。官方示例中的 `cudaGridDependencySynchronize()` 会等待所依赖的 primary kernel 完成并将结果写出。

> Please note that these methods provide the opportunity for the primary and secondary kernels to execute concurrently, however this behavior is opportunistic and not guaranteed to lead to concurrent kernel execution. Reliance on concurrent execution in this manner is unsafe and can lead to deadlock.

这些机制只提供 primary kernel 与 secondary kernel 并发执行的机会，并不保证它们确实会同时运行。如果程序的正确性依赖二者必须并发执行，就不安全，且可能发生死锁。

**解读（不能依赖重叠取得进展）：** 如果 primary 等待 secondary 完成某件事，而 secondary 又要等 primary 释放资源才能获调度，即使硬件允许重叠，也可能死锁。正确性应在不发生并发时同样成立；并发只用来争取性能。

### 4.5.3. Use in CUDA Graphs（在 CUDA Graph 中使用）

> Programmatic Dependent Launch can be used in CUDA Graphs via stream capture or directly via edge data. To program this feature in a CUDA Graph with edge data, use a `cudaGraphDependencyType` value of `cudaGraphDependencyTypeProgrammatic` on an edge connecting two kernel nodes. This edge type makes the upstream kernel visible to a `cudaGridDependencySynchronize()` in the downstream kernel. This type must be used with an outgoing port of either `cudaGraphKernelNodePortLaunchCompletion` or `cudaGraphKernelNodePortProgrammatic`.

可以通过 stream capture 或直接设置 edge data，在 CUDA Graph 中使用 Programmatic Dependent Launch。如果直接设置 graph edge，需要把连接两个 kernel node 的 edge 的 `cudaGraphDependencyType` 设为 `cudaGraphDependencyTypeProgrammatic`。这样，downstream kernel 内的 `cudaGridDependencySynchronize()` 就能识别该 upstream kernel。该 edge type 的 outgoing port 必须是 `cudaGraphKernelNodePortLaunchCompletion` 或 `cudaGraphKernelNodePortProgrammatic`。

> The resulting graph equivalents for stream capture are as follows:

通过 stream capture 构造 graph 时，对应关系如下：

> | Stream code (abbreviated)<br>Stream 代码（节选） | Resulting graph edge<br>生成的 Graph 边 |
> | --- | --- |
> | `cudaLaunchAttribute attribute;`<br>`attribute.id = cudaLaunchAttributeProgrammaticStreamSerialization;`<br>`attribute.val.programmaticStreamSerializationAllowed = 1;` | `cudaGraphEdgeData edgeData;`<br>`edgeData.type = cudaGraphDependencyTypeProgrammatic;`<br>`edgeData.from_port = cudaGraphKernelNodePortProgrammatic;` |
> | `cudaLaunchAttribute attribute;`<br>`attribute.id = cudaLaunchAttributeProgrammaticEvent;`<br>`attribute.val.programmaticEvent.triggerAtBlockStart = 0;` | `cudaGraphEdgeData edgeData;`<br>`edgeData.type = cudaGraphDependencyTypeProgrammatic;`<br>`edgeData.from_port = cudaGraphKernelNodePortProgrammatic;` |
> | `cudaLaunchAttribute attribute;`<br>`attribute.id = cudaLaunchAttributeProgrammaticEvent;`<br>`attribute.val.programmaticEvent.triggerAtBlockStart = 1;` | `cudaGraphEdgeData edgeData;`<br>`edgeData.type = cudaGraphDependencyTypeProgrammatic;`<br>`edgeData.from_port = cudaGraphKernelNodePortLaunchCompletion;` |

**解读（Graph edge 对照）：** 三行都使用 `cudaGraphDependencyTypeProgrammatic`。前两种 stream 属性对应 `cudaGraphKernelNodePortProgrammatic`；当 `triggerAtBlockStart = 1` 时，对应 `cudaGraphKernelNodePortLaunchCompletion`。Graph 中的 programmatic edge 仍需由下游 kernel 在使用上游数据前完成依赖同步；改变 port 并不自动证明数据已就绪。表格按官方页面恢复列与行，代码保持原样。
