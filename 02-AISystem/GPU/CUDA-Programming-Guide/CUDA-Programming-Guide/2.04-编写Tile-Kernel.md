## 2.4. Writing Tile Kernels（编写 tile kernel）

> CUDA Tile provides a different approach to writing GPU kernel code than the single instruction multiple thread (SIMT) model covered in the previous chapters. Tile programming allows programmers to express parallelism differently and leaves the lowest level of parallelism to the compiler and built-in operations. By doing so, tile provides a simpler way to access recent performance features of NVIDIA GPUs such as the tensor memory accelerator (TMA) unit and the tensor cores.

CUDA Tile 提供了一种不同于前面章节所介绍的 SIMT（Single Instruction, Multiple Thread，单指令多线程）模型的 GPU kernel 编写方式。Tile 编程让程序员以不同方式表达并行性，将最底层的并行工作交给编译器和内建操作。这样就能更简单地使用 NVIDIA GPU 较新的性能特性，例如 Tensor Memory Accelerator（TMA）单元和 Tensor Core。

> CUDA Tile programming is available in Python through the cuTile Python package `cuda.tile`.

Python 中可以通过 cuTile Python 包 `cuda.tile` 使用 CUDA Tile 编程。

> CUDA Tile C++ is available in the CUDA Toolkit from version 13.3 onward.

从 CUDA Toolkit 13.3 开始，可以使用 CUDA Tile C++。

> The application code surrounding a tile kernel for tasks like allocating device memory, transferring data between host and device, and sequencing kernel launches is identical to what the preceding chapters described for SIMT kernels. A tile kernel operates on global memory allocated with the standard CUDA APIs, and its results are copied back to the host in the same way. The only thing that changes is what the programmer writes code inside the kernel itself.

围绕 tile kernel 的应用程序代码，例如分配 device memory、在 host 与 device 之间传输数据，以及安排 kernel 启动顺序，与前面章节介绍的 SIMT kernel 使用方式相同。Tile kernel 操作的是通过标准 CUDA API 分配的 global memory，其结果也以相同方式复制回 host。变化仅在于程序员如何编写 kernel 内部的代码。

> In a SIMT kernel, the programmer thinks in terms of individual threads: computing a global thread index, loading the thread’s elements, performing operations on them, and storing the results. In a tile kernel, the programmer thinks at the level of an entire block: loading a tile of many elements, performing an operation on the whole tile, and storing the result. The compiler takes responsibility for mapping tile operations to the hardware threads of each block, a concern that the SIMT programmer handles explicitly.

在 SIMT kernel 中，程序员以单个线程为单位思考：计算全局线程索引，加载该线程负责的元素，对元素进行运算，然后存储结果。在 tile kernel 中，程序员以整个 block 为单位思考：加载包含多个元素的 tile，对整个 tile 执行操作，再存储结果。编译器负责将 tile 操作映射到各 block 的硬件线程上，而这些工作在 SIMT 编程中需要由程序员显式处理。

> This chapter focuses exclusively on that difference: how to write the kernel entry point and the tile operations within it. Every pattern is demonstrated in both CuTile Python (`cuda.tile`) and CUDA Tile C++ (`cuda::tiles`), which share a common compiler backend (CUDA Tile IR) and therefore share the same execution semantics.

本章集中讨论这一差别：如何编写 kernel 入口及其中的 tile 操作。每种模式都分别通过 cuTile Python（`cuda.tile`）和 CUDA Tile C++（`cuda::tiles`）展示。二者共用编译器后端 CUDA Tile IR，因此具有相同的执行语义。

### 2.4.1. Kernel and Function Declarations（Kernel 与函数声明）

> A tile kernel is the GPU entry point, it executes once per block in the launch grid. A tile function is callable from a tile kernel or another tile function, but is not itself an entry point. As with SIMT kernels, tile kernels cannot be called directly from host code; they must be launched.

Tile kernel 是 GPU 的入口点，launch grid 中的每个 block 都执行一次。Tile function 可以由 tile kernel 或其他 tile function 调用，但它本身不是入口点。与 SIMT kernel 一样，tile kernel 不能通过 host 代码直接进行普通函数调用，而必须启动执行。

> In CUDA Tile C++:

在 CUDA Tile C++ 中：

- > `__tile_global__` is the tile analog of `__global__` and marks a tile kernel entry point

  `__tile_global__` 对应 SIMT 中的 `__global__`，用于标记 tile kernel 入口点。

- > `__tile__` is the tile analog of `__device__` and indicates a function that should be compiled for the GPU and be callable from other `__tile__` or `__tile_global__` functions.

  `__tile__` 对应 SIMT 中的 `__device__`，表示该函数应编译为 GPU 代码，并可以由其他 `__tile__` 或 `__tile_global__` 函数调用。

> Array and scalar parameters are passed the same way as in SIMT kernels. Tile code and SIMT code can coexist: a single `.cu` file can define both `__tile_global__` and `__global__` kernels, and a single host program can launch both.

数组和标量参数的传递方式与 SIMT kernel 相同。Tile 代码可以与 SIMT 代码共存：同一个 `.cu` 文件可以同时定义 `__tile_global__` 和 `__global__` kernel，同一个 host 程序也可以启动这两类 kernel。

> Note: Currently, `__tile__` functions cannot be called from `__global__` or `__device__` functions. Similarly, `__device__` functions cannot be called from `__tile_global__` or `__tile__` functions. This limitation may be lifted in future versions of CUDA.

注意：目前不能从 `__global__` 或 `__device__` 函数调用 `__tile__` 函数；同样，也不能从 `__tile_global__` 或 `__tile__` 函数调用 `__device__` 函数。未来的 CUDA 版本可能会解除这一限制。

> In cuTile Python:

在 cuTile Python 中：

- > The `@ct.kernel` decorator marks a function as a tile kernel entry point

  `@ct.kernel` 装饰器将函数标记为 tile kernel 入口点。

- > The `@ct.function` decorator marks a function callable from a tile kernel or another tile function.

  `@ct.function` 装饰器将函数标记为可以由 tile kernel 或其他 tile function 调用的函数。

> In practice, any function called from a kernel is automatically compiled as tile code, so the `@ct.function` decorator is optional. Array parameters accept any device-resident array that exposes DLPack or the CUDA Array Interface. For example, PyTorch tensors and CuPy arrays. Scalar parameters are passed directly.

实际上，kernel 调用的函数会自动编译为 tile 代码，因此 `@ct.function` 装饰器是可选的。数组参数可以接收任何驻留在 device 上、提供 DLPack 或 CUDA Array Interface 的数组，例如 PyTorch tensor 和 CuPy array。标量参数则直接传递。

**解读：** Tile 与 SIMT kernel 可以使用同一套 host 侧内存和调度设施，但函数体属于不同的编译与执行语境。“函数自动编译为 tile 代码”仍要求其内容属于支持的语言子集，不表示可以在 kernel 中任意调用普通 Python 库。

```cpp
#include "cuda_tile.h"

// Tile kernel entry point. Cannot be called directly; must be launched.
__tile_global__ void my_kernel(float* a, float* b, float* c) {
    ...
}

// Tile function. Callable from tile kernels and tile functions.
__tile__ float helper(float x, float y) {
    return x + y;
}
```

### 2.4.2. Launching Kernels（启动 kernel）

> A tile kernel is launched on a grid of tile blocks, just as a SIMT kernel is launched on a grid of thread blocks. The programmer specifies the grid shape, up to three dimensions. From the programmer’s perspective, each tile block is executed by a single logical thread. Parallelism within the block is managed by the compiler.

Tile kernel 在由 tile block 构成的 grid 上启动，类似于 SIMT kernel 在由 thread block 构成的 grid 上启动。程序员指定 grid 形状，最多三维。从程序员角度看，每个 tile block 由一个逻辑线程执行，block 内的并行性由编译器管理。

> In C++, tile kernels reuse the familiar triple-chevron launch syntax from SIMT. The first chevron argument is the grid shape (number of tile blocks). The second is the per-block thread count from SIMT; for tile kernels the compiler determines the thread count internally, and the second argument must be 1. A tile kernel is also an ordinary CUDA kernel, so it can be launched through the runtime’s existing APIs `cudaLaunchKernel` and `cudaLaunchKernelEx` with the same `grid, 1` configuration. This is useful when integrating tile kernels into a codebase that already drives launches through those APIs.

在 C++ 中，tile kernel 沿用 SIMT 的三尖括号启动语法。第一个参数是 grid 形状，即 tile block 的数量。第二个参数在 SIMT 中表示每个 block 的线程数；对于 tile kernel，线程数由编译器在内部决定，因此第二个参数必须为 1。Tile kernel 同时也是普通的 CUDA kernel，因此也可以使用 runtime 现有的 `cudaLaunchKernel` 和 `cudaLaunchKernelEx` API，并采用相同的 `grid, 1` 配置启动。将 tile kernel 集成到已经使用这些 API 管理启动的代码库时，这一点很有用。

> In Python, `ct.launch` takes four positional arguments: a CUDA stream, a grid tuple specifying the number of tile blocks in each dimension, the kernel object, and a tuple of kernel arguments.

在 Python 中，`ct.launch` 接收四个位置参数：CUDA stream、指定各维度 tile block 数量的 grid 元组、kernel 对象，以及包含 kernel 参数的元组。

```cpp
my_kernel<<<dim3(num_blocks_x, num_blocks_y), 1>>>(a, b, c);  // second arg must be 1
```

**解读：** C++ 启动参数中的 `1` 不是“GPU 只用一个硬件线程执行这个 tile”。它表达 tile kernel 的启动约定，内部使用多少线程、如何分配元素，由编译器决定。程序员显式控制的是 grid 覆盖多少个逻辑 block，以及每个 block 处理多大的 tile。

#### 2.4.2.1. Grid-Sizing Pattern（Grid 大小的确定方式）

> A common pattern is to launch enough blocks to cover a full array, including a final block which potentially exceeds the size of the array in one or more dimensions.

常见做法是启动足够多的 block 覆盖整个数组；最后一个 block 可能在一个或多个维度上超过数组边界。

```cpp
int num_blocks = (N + tile_size - 1) / tile_size;   // ceil division -> covers partial tail
kernel<<<num_blocks, 1>>>(in, out, N);
```

> Handling the case where the size of an array is not perfectly divisible by the size of tiles is discussed in the subsections of Section 2.4.6.

当数组大小不能被 tile 大小整除时，如何处理边界将在第 2.4.6 节的各小节中介绍。

### 2.4.3. Querying Block Position（查询 block 位置）

> Each block needs to know where it sits in the grid so it can determine which portion of the data to process. In SIMT, the programmer combines `blockIdx` and `threadIdx` to compute a global thread index. In tile code, only the block index is needed. The compiler handles all thread-level indexing within the block.

每个 block 都需要知道自己在 grid 中的位置，才能确定负责处理哪一部分数据。在 SIMT 中，程序员结合 `blockIdx` 和 `threadIdx` 计算全局线程索引；在 tile 代码中，只需要 block 索引，block 内所有线程级索引都由编译器处理。

> In C++, `ct::bid()` returns a `uint3` containing the block index in all three dimensions. `ct::num_blocks()` returns a `dim3` with the total number of blocks in each dimension (as determined by the kernel launch parameters). Individual components are accessed via .x, .y, .z.

在 C++ 中，`ct::bid()` 返回一个 `uint3`，包含三个维度上的 block 索引；`ct::num_blocks()` 返回一个 `dim3`，包含由 kernel 启动参数确定的各维度 block 总数。通过 `.x`、`.y`、`.z` 访问相应分量。

> In Python, `ct.bid(axis)` returns the current block’s index along the given axis (0, 1, or 2) as an `int32` scalar. `ct.num_blocks(axis)` returns the total number of blocks along that axis – useful for bounds checks and loop counts.

在 Python 中，`ct.bid(axis)` 返回当前 block 在指定轴（0、1 或 2）上的索引，类型为 `int32` 标量。`ct.num_blocks(axis)` 返回该轴上的 block 总数，可以用于边界检查和确定循环次数。

```cpp
#include "cuda_tile.h"

__tile_global__ void my_kernel(float* a, float* b, float* c) {
    namespace ct = cuda::tiles;
    int bid_x = ct::bid().x;          // block index along .x
    int bid_y = ct::bid().y;          // block index along .y
    int num_x = ct::num_blocks().x;   // total blocks along .x
}
```

### 2.4.4. Creating Tiles（创建 tile）

> With the block’s identity established, the next question is what tile kernels actually operate on. That’s the tile: a fixed-size, multidimensional array of scalar elements whose shape and element type are known at compile time. Each dimension of a tile must be a power of two. Tiles have value semantics. This means copying a tile copies its elements and the two copies are fully independent. Despite this, copies are cheap because the compiler controls how tiles are represented internally in hardware. The programmer does not allocate or free memory for tiles.

确定 block 的身份后，下一个问题是 tile kernel 实际操作什么对象。答案是 tile：一种大小固定的多维标量数组，其形状和元素类型在编译期已知。Tile 的每个维度都必须是 2 的幂。Tile 具有值语义：复制 tile 会复制其中的元素，两份值完全独立。不过，复制仍然很便宜，因为编译器控制 tile 在硬件内部的表示方式。程序员不需要为 tile 分配或释放内存。

**解读：** Tile 是编程模型中的值，不要求程序员将它固定放在某种内存空间。`auto y = x` 表达独立值语义，编译器可以优化其实际表示，因此不必等同于一次完整内存拷贝；但较大的 tile 和较多同时存活的值仍会增加资源压力。“不用手动分配”不代表没有硬件存储成本。

> In practice, tiles are created either by loading data from arrays (Tile-Space Loads and Stores) or by using factory functions that produce tiles filled with a specified pattern.

实际使用中，tile 通常通过从数组加载数据来创建，参见“Tile-Space Loads and Stores”；也可以使用工厂函数，生成按指定模式填充的 tile。

> In C++, the tile type is explicit: `ct::tile<T, ct::shape<dims...>>`, where T is the element type and `ct::shape<dims...>` encodes the dimensions as template arguments (the integer values are the compile-time sizes along each axis). For example, `ct::tile<float, ct::shape<8>>` is a 1-D tile of 8 floats, and `ct::tile<float, ct::shape<4, 4>>` is a 4×4 `float` tile. Because the shape is part of the type, it is always known at compile time.

在 C++ 中，tile 类型显式写为 `ct::tile<T, ct::shape<dims...>>`，其中 `T` 是元素类型，`ct::shape<dims...>` 通过模板参数编码各维度，其整数值就是各轴在编译期确定的大小。例如，`ct::tile<float, ct::shape<8>>` 是包含 8 个 `float` 的一维 tile，`ct::tile<float, ct::shape<4, 4>>` 是 4 × 4 的 `float` tile。由于形状是类型的一部分，因此它始终在编译期已知。

> Factory functions take the full tile type (Tile below) as a template parameter:

工厂函数使用完整 tile 类型作为模板参数，下文记为 `Tile`：

- > `ct::zeros<Tile>()` and `ct::ones<Tile>()` - tiles filled with zeros or ones.

  `ct::zeros<Tile>()` 和 `ct::ones<Tile>()`：分别生成全部填充为 0 或 1 的 tile。

- > `ct::full<Tile>(val)` - tile where every element has value `val`.

  `ct::full<Tile>(val)`：生成每个元素都等于 `val` 的 tile。

- > `ct::iota<Tile>()` - tile containing `(0, 1, ..., N-1)`, where N is the tile’s size.

  `ct::iota<Tile>()`：生成包含 `(0, 1, ..., N-1)` 的 tile，其中 N 是 tile 的元素总数。

> C++ examples throughout this chapter use a using alias (e.g., `using f32x4x4 = ct::tile<float, ct::shape<4, 4>>`) to keep tile types readable at the call site.

本章的 C++ 示例使用 using 类型别名，例如 `using f32x4x4 = ct::tile<float, ct::shape<4, 4>>`，使调用位置的 tile 类型保持易读。

> In Python, both the shape tuple and the `dtype` arguments to a tile factory are compile-time values. Python literals (like `(64, 64)` and `ct.float32`) satisfy this naturally. They can also be supplied using Constant-annotated kernel parameters as shown below in Python Constant[T]. The resulting tile exposes `.shape`, `.dtype`, and `.ndim` properties that reflect its compile-time attributes.

在 Python 中，tile 工厂函数的形状元组和 `dtype` 参数都必须是编译期值。Python 字面量，例如 `(64, 64)` 和 `ct.float32`，天然满足这一条件；也可以通过带有 `Constant` 注解的 kernel 参数提供，详见下文“Python Constant[T]”。生成的 tile 提供 `.shape`、`.dtype` 和 `.ndim` 属性，反映其编译期属性。

> The factory functions are:

相应工厂函数如下：

- > `ct.zeros(shape, dtype)` and `ct.ones(shape, dtype)` - tiles filled with zeros or ones.

  `ct.zeros(shape, dtype)` 和 `ct.ones(shape, dtype)`：分别生成全部填充为 0 或 1 的 tile。

- > `ct.full(shape, fill_value, dtype)` - tile with an arbitrary constant value.

  `ct.full(shape, fill_value, dtype)`：生成填充为任意指定常量值的 tile。

- > `ct.arange(size, dtype=...)` - 1-D tile containing `[0, 1, ..., size-1]`.

  `ct.arange(size, dtype=...)`：生成包含 `[0, 1, ..., size-1]` 的一维 tile。

```cpp
#include "cuda_tile.h"

__tile__ void factories() {
    namespace ct = cuda::tiles;

    using i32x8   = ct::tile<int,   ct::shape<8>>;      // 1-D: 8 ints
    using f32x4x4 = ct::tile<float, ct::shape<4, 4>>;   // 2-D: 4x4 floats

    auto z      = ct::zeros<f32x4x4>();       // all zeros
    auto o      = ct::ones<f32x4x4>();        // all ones
    auto filled = ct::full<f32x4x4>(3.14f);   // all 3.14
    auto seq    = ct::iota<i32x8>();          // {0, 1, 2, 3, 4, 5, 6, 7}
}
```

### 2.4.5. Compile-Time Constants（编译期常量）

> The tile compiler generates specialized machine code for each combination of tile shapes, data types, and other structural parameters. Values that influence the generated code must therefore be known at compile time. That is, the shape and data type of the tile must be known at compile time. Creating Tiles used literals to specify tile shapes and data types: `ct.zeros((64, 64), dtype=ct.float32)` and `ct::tile<int, ct::shape<8>>`.

Tile 编译器会为 tile 形状、数据类型及其他结构参数的每种组合生成专门的机器码。因此，影响代码生成的值必须在编译期已知，也就是说，tile 的形状和数据类型必须在编译期确定。前面的“Creating Tiles”使用字面量指定形状和类型，例如 `ct.zeros((64, 64), dtype=ct.float32)` 和 `ct::tile<int, ct::shape<8>>`。

> The shape can also be passed through the kernel interface as compile-time-known values, as shown in the following sections.

形状也可以通过 kernel 接口，作为编译期已知的值传入，以下各节将展示这种方式。

#### 2.4.5.1. Python Constant[T]（Python 中的 Constant[T]）

> The `ct.Constant[T]` type hint on a kernel parameter marks it as constant-embedded. This means that every use of that parameter inside the kernel behaves as if the literal value were written in its place. The type argument is optional, `ct.Constant` without a type argument embeds a constant of any type. `ct.Constant` is most commonly used on integers, `ct.Constant[int]`, on parameters that drive tile shapes and loop bounds.

在 kernel 参数上使用 `ct.Constant[T]` 类型注解，会将该参数标记为嵌入的常量。这意味着，kernel 内每次使用该参数，都相当于直接在该位置写入相应字面量。类型参数可省略，单独使用 `ct.Constant` 可以嵌入任意类型的常量。最常见的用法是 `ct.Constant[int]`，用于控制 tile 形状和循环边界的整数参数。

**解读：** `ct.Constant` 参与 kernel 的编译特化，不是上一节 GPU memory space 中的 constant memory。改变决定 tile 形状的常量，可能需要生成另一份代码；array 的运行时长度则可以变化。必须在编译时确定的是 tile 自身形状，并非被处理的整个 array 大小。

```python
import cuda.tile as ct

@ct.kernel
def my_kernel(TILE: ct.Constant[int]):
    # TILE is constant-embedded: wherever TILE appears, the compiler sees its
    # literal value (e.g., 128) and generates specialized code. Here TILE drives
    # the shape of a factory-built tile.
    zeros = ct.zeros((TILE,), dtype=ct.float32)
```

#### 2.4.5.2. C++ integral_constant and `_ic` Literals（C++ integral_constant 与 `_ic` 字面量）

> In CUDA Tile C++, compile-time values are expressed through `ct::integral_constant`, a type whose numeric value is encoded in the type itself. The `_ic` literals from the `ct::literals` namespace provide a concise shorthand: `0_ic` produces a `ct::integral_constant<0>` value.

CUDA Tile C++ 使用 `ct::integral_constant` 表达编译期值，其数值编码在类型本身中。`ct::literals` 命名空间中的 `_ic` 字面量提供简洁写法：`0_ic` 生成一个 `ct::integral_constant<0>` 值。

> APIs that take compile-time values accept both the non-type template parameter (NTTP) form and the `_ic` literal form. For example, `ct::cat` concatenates two tiles along a given dimension, and that dimension must be known at compile time. The two lines below call `ct::cat` with the same compile-time axis; they differ only in where the compile-time value is written:

接收编译期值的 API，既支持非类型模板参数（NTTP）形式，也支持 `_ic` 字面量形式。例如，`ct::cat` 沿指定维度拼接两个 tile，这个维度必须在编译期确定。下面两行用相同的编译期轴调用 `ct::cat`，只是编译期值写在不同位置：

```cpp
#include "cuda_tile.h"

__tile__ void concat_demo() {
    namespace ct = cuda::tiles;
    using namespace ct::literals;

    using T = ct::tile<int, ct::shape<4, 8>>;
    T lhs = ct::full<T>(0);
    T rhs = ct::full<T>(1);

    auto a = ct::cat<0>(lhs, rhs);     // NTTP form
    auto b = ct::cat(lhs, rhs, 0_ic);  // _ic form
}
```

> There is one other place where `_ic` literals routinely appear. Each of `ct::extents` and `ct::shape` has an NTTP form (for example, `ct::extents<std::uint32_t, 4, 8>`) and a brace form. Unlike the NTTP form, the brace form accepts runtime values, so it is the form you reach for when one or more dimensions are only known at launch: `_ic` literals for the compile-time dims, plain variables for the runtime ones. Tile-space APIs like `ct::tensor_span` and `ct::partition_view` (covered in Tile-Space Loads and Stores) use this form to wrap such arrays:

`_ic` 字面量还经常用于另一个地方：`ct::extents` 和 `ct::shape` 都具有 NTTP 形式，例如 `ct::extents<std::uint32_t, 4, 8>`，以及花括号形式。与 NTTP 形式不同，花括号形式可以接收运行时值。因此，当一个或多个维度只有在启动时才能确定时，可以使用这一形式：编译期维度使用 `_ic` 字面量，运行时维度使用普通变量。后文“Tile-Space Loads and Stores”介绍的 `ct::tensor_span`、`ct::partition_view` 等 tile-space API 使用这种形式封装数组：

```cpp
auto shape2d = ct::extents{8_ic, length};  // 8 is compile-time; length is runtime
```

> `_ic` literals are the uniform shorthand for a compile-time value wherever a value-form API argument calls for one, such as a `ct::cat` dimension or an extents or shape component.

只要某个采用值形式的 API 参数需要编译期常量，就可以统一使用 `_ic` 字面量作为简写，例如 `ct::cat` 的维度参数，或 extents、shape 中的某个分量。

**解读：** `ct::extents{8_ic, length}` 中，8 是编译期信息，`length` 可以到运行时才确定。它描述被访问数组的范围；不能由此推断 tile 可以具有任意运行时形状。类似地，`ct::cat<0>(...)` 与 `ct::cat(..., 0_ic)` 都向编译器提供同一个已知的拼接轴。

### 2.4.6. Loading and Storing Tiles（加载与存储 tile）

> As Section 1.2.2.3.1 first introduced, there are two key memory objects in the CUDA tile programming model: tiles and arrays. An array is a multidimensional container of elements in global memory visible to all blocks of a tile kernel. A tile is also a multidimensional container of elements, but is local to a single block of CUDA tile code. A tile is often a subset of elements of an array. This section discusses loading from arrays into tiles so they can be used in tile kernels, and storing tiles back to arrays.

如第 1.2.2.3.1 节首次介绍，CUDA Tile 编程模型中有两类关键内存对象：tile 和 array。Array 是 global memory 中的多维元素容器，对 tile kernel 的所有 block 可见；tile 也是多维元素容器，但局限于单个 CUDA Tile block。Tile 通常包含 array 中的一部分元素。本节讨论如何将 array 中的数据加载到 tile，以便在 tile kernel 内使用，以及如何将 tile 存回 array。

> Two methods of loading and storing tiles are covered in subsequent sections

后续章节将介绍两种 tile 加载与存储方法：

- > Tile-Space Loads and Stores covers loads and stores using tile-space indices that use view objects which prescribe predictable patterns for how the elements of the array map to tiles

  “Tile-Space Loads and Stores”介绍使用 tile-space 索引的加载和存储，通过 view 对象指定 array 元素到 tile 的规则映射。

- > Gather and Scatter covers loads and stores which use a tile of indices or pointers to indicate the element of an array which is the source or target of a tile element when loaded or stored, respectively

  “Gather and Scatter”介绍使用索引 tile 或指针 tile 的加载和存储；其中每个索引或指针指定 array 中的一个元素，作为对应 tile 元素加载时的数据源，或存储时的目标。

> Performance note: Tile-space loads can be lowered by the compiler to the Tensor Memory Accelerator (TMA) on supported hardware, which is significantly faster than per-element gather. (For the C++ side, see also C++ Performance Tips.)

性能说明：在支持的硬件上，编译器可以将 tile-space 加载转换为 Tensor Memory Accelerator（TMA）操作，其速度显著快于逐元素 gather。C++ 相关内容另见“C++ Performance Tips”。

> The programmer must decide what value out-of-bounds elements take on a load. Out-of-bounds writes are silently discarded by default in Python, and in C++ when the masked variants are used.

程序员必须决定加载时越界元素采用什么值。Python 默认静默丢弃越界写入；C++ 使用带 mask 的版本时，也会静默丢弃越界写入。

#### 2.4.6.1. Tile-Space Loads and Stores（Tile-space 加载与存储）

> With tile-space loads, a view object is created which specifies how an array is partitioned into a grid of tile-sized regions. This mapping is called the tile-space, and a tile kernel can load or stores one region at a time using a tile-space index.

使用 tile-space 加载时，先创建一个 view 对象，指定如何将 array 划分为由 tile 大小区域构成的网格。这种映射称为 tile-space，tile kernel 可以通过 tile-space 索引，每次加载或存储其中一个区域。

> Central to the idea of tile-space loads is the tiled view of an array, which specifies how the elements of the array are mapped to tiles of a specified size. The tiled view shown in Figure 19 is a partition view, which is a tile-space with non-overlapping tiles of the specified size with no gaps between tiles.

Tile-space 加载的核心是 array 的 tiled view：它指定 array 元素如何映射到给定大小的 tile。图 19 所示的是 partition view，它将 array 划分为指定大小、互不重叠、相邻区域之间没有间隙的 tile。

> Figure 19 Tile-space indexing for a partition view. A two-dimensional array of shape `(10, 16)` is partitioned for tiles of shape `(2, 4)`, producing a tile grid of shape `(5, 4)`. Each cell shows its tile-space index `(i, j)`. The highlighted region at tile-space index `(1, 2)` covers element indices `(2, 8)` through `(3, 11)`.

图 19：Partition view 的 tile-space 索引。形状为 `(10, 16)` 的二维数组按 `(2, 4)` 的 tile 形状划分，得到形状为 `(5, 4)` 的 tile 网格。每个单元格显示 tile-space 索引 `(i, j)`。高亮的 `(1, 2)` 区域覆盖元素索引 `(2, 8)` 到 `(3, 11)`。

**解读：** Partition view 的索引按 tile 计数。对形状 `(2, 4)`，tile-space 坐标 `(i, j)` 对应的元素起点是 `(2i, 4j)`，不是 `(i, j)`。因此 `(1, 2)` 指向从 `(2, 8)` 开始的区域；这个区别同样适用于一维向量示例。

> When the array dimensions are not perfectly divisible into tiles, tiles which cross the array boundary in one or more dimension will be partially filled. The programmer can specify behavior when loading these tiles, which will be introduced in Section 2.4.6.1.3.

当 array 的各维度不能被 tile 大小整除时，跨越一个或多个 array 边界的 tile 只能部分填满。程序员可以指定加载这些 tile 时的行为，详见第 2.4.6.1.3 节。

> A partition view is one of several tile-spaces that can be defined over an array. Two others are available in both languages:

Partition view 是 array 上可以定义的多种 tile-space 之一。两种语言还支持另外两种：

- > Chunks of a fixed shape separated by a stride, so chunks may leave gaps between them or overlap. C++ spells this `ct::strided_view`; Python passes a `traversal_steps` argument to `Array.tiled_view`.

  按固定步长分隔的固定形状数据块；这些块之间可以留有间隔，也可以重叠。C++ 使用 `ct::strided_view`，Python 则向 `Array.tiled_view` 传入 `traversal_steps` 参数。

- > Chunks selected along one dimension by a tile of element indices, for the irregular access patterns introduced in Gather and Scatter. C++ spells this `ct::gather_scatter_view`; Python uses `ct.load_advanced_indexing` and `ct.store_advanced_indexing`.

  由一个元素索引 tile 沿某个维度选取的数据块，用于“Gather and Scatter”介绍的不规则访问。C++ 使用 `ct::gather_scatter_view`，Python 使用 `ct.load_advanced_indexing` 和 `ct.store_advanced_indexing`。

> Partition views are the only tile-space this chapter demonstrates, and are what `Array.tiled_view` produces by default. For the others, see the API reference for each language (CUDA Tile C++ API Reference, cuTile Python tiled views and advanced indexing).

本章只演示 partition view，它也是 `Array.tiled_view` 默认生成的 tile-space。其他类型请参阅对应语言的 API 文档，即 CUDA Tile C++ API Reference，以及 cuTile Python 的 tiled view 和 advanced indexing 文档。

##### 2.4.6.1.1. Partition View Loads and Stores（Partition view 加载与存储）

> The structured tile-space load is the preferred way to move data between global memory and tiles. The kernel must first build a view object that defines the tile-space, then load or store one tile at a time by its tile-space index.

在 global memory 与 tile 之间移动数据时，首选结构化的 tile-space 加载。Kernel 首先构建定义 tile-space 的 view 对象，然后按照 tile-space 索引，每次加载或存储一个 tile。

> In C++, a partition view is constructed in two steps:

在 C++ 中，构建 partition view 分为两步：

- > `ct::tensor_span` - pairs a raw pointer with a `ct::extents`, giving the pointer multidimensional structure.

  `ct::tensor_span`：将原始指针与 `ct::extents` 配对，为指针所指向的数据附加多维结构。

- > `ct::partition_view` - divides the span into a grid of fixed-size tiles and exposes `.load(idx...)` / `.store(tile, idx...)` methods that operate in tile-space coordinates.

  `ct::partition_view`：将 span 划分成固定大小的 tile 网格，并提供 `.load(idx...)` / `.store(tile, idx...)` 方法，使用 tile-space 坐标进行访问。

> In Python, `Array.tiled_view(tile_shape)` returns a `TiledView` that partitions the array into tiles of the given shape. The view exposes `.load(index)` / `.store(index, tile)` methods that take a tile-space index, mirroring C++ `partition_view` directly.

在 Python 中，`Array.tiled_view(tile_shape)` 返回一个 `TiledView`，将 array 按指定形状划分为 tile。View 提供 `.load(index)` / `.store(index, tile)` 方法，接收 tile-space 索引，与 C++ 的 `partition_view` 直接对应。

> Note: The C++ example code in this chapter annotates pointer arguments with `__restrict__` and calls `ct::assume_aligned(ptr, 16_ic)` near the top of the kernel body. These are important performance annotations covered further in Section 2.4.12. The `_ic` suffix on numeric literals (e.g., `128_ic`, `8_ic`) marks them as compile-time constants, as introduced in Compile-Time Constants.

注意：本章 C++ 示例使用 `__restrict__` 标记指针参数，并在 kernel 函数体开头附近调用 `ct::assume_aligned(ptr, 16_ic)`。这些是重要的性能标注，第 2.4.12 节将进一步介绍。数值字面量上的 `_ic` 后缀，例如 `128_ic`、`8_ic`，表示编译期常量，已在“Compile-Time Constants”中介绍。

```cpp
__tile_global__ void vec_add(float* __restrict__ a, float* __restrict__ b, float* __restrict__ out) {
    namespace ct = cuda::tiles;
    using namespace ct::literals;

    a   = ct::assume_aligned(a,   16_ic);
    b   = ct::assume_aligned(b,   16_ic);
    out = ct::assume_aligned(out, 16_ic);

    // Step 1: attach a shape to each raw pointer. 128_ic marks 128 as a compile-time constant.
    auto aSpan = ct::tensor_span{a,   ct::extents{128_ic}};
    auto bSpan = ct::tensor_span{b,   ct::extents{128_ic}};
    auto oSpan = ct::tensor_span{out, ct::extents{128_ic}};

    // Step 2: partition each span into a tile space of fixed 8-element tiles.
    auto aView = ct::partition_view{aSpan, ct::shape{8_ic}};
    auto bView = ct::partition_view{bSpan, ct::shape{8_ic}};
    auto oView = ct::partition_view{oSpan, ct::shape{8_ic}};

    int  bx    = ct::bid().x;             // this block's tile-space index along .x
    auto aTile = aView.load(bx);          // pick the bx-th tile of a
    auto bTile = bView.load(bx);
    oView.store(aTile + bTile, bx);       // write the tile back at the bx-th position of out
}
```

**解读：** 这个 C++ 示例把 array 长度固定为 128、tile 大小固定为 8，因此完整覆盖需要 16 个 tile block。View 的构建只是描述指针、维度和划分方式，真正的数据传输发生在 `load` 和 `store`；未带 mask 的访问要求所选 tile 全部位于合法范围内。C++ view 的存储参数顺序为 `store(tile, index)`，Python view 则为 `store(index, tile)`。

##### 2.4.6.1.2. Python One-Call Load and Store（Python 的单次调用加载与存储）

> Python additionally offers a one-call form that takes the tile shape inline on each load and store, without an explicit view object. `ct.load(array, index, shape)` reads a tile of the given shape at the given tile-space index. `ct.store(array, index, tile)` is the corresponding write.

Python 还提供单次调用形式，无须显式创建 view 对象，直接在加载和存储调用中表达 tile 形状。`ct.load(array, index, shape)` 从给定 tile-space 索引加载指定形状的 tile；`ct.store(array, index, tile)` 是对应的写入操作。

> Both `ct.load`/`ct.store` and `Array.tiled_view` express the same tile-space access pattern. The difference is where the tile shape lives. With `Array.tiled_view`, the tile shape is bound once to a view object. With `ct.load`/`ct.store`, the tile shape is supplied inline on each call. Using `tiled_view` is preferred when the same partitioning is reused across multiple loads and stores. Use `ct.load`/`ct.store` when a single one-off load is more concise.

`ct.load` / `ct.store` 与 `Array.tiled_view` 表达相同的 tile-space 访问模式，差别在于 tile 形状存放的位置。使用 `Array.tiled_view` 时，tile 形状一次性绑定到 view 对象；使用 `ct.load` / `ct.store` 时，则在每次调用中直接提供 tile 形状。当多次加载和存储复用同一划分方式时，优先使用 `tiled_view`；对于单次访问，`ct.load` / `ct.store` 往往更简洁。

**解读（接口表述澄清）：** 原文将加载与存储统称为“每次提供 tile shape”，但 `ct.store(array, index, tile)` 没有独立的 `shape` 参数；写入形状由传入 tile 自身决定。`ct.load` 才显式接收 `shape`。上面给出的函数签名已经体现了这一点。

```python
@ct.kernel
def vec_add(a, b, c, TILE: ct.Constant[int]):
    bid = ct.bid(0)                                    # this block's tile-space index along axis 0
    a_tile = ct.load(a, index=(bid,), shape=(TILE,))   # (index, shape) = pick the bid-th TILE-sized region of a
    b_tile = ct.load(b, index=(bid,), shape=(TILE,))
    ct.store(c, index=(bid,), tile=a_tile + b_tile)    # write the tile back to the bid-th region of c
```

##### 2.4.6.1.3. Tile-Space Boundary Handling（Tile-space 边界处理）

> In C++, `partition_view` provides unmasked and masked variants:

在 C++ 中，`partition_view` 同时提供不带 mask 和带 mask 的版本：

- > `.load(idx...)` / `.store(tile, idx...)` assumes the tile is fully in-bounds. Partially out-of-bounds access is undefined behavior.

  `.load(idx...)` / `.store(tile, idx...)` 假定整个 tile 都在界内。即使只有部分元素越界，也会产生未定义行为。

- > `.load_masked(idx...)` / `.store_masked(tile, idx...)` handles partial edge tiles safely.

  `.load_masked(idx...)` / `.store_masked(tile, idx...)` 可以安全处理部分越界的边缘 tile。

  - > `.load_masked()` fills out-of-bounds positions with zero by default; alternative padding modes (such as NaN for `float` tiles) can be selected.

    `.load_masked()` 默认用 0 填充越界位置，也可以选择其他 padding mode，例如为浮点 tile 填充 NaN。

  - > `.store_masked()` silently discards out-of-bounds writes.

    `.store_masked()` 静默丢弃越界写入。

> Using the unmasked load and store variant is preferred when the array is perfectly divisible by the tile size. When boundary conditions must be handled, the masked variant can be used even for tiles which are fully populated.

当 array 大小能被 tile 大小整除时，优先使用不带 mask 的加载和存储版本。需要处理边界时，可以统一使用带 mask 的版本，即使某个 tile 实际上完全位于界内。

> This is also the first C++ example in the guide in which an array dimension is a runtime value. `ct::extents{N}` accepts a runtime dimension and `ct::extents` supports any mix of compile-time (`_ic`) and runtime values, so the span and partition view can wrap arrays whose size is known only at kernel launch.

这也是本指南中第一个 array 维度取运行时值的 C++ 示例。`ct::extents{N}` 接受运行时维度，`ct::extents` 还支持任意混合编译期 `_ic` 值和运行时值，因此 span 和 partition view 可以封装只有到 kernel 启动时才能确定大小的 array。

> In Python, `ct.load` accepts a `padding_mode` parameter that controls what value out-of-bounds elements receive. Two commonly used modes are:

在 Python 中，`ct.load` 接收 `padding_mode` 参数，用于控制越界元素的值。两种常见模式如下：

- > `PaddingMode.UNDETERMINED` (the default) - out-of-bounds element values are left to the implementation. The tile is still bounds-checked, so the load never reads memory outside the array; only the value an out-of-bounds lane receives is unspecified. This is appropriate when out-of-bounds lanes are never read.

  `PaddingMode.UNDETERMINED`（默认值）：越界元素的值由实现决定。Tile 仍然会进行边界检查，因此加载不会读取 array 之外的内存；未指定的只是越界 lane 获得的值。当越界 lane 的值从不被读取时，可以使用这种模式。

- > `PaddingMode.ZERO` - out-of-bounds elements are filled with zero.

  `PaddingMode.ZERO`：越界元素填充为 0。

> For stores, `ct.store` needs no `padding_mode` parameter: by default it bounds-checks the tile against the array and silently discards writes to out-of-bounds positions. The same rules apply to `tiled_view`, which fixes its `padding_mode` at view creation.

对于存储，`ct.store` 不需要 `padding_mode` 参数：默认会依据 array 边界检查 tile，并静默丢弃越界位置的写入。相同规则也适用于 `tiled_view`，不过它的 `padding_mode` 在创建 view 时确定。

> `ct.load` and `ct.store` also accept `check_bounds`, which defaults to `True`. Where `padding_mode` decides what an out-of-bounds lane contains, `check_bounds` decides whether the boundary is tested at all: with `check_bounds=False`, an access that reaches past the array is undefined behavior, reading or overwriting adjacent memory. It is the Python counterpart of the unmasked C++ `.load()` / `.store()` above, and carries the same guidance. `TiledView.load` and `TiledView.store` take the same keyword.

`ct.load` 和 `ct.store` 还接受 `check_bounds`，默认值为 `True`。`padding_mode` 决定越界 lane 中放什么值，而 `check_bounds` 决定是否执行边界检查。设为 `False` 时，超过 array 边界的访问属于未定义行为，可能读取或覆盖相邻内存。它对应前面 C++ 不带 mask 的 `.load()` / `.store()`，使用建议也相同。`TiledView.load` 和 `TiledView.store` 接受同样的关键字参数。

**解读：** `padding_mode` 决定越界位置填什么，`check_bounds` 决定是否检查边界，二者职责不同。将 `check_bounds=False` 不是允许越界，而是向编译器承诺不会越界。当前 `ct.load` 文档还注明，关闭这一检查需要 tileiras 13.4 或更新版本，不能只依据本章开头的 Tile C++ 最低版本推断所有 API 都可用。参见 [ct.load 参数说明](https://docs.nvidia.com/cuda/cutile-python/generated/cuda.tile.load.html)。

```cpp
__tile_global__ void edge_safe(float* __restrict__ in, float* __restrict__ out, int N) {
    namespace ct = cuda::tiles;
    using namespace ct::literals;

    in  = ct::assume_aligned(in,  16_ic);
    out = ct::assume_aligned(out, 16_ic);

    // ct::extents{N} uses a runtime dimension; 128_ic stays compile-time.
    auto inView  = ct::partition_view{ct::tensor_span{in,  ct::extents{N}}, ct::shape{128_ic}};
    auto outView = ct::partition_view{ct::tensor_span{out, ct::extents{N}}, ct::shape{128_ic}};

    int  bx   = ct::bid().x;
    auto tile = inView.load_masked(bx);    // masked load: OOB lanes default to 0
    outView.store_masked(tile, bx);        // masked store: OOB writes silently discarded
}
```

> Inside the C++ kernel, `.load_masked()` and `.store_masked()` handle the partial edge tile. Inside the Python kernel, `PaddingMode.ZERO` on the load ensures the partial edge tile is zero-padded, and `ct.store`, with its default bounds checking, silently discards writes beyond the array boundary. For the complete set of padding modes, masking options, and padding values, see the API reference for each language (CUDA Tile C++ view padding, cuTile Python padding modes).

在 C++ kernel 内，`.load_masked()` 和 `.store_masked()` 处理部分越界的边缘 tile。在 Python kernel 内，加载时的 `PaddingMode.ZERO` 保证边缘 tile 的越界部分填充为 0，而采用默认边界检查的 `ct.store` 会静默丢弃超出 array 边界的写入。完整的 padding mode、mask 选项和填充值请参阅对应语言的 API 文档，即 CUDA Tile C++ view padding 和 cuTile Python padding modes。

> Loading from or storing to a tile that lies entirely outside the array is undefined. The boundary handling discussed here only applies to tiles that are partially out-of-bounds in one or more dimension.

对完全位于 array 之外的 tile 进行加载或存储，行为未定义。这里讨论的边界处理仅适用于在一个或多个维度上部分越界的 tile。

**解读：** 以 `N = 10`、tile 大小 8 为例，索引 0 完全有效，索引 1 只有前两个元素有效，应按需填充剩余位置；索引 2 整个 tile 都在 array 之外，不在本节边缘填充保证之内。启动 grid 时应使用正确的向上取整数量，循环额外迭代也需要单独防护。若后续要做求和或矩阵乘法，通常需要零填充，使无效元素不参与结果；不能把 Python 默认的未确定填充值直接用于归约。

#### 2.4.6.2. Gather and Scatter（Gather 与 scatter）

> The tile-space loads in Tile-Space Loads and Stores used a partition view, which defines a regular, block-aligned partitioning of the array. When the access pattern is irregular or data-dependent such as a lookup table or a permutation, for example, gather and scatter operations allow a tile to be loaded from and stored to non-uniform and non-contiguous elements of an array, by arbitrary index or address.

“Tile-Space Loads and Stores”通过 partition view，定义了规则的、按块对齐的 array 划分。当访问模式不规则或取决于数据，例如查表或置换时，gather 和 scatter 允许根据任意索引或地址，从 array 中不均匀、非连续的元素加载 tile，或将 tile 写入这些位置。

> Gather and scatter operations look slightly different in C++ and Python:

Gather 和 scatter 在 C++ 与 Python 中的形式略有不同：

- > Python uses integer index tiles passed to `ct.gather()` / `ct.scatter()`, with built-in bounds checking.

  Python 将整数索引 tile 传给 `ct.gather()` / `ct.scatter()`，其中内建了边界检查。

- > C++ uses tiles of pointers passed to `ct::load()` / `ct::store()`, with masked variants `ct::load_masked()` and `ct::store_masked()` that accept a boolean mask tile to handle tiles at array boundaries.

  C++ 将指针 tile 传给 `ct::load()` / `ct::store()`；其带 mask 版本 `ct::load_masked()` 和 `ct::store_masked()` 接收布尔 mask tile，用于处理 array 边界上的 tile。

> In C++, gather and scatter work by forming a tile of pointers, one pointer per element, and passing the pointer tile to `ct::load()` or `ct::store()`. Arithmetic between a scalar pointer and an integer tile is performed element-wise, producing a tile of pointers. This is the standard idiom for constructing gather/scatter index tiles in C++.

在 C++ 中，先构造一个每个元素都是指针的 tile，再将它传给 `ct::load()` 或 `ct::store()`，即可执行 gather 或 scatter。标量指针与整数 tile 之间的算术逐元素进行，结果是一个指针 tile。这是在 C++ 中构建 gather/scatter 索引 tile 的标准写法。

> In Python, `ct.gather` loads the element at each index in the index tile. Bounds checking is on by default: out-of-bounds indices return a padding value (zero by default, configurable via `padding_value=`), and can be disabled with `check_bounds=False`. `ct.scatter` stores one value per index; out-of-bounds writes are silently discarded, and `check_bounds=False` applies here too.

在 Python 中，`ct.gather` 根据索引 tile 的每个索引加载相应元素。默认启用边界检查，越界索引返回填充值，默认是 0，可通过 `padding_value=` 配置；使用 `check_bounds=False` 可关闭检查。`ct.scatter` 为每个索引存储一个值，越界写入会被静默丢弃；它同样支持 `check_bounds=False`。

```cpp
__tile_global__ void vec_add_gather(int* __restrict__ a, int* __restrict__ b, int* __restrict__ out) {
    namespace ct = cuda::tiles;
    using namespace ct::literals;
    using i32x8 = ct::tile<int, ct::shape<8>>;

    a   = ct::assume_aligned(a,   16_ic);
    b   = ct::assume_aligned(b,   16_ic);
    out = ct::assume_aligned(out, 16_ic);

    int bx       = ct::bid().x;
    auto offsets = 8 * bx + ct::iota<i32x8>();   // element-level offsets, one per lane

    // scalar pointer + int tile = tile of pointers (one pointer per offset).
    auto aPtrs = a + offsets;
    auto bPtrs = b + offsets;

    auto aTile = ct::load(aPtrs);                // gather: one load per pointer
    auto bTile = ct::load(bPtrs);
    ct::store(out + offsets, aTile + bTile);     // scatter: one store per pointer
}
```

##### 2.4.6.2.1. Gather and Scatter Boundary Handling（Gather 与 scatter 的边界处理）

> Boundary handling for the gather/scatter operations introduced in Gather and Scatter follows different rules.

“Gather and Scatter”介绍的访问操作，采用不同的边界处理规则。

> In Python, `ct.gather` and `ct.scatter` are bounds-safe by default. Out-of-bounds reads return a padding value (zero by default), and out-of-bounds writes are silently dropped. Bounds checking can be disabled when you can prove every index is in range; doing so makes out-of-bounds access undefined behavior. See the API reference for the optional mask and padding-value knobs (CUDA Tile C++ load operations, cuTile Python load/store operations).

在 Python 中，`ct.gather` 和 `ct.scatter` 默认具有边界保护。越界读取返回填充值，默认是 0；越界写入静默丢弃。如果可以证明所有索引都在有效范围内，可以关闭边界检查，但此后越界访问将属于未定义行为。可选 mask 和填充值的设置参见对应 API 文档，即 CUDA Tile C++ load operations 和 cuTile Python load/store operations。

> In C++, bounds checking is not automatic. The programmer constructs a boolean mask (e.g., by comparing offsets against the array length) and passes it to `ct::load_masked` or `ct::store_masked`:

在 C++ 中，边界检查不是自动的。程序员需要构造布尔 mask，例如比较偏移与 array 长度，再将 mask 传给 `ct::load_masked` 或 `ct::store_masked`：

```cpp
__tile_global__ void gather_safe(int* __restrict__ arr, int* __restrict__ out, int N) {
    namespace ct = cuda::tiles;
    using namespace ct::literals;
    using i32x8 = ct::tile<int, ct::shape<8>>;

    arr = ct::assume_aligned(arr, 16_ic);
    out = ct::assume_aligned(out, 16_ic);

    int bx       = ct::bid().x;
    auto offsets = 8 * bx + ct::iota<i32x8>();   // element-level offsets, one per lane
    auto mask    = offsets < N;                  // boolean tile: true where the offset is in-bounds

    auto ptrs = arr + offsets;                   // tile of pointers, one per offset
    auto tile = ct::load_masked(ptrs, mask, 0);  // masked lanes get the pad value 0
    ct::store_masked(out + offsets, tile, mask); // masked lanes are skipped on the store
}
```

**解读：** Tile-space 一次指定规则区域，gather/scatter 则显式指定每个元素的位置。C++ 示例中 `offsets = 8 * bx + iota(...)` 产生非负偏移，所以只检查 `offsets < N`；推广到可能包含负数的索引时，还需检查下界。Python `ct.gather` 的负索引视为越界，不采用普通 Python 从末尾倒数的约定。参见 [ct.gather](https://docs.nvidia.com/cuda/cutile-python/generated/cuda.tile.gather.html)。

### 2.4.7. Control Flow（控制流）

> From the programmer’s perspective, a tile kernel follows a single control flow path per block. Scalar values in conditions and loop bounds drive the control flow, while tile operations within the body are distributed across hardware threads by the compiler.

从程序员角度看，每个 block 中的 tile kernel 都沿单一控制流路径执行。条件表达式和循环边界中的标量控制程序流程，代码体内的 tile 操作则由编译器分配到硬件线程上。

> Not every control-flow construct is supported. For example, returning from inside a loop is not allowed in tile code. See the API reference for each language (CUDA Tile C++ general principles, cuTile Python control flow) for the full list of restrictions.

并非所有控制流结构都受支持。例如，tile 代码不允许从循环内部返回。完整限制参见对应语言的 API 文档，即 CUDA Tile C++ general principles 和 cuTile Python control flow。

#### 2.4.7.1. Loops（循环）

> A common pattern is to iterate over tiles from an array, processing each in turn.

常见模式是遍历 array 中的各个 tile，依次进行处理。

> In C++, `ct::irange` is a forward range representing an increasing sequence of integers from a lower bound up to but excluding an upper bound, separated by an optional `step`. Using `ct::irange` provides the compiler with structured information about the iteration bounds, which may be used to better optimize the generated code. For the optimization to apply, the loop variable must be bound through a range-for expression over `ct::irange`.

在 C++ 中，`ct::irange` 是一个向前遍历的 range，表示从下界开始、到上界之前结束的递增整数序列，可以指定步长。它向编译器提供结构化的迭代边界信息，使生成的代码有机会获得更好的优化。要让这种优化生效，循环变量必须通过遍历 `ct::irange` 的 range-for 表达式绑定。

> In Python, the built-in `range()`, for, while, and nested loops are all supported in tile code.

在 Python 中，tile 代码支持内建的 `range()`、`for`、`while` 和嵌套循环。

> The `step` argument must be strictly positive; negative-step ranges are not supported.

`step` 参数必须严格大于 0，不支持负步长 range。

> The following single-block kernels sum all tiles of a 1D array:

下面这些只使用一个 block 的 kernel，将一维 array 中的所有 tile 累加起来：

```cpp
__tile_global__ void tile_sum(float* __restrict__ arr, float* __restrict__ out, int num_tiles) {
    namespace ct = cuda::tiles;
    using namespace ct::literals;
    using f32x8 = ct::tile<float, ct::shape<8>>;

    arr = ct::assume_aligned(arr, 16_ic);
    out = ct::assume_aligned(out, 16_ic);

    auto inView  = ct::partition_view{ct::tensor_span{arr, ct::extents{8 * num_tiles}},
                                      ct::shape{8_ic}};
    auto outView = ct::partition_view{ct::tensor_span{out, ct::extents{8_ic}},
                                      ct::shape{8_ic}};

    auto acc = ct::full<f32x8>(0.0f);
    // range-for over ct::irange gives the compiler structured iteration bounds.
    for (auto k : ct::irange(0, num_tiles)) {
        auto tile = inView.load(k);
        acc = acc + tile;                               // accumulate the k-th tile into acc
    }
    outView.store(acc, 0);                              // write the final result as the 0-th tile of out
}
```

**解读（示例结果）：** 这里的 `acc` 始终是 8 元素 tile。最终 `out[j] = Σ arr[8k + j]`，求和范围是所有 k，而不是将整个输入归约成一个标量。若要得到全数组总和，还需要对 `acc` 做一次 tile reduction。代码没有使用 block 索引划分工作，因此应按原文以单个 block 启动，否则多个 block 会重复计算并写入同一输出。

#### 2.4.7.2. Conditionals（条件分支）

> Standard `if/else` conditionals work normally. Because each block follows a single control flow path, the considerations for branch divergence within a warp do not apply to tile kernels.

标准 `if/else` 条件分支可以正常使用。由于每个 block 沿单一控制流路径执行，SIMT 中 warp 内 branch divergence 的考量不适用于 tile kernel。

```cpp
__tile_global__ void conditional_load(float* __restrict__ arr, float* __restrict__ out, int N) {
    namespace ct = cuda::tiles;
    using namespace ct::literals;
    using f32x8 = ct::tile<float, ct::shape<8>>;

    arr = ct::assume_aligned(arr, 16_ic);
    out = ct::assume_aligned(out, 16_ic);

    auto inView  = ct::partition_view{ct::tensor_span{arr, ct::extents{N}}, ct::shape{8_ic}};
    auto outView = ct::partition_view{ct::tensor_span{out, ct::extents{N}}, ct::shape{8_ic}};

    int bx   = ct::bid().x;
    int nb_x = ct::num_blocks().x;

    auto tile = ct::full<f32x8>(0.0f);    // default for the last-block branch
    // Scalar condition -> one control-flow path per block; no divergence to reason about.
    if (bx < nb_x - 1) {
        tile = inView.load(bx);           // all blocks except the last
    }
    outView.store_masked(tile, bx);       // masked to handle a potentially partial final tile
}
```

**解读（示例语义）：** 该分支故意不加载最后一个 tile，而是将其有效输出位置写成零；即使 N 能被 8 整除，最后一块也会被置零。它展示的是 block 级条件控制流，不是通用复制 kernel，也不是“只把越界元素补零”的实现。Grid 数量仍应与 array 的 tile 数量匹配。

### 2.4.8. Element-wise Arithmetic and Broadcasting（逐元素算术与广播）

> Tiles support standard element-wise arithmetic. When two operands have compatible but different shapes, the smaller is broadcast to match before the operation is performed.

Tile 支持标准逐元素算术运算。当两个操作数形状不同但兼容时，较小的操作数会先通过广播匹配形状，再执行运算。

#### 2.4.8.1. Broadcasting（广播）

> Broadcasting follows NumPy semantics: scalars are duplicated across the tile, singleton dimensions (length 1) are stretched to match the corresponding dimension of the other operand, and a lower-rank operand is aligned to the trailing dimensions of the higher-rank operand by treating the missing leading dimensions as singletons. If two corresponding dimensions are both non-singleton and unequal, the operation is ill-formed.

广播遵循 NumPy 语义：标量扩展到 tile 的所有位置；长度为 1 的维度扩展到另一个操作数对应维度的大小；阶数较低的操作数与高阶操作数的尾部维度对齐，缺失的前导维度视为长度 1。如果两个对应维度都不为 1，且大小不相等，则该运算不合法。

> The example below exercises both singleton stretching and rank promotion in a single addition: a rank-2 tile of shape 8x2 is rank-promoted to 1x8x2, then broadcast with a rank-3 tile of shape 4x1x2 to the common shape 4x8x2.

下面的例子在一次加法中同时展示长度为 1 的维度扩展和阶数提升：形状为 8 × 2 的二阶 tile，先提升为 1 × 8 × 2，再与形状为 4 × 1 × 2 的三阶 tile 广播，得到共同形状 4 × 8 × 2。

```cpp
auto x = ct::iota<ct::tile<int, ct::shape<8, 2>>>();      // 8x2   (rank 2)
auto y = ct::iota<ct::tile<int, ct::shape<4, 1, 2>>>();   // 4x1x2 (rank 3)
auto z = x + y;                                           // x promoted to 1x8x2, then broadcasts to 4x8x2
```

**解读：** 广播从尾部维度逐一对齐：`(8, 2)` 先视为 `(1, 8, 2)`，再与 `(4, 1, 2)` 比较，得到 `(4, 8, 2)`。这里两个输入分别在不同轴扩展，不能只按元素总数判断哪个是“较小操作数”。广播描述运算规则，不要求先在 global memory 中物化重复数据。

#### 2.4.8.2. Arithmetic Operators（算术运算符）

> All supported arithmetic operators apply element-wise to tiles and produce a new tile of the broadcast shape. A scalar combined with a tile is broadcast across every element. When operand types differ, the type that preserves more information is favored:

所有受支持的算术运算符都逐元素作用于 tile，并生成广播后形状的新 tile。标量与 tile 运算时，标量广播到全部元素。操作数类型不同时，优先采用能够保留更多信息的类型：

- > Tile combined with tile: the result is a tile of the type with the greater precision or range. For example:

  Tile 与 tile 运算：结果 tile 采用精度或取值范围更大的类型。例如：

  - > `int + float` yields `float`

    `int + float` 得到 `float`。

  - > `int16 + int32` yields `int32`

    `int16 + int32` 得到 `int32`。

- > Scalar combined with tile: when the scalar’s type is exactly representable in the tile’s element type (e.g., the integer literal 2 combined with an `int` tile, or `2.0f` combined with a `float` tile), the operation proceeds in the tile’s element type. When the scalar would have to narrow to fit the tile’s element type (e.g., the literal `2.5` combined with an `int` tile), the two languages differ:

  标量与 tile 运算：当标量类型能被 tile 的元素类型精确表示时，例如整数字面量 `2` 与 `int` tile 运算，或 `2.0f` 与 `float` tile 运算，就使用 tile 的元素类型执行。若标量必须经过窄化才能放入 tile 的元素类型，例如字面量 `2.5` 与 `int` tile 运算，则两种语言行为不同：

  - > Python promotes the result to a type that can hold both

    Python 将结果提升为能够容纳两者的类型。

  - > C++ rejects the expression as ill-formed

    C++ 将该表达式判定为不合法并拒绝编译。

> The snippets below illustrate the divergent scalar-tile case:

下面的片段展示了标量与 tile 运算时的这一差别：

```cpp
using i32x8 = ct::tile<int, ct::shape<8>>;
i32x8 x = ct::full<i32x8>(3);

x + 2;       // OK - int literal matches int tile element type
x + 2.5;     // ill-formed - 2.5 would narrow to int
```

> In practice, write scalar literals in the tile’s element type when you can and convert explicitly when you want a different precision. The same rules apply inside a kernel when the operands are loaded tiles:

实际编写代码时，尽量使用与 tile 元素类型一致的标量字面量；需要不同精度时，显式转换。当操作数是 kernel 中加载的 tile 时，同样遵循这些规则：

**解读：** 类型提升不保证所有数值都能无损表示。例如，将较大的整数转为单精度浮点数仍可能损失低位。代码移植时，应同时核对输出 dtype 和精度需求，不能只把 C++ 与 Python 的运算符拼写对应起来。

```cpp
__tile_global__ void elementwise(float* __restrict__ a, float* __restrict__ b, float* __restrict__ out, int N) {
    namespace ct = cuda::tiles;
    using namespace ct::literals;

    a   = ct::assume_aligned(a,   16_ic);
    b   = ct::assume_aligned(b,   16_ic);
    out = ct::assume_aligned(out, 16_ic);

    auto aView = ct::partition_view{ct::tensor_span{a,   ct::extents{N}}, ct::shape{8_ic}};
    auto bView = ct::partition_view{ct::tensor_span{b,   ct::extents{N}}, ct::shape{8_ic}};
    auto cView = ct::partition_view{ct::tensor_span{out, ct::extents{N}}, ct::shape{8_ic}};

    int  bx = ct::bid().x;
    auto x  = aView.load(bx);
    auto y  = bView.load(bx);
    // 2.0f matches the float tiles' element type, so no narrowing conversion is required.
    // The scalar is broadcast across every element; + then runs elementwise.
    auto z  = 2.0f * x + y;
    cView.store(z, bx);
}
```

**解读：** 此处 C++ 的 `load` 和 `store` 未带 mask。若按向上取整启动、N 又不是 8 的整数倍，最后一个 block 的访问就不满足该示例的前提；需要采用前文的 masked 版本处理。这个条件与程序是否使用逐元素加法无关。

> When you need explicit control over rounding mode or subnormal handling, mathematical functions that expose those choices explicitly are provided by the CUDA Tile APIs, both for element-wise arithmetic (for example, `ct.add`, `ct::add`) and for transcendentals (for example, `exp` and `tanh`).

当需要显式控制舍入模式或 subnormal（次正规数）处理时，CUDA Tile API 提供能够指定这些选项的数学函数，既包括逐元素算术，例如 `ct.add`、`ct::add`，也包括 `exp`、`tanh` 等超越函数。

### 2.4.9. Tile Primitives（Tile 基础操作）

> Factory functions (Creating Tiles), loads and stores (Tile-Space Loads and Stores), and element-wise arithmetic (Element-wise Arithmetic and Broadcasting) are all tile primitives, that is, operations that are part of the language. The programmer writes them at tile granularity and the compiler maps them to hardware, including tensor cores where available. This section covers other primitives that are available in CUDA tile.

工厂函数（“Creating Tiles”）、加载和存储（“Tile-Space Loads and Stores”）以及逐元素算术（“Element-wise Arithmetic and Broadcasting”）都是 tile primitive，即语言提供的基础操作。程序员按 tile 粒度表达这些操作，编译器将其映射到硬件，包括适用时的 Tensor Core。本节介绍 CUDA Tile 中其他可用的基础操作。

#### 2.4.9.1. Matrix Multiply（矩阵乘法）

> Matrix multiplication of two tiles is a fundamental operation to implementing a matrix multiplication between two arrays. CUDA Tile provides two forms of matrix multiplication between tiles: a pure matrix multiply (`matmul`), `a @ b`, and a matrix multiply-accumulate (`mma`), `a @ b + acc`. In `mma`, the accumulator carries partial products from one K-tile to the next. This is helpful in the inner loop of a tiled matrix multiplication. Both `matmul` and `mma` support 2D matrix multiplication and 3D batched multiplies as well as mixing the data type (precision) of operands and accumulator. The rank and element type constraints are documented in the API reference for the operations (CUDA Tile C++ matrix multiplication, cuTile Python `matmul`).

两个 tile 的矩阵乘法，是实现两个 array 矩阵乘法的基本操作。CUDA Tile 提供两种形式：纯矩阵乘法 `matmul`，即 `a @ b`；矩阵乘加 `mma`，即 `a @ b + acc`。在 `mma` 中，accumulator 保存从一个 K-tile 到下一个 K-tile 的部分乘积累加结果，适用于分块矩阵乘法的内层循环。`matmul` 和 `mma` 都支持二维矩阵乘法、三维批量矩阵乘法，以及操作数与 accumulator 使用不同数据类型或精度。阶数和元素类型限制参见相应 API 文档，即 CUDA Tile C++ matrix multiplication 和 cuTile Python matmul。

> A common pattern, used in the kernels below, is to accumulate in FP32 regardless of input precision and cast to the output element type on store. In Python this is `ct.mma(a, b, acc)` with an FP32-typed `acc`. In C++ it is `ct::mma(a, b, acc)` with an explicit FP32 accumulator type. The K-loop iterates `ceil(K / tk)` times so the right edge of A and the bottom edge of B are covered; partial K-tiles are zero-padded on load (`PaddingMode.ZERO` in Python, `.load_masked()` in C++), and partial M/N edge tiles on the C side are handled by store-side OOB-discard (`ct.store` in Python, `.store_masked()` in C++).

下面的 kernel 采用一种常见模式：无论输入精度如何，都使用 FP32 累加，并在存储时转换为输出元素类型。Python 使用具有 FP32 类型 `acc` 的 `ct.mma(a, b, acc)`；C++ 使用显式 FP32 accumulator 类型的 `ct::mma(a, b, acc)`。K 循环执行 `ceil(K / tk)` 次，以覆盖 A 的右侧和 B 的下侧边缘；部分有效的 K-tile 在加载时补零，Python 使用 `PaddingMode.ZERO`，C++ 使用 `.load_masked()`。C 在 M/N 方向的部分边缘 tile，则通过存储时丢弃越界写入处理：Python 使用 `ct.store`，C++ 使用 `.store_masked()`。

```cpp
__tile_global__ void gemm(const __half* __restrict__ A, const __half* __restrict__ B, float* __restrict__ C,
                          std::size_t M, std::size_t K, std::size_t N) {
    namespace ct = cuda::tiles;
    using namespace ct::literals;
    using f32_acc = ct::tile<float, ct::shape<32, 32>>;

    A = ct::assume_aligned(A, 16_ic);
    B = ct::assume_aligned(B, 16_ic);
    C = ct::assume_aligned(C, 16_ic);

    constexpr auto tm = 32_ic;
    constexpr auto tn = 32_ic;
    constexpr auto tk = 16_ic;

    auto aView = ct::partition_view{ct::tensor_span{A, ct::extents{M, K}}, ct::shape{tm, tk}};
    auto bView = ct::partition_view{ct::tensor_span{B, ct::extents{K, N}}, ct::shape{tk, tn}};
    auto cView = ct::partition_view{ct::tensor_span{C, ct::extents{M, N}}, ct::shape{tm, tn}};

    auto [bx, by, bz] = ct::bid();
    auto acc = ct::full<f32_acc>(0.0f);                 // FP32 accumulator

    std::size_t num_k = (K + tk - 1) / tk;
    for (auto k : ct::irange(std::size_t{0}, num_k)) {
        acc = ct::mma(aView.load_masked(bx, k),         // zero-pad partial K-tile
                      bView.load_masked(k, by),
                      acc);                             // acc += a @ b
    }
    cView.store_masked(acc, bx, by);                    // drop OOB edge lanes
}
```

**解读：** 该 GEMM 的每个 block 负责 C 中一个 32 × 32 区域，x 方向覆盖 M，y 方向覆盖 N，因此相应 grid 是 `(ceil(M / 32), ceil(N / 32), 1)`。循环沿 K 每次处理 16 个元素，加载的 A tile 为 32 × 16，B tile 为 16 × 32，乘加到 32 × 32 的 FP32 accumulator。尾部 K-tile 必须补零，否则无效值也会进入有效输出；M/N 边缘则通过 masked store 丢弃无效输出。

#### 2.4.9.2. Reductions and Scans（归约与扫描）

> Reductions are a tool for collapsing a tile into a scalar or a row of scalars. Computing the denominator of a softmax, the mean and variance of a layer norm, or the max in attention scoring all involve reduction operations.

Reduction（归约）将 tile 压缩成标量或一行标量。计算 softmax 的分母、layer norm 的均值和方差，或者 attention scoring 中的最大值，都需要归约操作。

> The one point worth internalizing up front is the shape of the result. Python drops the reduced axis by default (pass `keepdims=True` to keep it as length 1); C++ always keeps it, preserving the rank of the tile. The two snippets below both reduce a 2x4 tile along axis 1; the output shape is the visible difference.

首先需要理解结果形状。Python 默认删除被归约的轴，可传入 `keepdims=True` 将其保留为长度 1；C++ 始终保留该轴，因此 tile 的阶数不变。下面两个片段都沿 axis 1 对一个 2 × 4 的 tile 归约，明显差异在于输出形状。

```cpp
using namespace ct::literals;
using i32x2x4 = ct::tile<int, ct::shape<2, 4>>;

auto x = ct::iota<i32x2x4>();                         // [[0,1,2,3],[4,5,6,7]]
auto row_sums = ct::sum(x, 1_ic);                     // shape (2, 1) - axis kept
// row_sums == [[6], [22]]
```

> Scans are the running counterpart, producing a cumulative result along an axis. For example, prefix-sum (`cumsum`) produces an output equal in dimension to the input, where the value at a given index is the sum of all the elements up to and including that index along a specified axis. See the API reference for the full set available in each language (CUDA Tile C++ reductions and scans, cuTile Python reductions and scans).

Scan（扫描）是对应的累计操作，沿某个轴生成逐步累积的结果。例如，prefix-sum（前缀和，`cumsum`）生成与输入维度相同的输出，其中指定轴上某个索引的值，等于该轴上截至该位置、包含该位置在内的所有元素之和。各语言支持的完整操作参见 CUDA Tile C++ reductions and scans，以及 cuTile Python reductions and scans。

**解读：** Reduction 压缩一个轴，scan 保留该轴并输出每个位置的累计值。对 `[0, 1, 2, 3]`，求和归约得到 6，inclusive prefix-sum 得到 `[0, 1, 3, 6]`。C++ 保留归约轴、Python 默认删除归约轴，可能改变后续广播是否对齐，因此要把输出 shape 当作接口的一部分检查。

#### 2.4.9.3. Transpose and Permutation（转置与轴置换）

> Two related primitives reorder the axes of a tile without touching its data: `transpose` swaps the first two axes, and `permute` does an arbitrary reordering. They show up wherever a tile’s logical layout has to change between operation such as materializing the `transpose` of a `matmul` operand, swapping rows and columns in an attention block, or lining up axes before a broadcast.

两个相关的基础操作可以重新排列 tile 的轴，而不改变其数据内容：`transpose` 交换前两个轴，`permute` 执行任意轴重排。它们用于需要在不同操作之间改变 tile 逻辑布局的场景，例如生成 matmul 操作数的转置、交换 attention block 的行列，或在广播前对齐各个轴。

> In Python, `ct.transpose(x)` on a rank-2 tile swaps its two axes; on higher-rank tiles it takes explicit `axis0` / `axis1` arguments. `ct.permute(x, axes)` takes a tuple of axis indices. In C++, `ct::transpose(x)` interchanges the first two dimensions (trailing dimensions are preserved), and `ct::permute(x, map)` takes a `ct::dimension_map` describing the new order.

在 Python 中，`ct.transpose(x)` 对二阶 tile 交换两个轴；对更高阶 tile，需要显式指定 `axis0` / `axis1`。`ct.permute(x, axes)` 接收轴索引元组。在 C++ 中，`ct::transpose(x)` 交换前两个维度，其余尾部维度保持不变；`ct::permute(x, map)` 接收描述新顺序的 `ct::dimension_map`。

```cpp
using namespace ct::literals;
using t2d = ct::tile<int, ct::shape<2, 4>>;
using t3d = ct::tile<int, ct::shape<2, 2, 2>>;

auto tx = ct::iota<t2d>();
auto ty = ct::transpose(tx);                                     // shape (4, 2)

auto tz = ct::iota<t3d>();
auto tw = ct::permute(tz, ct::dimension_map{2_ic, 0_ic, 1_ic});  // axes (0,1,2) -> (2,0,1)
```

**解读：** Tile 转置或轴置换改变逻辑元素位置，不会自动把原始 global memory array 原地转置。要形成全局数组结果，仍需正确安排加载和存储。原文“不触碰数据”可以理解为不改变元素的数值内容，不应解释为在所有硬件映射下都没有数据重排成本。

#### 2.4.9.4. Element-wise Selection（逐元素选择）

> Element-wise selection is the tile form of a conditional: given a boolean tile and two operand tiles, each output element is picked from one or the other based on the corresponding boolean. The condition is broadcast to the operand shape; the operand types have to be compatible (see the API reference for the exact rules in each language: CUDA Tile C++ select, cuTile Python selection). Python spells it `ct.where(cond, x, y)`; C++ spells it `ct::select(cond, lhs, rhs)`.

逐元素选择是条件表达式的 tile 形式：给定一个布尔 tile 和两个操作数 tile，每个输出元素根据对应布尔值从其中一个操作数选取。条件会广播到操作数形状，操作数类型必须兼容，具体规则参见 CUDA Tile C++ select 和 cuTile Python selection。Python 写作 `ct.where(cond, x, y)`，C++ 写作 `ct::select(cond, lhs, rhs)`。

```cpp
using namespace ct::literals;
auto cond = ct::iota<ct::tile<int, ct::shape<4>>>() < 2;   // {T, T, F, F}
auto t    = ct::full<ct::tile<float, ct::shape<4>>>( 1.0f);
auto f    = ct::full<ct::tile<float, ct::shape<4>>>(-1.0f);
auto r    = ct::select(cond, t, f);                        // {1, 1, -1, -1}
```

**解读：** 标量 `if` 决定整个 block 走哪条控制流，`select` / `where` 则按布尔 tile 为各个元素选择结果。不能用“最后选择了安全值”替代前面加载时的 mask；如果候选值已经通过非法地址加载，后续选择不能消除那次非法访问。

Tile 代码通过 `ct` 命名空间中的函数，提供常见的逐元素数学操作：

各函数对输入 tile 逐元素执行相应操作，返回形状相同的 tile。这些操作也可作用于 tile 代码中的标量。

### 2.4.10. Atomic Memory Operations（内存原子操作）

> There are two situations where use of memory atomics is needed in tile code:

Tile 代码中有两种需要使用内存原子操作的情况：

- > In cross-block contention, each block produces a partial result and uses an atomic operation to merge it with the partial results of other blocks in a global memory location.

  Block 间竞争：每个 block 生成部分结果，并使用原子操作，在 global memory 的同一位置将它与其他 block 的部分结果合并。

- > In intra-block contention, multiple elements of a tile are written to the same location in memory.

  Block 内竞争：一个 tile 的多个元素写入同一个内存位置。

> An atomic on a tile performs one atomic update per element of the tile. The per-element operation is atomic, but the whole call is not. The order of the per-element atomic operations is unspecified.

对 tile 执行原子操作时，每个元素分别进行一次原子更新。单个元素的操作具有原子性，但整个调用并不是一个原子操作。各元素原子操作的执行顺序未指定。

**解读：** Tile 原子操作是许多个元素级原子操作的集合，不是一次覆盖整个 tile 的事务。其他执行者可能在不同时间观察到不同元素的更新，不能依靠这类调用实现整个 tile 的一致快照。

> In Python, atomics address the target by indices into the array, using the same convention as `ct.gather` and `ct.scatter`. Optional parameters control bounds checking, memory order, and thread scope. The defaults (bounds checking on, `ACQ_REL`, device scope) let the ordinary call pass only the array, the indices, and the update. A `TiledView` also exposes the reduction-style atomics as instance methods, named with an `atomic_store_` prefix (for example, `TiledView.atomic_store_add(index, update)`); these address the target by a tile-space index, do not return a value, and lower to an atomic reduction in PTX. When the prior value is not needed, the `TiledView` form is preferred for better performance.

Python 原子操作通过 array 索引定位目标，约定与 `ct.gather`、`ct.scatter` 相同。可选参数控制边界检查、memory order 和 thread scope。默认启用边界检查，使用 `ACQ_REL` 和 device scope，因此普通调用只需传入 array、索引和更新值。`TiledView` 还通过以 `atomic_store_` 开头的实例方法提供归约式原子操作，例如 `TiledView.atomic_store_add(index, update)`；这些方法通过 tile-space 索引寻址，不返回值，并会转换为 PTX 原子归约。无须旧值时，应优先使用 `TiledView` 形式以获得更好的性能。

> In C++, atomics take a pointer and a corresponding value: a raw pointer and scalar for a single location, or a tile of pointers and tile of values. The memory order is a compile-time type tag at the call site such as `ct::memory_order_relaxed_t{}`. The thread scope is a type tag of the same form and defaults to system-wide visibility when omitted.

C++ 原子操作接收指针和对应值：单个位置使用原始指针与标量，多个位置使用指针 tile 与数值 tile。Memory order 通过调用位置的编译期类型标签指定，例如 `ct::memory_order_relaxed_t{}`。Thread scope 也使用同样形式的类型标签，省略时默认为 system 范围的可见性。

> `ct::partition_view` and `ct::strided_view` additionally expose the reduction atomics (`atomic_add`, `atomic_sub`, `atomic_and`, `atomic_or`, `atomic_xor`, `atomic_max`, and `atomic_min`) as member functions. These address the target by a tile-space index rather than by pointer, and take the value tile first and the index last, as `.store()` does. Unlike the free functions, which return the value(s) previously in memory, they return nothing. As in Python, prefer them when the prior value is not needed: the member form lowers to a hardware reduction, whereas a tile of pointers lowers to one atomic operation per element. `ct::gather_scatter_view` does not provide them.

`ct::partition_view` 和 `ct::strided_view` 还将归约原子操作作为成员函数提供，包括 `atomic_add`、`atomic_sub`、`atomic_and`、`atomic_or`、`atomic_xor`、`atomic_max` 和 `atomic_min`。这些函数通过 tile-space 索引而非指针定位目标，参数顺序与 `.store()` 相同：值 tile 在前，索引在后。自由函数返回内存中的旧值，而这些成员函数不返回值。与 Python 一样，无须旧值时应优先使用成员函数形式，因为它会转换为硬件归约；指针 tile 形式则转换为逐元素原子操作。`ct::gather_scatter_view` 不提供这些成员函数。

#### 2.4.10.1. Cross-block Contention（Block 间的访问竞争）

> In the code example below, cross-block contention occurs because different blocks are writing to the same memory location, out. Without atomic operations, blocks running in parallel would lead to an incorrect answer. In this example, device thread scope is used (`ct::thread_scope_device_t{}` in C++, thread scope defaults to device-wide scope in Python) because the result of the memory operation must be visible to all blocks running on the device. The Python kernel uses `TiledView.atomic_store_add` because each block’s partial sum is accumulated into `out[0]` and immediately discarded.

下面的代码中，不同 block 写入同一内存位置 `out`，因此存在 block 间竞争。不使用原子操作时，并行运行的 block 会导致错误结果。这里采用 device thread scope，C++ 显式写为 `ct::thread_scope_device_t{}`，Python 则默认采用 device scope，因为内存操作的结果必须对 device 上所有运行中的 block 可见。Python kernel 使用 `TiledView.atomic_store_add`，因为各 block 的部分和只需累加到 `out[0]`，随后便不再需要该部分结果。

```cpp
__tile_global__ void block_sum(int* __restrict__ arr, int* __restrict__ out, std::size_t N) {
    namespace ct = cuda::tiles;
    using namespace ct::literals;
    constexpr auto TILE = 16_ic;

    arr = ct::assume_aligned(arr, 16_ic);
    out = ct::assume_aligned(out, 16_ic);

    auto aView = ct::partition_view{ct::tensor_span{arr, ct::extents{N}},
                                    ct::shape{TILE}};
    int bid = ct::bid().x;
    auto tile    = aView.load_masked(bid);        // partial final tile -> OOB lanes default to 0
    auto partial = ct::sum(tile, 0_ic);           // reduce to a 1-element tile

    ct::atomic_add(out, (int)partial,             // accumulate the scalar into out[0]
                   ct::memory_order_relaxed_t{},  // single-location accumulator -> relaxed suffices
                   ct::thread_scope_device_t{});  // visible across the device
}
```

**解读：** 此处先在 block 内将 tile 归约，再对 `out[0]` 执行一次原子累加，减少了竞争次数。启动前仍需把输出初始化为零，并在 host 读取最终结果前等待 kernel 完成。Device scope 规定需要覆盖的参与线程范围；`relaxed` 适用于这个单地址累加示例，但不会自动为其他数据建立发布或获取顺序。不能把“可见范围”当成全 device 同步。

#### 2.4.10.2. Intra-block Contention（Block 内的访问竞争）

> In the code fragment below, intra-block contention occurs because all values of a tile are atomically added to a single location in memory.

下面的片段中，tile 的全部元素都原子加到同一个内存位置，因此存在 block 内竞争。

> In this example, each element in the `ptrs` tile points to the same location in memory, `slot`. Each element of the tile created by `ct::iota<i32x16>()` is atomically added to the value stored in that memory location. The order in which multiple atomic operations from a tile to a single memory address are carried out is unspecified. The block thread scope `ct::thread_scope_block_t{}` is used to specify that the result of the atomic operations need only be visible within this thread block.

本例的 `ptrs` tile 中，每个元素都指向同一个内存位置 `slot`。`ct::iota<i32x16>()` 创建的 tile 中的每个元素，都分别原子加到该位置保存的值上。一个 tile 针对同一地址执行多个原子操作时，其执行顺序未指定。这里使用 block thread scope，即 `ct::thread_scope_block_t{}`，表示原子操作的结果只需要在当前 thread block 内可见。

```cpp
using i32x16 = ct::tile<int, ct::shape<16>>;

int* slot = /* pointer to the contended location */;

// 16 lanes all aim at the same address. Add is commutative, so the
// unspecified ordering doesn't affect this sum; block scope suffices
// since contention stays within one block.
auto ptrs = ct::full<ct::tile<int*, ct::shape<16>>>(slot);
ct::atomic_add(ptrs, ct::iota<i32x16>(),
            ct::memory_order_relaxed_t{},
            ct::thread_scope_block_t{});
```

> Note: This is shown for illustrative purposes only. To sum a tile into a scalar within a block, the tile reduction operation shown in Section 2.4.9.2 is the preferred method.

注意：该代码仅用于说明原理。若要在 block 内将 tile 求和为标量，首选第 2.4.9.2 节介绍的 tile reduction 操作。

**解读：** 对 0 到 15 的整数累加，示例会在 `slot` 原值上增加 120，前提是地址有效且计算不溢出。Block scope 足够的关键条件是竞争仅发生在同一 block 内；若其他 block 也更新同一位置，就必须重新选择覆盖所有参与者的 scope。同样的归约通常直接使用 `ct::sum` 更清楚，也避免把 block 内局部求和变成共享地址竞争。

#### 2.4.10.3. Supported Atomic Operations（支持的原子操作）

> Tile code supports a variety of atomic memory operations which differ in how the value being written is combined with the value that exists in memory:

Tile 代码支持多种内存原子操作，区别在于如何将待写入值与内存中已有的值组合：

- > `atomic_and` - performs element-wise atomic bitwise AND between the passed value(s) and the value(s) in memory

  `atomic_and`：对传入值与内存中的值，逐元素执行原子按位 AND。

- > `atomic_or` - performs element-wise atomic bitwise OR between the passed value(s) and the value(s) in memory

  `atomic_or`：对传入值与内存中的值，逐元素执行原子按位 OR。

- > `atomic_xor` - performs element-wise atomic bitwise XOR between the passed value(s) and the value(s) in memory

  `atomic_xor`：对传入值与内存中的值，逐元素执行原子按位 XOR。

- > `atomic_max` - performs element-wise comparison between the passed value(s) and the value(s) in memory and stores the larger value into memory

  `atomic_max`：逐元素比较传入值与内存中的值，将较大者写回内存。

- > `atomic_min` - performs element-wise comparison between the passed value(s) and the value(s) in memory and stores the smaller value into memory

  `atomic_min`：逐元素比较传入值与内存中的值，将较小者写回内存。

- > `atomic_add` - adds the passed value(s) to the value(s) in memory and stores the result into memory

  `atomic_add`：将传入值加到内存中的值上，并将结果写回内存。

- > `atomic_sub` (C++ only) - subtracts the passed value(s) from the value(s) in memory and stores the result into memory

  `atomic_sub`（仅 C++）：从内存中的值减去传入值，并将结果写回内存。

- > `atomic_xchg` - writes the passed value(s) to memory and returns the value(s) that were in memory before the write

  `atomic_xchg`：将传入值写入内存，并返回写入前内存中的值。

- > `atomic_cas` (`atomic_compare_exchange` in C++) - performs element-wise comparison between the value(s) in memory and expected value(s) passed as arguments. If they match, the value in memory is replaced with the desired value(s)

  `atomic_cas`（C++ 中称为 `atomic_compare_exchange`）：逐元素比较内存中的值与参数提供的期望值；匹配时，将内存中的值替换为指定的新值。

> For complete documentation on all supported atomic memory operations, refer to the memory operations sections of the CUDA Tile C++ API Reference or cuTile Python API Reference.

全部受支持的内存原子操作的完整说明，参见 CUDA Tile C++ API Reference 或 cuTile Python API Reference 的内存操作部分。

### 2.4.11. Optimization Hints（优化提示）

> An optimization hint is metadata attached to a source construct (a tile kernel function, a load/store call site, and so on) that guides the compiler’s code generation. Hints do not change the semantics of the program: a kernel compiles and runs identically with or without them, so they can be added, removed, or tuned freely without affecting correctness. The compiler may also ignore any hint.

Optimization hint（优化提示）是附加在源码结构上的元数据，例如附加到 tile kernel 函数、load/store 调用位置等，用于指导编译器生成代码。Hint 不改变程序语义：无论是否提供 hint，kernel 编译和运行时的语义都相同，因此可以自由添加、删除或调节 hint，而不影响正确性。编译器也可以忽略任何 hint。

**解读：** “语义不变”不等于“机器码和运行时间不变”，hint 的目的正是影响实现选择。这一节的性能提示还需与下一节的 `__restrict__`、`assume_aligned` 区分：后两者需要程序真实满足所声明的条件。

> Hints share two general properties:

Hint 具有两个共同特性：

- > Hints are per-construct. A hint applies to the specific kernel function or the specific call expression it is attached to, not to the surrounding code.

  Hint 针对特定结构生效，只作用于它所附加的 kernel 函数或具体调用表达式，不作用于周围代码。

- > Hints can be specified per architecture. Each hint may be set to a different value for different GPU architectures, or to a single value that applies to every target.

  Hint 可以按架构指定：同一个 hint 可以针对不同 GPU 架构设为不同值，也可以用一个值作用于全部目标。

> The two languages expose hints differently:

两种语言提供 hint 的方式不同：

- > C++ uses a C++ attribute that you place on the relevant declaration or statement.

  C++ 使用放在相应声明或语句上的 C++ attribute。

- > Python uses keyword arguments on the kernel decorator and on individual memory-operation call sites.

  Python 使用 kernel 装饰器，以及各个内存操作调用位置的关键字参数。

> The set of hint kinds, what each hint actually controls, is shared between the two languages and is documented in Hint Kinds.

Hint 的类型及各类型实际控制的内容，在两种语言之间是共通的，详见“Hint Kinds”。

#### 2.4.11.1. C++ – the `cutile::hint` Attribute（C++ 的 `cutile::hint` 属性）

> In C++, hints are expressed with the C++ attribute `cutile::hint`:

在 C++ 中，通过 C++ attribute `cutile::hint` 表达提示：

```cpp
[[ cutile::hint(arch, kind1=value1, kind2=value2, ...) ]]
```

> The first argument is the target architecture, encoded as an integer using the same convention as the `__CUDA_ARCH__` macro (for example, 900 for `sm_90` and 1000 for `sm_100`). The special value 0 denotes an architecture-agnostic hint that applies to every target architecture. Each remaining argument is a `kind=value` pair that specifies a hint kind and its value.

第一个参数指定目标架构，编码为整数，采用与 `__CUDA_ARCH__` 宏相同的约定，例如 900 对应 `sm_90`，1000 对应 `sm_100`。特殊值 0 表示与架构无关、适用于所有目标的提示。其余参数均为 `kind=value` 对，指定提示类型及其值。

> A `cutile::hint` attribute applies to the construct it precedes:

`cutile::hint` attribute 作用于紧随其后的结构：

- > For tile kernel functions, place the attribute on the function declaration.

  对于 tile kernel 函数，将 attribute 放在函数声明上。

- > For memory operations such as `ct::load`, `ct::store`, and `ct::partition_view` loads/stores, place it on the expression-statement containing the call.

  对于 `ct::load`、`ct::store` 以及 `ct::partition_view` 加载和存储等内存操作，将 attribute 放在包含相应调用的表达式语句上。

> Other placements have limitations; see the CUDA Tile C++ hint specification for the full set of rules.

其他放置位置有相应限制，完整规则参见 CUDA Tile C++ hint specification。

> The kernel below illustrates both placements: a kernel-level hint that sets a different `num_cta_in_cga` for `sm_90` and `sm_100`, and an expression-statement hint that marks a particular load as bandwidth-heavy.

下面的 kernel 展示两种放置方式：kernel 级 hint 分别为 `sm_90` 和 `sm_100` 设置不同的 `num_cta_in_cga`；表达式语句上的 hint 则将一次具体加载标记为高带宽流量操作。

```cpp
[[ cutile::hint(900,  num_cta_in_cga=4),    // sm_90:  prefer 4 CTAs per cluster
   cutile::hint(1000, num_cta_in_cga=8) ]]  // sm_100: prefer 8 CTAs per cluster
__tile_global__ void optimization_hints(float* __restrict__ in,
                                        float* __restrict__ out) {
    namespace ct = cuda::tiles;
    using namespace ct::literals;

    in  = ct::assume_aligned(in,  16_ic);
    out = ct::assume_aligned(out, 16_ic);

    auto inSpan  = ct::tensor_span{in,  ct::extents{128_ic}};
    auto outSpan = ct::tensor_span{out, ct::extents{128_ic}};
    auto inView  = ct::partition_view{inSpan,  ct::shape{8_ic}};
    auto outView = ct::partition_view{outSpan, ct::shape{8_ic}};

    int bx = ct::bid().x;

    // Expression-statement hint: tag this particular load as bandwidth-heavy.
    ct::tile<float, ct::shape<8>> tile;
    [[ cutile::hint(0, latency=8) ]]
    tile = inView.load(bx);

    outView.store(tile, bx);
}
```

> When several hints of the same kind apply to the same construct, an architecture-specific hint overrides an architecture-agnostic one.

当同一结构适用多个同类型 hint 时，针对特定架构的 hint 会覆盖与架构无关的 hint。

#### 2.4.11.2. Python – Decorator Arguments and Call-Site Keywords（Python 的装饰器参数与调用位置关键字）

> Python exposes hints in two ways:

Python 通过两种方式提供 hint：

- > Kernel-level hints are keyword arguments to the `@ct.kernel(...)` decorator. A compiled kernel object also has a `.replace_hints(**hints)` method that returns a new kernel with overridden hints; the new kernel has its own JIT cache, which makes `replace_hints` the natural building block for autotuning loops.

  Kernel 级 hint 是 `@ct.kernel(...)` 装饰器的关键字参数。编译后的 kernel 对象还提供 `.replace_hints(**hints)` 方法，返回一个覆盖了指定 hint 的新 kernel。新 kernel 拥有独立的 JIT cache，因此 `replace_hints` 很适合作为 autotuning 循环的基础。

- > Per-call hints are keyword arguments on memory-operation call sites: `ct.load` / `ct.store`, `TiledView.load` / `TiledView.store`, and `ct.gather` / `ct.scatter`.

  单次调用的 hint，是内存操作调用位置的关键字参数，包括 `ct.load` / `ct.store`、`TiledView.load` / `TiledView.store` 和 `ct.gather` / `ct.scatter`。

> For per-architecture values, wrap the value in `cuda.tile.ByTarget(*, default=..., sm_XXX=..., sm_YYY=...)`. Architecture keys must be strings of the form `"sm_<major><minor>"` (for example, `"sm_100"` or `"sm_120"`). A plain (non-ByTarget) value applies to every target – it is the Python equivalent of the C++ architecture-agnostic hint with `arch=0`.

要按架构设置不同值，可以用 `cuda.tile.ByTarget(*, default=..., sm_XXX=..., sm_YYY=...)` 包装。架构键必须采用 `"sm_<major><minor>"` 形式，例如 `"sm_100"` 或 `"sm_120"`。普通值，即未使用 `ByTarget` 的值，适用于所有目标，对应 C++ 中 `arch=0` 的架构无关 hint。

> The kernel below is the direct Python counterpart of the C++ example above: `ByTarget` carries the kernel-level hint, the `latency=8` keyword carries the per-call hint, and `replace_hints` produces a re-tuned kernel without editing the source.

下面的 kernel 是前面 C++ 示例的直接 Python 对应版本：`ByTarget` 携带 kernel 级 hint，`latency=8` 关键字携带调用位置 hint，而 `replace_hints` 无须修改源码就能生成重新调节过的 kernel。

```python
@ct.kernel(num_ctas=ByTarget(sm_90=4, sm_100=8))
def optimization_hints(in_, out, TILE: ct.Constant[int]):
    bid = ct.bid(0)

    # Per-call hint: this particular load is bandwidth-heavy.
    tile = ct.load(in_, index=(bid,), shape=(TILE,), latency=8)

    ct.store(out, index=(bid,), tile=tile)


# Autotuning: produce a new kernel with overridden hints without editing the
# source. The new kernel has its own JIT cache.
tuned_kernel = optimization_hints.replace_hints(num_ctas=8)
```

**解读（代码依赖）：** 该片段直接使用 `ByTarget`，但未展示导入。运行时需要先写 `from cuda.tile import ByTarget`，或把调用写成 `ct.ByTarget(...)`。`replace_hints` 返回新 kernel；要使用调整后的版本，需要在后续启动中传入 `tuned_kernel`，仅创建对象不会改变已经启动的 kernel。参见 [cuTile 按架构配置与性能调节](https://docs.nvidia.com/cuda/cutile-python/performance.html)。

#### 2.4.11.3. Hint Kinds（提示类型）

> The following hints are shared between the two languages. Within each hint, the C++ name and Python name entries are different spellings of the same underlying hint; everything else is the same: where the hint applies, its values, its meaning.

下面这些 hint 由两种语言共同支持。每种 hint 中，C++ name 和 Python name 是同一底层提示的不同写法；其他方面，包括适用位置、允许值和含义，均相同。

##### 2.4.11.3.1. CTAs per cluster（每个 cluster 的 CTA 数量）

- > C++ name: `num_cta_in_cga` (kernel attribute).

  C++ 名称：`num_cta_in_cga`，作为 kernel attribute 使用。

- > Python name: `num_ctas` (`@ct.kernel` decorator argument).

  Python 名称：`num_ctas`，作为 `@ct.kernel` 装饰器参数使用。

- > Allowed values: 1, 2, 4, 8, 16. On `sm_80`, only 1 is applicable.

  允许值：1、2、4、8、16。在 `sm_80` 上，只能使用 1。

- > Meaning: the number of cooperative thread arrays (CTAs) that the compiler should prefer per cooperative group array (CGA) when launching the kernel.

  含义：启动 kernel 时，编译器应优先为每个 cooperative group array（CGA）采用多少个 cooperative thread array（CTA）。

##### 2.4.11.3.2. Occupancy（占用率提示）

- > C++ name: `occupancy` (kernel attribute).

  C++ 名称：`occupancy`，作为 kernel attribute 使用。

- > Python name: `occupancy` (`@ct.kernel` decorator argument).

  Python 名称：`occupancy`，作为 `@ct.kernel` 装饰器参数使用。

- > Allowed values: any integer in the inclusive range `[1, 32]`.

  允许值：闭区间 `[1, 32]` 内的任意整数。

- > Meaning: the target number of active CTAs per streaming multiprocessor (SM). The compiler treats the value as a recommendation and will try to honor it during code generation.

  含义：每个 streaming multiprocessor（SM）的目标活跃 CTA 数量。编译器将其视为建议，并在代码生成期间尽量遵循。

##### 2.4.11.3.3. Memory access `latency`（内存访问延迟提示）

- > C++ name: `latency` (attribute on the expression-statement containing the call).

  C++ 名称：`latency`，作为包含该调用的表达式语句上的 attribute 使用。

- > Python name: `latency` (keyword argument on the call site).

  Python 名称：`latency`，作为调用位置的关键字参数使用。

- > Applies to: tile-space loads and stores (`ct::partition_view` in C++; `Array.tiled_view` and `ct.load` / `ct.store` in Python) as well as gather/scatter (`ct::load` / `ct::store` with pointer tiles in C++; `ct.gather` / `ct.scatter` in Python).

  适用于：tile-space 加载和存储，即 C++ 的 `ct::partition_view`、Python 的 `Array.tiled_view` 和 `ct.load` / `ct.store`；也适用于 gather/scatter，即 C++ 接收指针 tile 的 `ct::load` / `ct::store`，以及 Python 的 `ct.gather` / `ct.scatter`。

- > Allowed values: any integer in the inclusive range `[1, 10]`, where 1 indicates light DRAM traffic and 10 indicates heavy traffic. Larger values typically cause the compiler to schedule a larger prefetch depth.

  允许值：闭区间 `[1, 10]` 内的任意整数，其中 1 表示较轻的 DRAM 流量，10 表示较重的流量。较大的值通常使编译器安排更大的预取深度。

##### 2.4.11.3.4. Allow TMA（允许使用 TMA）

- > C++ name: `allow_tma` (attribute on the expression-statement containing the call).

  C++ 名称：`allow_tma`，作为包含该调用的表达式语句上的 attribute 使用。

- > Python name: `allow_tma` (keyword argument on the call site).

  Python 名称：`allow_tma`，作为调用位置的关键字参数使用。

- > Applies to: tile-space loads and stores only (`ct::partition_view` in C++; `Array.tiled_view` and `ct.load` / `ct.store` in Python). Gather and scatter operations do not accept this hint.

  仅适用于 tile-space 加载和存储，即 C++ 的 `ct::partition_view`、Python 的 `Array.tiled_view` 和 `ct.load` / `ct.store`。Gather 和 scatter 操作不接受这一 hint。

- > Allowed values: `true` / `false` (C++) or `True` / `False` (Python). TMA is allowed by default; setting the hint to `false`/`False` instructs the compiler not to lower this particular load or store to TMA on hardware that supports it.

  允许值：C++ 中为 `true` / `false`，Python 中为 `True` / `False`。默认允许 TMA；设为 `false` / `False` 时，要求编译器即使在支持 TMA 的硬件上，也不要将这一次加载或存储转换为 TMA 操作。

**解读：** 这里几个数值的单位各不相同，不能套用上一节 SIMT 的百分比 occupancy 定义，也不能把 `latency=8` 理解成 8 个周期。根据本节原文，可归纳如下：

| 提示 | 控制的内容 | 容易混淆的地方 |
| --- | --- | --- |
| `num_cta_in_cga` / `num_ctas` | 每个 cluster 倾向采用的 CTA 数量 | 不是 grid 的 block 总数，也不是每个 block 的线程数 |
| `occupancy` | 每个 SM 的目标活跃 CTA 数量 | 不是活跃 warp 比例或百分比，也不保证实际达到该数量 |
| `latency` | 1–10 的 DRAM 流量提示，影响预取安排 | 不是实测延迟，更大不保证更快 |
| `allow_tma` | 是否允许该次 tile-space 访存使用 TMA | 允许使用不保证一定选用；关闭也不改变访问结果 |

这些提示应围绕具体形状、架构和瓶颈调节，最终以满足正确性前提的实际性能为准。

### 2.4.12. C++ Performance Tips（C++ 性能建议）

> The C++ kernels in this guide all use the same handful of annotations and idioms. This section explains what they do and why they matter.

本指南的 C++ kernel 一直使用一组相同的标注和惯用写法。本节说明它们的作用及其重要性。

#### 2.4.12.1. Use `__restrict__` Pointers for Arrays in Memory（为内存数组使用 `__restrict__` 指针）

> The `__restrict__` keyword tells the compiler that the region of memory accessed through a pointer will only be accessed through that pointer for the life of the pointer. See Section 5.4.1.4.

`__restrict__` 关键字告知编译器：在指针的有效期内，通过该指针访问的内存区域只会通过它访问。参见第 5.4.1.4 节。

> In tile C++, using arrays in memory which adhere to these conditions and labeling the pointers to them with the `__restrict__` keyword is essential for good memory-operation performance.

在 Tile C++ 中，使用满足这些条件的内存数组，并用 `__restrict__` 标记其指针，对获得良好的内存操作性能至关重要。

> To see why, consider an element-wise copy which uses arrays whose pointers are not `__restrict__`:

为理解原因，考虑下面的逐元素复制，其中数组指针未标记为 `__restrict__`：

```cpp
__tile_global__ void tile_elementwise_copy(float* out, float const* in) {
    namespace ct = cuda::tiles;

    using f32x64 = ct::tile<float, ct::shape<64>>;
    using i32x64 = ct::tile<int, ct::shape<64>>;

    auto inPtrs  = in  + 64 * ct::bid().x + ct::iota<i32x64>();
    auto outPtrs = out + 64 * ct::bid().x + ct::iota<i32x64>();

    auto data = ct::load(inPtrs);   // (1)
    ct::store(outPtrs, data);       // (2)
}
```

> How the compiler parallelizes tile operations can generally be ignored in CUDA Tile programs. However, we will consider it here to understand why using non-overlapping arrays enables the compiler to generate better-performing code.

在 CUDA Tile 程序中，通常无须关心编译器如何并行化 tile 操作。但这里需要考虑这一点，才能理解为什么不重叠的数组有助于编译器生成性能更好的代码。

> Consider how the compiler will parallelize the load and store tile operations. If the input and output arrays do not overlap, the load can be parallelized into a set of independent memory read operations. Similarly, the store can be parallelized into multiple memory write operations, each of which depends only on the load operations for the data element(s) it writes.

考虑编译器如何并行化 tile 加载和存储。如果输入与输出数组不重叠，加载可以拆分为一组相互独立的读取；同样，存储可以拆分为多个写入，每个写入只依赖于它所写元素对应的加载。

> If, however, the input and output arrays may overlap, then the compiler must ensure that all memory load operations for the entire tile have completed prior to issuing any of the memory store operations to ensure correct program semantics. Otherwise, a store operations could execute and overwrite an element before it has been read in a load operation, resulting in incorrect program execution. This limits the compiler’s ability to interleave reads and writes, since all reads must complete before any writes can be issued.

如果输入和输出数组可能重叠，编译器就必须保证整个 tile 的全部加载都完成后，才能发出任何存储，以维持正确的程序语义。否则，某次写入可能在对应元素尚未被加载前就将其覆盖，造成错误。这限制了编译器交错安排读写的能力，因为必须先完成全部读取，才能开始任何写入。

> In short, when the compiler cannot guarantee non-overlapping arrays, it must generate more conservative code. This is why using non-overlapping arrays and informing the compiler of this using the `__restrict__` keyword on their pointers helps achieve best performance.

简言之，当编译器无法保证数组不重叠时，就必须生成更保守的代码。因此，使用不重叠的数组，并通过指针上的 `__restrict__` 将这一事实告知编译器，有助于获得最佳性能。

> Labeling a pointer with `__restrict__` when the memory region can be accessed by another pointer will result in undefined behavior.

如果某个内存区域可以通过另一个指针访问，却仍将其指针标记为 `__restrict__`，将导致未定义行为。

**解读：** 原文在这里说明的是同一 tile 内的读取与写入依赖。去掉 `__restrict__` 并不能自动把重叠数组的跨 block 复制变成安全的 `memmove`：不同 block 没有因此获得全局执行顺序。使用该限定符时，应保证实际访问满足其别名约束。

#### 2.4.12.2. Mark Array Pointers as 16-Byte Aligned（将数组指针标记为 16 字节对齐）

> Mark pointers to arrays as 16-byte aligned with `ct::assume_aligned`:

通过 `ct::assume_aligned`，将数组指针标记为 16 字节对齐：

```cpp
__tile_global__ void foo(float* __restrict__ in) {
    namespace ct = cuda::tiles;
    using namespace ct::literals;

    in = ct::assume_aligned(in, 16_ic);

    ct::tensor_span t{in, ct::extents{256_ic, 256_ic}};
    ct::partition_view{t, ct::shape{4_ic, 4_ic}};

    // ...
}
```

> This alignment guarantee is necessary for `ct::partition_view` to use the Tensor Memory Accelerator (TMA). You must provide 16-byte-aligned pointers at runtime when using this technique, or behavior is undefined.

要让 `ct::partition_view` 使用 Tensor Memory Accelerator（TMA），必须提供这一对齐保证。采用这种方式时，运行期间必须实际传入 16 字节对齐的指针，否则行为未定义。

> Pointers returned by CUDA memory allocators such as `cudaMalloc` are guaranteed to be at least 16-byte aligned.

`cudaMalloc` 等 CUDA 内存分配器返回的指针，保证至少按 16 字节对齐。

**解读：** `ct::assume_aligned` 不会移动数据、修正地址或执行运行时对齐检查。即使分配得到的基址对齐，从中偏移得到的子指针也不一定对齐；例如对齐的 `float* p`，`p + 1` 仅增加 4 字节，不能直接承诺仍按 16 字节对齐。必须检查实际传入的地址。

#### 2.4.12.3. Prefer `ct::partition_view` for Memory Access（优先使用 `ct::partition_view` 访问内存）

> Prefer `ct::partition_view` over the gather and scatter forms `ct::load` and `ct::store` for structured memory access. The view-based form can be lowered to the Tensor Memory Accelerator (TMA) on supported hardware, which is significantly faster than per-element gather. See Gather and Scatter for the gather/scatter context.

对于结构化内存访问，应优先使用 `ct::partition_view`，而不是 gather/scatter 形式的 `ct::load` 和 `ct::store`。在支持的硬件上，view 形式可以转换为 TMA 操作，显著快于逐元素 gather。相关背景见“Gather and Scatter”。

**解读：** Partition view 向编译器提供规则形状和访问结构，因而有机会使用 TMA；显式指针 tile 则提供更一般的逐元素寻址。应按算法的访问模式选择接口，不能因为某一 API 可以使用 TMA，就认为它对所有数据规模和访问模式都必然更快。

#### 2.4.12.4. Use `ct::irange` for Bounded Loops（使用 `ct::irange` 表达有界循环）

> Use `ct::irange` instead of a plain for loop when iterating over a fixed range. The structured form lets the compiler apply optimizations such as pipelining and vectorization that aren’t available when the loop bounds and `step` are opaque integer expressions (see Control Flow):

遍历固定范围时，使用 `ct::irange` 代替普通 `for` 循环。结构化形式让编译器可以应用流水化、向量化等优化；当循环边界和步长只是缺少结构信息的整数表达式时，这些优化便难以利用。参见“Control Flow”。

```cpp
for (auto idx : ct::irange(lowerBound, upperBound, step)) {
    // ...
}
```

**解读：** 本章把底层线程分工交给编译器，但程序员仍负责选择 tile 形状、组织全局数据、处理边界、保证跨 block 访问正确，并提供真实有效的编译信息。结构化表达让编译器更容易优化，不会消除这些算法与数据层面的责任。
