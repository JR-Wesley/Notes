## CUDA 指令概览

### 浮点指令
- **FMA (Fused Multiply-Add)**：`a * b + c` 在一条指令中完成
  - 更高精度（只有一次舍入）
  - 更高吞吐量
  - NVCC 默认开启 FMA

### 标准函数 vs 内置函数

| 类型 | 例子 | 精度 | 速度 | 使用场景 |
|------|------|------|------|----------|
| 标准函数 | `sqrtf`, `sinf`, `expf` | 高 (IEEE) | 较慢 | 需要精确结果 |
| 内置函数 | `__fsqrt_rn`, `__sinf` | 较低 (~2 ulp) | **快数倍** | 对精度不敏感的计算 |

```c
// 标准函数: 适用于需要 IEEE 精度的场景
float r1 = sqrtf(x);      // 完整精度
float r2 = sinf(x);       // 完整精度

// 内置函数: 速度快, 精度略低
float r3 = __fsqrt_rn(x); // 快速平方根
float r4 = __sinf(x);     // 快速正弦 (注意: 同名但前缀 __)
float r5 = __fdividef(a, b); // 快速除法 (比 a/b 快)
```

> [!note] 性能权衡
> 典型场景: 图像处理、深度学习推理 → 用内置函数
> 科学计算、金融分析 → 用标准函数

## 原子操作 (Atomic Operations)

### 常用原子操作

```c
int atomicAdd(int *addr, int val);         // 原子加
int atomicCAS(int *addr, int compare, int val);  // Compare-And-Swap
int atomicExch(int *addr, int val);        // 原子交换
int atomicMax(int *addr, int val);         // 原子取最大值
int atomicMin(int *addr, int val);         // 原子取最小值
```

### 原子操作的代价

- **Fermi**: 原子操作非常慢（通过 DRAM 实现），大量冲突时性能极差
- **Kepler**: 大幅改进，共享内存上的原子操作接近本地操作速度
- **同一地址冲突**: 大量线程竞争同一个地址 → 严重的序列化

### 优化策略: 分层归约

```c
// 坏: 所有线程直接 atomicAdd 到同一个地址
// atomicAdd(&global_sum, partial_sum) → 序列化!

// 好: 先在 block 内归约, 最后只做一次 atomicAdd
__shared__ int smem[BLOCK_SIZE];
smem[tid] = partial_sum;
__syncthreads();
// ... 在共享内存中归约 ...
if (tid == 0) atomicAdd(&global_sum, smem[0]);  // 每个 block 只一次
```

## 综合优化案例

### 优化层次

```
1. 基线: 标准函数 + 朴素实现
2. 单精度优先: 用 float 替代 double (如果精度允许)
3. 内置函数: 替换为快速数学函数
4. 原子优化: 减少原子操作冲突
5. 组合: 以上所有技术叠加
```

### 效果对比 (参考数据)

| 优化 | 相对加速 |
|------|----------|
| 基线 (双精度 + 标准函数) | 1.0× |
| 切换单精度 | ~2× |
| 用内置函数 | ~1.5× 额外 |
| 原子优化 | ~1.3× 额外 |
| **全部叠加** | **~4×** |

---

## 核心结论

1. **默认用 `float` 而非 `double`**，除非必须 (GPU 的单精度吞吐量远高于双精度)
2. **内置函数是低成本的加速器**，对精度要求不高时必须使用
3. **FMA 是免费的精度和速度优化**，编译器自动启用
4. **原子操作要谨慎**: 减少竞争 → 先在本地聚合再写入全局
