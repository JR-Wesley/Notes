# LLM推理并行优化的必备知识

>
> 主题围绕矩阵切分、线性层并行、Attention 与 MLA 的关键技术。核心判断是：并行策略必须同时回答“切什么维度、局部结果是否完整、如何通信恢复结果”三个问题。

## 一、矩阵切分是理解并行的基础

先从线性层出发。设 

\[
Y = XW
\]

其中 \\n$X\in\mathbb{R}^{M\times N}$，$W\in\mathbb{R}^{N\times K}$。

按切分方式，局部结果是否可直接拼接决定通信类型。

| 切分方式 | 每张 GPU 的计算 | 如何恢复完整结果 |
| --- | --- | --- |
| \(W\) 按列切分 | \(Y_i = XW_i\) | 按列拼接（Gather/AllGather） |
| \(X\) 按行切分 | \(Y_i = X_iW\) | 按行拼接（Gather/AllGather） |
| \(X\) 按列切分，\(W\) 按行对应切分 | 计算的是同一输出元素的局部贡献 \(Y_i\) | 逐元素求和（Reduce/AllReduce） |

这三类里，前两类产出的都是完整输出片段，后者是同元素的部分和。前两类只在后续层需要完整输出时才必须重组；若后续算子也能消费分片，就可延迟甚至省去重组。

对于两层 MLP：

\[
Y=\phi(XW_1)W_2
\]

若切 \(W_1\) 的列和 \(W_2\) 的行，且 \(\phi\) 是逐元素激活（例如 GELU、ReLU），则

\[
Y=\sum_i \phi(XW_{1,i})W_{2,i}
\]

中间激活可以按分片保留到最后再归约，这就是推理下 MLP 常见 TP/ SP 组合的关键理解点。

## 二、并行方式与作用范围

| 方式 | 分配对象 | 主要作用与代价 |
| --- | --- | --- |
| DP（数据并行） | 不同请求或 batch | 提高吞吐，通常需多份模型副本 |
| TP（张量并行） | 层内权重、隐藏维度、attention heads | 降低单卡权重负担，增加层内通信 |
| SP（序列并行） | token 维切分（常与 TP 配合） | 降低激活与重复计算，需与邻近算子布局衔接 |
| CP（上下文并行） | attention 上下文与 KV 维度 | 分摊长上下文负担，需跨 token 汇总/交换统计 |
| PP（流水线并行） | 按层分发模型 | 降低层级显存与计算压力，带来阶段间传输和气泡 |
| 参数分片 | 权重参数 | 降低参数副本，计算前常需预取或重组 |

Megatron 的 SP 与 Attention 的 CP 并不等价：SP 常与 TP 联动承担 layer 内激活布局问题，CP 则更多处理跨 token 的注意力依赖。

相关参考：[(Megatron 论文)](https://arxiv.org/abs/2205.05198)。

## 三、Attention 的难点在于 Softmax 归一化范围

\[
O=\operatorname{softmax}\left(\frac{QK^\top}{\sqrt d}\right)V
\]

并行切分时，Q/K/V 的可切分性不同，关键在“归一化是否跨本地分片范围”。

| 切分对象 | 可否直接并行后合并 | 说明 |
| --- | --- | --- |
| Q 的序列维 | 可以沿 query 维度拼接 | 不同 query 间近似独立，但各 query 要能看到所需的 KV |
| K 的序列维 | 不可直接拼接 | 每块 softmax 的归一化分母不同，不能简单拼接 |
| V 的序列维 | 需配合对应注意力权重后可汇总 | 本质是矩阵乘法中的收缩维切分 |

这也是“切序列不一定影响 softmax”的常见误解源头：只有不切 softmax 的归一化轴时该说法才成立。

## 四、分块 Attention 的正确归并

对某个 query，记第\(i\)块 KV 分支为 \(s_i\)。

\[
m_i = \max(s_i),\quad l_i = \sum_j e^{s_{ij}-m_i},\quad u_i = \sum_j e^{s_{ij}-m_i}v_{ij}
\]



\[
m=\max_i m_i,
\]

\[
O=\frac{\sum_i e^{m_i-m}u_i}{\sum_i e^{m_i-m}l_i}
\]

所以分块输出不能平均。必须携带归一化统计量（max 与 sum）才可正确拼接。这个结构支持树形归并：

- 先分块局部算 softmax 分子/分母统计；
- 再进行递归归约。

对应到实现里即为树形或层次化 Attention 聚合。

参考：[(Tree Attention)](https://arxiv.org/abs/2408.04093)

## 五、Prefill / Decode / Prefix Cache 的并行差异

| 场景 | 计算特点 | 并行与通信重点 |
| --- | --- | --- |
| Prefill | 通常 Q 维较大（并行处理输入上下文） | Q/KV 分配、通信与计算重叠、因果 mask 与负载均衡 |
| Decode | 每步通常新 token=1，历史 KV 长 | 将 query 广播到 KV 分片，合并局部输出与归一化统计 |
| Prefix Cache 命中 | 前缀 KV 可复用，仅新增尾部计算 | 注意前缀 KV 的驻留位置与搬运成本，分配新旧尾部负载 |

Prefix Cache 省去的是重复前缀计算，但不会消除对历史 KV 的访问与注意力融合。

## 六、MLA 的并行重构

MLA 用低维潜变量压缩 KV（见 DeepSeek-V2 论文：[DeepSeek-V2](https://arxiv.org/abs/2405.04434)）。压缩后，Q/K/V 不再以同一维度习惯出现，因此并行布局必须同步重看。

- **显式展开 KV**：先从压缩向量恢复 head 级 K/V，再按常规注意力走。
- **矩阵吸收**：通过线性变换吸收，重构到压缩空间内完成更多计算。

`W_{down}` 是否分片不是数学限制，通常由实现成本、压缩维大小、重复计算和通信开销决定。

## 关键边界与局限

- “计算量减半”不等于“耗时减半”；通信、同步粒度、算子吞吐和负载不均都可主导尾延迟。
- 权重切分后显存收益需同时计入激活、KV cache、通信缓冲区和临时工作区。
- `SP = DP` 不是通用关系。
- Attention 的 head 切分不必立即 AllGather；若下一层输出投影可消费分片，可延后到投影后归约。
- 公式级估算受内存生命周期、是否原地、是否保留副本和通信栈实现影响。

## 适用条件与可操作检查清单

对每个算子建议按四步记录：

1. 输入形状；
2. 切分维度；
3. 局部输出是“完整片段”还是“局部和”；
4. 下一层需的通信与布局。

这套检查比只背 DP/TP/SP 更容易对应到真实框架代码。
