# Chapter 1

## 展开 1.3：Transformer Block 整体数据流

---

### ① Formal Definition（形式化定义）

**Transformer Block** 是构成 Transformer 模型的基本计算单元，完成一轮完整的特征变换。对于 Decoder-only 架构（如 GPT 系列），一个标准 Block 的计算定义为：

设输入隐藏状态为 **x ∈ ℝ^(s×h)**，其中 **s** 为序列长度，**h** 为隐藏维度。一个 Block 执行以下变换：

```
x_norm1 = Norm1(x)                    # 第一次归一化
attn_out = Attention(x_norm1)         # 多头自注意力
x_res1 = x + attn_out                 # 第一次残差连接

x_norm2 = Norm2(x_res1)               # 第二次归一化
mlp_out = MLP(x_norm2)                # 前馈网络
x_res2 = x_res1 + mlp_out             # 第二次残差连接

Output = x_res2
```

**关键数据流特征**：

- **分支（Fork）**：残差连接将输入同时送入两条路径——一条通过子层（Attention/MLP）计算变换，另一条保持原值不变
- **汇合（Join/Add）**：两条路径在子层输出处做逐元素加法，形成残差连接
- **两次子层结构**：每个 Block 包含 Attention 子层和 MLP 子层，每个子层内部采用 Pre-LN（先归一化再计算）布局

**Pre-LN vs Post-LN 的数学表达差异**：

| 布局 | 计算顺序 |
|------|----------|
| Pre-LN（现代 LLM 标准） | `x + Sublayer(Norm(x))` |
| Post-LN（原始论文） | `Norm(x + Sublayer(x))` |

Pre-LN 提供更稳定的梯度流，是现代大规模 LLM 的首选。

---

### ② System Design View（系统视角）

**在整个训练系统中的位置**：

Transformer Block 是模型前向传播的**核心循环体**。一个 L 层的模型就是该 Block 的 L 次串行堆叠：

```
Input → Embedding → [Block_1 → Block_2 → ... → Block_L] → LM Head → Output
```

**输入 / 输出 / 依赖关系**：

```
┌─────────────────────────────────────────────────────────┐
│                   Transformer Block                      │
│                                                          │
│  输入: hidden_states (s × h)                             │
│        attention_mask (s × s)  ← 因果掩码                  │
│                                                          │
│  ┌─────────────┐                                         │
│  │  LayerNorm1  │ ← 输入标准化                              │
│  └──────┬──────┘                                         │
│         │                                                 │
│  ┌──────▼──────┐    ┌─────────────┐                      │
│  │  Attention  │    │  残差分支    │                      │
│  │  Q/K/V投影  │    │ (恒等映射)   │                      │
│  │  Score计算  │    └──────┬──────┘                      │
│  │  Softmax    │           │                              │
│  │  Value聚合  │           │                              │
│  └──────┬──────┘           │                              │
│         │                  │                              │
│         └──────┬───────────┘                              │
│                │ 逐元素加法 (+)                             │
│         ┌──────▼──────┐                                   │
│         │  LayerNorm2  │                                   │
│         └──────┬──────┘                                   │
│                │                                           │
│         ┌──────▼──────┐    ┌─────────────┐                │
│         │    MLP      │    │  残差分支    │                │
│         │  FC1 → Act  │    │ (恒等映射)   │                │
│         │  → FC2      │    └──────┬──────┘                │
│         └──────┬──────┘           │                        │
│                │                  │                        │
│                └──────┬───────────┘                        │
│                       │ 逐元素加法 (+)                      │
│                ┌──────▼──────┐                             │
│                │   Output    │                             │
│                └─────────────┘                             │
│                                                          │
│  输出: hidden_states' (s × h)  ← 形状不变                   │
└─────────────────────────────────────────────────────────┘
```

**核心设计约束**：

1. **形状一致性**：Block 输入输出形状完全相同 (s × h)，确保可堆叠性
2. **残差通道**：始终保留一条从输入端到输出端的恒等路径，梯度可直通传播
3. **归一化前置**：数据先被标准化再进入计算密集的子层

### ③ Implementation Mapping（工程映射）

**PyTorch 映射**（`torch.nn.TransformerEncoderLayer`）：

```python
# PyTorch 原生实现的核心结构
class TransformerEncoderLayer(nn.Module):
    def __init__(self, d_model, nhead, dim_feedforward, dropout):
        self.self_attn = MultiheadAttention(d_model, nhead)
        self.linear1 = nn.Linear(d_model, dim_feedforward)
        self.linear2 = nn.Linear(dim_feedforward, d_model)
        self.norm1 = nn.LayerNorm(d_model)
        self.norm2 = nn.LayerNorm(d_model)
        self.dropout = nn.Dropout(dropout)

    def forward(self, src):
        # Pre-LN 结构
        src2 = self.norm1(src)
        src2 = self.self_attn(src2, src2, src2)
        src = src + self.dropout(src2)       # 残差连接1

        src2 = self.norm2(src)
        src2 = self.linear2(F.relu(self.linear1(src2)))
        src = src + self.dropout(src2)       # 残差连接2
        return src
```

**Megatron-LM 映射**（`ParallelTransformerLayer`）：

Megatron 对 Block 做了两项关键修改以适应并行：

1. **LayerNorm 替换为 RMSNorm**：减少计算开销
2. **插入通信操作**：在 Attention 和 MLP 的线性层前后插入 `f`（前向通信）和 `g`（反向通信）操作，实现张量并行

核心结构位于 `megatron/model/transformer.py` 的 `ParallelTransformerLayer` 类。

**DeepSpeed 映射**：

DeepSpeed 本身不修改 Block 结构，但通过 **Activation Checkpointing** 在 Block 边界插入检查点标记，重计算粒度为整个 Transformer Block。

### ④ Complexity Analysis（复杂度分析）

**计算复杂度（单层 Block，前向传播）**：

| 子模块 | FLOPs | 说明 |
|--------|-------|------|
| Q/K/V 投影 | 3 × (2sh²) | 三个权重矩阵乘 |
| Attention Score | 2s²h | Q×K^T |
| Attention Output 投影 | 2sh² | 聚合后投影 |
| MLP FC1 | 2sh × 4h = 8sh² | 扩维 4 倍 |
| MLP FC2 | 2s × 4h × h = 8sh² | 回缩至 h |
| **单层总计** | **~24sh² + 2s²h** | 忽略 LayerNorm |

当序列长度 s 较大时，**s²h 项**（Attention Score 计算）成为瓶颈——这也是 FlashAttention 优化的目标。

**显存占用（单层 Block 激活值，训练时）**：

| Tensor | 大小 | 必须保留的原因 |
|--------|------|---------------|
| Q/K/V | 3sh | 反向需重算 Score 梯度 |
| Attention Score | s²×num_heads | Softmax 反向输入 |
| Attention Dropout Mask | s²×num_heads | 反向还原 Dropout |
| MLP 中间激活 | s × 4h | FC2 反向输入 |
| **单层激活总计** | **O(s²h + sh)** | 序列长度二次方项主导 |

---

### ⑤ Design Trade-offs（权衡）

**Trade-off 1：Pre-LN vs Post-LN**

| 维度 | Pre-LN（现代 LLM） | Post-LN（原始论文） |
|------|---------------------|---------------------|
| 训练稳定性 | ✅ 梯度在残差路径上无额外变换 | ❌ 深层网络输出方差爆炸 |
| 收敛速度 | 略慢（需稍大学习率 warmup） | 较快 |
| 最终效果 | 略低于 Post-LN（有争议） | 理论上上限更高 |
| 工程选型 | **Llama / GPT-3 / Megatron 均采用** | 已基本废弃 |

选择 Pre-LN 的核心原因：**在大规模训练中，稳定性优先于理论最优收敛效果**。

**Trade-off 2：残差连接的必要性**

残差连接引入了**额外显存开销**（保留输入副本以各加法反向传播），但它提供了一条**恒等梯度通道**：

```
∂Loss/∂x_in = ∂Loss/∂x_out × (1 + ∂Sublayer(x)/∂x_in)
```

其中常数项 "1" 确保了即使子层梯度消失，梯度仍能通过恒等路径反向传播。**去掉残差连接，超过 12 层的 Transformer 几乎无法有效训练。**

**Trade-off 3：Block 作为并行切分的最小单元**

- **Pipeline Parallel** 的切分边界恰好在 Block 之间（两个残差连接合点）
- **Activation Checkpointing** 的重计算粒度通常为一个完整 Block
- 这种设计约束来自残差连接的**数据依赖性**：Block 内部存在跨子层的依赖，不适合再做更细粒度的流水切分

## 展开 4.1：参数量计算

---

### ① Formal Definition（形式化定义）

**参数量**（Number of Parameters）指模型中所有可学习的权重矩阵与偏置向量的元素总数，单位通常为 **#Params** 或 **Parameters**，并以 **M**（百万）或 **B**（十亿）度量。对于标准的 Decoder-only Transformer（如 GPT、Llama 系列），参数量可通过以下配置参数精确计算：

| 符号 | 含义 |
|------|------|
| \( V \) | 词表大小（Vocabulary size） |
| \( L \) | Transformer 层数（Number of layers） |
| \( h \) | 隐藏维度（Hidden size, \( d_{model} \)） |
| \( n_{heads} \) | 注意力头数（Number of attention heads） |
| \( d_{head} \) | 每个头的维度，通常 \( d_{head} = h / n_{heads} \) |
| \( d_{ff} \) | FFN 中间层维度（通常 \( 4h \) 或由比例因子决定） |

**关键前提**：
- 该模型采用 **Pre-LN** 结构，每层包含 Self-Attention Block 和 MLP Block。
- 不使用偏置项（如 Llama 系列），或使用偏置（如 GPT-2）需另行计算。
- 采用 **无共享权重** 的嵌入层和输出头（Weight tying 情况需调整）。

**参数量计算分模块如下**：

---

#### 4.1.1 Embedding 层

- **Token Embedding**：矩阵 \( W_{te} \in \mathbb{R}^{V \times h} \)，参数量 = \( V \times h \)。
- **Position Embedding**：
  - 如果是可学习位置嵌入（Learned Positional Embedding，如 GPT-2）：矩阵 \( W_{pe} \in \mathbb{R}^{max\_seq\_len \times h} \)，参数量 = \( max\_seq\_len \times h \)。
  - 现代 LLM 多采用 **RoPE（Rotary Position Embedding）** 等无参数方案，此时此项为 **0**。

**Embedding 总参数量**：
\[
P_{embed} = V \times h + P_{pos}
\]
其中 \( P_{pos} \) 取决于位置嵌入方案，一般为 0（RoPE）或 \( max\_seq\_len \times h \)。

---

#### 4.1.2 单个 Transformer Block 的参数量

每个 Block 由 Self-Attention 和 MLP 构成，外加两个 LayerNorm/RMSNorm。

##### a) Self-Attention 参数

- **Q 投影**：\( W_Q \in \mathbb{R}^{h \times (n_{heads} \cdot d_{head})} = \mathbb{R}^{h \times h} \)，参数量 = \( h^2 \)。
- **K 投影**：\( W_K \in \mathbb{R}^{h \times (n_{heads} \cdot d_{head})} = \mathbb{R}^{h \times h} \)，参数量 = \( h^2 \)。
- **V 投影**：\( W_V \in \mathbb{R}^{h \times (n_{heads} \cdot d_{head})} = \mathbb{R}^{h \times h} \)，参数量 = \( h^2 \)。
- **Output 投影**：\( W_O \in \mathbb{R}^{(n_{heads} \cdot d_{head}) \times h} = \mathbb{R}^{h \times h} \)，参数量 = \( h^2 \)。

> 注意：Q、K、V 投影通常合并为一个大矩阵 \( W_{qkv} \in \mathbb{R}^{h \times 3h} \)，参数量 = \( 3h^2 \)。实际等价。

**Attention 模块总参数量**：\( 4h^2 \)（无论是否分头，维度均为 h×h，共四个矩阵）。

##### b) MLP 参数（标准 FFN）

- **第一线性层**（升维）：\( W_{fc1} \in \mathbb{R}^{h \times d_{ff}} \)，参数量 = \( h \times d_{ff} \)。
- **第二线性层**（降维）：\( W_{fc2} \in \mathbb{R}^{d_{ff} \times h} \)，参数量 = \( d_{ff} \times h \)。

**MLP 总参数量**：\( 2 \cdot h \cdot d_{ff} \)。对于标准 \( d_{ff} = 4h \)，则为 \( 8h^2 \)。

##### c) LayerNorm / RMSNorm

每个 Block 包含 2 个归一化层，每层参数为一个可学习的缩放向量（RMSNorm）或缩放 + 偏移（LayerNorm），维度为 \( h \)。

- **RMSNorm**（现代 LLM 主流）：每层参数量 = \( h \)。
- **LayerNorm**：每层参数量 = \( 2h \)（含 weight 和 bias）。

**每 Block 归一化参数量**：
- RMSNorm: \( 2h \)
- LayerNorm: \( 4h \)

通常可忽略（\( O(h) \) vs \( O(h^2) \)），但精确计算时需计入。

##### 单层 Block 总参数量（无偏置）

\[

P_{block} = 4h^2 \ (\text{Attention}) + 2h \cdot d_{ff} \ (\text{MLP}) + 2h \ (\text{RMSNorm})

\]

当 \( d_{ff} = 4h \) 时：

\[

P_{block} = 4h^2 + 8h^2 + 2h = 12h^2 + 2h

\]

若使用 LayerNorm，则为 \( 12h^2 + 4h \)。

---

#### 4.1.3 最终输出层（LM Head）

- 若 **权重不共享**：输出投影矩阵 \( W_{lm} \in \mathbb{R}^{h \times V} \)，参数量 = \( h \times V \)。
- 若 **权重共享**（Weight Tying，常见于 GPT-2 及部分模型）：LM Head 与 Token Embedding 共享权重，此项为 **0**。

现代大模型（如 Llama、GPT-3）通常 **不共享** 权重，因此需单独计入 \( h \times V \)。

---

#### 4.1.4 总参数量公式

**通用公式**（无偏置，RoPE 位置编码，RMSNorm，不共享嵌入）：
\[
P_{total} = \underbrace{V \times h}_{\text{Embedding}} + L \times \left( 12h^2 + 2h \right) + \underbrace{h \times V}_{\text{LM Head}} + \underbrace{P_{pos}}_{\text{可能为 0}}
\]

简化（忽略 O(h) 项）：

\[

P_{total} \approx 12Lh^2 + 2Vh

\]

**实际比例**：
- 主体部分 \( 12Lh^2 \) 占据绝大部分参数量（>99% 当 h 较大时）。
- 词表项 \( 2Vh \) 仅在 V 极大（如 250k+ 词表）时有显著影响。

### ② System Design View（系统视角）

参数量在整个训练系统中的位置：

```
模型架构参数 (L, h, V, ...)
       │
       ▼
  参数量计算 ──────────────> 决定存储需求（模型文件大小）
       │
       ├──> 确定单卡显存能否容纳参数 + 梯度 + 优化器
       │
       ├──> 驱动并行策略选择：
       │        · 若参数 显存 > 单卡上限 → 必须 ZeRO-3 / TP / PP
       │
       └──> 作为 4.3 显存模型 的输入，进一步计算总显存
```

**输入**：模型超参数（h, L, n_heads, d_ff, V, 是否共享权重等）。
**输出**：总参数量和每模块参数量分布。

依赖关系：参数量是 **4.3 Memory 组成** 中“模型参数显存”的直接来源，是 ZeRO 分片决策（20.1）的输入，是估算通信量（梯度同步 AllReduce）的基础。

### ③ Implementation Mapping（工程映射）

各框架中如何获取参数量：

**PyTorch**：

```python
total_params = sum(p.numel() for p in model.parameters())
trainable_params = sum(p.numel() for p in model.parameters() if p.requires_grad)
```

HuggingFace Transformers 中，可通过 `model.num_parameters()` 直接获取。

**Megatron-LM**：
- 在 `megatron/training/arguments.py` 中有函数 `_print_num_parameters` 用于打印参数量。
- 通过收集所有层中 `torch.nn.Parameter` 并求和得到，同时区分嵌入、Transformer 层、LM Head。

**DeepSpeed**：
- 初始化时，框架通过遍历模型参数统计总参数量，用于决定 ZeRO 分片划分方式（`ds_config` 中 `train_batch_size` 等不直接影响参数计数）。
- 也提供 `ds_report` 工具显示模型估算参数。

### ④ Complexity Analysis（复杂度分析）

**参数量规模的增长**（O-notation）：
- 主体项：\( O(L \cdot h^2) \)
- 词表项：\( O(V \cdot h) \)

对于典型 7B 模型（Llama 2 7B）：\( L=32, h=4096, d_{ff}=11008 \)，计算如下：

\[

P_{block} = 4 \times 4096^2 + 2 \times 4096 \times 11008 + 2 \times 4096 \approx 67.1M + 90.2M + 0.008M \approx 157.3M

\]

\[

P_{total} \approx 32 \times 157.3M + 2 \times 32000 \times 4096 \approx 5.03B + 0.26B \approx 5.29B \ (实际 6.74B 因使用了 GQA 和偏置等细微差异)

\]

**参数分布**（典型模型）：
- Embedding + LM Head：~1-3%
- Transformer Blocks 的 Attention 部分：~1/3
- Transformer Blocks 的 MLP 部分：~2/3

**Scaling**：
- 扩大 h 对参数量影响显著（平方级），扩大 L 线性增长。
- 例如：将 h 从 4096 增至 8192，参数量大致增至 4 倍。

---

### ⑤ Design Trade-offs（权衡）

**Trade-off 1: 词表大小 V 与计算开销**
- 增大 V 提升多语言表示能力，但 Embedding 和 LM Head 矩阵巨大（如 Qwen 词表 152k，h=4096 时，Embedding 参数 ~623M，占比可观）。
- 词表权重经常通过词汇分组（如 ZeRO-2 参数分片）或结合 Sequence Parallel 减少单卡存储。

**Trade-off 2: 权重共享（Weight Tying）**
- 共享 Embedding 和 LM Head 可节省 \( h \times V \) 参数，但限制了输出表达能力。
- 现代大模型（GPT-3、Llama）通常不共享，以换取更好的生成质量。

**Trade-off 3: 注意力头数与维度**
- 保持 h 不变，改变 \( n_{heads} \) 仅改变 \( d_{head} \)，不影响 Attention 的参数量（仍为 \( 4h^2 \)）。
- 多头设置影响计算特征和后续 TP 切分，无参数量影响。

**Trade-off 4: 使用 GQA/MQA**
- 分组查询注意力（GQA）或多查询注意力（MQA）减少 K、V 投影的参数量：
  - MQA: K, V 投影各只有一个头，尺寸 \( h \times d_{head} \)，即 K/V 投影各 \( h \cdot d_{head} = h^2 / n_{heads} \)，总 Attention 参数量降至 \( h^2 + 2h^2/n_{heads} + h^2 = 2h^2 + 2h^2/n_{heads} \)。
- 显著降低参数量和 KV Cache 大小，Llama 2 70B 使用了 GQA。

**Trade-off 5: FFN 扩维比例**
- 标准为 4 倍，如 LLaMA 用 \( d_{ff} \approx 8/3 \times h \) 进行了调整，变更为其他比例会影响 MLP 参数量（\( 2hd_{ff} \)）。
- 更大的扩维比例提高模型容量，但增大显存和计算量。

这些权衡表明，参数量公式不仅是静态估算，也是架构设计的直接反馈。

- **系统设计题目**：选择一个模型（如 Llama 3 8B 配置），分别计算使用 MHA、GQA (8 groups)、MQA 时的 Attention 参数量，并估算总参数量变化。

## 展开 4.2：FLOPs 计算

---

### ① Formal Definition（形式化定义）

**FLOPs**（Floating Point Operations）指模型在一次前向传播（forward pass）或一次完整训练迭代（forward + backward）中所执行的浮点运算次数。它是衡量计算需求的精确指标，通常以 **FLOPS**（每秒浮点运算次数）作为硬件吞吐单位时，FLOPs 直接决定理论最小执行时间。

对于 Transformer 模型，FLOPs 计算基于矩阵乘法的运算量。一个形如 \( C = A \times B \)，其中 \( A \in \mathbb{R}^{m \times k} \)，\( B \in \mathbb{R}^{k \times n} \) 的矩阵乘法，包含 **2 × m × n × k** 次浮点运算（含乘法和加法，通常忽略偏置、激活函数等的微小开销，仅计算矩阵乘主导项）。该值亦称为 **MACs**（Multiply-Accumulate Operations）的 2 倍（1 MAC ≈ 2 FLOPs），工程中通常直接使用 FLOPs。

**通用前提**：
- 只考虑 **矩阵乘法** 和 **Attention Score 计算** 等稠密运算；LayerNorm、Softmax、残差加法等按 O(s·h) 或 O(s²) 但系数极小，常忽略。
- 序列长度记为 \( s \)，隐藏维度 \( h \)，头数 \( n_{heads} \)，每个头维度 \( d_{head} = h / n_{heads} \)，FFN 中间维度 \( d_{ff} \)（标准为 \( 4h \)）。
- 使用 **Pre-LN** 结构，无偏置（现代 LLM 惯例），且采用因果自注意力（causal attention），其对计算量的影响仅在于掩码不减少实际乘加次数，因此 **因果掩码不改变 FLOPs**（仍需计算完整的 QK^T）。

---

#### 4.2.1 前向 FLOPs 推导（单层 Transformer Block）

以下按子模块拆解：

##### a) Self-Attention 模块

**1. Q、K、V 投影**（通常合并为单个矩阵乘）
输入 \( X \in \mathbb{R}^{s \times h} \)，权重 \( W_{qkv} \in \mathbb{R}^{h \times 3h} \)。
FLOPs = \( 2 \times s \times h \times 3h = 6 s h^2 \)。

**2. 计算 Attention Score**（Q × K^T）
\( Q \in \mathbb{R}^{s \times h} \)，\( K^T \in \mathbb{R}^{h \times s} \) → \( \text{Scores} \in \mathbb{R}^{s \times s} \)。
FLOPs = \( 2 \times s \times h \times s = 2 s^2 h \)。
（若细分至多头，每个头执行 \( s \times d_{head} \times s \) 的乘法，总 FLOPs 不变，因为 \( n_{heads} \times 2 \times s \times d_{head} \times s = 2 s^2 h \)。）

**3. Softmax（忽略）**
计算复杂度 \( O(s^2) \)，与矩阵乘相比可忽略（通常不计入）。

**4. 加权求和**（Attention output = softmax(Scores) × V）
\( \text{AttnWeights} \in \mathbb{R}^{s \times s} \)，\( V \in \mathbb{R}^{s \times h} \)。
FLOPs = \( 2 \times s \times s \times h = 2 s^2 h \)。

**5. Output 投影**
输出权重 \( W_O \in \mathbb{R}^{h \times h} \)，输入 \( \in \mathbb{R}^{s \times h} \)。
FLOPs = \( 2 \times s \times h \times h = 2 s h^2 \)。

**Attention 总前向 FLOPs**：
\[
F_{attn} = 6 s h^2 + 2 s^2 h + 2 s^2 h + 2 s h^2 = 8 s h^2 + 4 s^2 h
\]

（注：QKV 合并投影 6sh²，两处 \( s^2 h \) 项分别对应 Score 计算和加权聚合，输出投影 2sh²，合计 \( 8sh^2 + 4s^2 h \)。）

##### b) MLP 模块

**1. 第一线性层（h → d_ff）**
权重 \( W_{fc1} \in \mathbb{R}^{h \times d_{ff}} \)，输入 \( \in \mathbb{R}^{s \times h} \)。
FLOPs = \( 2 \times s \times h \times d_{ff} = 2 s h d_{ff} \)。
**2. 激活函数**（如 SiLU）为逐元素操作，FLOPs ≈ \( O(s \cdot d_{ff}) \)，忽略。
**3. 第二线性层（d_ff → h）**
权重 \( W_{fc2} \in \mathbb{R}^{d_{ff} \times h} \)，输入 \( \in \mathbb{R}^{s \times d_{ff}} \)。
FLOPs = \( 2 \times s \times d_{ff} \times h = 2 s h d_{ff} \)。

**MLP 总前向 FLOPs**：
\[
F_{mlp} = 4 s h d_{ff}
\]
当 \( d_{ff} = 4h \) 时，\( F_{mlp} = 16 s h^2 \)。

##### c) 归一化层与残差

LayerNorm/RMSNorm 和残差加法均为逐元素操作，FLOPs 为 \( O(s \cdot h) \)，远小于矩阵乘项，**工程上常忽略**。

##### d) 单层 Block 总前向 FLOPs

\[

F_{block} = \underbrace{8 s h^2 + 4 s^2 h}_{\text{Attention}} + \underbrace{4 s h d_{ff}}_{\text{MLP}}

\]

对于标准 \( d_{ff} = 4h \)：

\[

F_{block} = 8 s h^2 + 16 s h^2 + 4 s^2 h = 24 s h^2 + 4 s^2 h

\]

##### e) 整个模型（L 层）前向 FLOPs

\[

F_{fwd} = L \times \left( 24 s h^2 + 4 s^2 h \right)

\]

嵌入层（查表）和输出 LM Head（矩阵乘 \( s \times h \times V \)）的 FLOPs 为：

- Embedding：通常视为索引操作，无浮点计算。
- LM Head：\( 2 s h V \)。当 V 很大时有一定占比，但通常与 Transformer 主体相比仍较小，可附加：
\[
F_{fwd} \approx L \times (24 s h^2 + 4 s^2 h) + 2 s h V
\]

---

#### 4.2.2 反向传播 FLOPs

反向传播（backward pass）计算权重梯度和输入梯度。对于每个矩阵乘法，反向所需的浮点运算约为前向的 **2 倍**（需分别计算关于输入和权重的梯度，各涉及一次矩阵乘）。该比例在 Transformer 这种以矩阵乘为主体的模型中近似精确。

因此，**单次迭代（forward + backward）的总 FLOPs** 通常为：

\[

F_{total} \approx 3 \times F_{fwd}

\]

即反向 FLOPs ≈ 2 × 前向 FLOPs，合计 3 倍。

因此：

\[

F_{total\_iter} \approx 3 L \times (24 s h^2 + 4 s^2 h) + \text{额外输出层}

\]

若需要包含优化器步骤的 FLOPs（如 Adam 更新），它们仅为参数量的常数倍（每个参数约 3~5 次操作），占比极小，通常不计入训练吞吐量 FLOPs。

---

### ② System Design View（系统视角）

FLOPs 计算连接模型架构与硬件执行时间：

```
模型配置 (L, h, s, ...)
       │
       ▼
  FLOPs 计算 ────────────> 决定单次迭代的最小计算量
       │
       ├──> 结合硬件峰值算力 → 估算理论最少迭代时间
       │
       ├──> 与显存带宽结合 → 通过 Roofline 判断 Kernel 是 Compute Bound 还是 Memory Bound
       │
       ├──> 作为 Scaling 分析基础：强扩展时总 FLOPs 不变，弱扩展时 FLOPs 随 batch 增加
       │
       └──> 用于 MFU (Model FLOPs Utilization) 计算，衡量实际训练效率
```

**输入**：模型超参数，序列长度 s，批大小（batch size）不影响单样本 FLOPs，总 FLOPs 线性乘 B。
**输出**：一次前向/迭代的浮点运算数。
**依赖**：FLOPs 值是 **4.3 显存模型** 中 " 激活值 " 部分的间接输入（激活量大小隐含计算量），也是 **25.2 Compute Model** 和 **25.4 Scaling Model** 的核心输入。

### ③ Implementation Mapping（工程映射）

**PyTorch**：
没有直接返回 FLOPs 的官方 API，常用 `fvcore` 或 `thop` 等第三方库：

```python
from fvcore.nn import FlopCountAnalysis
flops = FlopCountAnalysis(model, input_tensor)
print(flops.total())
```

或用 `torch.utils.flop_counter`（PyTorch 1.13+ 实验性功能）。注意这些工具可能低估 Attention 部分的 FLOPs（将 softmax 视为小运算），但可用于工程估算。

**Megatron-LM**：
在 `megatron/training/arguments.py` 中定义了一个函数 `_print_flops_per_token`，它会根据公式估算每个 token 的 FLOPs（即前向 \( \frac{F_{fwd}}{s} \)），用于向用户报告模型训练吞吐量。简化公式为：

```python
flops_per_token = 12 * hidden_size**2 * num_layers * (1 + ffn_multiplier_factor) 
                  + 2 * num_attention_heads * head_dim * hidden_size * num_layers
```

实际上就是上述 \( 24h^2 + 4sh \) （去掉 s 因子）的变形。

**DeepSpeed**：
DeepSpeed 主要关注显存和通信调度，FLOPs 计算通常不在框架内主动输出，但配合 Megatron 时会继承 Megatron 的计算。其 `ds_report` 不含 FLOPs 细节。

**实际训练中**，通过测量迭代时间和 GPU 理论峰值算力反推 MFU：
\[
\text{MFU} = \frac{\text{理论 FLOPs}}{\text{实际执行时间} \times \text{GPU 峰值 FLOPS}}
\]

### ④ Complexity Analysis（复杂度分析）

**复杂度增长量级**：

| 模块 | 计算复杂度 | 主导场景 |
|------|-----------|---------|
| QKV 投影 + Out 投影 | \( O(s h^2) \) | h 大时主导 |
| Attention Score + Aggregation | \( O(s^2 h) \) | s 大时主导 |
| MLP | \( O(s h d_{ff}) = O(s h^2) \) (若 d_ff ∝ h) | 常数倍于 Attention 线性部分 |
| **单层总计** | \( O(s h^2 + s^2 h) \) | |
| **L 层模型前向** | \( O(L s h^2 + L s^2 h) \) | |

**当 \( s \ll h \) 时**（如预填充短句子），\( s h^2 \) 项主导，FLOPs 随隐藏维度平方增长。
**当 \( s \) 与 \( h \) 可比或更大时**（长文本训练/推理），\( s^2 h \) 项快速占据主导，这是长上下文训练需要 Sequence Parallel 和 FlashAttention 优化的根本原因。

**注意力机制的二次复杂度**在长序列场景下会成为核心瓶颈。即使使用 FlashAttention，FLOPs 总量不变，但通过减少 HBM 访存大幅提升实际吞吐。

**批大小 B 的影响**：
总训练 FLOPs = \( B \times F_{fwd} \times 3 \)（含反向）。B 增加不改变单个 token 的 FLOPs，只成倍增加总计算量。数据并行时，每张卡的计算量为 \( (B/DP) \times F_{fwd} \times 3 \)。

**反向传播的精确因子**：
严格推导下，对于 Linear 层反向的乘法次数确实为前向的 2 倍（一个关于输入，一个关于权重），但有梯度累积、LayerNorm 反向等微小差异，工程上 2x 是精度足够的近似。

---

### ⑤ Design Trade-offs（权衡）

**Trade-off 1：增大隐藏维度 h  vs. 增加层数 L**
- 增大 h 带来计算量的平方级增长（\( O(s h^2) \) 主导），而增加 L 仅为线性增长。
- 为了在固定算力预算下最大化模型容量，设计时常选用较深的窄模型（如 L 很大，h 适中），使得参数量相同时 FLOPs 更友好。
- 举例：相同参数下，更深的模型（更大的 L）通常比更宽的模型（更大的 h）计算量更小，但并行化更难（PP 段数增多，通信/气泡增加）。

**Trade-off 2：长序列训练 vs. 计算效率**
- 序列长度 s 增加会导致 Attention 的二次复杂度项 \( s^2 h \) 急剧膨胀，成为计算瓶颈。
- 缓解手段：FlashAttention（不改变 FLOPs 但提升实际利用率），稀疏注意力（减少 s² 项系数），Sequence Parallel（分散激活存储）。
- 极端长上下文时，即使算力充足，显存带宽仍可能成为瓶颈（Attention Score 矩阵过大，访存量成为 Roofline 瓶颈）。

**Trade-off 3：GQA/MQA 对 FLOPs 的“无影响”与 KV Cache 优化**
- GQA/MQA 减少 K、V 投影的参数量，但 **并不减少** FLOPs。因为 K 和 V 的投影计算量是 \( 2 s h d_{head} \times n_{kv\_heads} \)，若减少 KV 头数，该项 FLOPs 等比例下降，而 Q 投影不变。实际上 FLOPs 会减少一部分，但不影响 Attention Score 和 Aggregation 的 \( O(s^2 h) \) 项（由于 K/V 被广播，仍参与完整的矩阵乘）。因此，GQA 的 FLOPs 减少仅限于投影阶段，系数为 \( (1 + 1/g) \) 类型的减少，对于大 s 主导的二次项无效。设计时需清楚：GQA 主要优化显存（KV Cache），非计算。

**Trade-off 4：FLOPs 估算的忽略项**
- 我们忽略了 LayerNorm、残差、Dropout、Softmax、激活函数等。这些在短序列或极宽模型时占比可达 2~5%，但通常不影响宏观分析。若需精准建模，可使用自动 FLOPs 计数器加上经验修正。
- 反向传播的“2x”忽略了一些额外操作（如 Attention 反向中 softmax 梯度等），但相对矩阵乘仍小。

**Trade-off 5：MFU 与计算模式**
- FLOPs 理论值很高，但实际 MFU 常低于 60%，主要原因：内存墙导致的停顿（Memory Bound Kernel）、通信开销、不能充分重叠的 Stream、Kernel Launch 开销等。
- 因此，FLOPs 是性能上界，真正的优化必须结合 Bandwidth 分析（Chapter 9 Roofline）和通信模型（Chapter 16/25.3）才能定位瓶颈。

## 展开 4.3：Memory 组成

---

### ① Formal Definition（形式化定义）

**训练过程中的 GPU 显存占用** 是指在一次完整的前向 + 反向 + 优化器更新周期中，所有必须在 GPU 高带宽显存（HBM）中驻留的数据所占用的存储总量。其单位通常为 **GB**（\(1\text{ GB}=10^9\text{ bytes}\) 或 \(2^{30}\) bytes，工业界常混用，本文采用标准 1 GB = \(10^9\) bytes 以便与硬件规格对齐）。

对于标准的 Decoder-only Transformer 模型，在混合精度训练（FP16/BF16 权重与激活，FP32 主权重与优化器状态）下，显存可严格划分为 **四类核心组件**：

| 组件 | 符号 | 数据精度 | 占显存公式 | 说明 |
|------|------|---------|-----------|------|
| **模型参数** | \(M_{param}\) | FP16/BF16（2 bytes） | \(2P\) | P 为总参数量（见 4.1） |
| **梯度** | \(M_{grad}\) | FP16/BF16（2 bytes） | \(2P\) | 每参数对应一个梯度 |
| **优化器状态** | \(M_{optim}\) | FP32（4 bytes）为主 | \(k \times 4P\) | k 取决于优化器（Adam 时 k=2） |
| **激活值** | \(M_{act}\) | FP16/BF16（2 bytes）为主 | 动态，见下文分解 | 前向产生的中间张量，反向必需 |

此外还存在一些**暂时性/框架开销**（通信缓冲区、内存碎片、CUDA 上下文等），但不属于模型分析核心，将在性能建模篇（Chapter 25）中纳入余量。

**混合精度训练（标准配置）下的量化公式**：
- 参数、梯度：各 **2P** bytes（FP16/BF16）
- Adam 优化器状态：保存 FP32 的 `exp_avg` 和 `exp_avg_sq`，即 **2 × 4P = 8P** bytes
- 另有一个可选的 FP32 主权重副本（“master weights”），占 **4P** bytes

因此，**模型状态（Model States）总计**：

\[

M_{model\_states} = 2P\ (\text{参数}) + 2P\ (\text{梯度}) + 8P\ (\text{Adam}) + 4P\ (\text{FP32 Master 权重}) = 16P\ \text{bytes}

\]

如果没有 FP32 Master 权重副本（某些框架直接通过 BF16 + 混合精度实现），则为 **12P bytes**。但实践中，DeepSpeed/Megatron 普遍保留 master weights（ZeRO 1/2/3 的配置会改变存储分布）。

**激活值显存**（\(M_{act}\)）的计算不固定，取决于模型层数、隐藏维度、序列长度以及使用了何种重计算/并行策略。一般形式：
\[
M_{act} = L \times (\text{每层保留的激活张量大小}) + \text{跨层共享输入}
\]
未使用 Activation Checkpointing 时，每层需保存所有用于反向的中间结果（见下文分解）；使用重计算时，仅保留检查点（Checkpoint）间的边界激活。

---

### ② System Design View（系统视角）

在整个训练系统的资源管理链条中，Memory 组成是核心的“可行域约束”：

```
模型配置 (L, h, s, B, ...)
       │
       ▼
 Memory 组成分析 ────────────> 判断单卡能否装下完整训练状态
       │
       ├──> 若 M_model_states 超显存 → 必须启用 ZeRO-3 或 TP/PP 切分参数
       ├──> 若 M_act 超显存 → 必须启用 Activation Checkpoint、Sequence Parallel 或减少 batch size
       │
       └──> 作为 8.1 显存瓶颈的直接输入，驱动分布式动机决策
```

**输入**：
- 模型参数量 P（来自 4.1）
- 每层激活值张量配置（由模型结构、序列长度 s、隐藏维度 h、微批大小 micro batch size b 决定）
- 优化器类型（Adam/AdamW/SGD）
- 是否使用混合精度、重计算、序列并行等

**输出**：
- 各组件显存占用绝对值（GB）及占比
- 单卡训练可行性结论
- 为并行策略（DP/TP/PP/ZeRO）提供数据切分依据

**依赖关系**：
- 向前依赖 4.1 参数量、4.2 FLOPs（激活值大小与计算图相关）
- 向后为 Chapter 8（单 GPU 瓶颈）、Chapter 10~13（并行策略）、Chapter 21（DeepSpeed ZeRO 实现）提供关键输入

### ③ Implementation Mapping（工程映射）

各框架对显存的观测与管理：

**PyTorch**：
- 使用 `torch.cuda.memory_allocated()` 和 `torch.cuda.max_memory_allocated()` 观测 PyTorch 分配器管理的显存。
- 使用 `torch.cuda.memory_reserved()` 查看缓存池。
- 通过 `torch.profiler` 结合 `memory_profile` 可追踪张量生命周期。

**Megatron-LM**：
- 显存分配统计在 `megatron/training/training.py` 中，通过记录 `torch.cuda.memory_allocated()` 打印各阶段占用。
- 根据用户配置估算激活内存，决定是否启用重计算和序列并行，并计算微批大小（micro batch size）是否可行。

**DeepSpeed**：
- ZeRO 初始化时会计算每个阶段（1/2/3）的参数分片与优化器状态分布，显存缩减量由公式估算得出。
- 激活内存由 Activation Checkpointing 模块管理，DeepSpeed 在 `deepspeed/runtime/zero/stage3.py` 等中通过参数收集 - 释放来控制。
- 提供 `memory_breakdown()` 函数获取详细显存分解（通过 `ds_engine.memory_breakdown()`）。

**典型显存跟踪代码片段（PyTorch）**：

```python
allocated = torch.cuda.memory_allocated() / 1024**3
reserved = torch.cuda.memory_reserved() / 1024**3
print(f"Allocated: {allocated:.2f} GB, Reserved: {reserved:.2f} GB")
```

### ④ Complexity Analysis（复杂度分析）

#### 4.3.1 模型状态显存（参数/梯度/优化器）复杂度

- 随参数量 P 线性增长：\( O(P) \)。
- 使用 Adam 混合精度时，每参数固定 16 bytes（或 12 bytes）。
- 典型示例：一个 7B 模型（P=7e9），模型状态显存 ≈ 7e9 × 16 = 112 GB（远超单卡 80 GB A100）。这正是必须采用 ZeRO-3 或张量并行的直接原因。

#### 4.3.2 激活值显存复杂度

假设微批大小 \( b \)，序列长度 \( s \)，隐藏维度 \( h \)，FFN 中间维度 \( d_{ff} \)，注意力头数 \( n_h \)，层数 \( L \)。不使用 Activation Checkpointing 时，每层必须保留的反向所需张量包括：

**Attention 子层保留项**：
1. **QKV 投影前的输入**（残差分支起点，用于残差梯度）：\( b \times s \times h \) × 2 bytes（FP16）
2. **Attention 的 Q、K、V**（用于 Score 反向）：各 \( b \times s \times h \)，共 3 个张量 → \( 3 b s h \) × 2 bytes
3. **Softmax 前的 Score 或 Softmax 输出**（取决于实现，通常需保留 Attention Weights）：\( b \times n_h \times s \times s \) × 2 bytes
4. **Attention Dropout Mask**（若有）：与 Score 同大小，\( b \times n_h \times s \times s \) × 1 byte（bool mask 或 bitmask）
5. **Output 投影前的聚合结果**（即 softmax × V 的结果）：\( b \times s \times h \) × 2 bytes

**MLP 子层保留项**：
1. **MLP 输入**（残差分支起点）：\( b \times s \times h \) × 2 bytes
2. **FC1 输出（激活前/后）**：\( b \times s \times d_{ff} \) × 2 bytes

**LayerNorm 保留项**：通常只保留输入（已包含在子层输入中），或额外保留用于归一化反向的统计量，量级为 \( O(b s) \)，忽略。

**单层激活量（主要项）近似**：
\[
M_{act\_layer} \approx \text{(Attention 部分)} + \text{(MLP 部分)}
\]
其中 Attention 的 Score 矩阵 \( b n_h s^2 \) 通常是大头。若使用 FlashAttention，由于其不将完整的 Score 矩阵写入 HBM，而是重计算 softmax，则 **该 \( s^2 \) 项完全消失**（这是其最大增益）。

**无 FlashAttention 时单层激活总量**（粗估）：
\[
M_{act\_layer\_no\_flashattn} \approx 2b \cdot s \cdot h \cdot (1+1+3+1)_{\text{多个输入/输出}} + 2b \cdot n_h \cdot s^2 + 2b \cdot s \cdot d_{ff}
\]
简化为：
\[
\approx 2b \left( k_1 s h + n_h s^2 + s d_{ff} \right) \ \ \text{bytes}
\]
其中 \( k_1 \) 为系数（6~10）。

**使用 FlashAttention 后**（去掉 \( n_h s^2 \) 项）：
\[
M_{act\_layer\_with\_FA} \approx 2b \left( k_2 s h + s d_{ff} \right)
\]
成为线性依赖于序列长度 \( s \)。

**总激活显存**（无重计算）：
\[
M_{act} = L \times M_{act\_layer} + \text{Embedding 输出等}
\]

#### 4.3.3 复杂度总结

| 组件 | 数量级 | 关键变量 |
|------|--------|----------|
| 模型参数/梯度/优化器 | \( O(P) \) | 隐藏维度 h, 层数 L |
| 激活值（无 FlashAttn, 无重计算） | \( O(L \cdot (b s h + b n_h s^2 + b s d_{ff})) \) | 序列长度 s² 主导 |
| 激活值（有 FlashAttn, 无重计算） | \( O(L \cdot b s h) \) | 微批大小 b, 序列长度 s 线性 |

当序列较长时，激活显存可远超模型状态。例如，训练 7B 模型，b=1, s=4096, h=4096, L=32，无 FA 时激活可能占据 ~60 GB，而有 FA 则降至 ~20 GB。加上模型状态的 112 GB，单卡显然无法容纳——必须分布式。

### ⑤ Design Trade-offs（权衡）

**Trade-off 1：模型状态 vs. 激活值**
- 在短序列训练中，模型状态（参数/优化器）占主导，优化策略是 ZeRO-1/2 或张量并行切分参数。
- 在长序列或大微批训练中，激活值可能成倍超过模型状态，必须启用 Activation Checkpoint 或 Sequence Parallel，以时间（重计算）换空间。
- 真正的瓶颈定位必须通过显存建模（25.1）完成。

**Trade-off 2：重计算 vs. 通信 vs. 参数分片**
- Activation Checkpoint 不引入额外通信，只增加额外前向计算（约 1.3~1.5 倍计算量），是最“廉价”的激活缩减手段。
- 序列并行（Sequence Parallel）将激活按序列维度切分，但引入通信（在 LayerNorm 和 Attention 处），与张量并行通信叠加时要小心。
- ZeRO-3 将参数、梯度、优化器状态分片，但运行时需要 AllGather 参数，增加通信量，需结合 NVLink 带宽评估。

**Trade-off 3：微批大小 b 的选择**
- b 越大，激活显存线性增加，但有利于提高 GPU 计算利用率（更大矩阵乘更高效）。
- 通常采用“梯度累积”技术使用逻辑大批次，维持小微批以控制激活显存，从而平衡计算效率和显存约束。

**Trade-off 4：FlashAttention 的取舍**
- 开启 FA 消除了 Score 矩阵的显存占用，允许更大序列长度或更大微批。
- 但 FA 对某些极端 head 维度或非标准注意力变体可能不支持，必须退回到标准实现。
- 在显存分析中，必须明确是否假设 FA，因为结果差异巨大。

**Trade-off 5：框架开销与碎片**
- 实际显存占用常比理论估算高 10%~20%。这部分来自：通信缓冲区（AllReduce/Gather 的临时缓冲）、cuBLAS/cuDNN 工作空间、PyTorch 分配器缓存碎片、CUDA 上下文等。
- 要精密建模，必须对齐到 25.1 Memory Model，结合框架实测。
