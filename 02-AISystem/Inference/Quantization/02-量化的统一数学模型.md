# 量化的统一数学模型：从数值映射到执行合同

本文位于“数值表示基础”与“量化方案分类”之间。[[01-数值表示与误差基础]] 已经解释有限 bit pattern 为什么只能形成离散数值集合；本文把这一事实抽象成从原始 Tensor 到低精度表示、再到计算的统一数学模型；[[03-量化方案的分类维度与粒度]] 则在本文符号之上讨论一套方案如何在多个独立分类轴上取值。因此，本文负责建立共同语言，不负责穷举格式、算法或 Kernel。

本文的核心不是某一条 scale 公式，而是依次回答四个问题：可存储的码字是什么，码字怎样映射到重建值，哪些元素共享映射参数，以及误差按什么目标衡量。传统 INT8/INT4 affine quantization、非均匀查表量化、带 Tensor scale 的 FP8、block floating point 与 microscaling 都是这套模型的不同实例，而不是彼此孤立的新概念。

## 2. 贯穿示例：把 BF16 Linear 权重量化为 group-wise INT4

先看一个常见的 LLM weight-only inference 场景。模型 checkpoint 中某个 Linear 层的权重原本用 BF16 保存；部署前把权重离线量化成 group-wise symmetric INT4，activation 在推理时仍保持 BF16。这类路径常简称为 `W4A16`，但这里的 `16` 必须进一步说明是 BF16 还是 FP16，accumulator 也要单独说明。

为了可以手算，下面只取一行权重中的 8 个元素作为一个教学 group：

$$
W_g=[-1,-0.5,-0.25,0,0.125,0.5,0.75,1].
$$

这些数都能被 BF16 精确表示，因此本例先隔离 INT4 量化误差，不把源格式的 representation error 混进来。真实模型可能沿 Linear 权重 $W[M,K]$ 的 K 轴每 32、64 或 128 个元素分组；group size 8 只是缩小后的演示，不代表某个标准格式或 Kernel 合同。

### 2.1 先把目标方案写完整

| 分类轴 | 本例选择 | 它决定什么 |
| --- | --- | --- |
| Source object | Linear weight 的一行，源 dtype 为 BF16 | 原始数值和矩阵语义 |
| Partition | 沿 K 轴每 8 个元素一组 | 哪些权重共享 scale |
| Element code | signed INT4，逻辑范围 $[-7,7]$ | 可用整数码字；`-8` 留空以保持正负对称 |
| Mapping | symmetric uniform、$Z=0$、RNE | 怎样从实数选择整数 code |
| Metadata | 每组一个 FP16 scale | decoder 怎样恢复真实单位 |
| Storage | two's-complement nibble，低 nibble 在前 | codes 怎样装入 bytes |
| Runtime | activation 为 BF16，权重 fused decode 后参与 GEMM | 不物化完整 BF16 权重副本 |
| Accumulation | 以具体 Kernel 合同为准，教学上假设 FP32 accumulate | 部分和在哪种精度中保存 |

这张表说明，“量化到 INT4”不是一次 dtype cast。目标对象实际上是 `packed INT4 codes + FP16 scales + group/layout descriptor`，运行时还必须有与它匹配的解码和计算路径。

### 2.2 Statistics：用本组最大绝对值确定覆盖范围

本例不做 percentile 或 MSE clipping，直接取

$$
a_g=\max_i|w_i|=1.
$$

对称 INT4 使用 $q_{\max}=7$，所以理想 scale 为

$$
S_g=\frac{a_g}{q_{\max}}=\frac{1}{7}\approx0.142857.
$$

这一步属于 statistics/range policy：它选择这一组 INT4 网格覆盖约 $[-1,1]$。如果组中出现权重 4，scale 会变成 $4/7$，同组普通权重的格点也会随之变疏；这就是 outlier 为什么会影响整组元素。

### 2.3 Normalize、round 与 clip：BF16 值变成 logical INT4 code

Encoder 为

$$
q_i=\operatorname{clip}\!\left(
\operatorname{round}\!\left(\frac{w_i}{S_g}\right),-7,7
\right).
$$

例如 $w=-0.5$ 时，$w/S_g=-3.5$；RNE 在两个候选 `-3` 与 `-4` 中选择偶数 `-4`。$w=0.75$ 时，$w/S_g=5.25$，舍入为 5。整组 logical codes 为

$$
Q_g=[-7,-4,-2,0,1,4,5,7].
$$

此时只有数学上的整数 code，还没有获得真实的 4-bit storage。如果程序把这些值放在 `int8` Tensor 中，它仍占 8 bit/element。

### 2.4 Metadata 也会舍入：FP16 scale 改变最终重建值

理想 scale $1/7$ 不能被 FP16 精确表示。若 checkpoint 实际保存

$$
\tilde S_g=\operatorname{FP16}(1/7)=0.142822265625,
$$

decoder 使用的就必须是 $\tilde S_g$，而不是推导时的无限精度 $1/7$：

$$
\hat w_i=\tilde S_g q_i.
$$

| BF16 source $w_i$ | INT4 code $q_i$ | reconstructed $\hat w_i$ | 总误差 $\hat w_i-w_i$ |
| ---: | ---: | ---: | ---: |
| -1 | -7 | -0.999755859375 | 0.000244140625 |
| -0.5 | -4 | -0.5712890625 | -0.0712890625 |
| -0.25 | -2 | -0.28564453125 | -0.03564453125 |
| 0 | 0 | 0 | 0 |
| 0.125 | 1 | 0.142822265625 | 0.017822265625 |
| 0.5 | 4 | 0.5712890625 | 0.0712890625 |
| 0.75 | 5 | 0.714111328125 | -0.035888671875 |
| 1 | 7 | 0.999755859375 | -0.000244140625 |

这里的总误差同时包含 element rounding 与 scale rounding。按这 8 个元素计算，reconstruction MSE 约为 $1.6301\times10^{-3}$，RMSE 约为 $0.04037$。这只评价权重重建，不等于 Linear 输出 MSE，更不等于模型任务质量变化。

### 2.5 Pack：8 个 logical codes 变成 4 个 bytes

采用 4-bit two's-complement，并约定第一个 code 放 low nibble，负数先按模 16 转成 nibble：`-7→0x9`、`-4→0xC`、`-2→0xE`。于是

```text
logical codes: [-7, -4, -2, 0, 1, 4, 5, 7]
nibbles:       [ 9,  C,  E, 0, 1, 4, 5, 7]
packed bytes:  [0xC9, 0x0E, 0x41, 0x75]
```

8 个 weight codes 的 data payload 从 BF16 的 16 bytes 降到 4 bytes，但该组还需 2 bytes 的 FP16 scale，因此这个微型示例的理想总成本是 6 bytes，即 6 bit/weight。若真实部署使用 group size 128，同样每组一个 FP16 scale，则理想成本为

$$
4+\frac{16}{128}=4.125\ \text{bit/weight},
$$

还未计入 padding、alignment、shape 与 format descriptor。Group 越小通常越贴合局部分布，但 metadata 摊销越高。

### 2.6 Runtime：不用先恢复整张 BF16 权重矩阵

推理时，activation $A$ 仍由 BF16 Tensor 提供。概念上可以先恢复 $\hat W$，再计算

$$
Y\approx A\hat W^\top.
$$

高效实现通常加载 packed bytes 和相应 scale，在寄存器或 shared memory 中 unpack/sign-extend codes、应用 $\tilde S_g$，随即把恢复值送入矩阵计算，而不把完整 $\hat W$ 写回 HBM。这就是 fused dequantization。具体是转换成 BF16/FP16 operand 后使用 MMA，还是由某种低精度指令直接消费 code 与 scale，必须由目标 Kernel 和硬件合同决定，不能从 `W4A16` 名字推断。

这个例子把完整路径连了起来：

$$
W_{\mathrm{BF16}}
\rightarrow \text{group/statistics}
\rightarrow (Q_{\mathrm{INT4}},S_{\mathrm{FP16}})
\rightarrow B_{\mathrm{packed}}
\rightarrow \text{unpack/decode}
\rightarrow A_{\mathrm{BF16}}\hat W^\top
\rightarrow Y.
$$

后文每个抽象符号都可以回到这个例子定位：$Q$ 是 logical INT4 codes，$M$ 至少包含 FP16 scale 与 group/layout 信息，$B$ 是 `0xC9 0x0E 0x41 0x75` 加 metadata 的物理表示，$D$ 是 sign-extend 后乘以 $\tilde S_g$ 的 decoder。

### 2.7 对照示例：BF16 token activation 动态量化为 INT8

权重通常可以在部署前离线量化并长期保存；activation 则由当前请求产生，分布随 batch、token 和时间变化。假设某个 token 的 BF16 hidden vector 片段为

$$
A_t=[0.5,-1,2,0],
$$

并在运行时对该 token 计算 symmetric INT8 scale。取 $q_{\max}=127$，则

$$
S_t=\frac{\max|A_t|}{127}=\frac{2}{127},
$$

$$
Q_t=\operatorname{round}(A_t/S_t)=[32,-64,127,0],
$$

对应重建值约为

$$
\hat A_t=[0.50394,-1.00787,2,0].
$$

这里 scale $S_t$ 不是 checkpoint 中的静态参数，而是推理时由当前 token reduction 得到的临时 metadata。INT8 code 已经自然占一个 byte，通常不需要 INT4 式 nibble packing，但 quantize、scale 生成与 metadata load 会进入在线 latency。若后续 Kernel 执行 W8A8 integer dot product，还必须同时知道权重 scale、zero-point 与 accumulator/output contract；若只是把 INT8 activation 再解码后参与浮点计算，获得的系统收益又不同。

两个示例共享同一数学模型，却位于不同生命周期：

| 对比项 | BF16 weight → INT4 | BF16 activation → INT8 |
| --- | --- | --- |
| 参数产生时间 | 部署前静态计算 | 当前 token 到来后动态计算 |
| Metadata 生命周期 | 随 checkpoint/权重常驻 | 请求或算子级临时存在 |
| 主要收益 | checkpoint/HBM weight traffic 降低 | activation traffic 或整数计算机会 |
| 主要新增成本 | 低位 packing、scale load、fused decode | runtime statistics、quantize、同步与 scale 传递 |

因此 static/dynamic 描述的是参数生命周期，不是 INT4/INT8 的固有属性；weight/activation 描述的是量化对象，也不自动决定 codebook 或 granularity。

## 3. 统一对象：量化 Tensor 由 codes 与解释参数共同构成

### 3.1 先看完整数据路径

高精度 Tensor 经过量化后，逻辑结果不是孤立的“INT4 数组”，而是低位 codes $Q$ 与解释它们的 metadata $M$：

$$
X_{\mathrm{real}}
\xrightarrow{\mathrm{quantize}}
(Q,M)
\xrightarrow{\mathrm{encode/pack}}
B.
$$

$M$ 可以包含 scale、zero-point、codebook、group/block shape、element format 与 axis 等；$B$ 是真正写入 checkpoint、HBM 或通信 buffer 的 bitstream。反向路径为

$$
B
\xrightarrow{\mathrm{unpack/parse}}
(Q,M)
\xrightarrow{\mathrm{dequantize}}
\hat{X}.
$$

这条路径包含三个必须分开的命名空间：**real-value domain** 中有 $X$ 与 $\hat X$；**logical-code domain** 中有整数、浮点 bit pattern或 table index $Q$；**physical-bit domain** 中有 bytes、nibbles、word packing、padding 和 alignment。数学上把 code限制到 $[-8,7]$ 并不会自动得到 4-bit storage；只有 pack到 bitstream并由相同 layout contract解码，才形成可交换的低位数据。

| 表示层        | 核心对象                                     | 必须回答                                  |
| ---------- | ---------------------------------------- | ------------------------------------- |
| 数值映射层      | range、scale、zero-point、codebook          | 哪些实数能被重建，间距与误差如何？                     |
| 逻辑码字层      | INT、FP、table index                       | code 的位宽、signedness、特殊值是什么？           |
| Metadata 层 | scale Tensor、zero-point、block descriptor | 哪些 code 共享参数，参数自身怎样编码？                |
| 物理存储层      | bitstream、packing、layout                 | bit 顺序、padding、alignment 与 shape 是什么？ |
| 恢复与计算层     | unpack、decode、MMA                        | 是否生成高精度 Tensor，还是边解码边计算？              |

因此，后文的 encoder/decoder首先定义数学语义；packing和Kernel是对该语义的物理实现。二者必须一致，但不能互相替代。

### 3.2 再定义标量量化器

设原始标量为 $x\in\mathbb{R}$，可存储码字的有限集合为 $\mathcal{I}$，量化参数与元数据统称为 $\theta$。一个完整量化器可写成 encoder 与 decoder：

$$
q=E_\theta(x),\qquad q\in\mathcal{I},
$$

$$
\hat{x}=D_\theta(q),
$$

其中 $q$ 是实际编码或存储的 code，$\hat{x}$ 是 decode/dequantize 后的重建值。给定 $\theta$ 后，decoder 产生的有限集合

$$
\mathcal{C}_\theta=\{D_\theta(q):q\in\mathcal{I}\}
$$

就是该组数据的 **reconstruction codebook**。量化误差为

$$
e(x)=\hat{x}-x.
$$

这个写法有意区分 $\mathcal{I}$ 与 $\mathcal{C}_\theta$。对 affine INT8，$\mathcal{I}$ 是 `int8` 或 `uint8` 的整数集合，而 $\mathcal{C}_\theta$ 是经过 scale 与 zero-point 映射后的实数格点；对 NF4，$q$ 可以是 4 bit table index，decoder 再查找非均匀浮点码字；对 FP8，$q$ 的 bit pattern 本身具有浮点解码规则，而外层 Tensor scale 还会再次改变最终重建集合。所谓“codebook”必须说明是在 element format 层，还是包含 metadata 后的 Tensor reconstruction 层。

从标量推广到 Tensor 时，需要进入上表中的 **Tensor 组织层**。量化器先由 partition function $P$ 将元素分到若干组 $G_1,\ldots,G_K$，每组计算或学习自己的 $\theta_k$：

$$
q_i=E_{\theta_{g(i)}}(x_i),\qquad
\hat{x}_i=D_{\theta_{g(i)}}(q_i),
$$

其中 $g(i)$ 表示元素 $i$ 属于哪一组。Per-tensor、per-channel、per-token 与 per-block 的数学区别首先就是 $g(i)$ 不同；它们不会自动决定 codebook、对称性或舍入方法。粒度的布局和开销将在下一篇单独展开。

## 4. 数学表示层：先掌握 uniform affine INT

本文先讲 uniform affine INT，因为它把 scale、zero-point、clipping 与 rounding 的职责暴露得最清楚。它只是统一模型的一个特例；第 7 节再把相同符号扩展到查表码本与浮点码本。

### 4.1 Scale 决定整数 code 的实数语义

最常见的线性整数方案把重建值放在等间距格点上。设整数码字范围为 $[q_{\min},q_{\max}]$，scale $S>0$，integer zero-point 为 $Z$，则 decoder 为

$$
D_{S,Z}(q)=S(q-Z).
$$

相应 encoder 为

$$
E_{S,Z}(x)=
\operatorname{clip}\!\left(
\operatorname{round}\!\left(\frac{x}{S}\right)+Z,
q_{\min},q_{\max}
\right).
$$

这就是常见的 affine uniform quantization。其 reconstruction codebook 为

$$
\mathcal{C}_{S,Z}=\{S(q-Z)\mid q\in\mathbb{Z},\ q_{\min}\le q\le q_{\max}\},
$$

相邻重建值始终相差 $S$，所以 $S$ 同时是 quantization step size。这里采用“实数单位/整数 code”的 scale 约定；部分论文或 Kernel 保存它的倒数 $S^{-1}$ 并写成 $q=\operatorname{round}(xS^{-1})$。二者数学等价，但变量同名时非常容易造成方向错误，因此分析实现必须从实际 encode/decode 公式判断 scale 的语义。

例如同一个 INT4 code $q=5$，当 $S=0.1$ 时表示 $\hat x=0.5$，当 $S=2$ 时表示 $\hat x=10$。这说明 dtype只限定 code domain，scale才把 codebook放到目标 Tensor 的实数坐标系。可以把 symmetric integer quantization类比为“整数 significand + 外部 exponent-like scale”，但这只是帮助理解：任意浮点 scale不必是2的幂，也不等同于 IEEE exponent encoding。

### 4.2 Uniform codebook 是一张离散网格

若 $S=0.25,Z=0$，reconstruction codebook是

$$
\ldots,-0.50,-0.25,0,0.25,0.50,\ldots
$$

bit数固定时，扩大覆盖范围必须增大 $S$，相邻grid point变远；减小 $S$ 能提高局部absolute resolution，却缩小有限码字能覆盖的range。这个 range–resolution trade-off 是 uniform quantization的基本约束。浮点和non-uniform codebook改变了格点分布，但有限码字下“把表示能力分配到哪里”的问题仍然存在。

Zero-point 的主要价值不是笼统地“提高精度”，而是让真实值零可被整数码字精确表示：

$$
D_{S,Z}(Z)=0.
$$

这对 zero padding、ReLU、稀疏值，以及把多个量化算子连接起来很重要。若 $Z$ 必须是整数且落在 code range 内，零才能无误差表示。某些方案使用浮点 zero-point、隐式 offset，或者根本不要求零属于 codebook；看到“asymmetric”时不能默认其 metadata 一定是传统 integer $Z$。

### 4.3 Range policy 与 zero alignment：怎样放置这张网格

Range policy 与 zero alignment 都属于数学表示层，但回答不同问题。前者选择有限码字覆盖哪段实数范围，后者规定真实值零与码字怎样对齐；它们共同决定 $S$ 与 $Z$，却不改变“uniform 表示相邻重建值等距”这一事实。

#### Affine range fitting

设一组数据希望覆盖的 clipping range 为 $[\alpha,\beta]$，且 $\alpha<\beta$。对 affine mapping，先令两端跨度相等：

$$
S=\frac{\beta-\alpha}{q_{\max}-q_{\min}}.
$$

再令 $\alpha$ 尽量映射到 $q_{\min}$，可取

$$
Z=\operatorname{clip}\!\left(
\operatorname{round}\!\left(q_{\min}-\frac{\alpha}{S}\right),
q_{\min},q_{\max}
\right).
$$

若要求零精确可表示，通常先把观测范围扩展为 $\alpha\leftarrow\min(\alpha,0)$、$\beta\leftarrow\max(\beta,0)$。由于 $Z$ 需要舍入为整数，最终 codebook 端点一般只近似等于原始 $\alpha$ 和 $\beta$；不能同时假定两端严格对齐、零严格对齐且 $S$ 固定不变。

#### Symmetric range fitting

**Symmetric quantization** 是 affine family 的一个受约束子类，常令 $Z=0$，并以 $a=\max(|\alpha|,|\beta|)$ 设置范围。对于有符号 $b$ bit 存储，一种常见选择是使用对称码字 $[-(2^{b-1}-1),2^{b-1}-1]$：

$$
S=\frac{a}{2^{b-1}-1},\qquad Z=0.
$$

INT8 时这对应 $[-127,127]$，会空出存储码字 $-128$，换来正负完全对称的有限 codebook。另一些框架允许 $[-128,127]$ 全范围，或者使用不同端点与 midpoint 约定。因此“symmetric INT8”仍不足以唯一确定 scale 公式；必须同时记录 quantization range。

Asymmetric 并不意味着 non-uniform。上述 affine asymmetric 方案仍是等间距 uniform codebook，只是零点相对整数区间发生平移；symmetric 也不必然意味着 uniform，例如一个正负成对但间距不等的查表 codebook 可以是 symmetric non-uniform quantization。这两组术语属于不同分类轴。

### 4.4 Mapping pipeline：normalize、round、clip 与 encode

确定 codebook 的位置之后，encoder 还要规定输入怎样投影到它。下面四步属于 **mapping/encoding**，不能从 `INT4`、`INT8` 等 element dtype 名称自动推出。

#### Clipping：先决定有限码字覆盖哪里

设有效实数范围为 $[\alpha,\beta]$，可先写

$$
x_c=\operatorname{clip}(x,\alpha,\beta).
$$

Clipping是主动范围选择：它牺牲尾部值，换取主体区域更小的step。浮点算术overflow则是精确结果超过格式范围；二者表象都可能是饱和到边界，但语义和可控参数不同。

#### Normalize：从实数单位进入 code units

Affine encoder 可以拆成三个阶段：

$$
r=\frac{x}{S},\qquad
q^*=\operatorname{round}(r)+Z,\qquad
q=\operatorname{clip}(q^*,q_{\min},q_{\max}).
$$

Normalize除以 $S$ 后，1 个 code unit对应 $S$ 个真实单位。实现若保存 inverse scale，则会改写成乘法，但应得到相同 code-space坐标。

#### Rounding：把连续坐标投影到离散 code

Normalize 把真实单位转换为 code-space 单位；round 将连续位置投影到离散整数；clip 处理超出可用 code range 的值。这三步产生的误差性质不同。在 clipping range 内，round-to-nearest 的绝对误差通常满足

$$
|\hat{x}-x|\le \frac{S}{2},
$$

中点 tie 如何处理由具体 rounding rule 决定。超出 $[\alpha,\beta]$ 后，误差不再受 $S/2$ 约束，而会随超界距离增大。例如上界饱和时，误差近似为 $x-D(q_{\max})$。因此减小 clipping range 可以减小范围内的 step size，却会增加 tail clipping；扩大范围可以保留 outlier，却让主体区域的格点变稀。

Round-to-nearest-even（RNE）在tie时选择最低有效位为偶数的候选，减少长期向单侧取整的偏差；truncation直接丢弃小数部分，通常带有方向性偏差；stochastic rounding按到相邻码字的距离分配概率，常用于低精度训练。Rounding policy属于mapping，不是INT4、FP8等dtype名称自动决定的属性。

#### Encode：logical code 到有限 bit pattern

Rounding得到的逻辑整数还要按code dtype解释。Signed INT4的bit pattern `1110` 若采用二进制补码表示 $-2$，作为unsigned nibble则是14。恢复时必须先按相同signedness做sign extension，再应用zero-point和scale。具体nibble顺序、word packing与vector load留到存储篇展开，但它们已经属于量化格式的必要contract。

这构成量化范围选择的基本 bias–resolution trade-off。直接使用 min/max 可以避免校准样本上的 clipping，但一个极端 outlier 就可能显著增大所有普通值的 rounding error。Percentile、MSE、KL divergence 等 calibration 方法，本质上是在不同目标下选择 $[\alpha,\beta]$，而不是创造一种新的 storage dtype。

## 5. 评价层：误差必须对应评价目标

前三节定义“怎样表示”，本节转到“怎样判断这种表示是否足够好”。评价目标不属于 element codebook 或 mapping 本身，而是选择参数、比较方案和训练模型时使用的准则。

最简单的 Tensor distortion 是均方误差：

$$
\mathcal{L}_{\mathrm{MSE}}(X,\hat{X})
=\frac{1}{N}\sum_{i=1}^{N}(x_i-\hat{x}_i)^2.
$$

也可以使用最大绝对误差、平均绝对误差、signal-to-quantization-noise ratio，或按元素重要性加权：

$$
\mathcal{L}_{W}(X,\hat{X})
=(X-\hat{X})^\top W(X-\hat{X}).
$$

但是，局部 reconstruction MSE 较小不等于模型输出误差或任务 loss 一定较小。某些权重方向对层输出极其敏感，某些 activation outlier 又可能只在少数 token 出现。GPTQ 的二阶近似、AWQ 的 activation-aware 保护、QAT 的任务损失训练，都可理解为改变了“什么误差最重要”或让模型参数适应该误差；这些算法将在后续专项中展开。

### 5.1 误差来源沿数据路径分层

量化误差至少可以拆成以下来源：

| 误差来源 | 发生位置 | 主要控制变量 |
| --- | --- | --- |
| Range estimation error | statistics / calibration | 数据代表性、observer、动态或静态参数 |
| Clipping error | mapping 边界 | $[\alpha,\beta]$、outlier policy |
| Rounding error | 连续值投影到 codebook | step/codebook density、rounding rule |
| Metadata quantization error | scale/zero-point 的存储 | metadata dtype、二次量化、shared scale |
| Packing/interpretation error | storage 与 load | nibble 顺序、signedness、layout、type tag |
| Arithmetic error | decode/compute/accumulate | operand dtype、accumulator precision、reduction order |
| Model/task error | 网络输出 | 层敏感度、误差传播、模型适配方法 |

其中 packing/interpretation error 通常属于实现错误而非方案允许的有损误差，但在系统调试中必须单列。Metadata 也不是“免费且精确”的：scale 可能以 FP16、BF16、FP8 或 exponent-only code 存储，其舍入会整体移动一组元素的 reconstruction codebook；scale 本身还可能被 double quantization 再压缩。

## 6. 基础特例的闭环验证：affine UINT8

这个例子把第 3–5 节连成一次完整闭环：先确定 code domain 与映射参数，再执行 encode/decode，最后观察范围内舍入误差与范围外 clipping error。它不是新的量化类别。

考虑一组高精度值，校准范围为 $[-1.2,0.8]$，使用 `uint8` code range $[0,255]$、RNE 和 affine mapping。Scale 为

$$
S=\frac{0.8-(-1.2)}{255}=\frac{2}{255}\approx0.0078431373,
$$

zero-point 为

$$
Z=\operatorname{round}\left(0-\frac{-1.2}{S}\right)=153.
$$

对 $x\in\{-1.2,-0.5,0,0.3,0.8,1.0\}$ 逐个执行 normalize、round、offset、clip 与 decode，可得：

| $x$ | $x/S+Z$ | $q$ | $\hat{x}=S(q-Z)$ | 误差 $\hat{x}-x$ | 说明 |
| ---: | ---: | ---: | ---: | ---: | --- |
| -1.2 | 0 | 0 | -1.2 | 0 | 下端点 |
| -0.5 | 89.25 | 89 | $-128/255\approx-0.501961$ | $-0.001961$ | 范围内舍入 |
| 0 | 153 | 153 | 0 | 0 | zero-point 精确表示零 |
| 0.3 | 191.25 | 191 | $76/255\approx0.298039$ | $-0.001961$ | 范围内舍入 |
| 0.8 | 255 | 255 | 0.8 | 0 | 上端点 |
| 1.0 | 280.5 | 255 | 0.8 | -0.2 | 超范围后 clipping |

这个例子也揭示 metadata 与 storage 的区别：每个 $q$ 只占 1 byte，但要解释这些 byte，消费者还需要 $S$、$Z$、code dtype、参数作用范围与 layout。若仅保存 `0, 89, 153, 191, 255` 而丢失这些信息，就无法恢复对应的实数语义。

## 7. 数学表示层的扩展：非均匀、浮点与层次化 codebook

Affine UINT8 的网格只是 **element codebook/mapping geometry** 这一分类轴上的一个取值。换成非均匀查表或浮点解码时，Tensor 组织层、metadata 与执行层仍可沿用第 3 节的对象模型。

### 7.1 通用 decoder：把 element codebook 与 group scale 分开

大量方案可以进一步统一为

$$
\hat{x}_i=S_{g(i)}D(q_i;\theta_{g(i)}),
$$

其中 $D$ 是element decoder。Symmetric INT令 $D(q)=q$；asymmetric INT令 $D(q;Z)=q-Z$；FP8令 $D$ 按具体浮点encoding解释bit pattern；NF4令 $D(q;C)=C[q]$。MX类格式则把element decode与规范定义的block scale结合。看到新格式时，首先确定 $q$、$D$、$S_g$ 和 $\theta_g$，无需另造一套不相容的数学语言。

### 7.2 显式 codebook：non-uniform table lookup

Affine integer quantization 不是统一模型的边界。设有任意排序的重建表

$$
\mathcal{C}=\{c_0,c_1,\ldots,c_{K-1}\},
$$

nearest-neighbor scalar quantizer 可写为

$$
E(x)=\underset{j}{\arg\min}\ |x-c_j|,
\qquad D(j)=c_j.
$$

若 $c_j$ 间距不等，就是 non-uniform quantization。K-means weight sharing、NF4 和某些对数量化都可以在这一框架下描述；差异在 codebook 如何生成、是否固定、是否按组缩放，以及 lookup 能否被硬件高效实现。

### 7.3 隐式 codebook：浮点 encoding

浮点 element format 也提供非均匀 codebook，只是 decoder 由 sign/exponent/fraction 规则实现，而不是显式 table lookup。若在外层增加 scale $S_g$，则可写为

$$
q_i=\operatorname{encode}_{\mathrm{FP}}(x_i/S_g),
\qquad
\hat{x}_i=S_g\operatorname{decode}_{\mathrm{FP}}(q_i).
$$

这与 affine INT 在统一数据路径上具有相同结构，却具有不同的 element codebook、overflow 规则和硬件 compute contract。传统 block-scaled FP8 与标准 MX 的具体差异，不能仅凭这条抽象公式判断，后续必须加入规范规定的 block size、scale code、特殊值和 dot-product 语义。

### 7.4 层次化表示：Metadata 本身也可以被量化

Metadata 在这里不是突然加入的存储附件，而是第 3 节中 $M$ 的数值部分：它参与 decoder，因而直接决定 reconstruction codebook。若 scale 本身再次编码，统一 decoder 就自然递归一层。

#### Scale 的递归编码

当group很小时，scale数量增多。若local scale $S_g$ 也被低位编码，可引入global scale $S_0$ 与scale code $q^S_g$：

$$
S_g\approx S_0D_S(q^S_g),
$$

于是数据重建为

$$
\hat{x}_i
=S_0D_S(q^S_{g(i)})D_X(q^X_i).
$$

这就是hierarchical scaling或double quantization的基本结构。它降低metadata bytes，却增加scale reconstruction error和一层decode。OCP MX的E8M0 block scale、QLoRA对量化常数的double quantization、NVFP4的local/global scale虽然都可放入该递归模型，但codebook、粒度和标准语义不同，不能因为公式相似就视为同一格式。

#### Metadata 与 codes 必须保持绑定

Codes、scale和zero-point必须以一致的group ordering绑定。仅保存packed codes而遗漏scale Tensor，或使用错误axis解释scale，得到的不是“略有误差”的同一Tensor，而是另一组数值。Format version、shape、axis、group size与layout descriptor因此也是语义metadata，不能全部视为文件容器的无关附属信息。

## 8. 存储与执行层：同一数学语义的不同实现

到第 7 节为止，讨论的是量化表示的数学语义。本节不再引入新的 codebook 分类，而是说明相同 decoder 怎样落实为内存路径与计算合同。

### 8.1 Dequantization 的三种实现形态

**Logical dequantization** 是数学关系 $\hat{x}=D_\theta(q)$；它不要求内存中出现高精度副本。**Materialized dequantization** 先把完整 $\hat X$ 写成FP16/BF16/FP32 Tensor，再交给普通算子，路径简单但可能重新产生大量HBM traffic。**Fused dequantization** 在load packed data后于register/shared memory中decode，并立即送入MMA或其他计算，不把完整高精度Tensor写回HBM。

三种形态可以实现相同的logical values，却有完全不同的带宽和Kernel结构。后续存储与Kernel篇会深入physical path；在数学基础篇先建立这一区分，是为了避免把“公式里出现dequantize”误解成“一定先生成完整FP16 Tensor”。

### 8.2 从 dequantize-then-compute 到整数计算

概念上，量化矩阵乘可先把输入重建为高精度再计算：

$$
Y\approx \hat{X}\hat{W}.
$$

但 affine integer scheme 允许把大部分工作移到整数域。若

$$
\hat{x}_i=S_x(q_{x,i}-Z_x),\qquad
\hat{w}_i=S_w(q_{w,i}-Z_w),
$$

则一个 dot product 为

$$
\sum_i \hat{x}_i\hat{w}_i
=S_xS_w\sum_i(q_{x,i}-Z_x)(q_{w,i}-Z_w).
$$

展开后得到

$$
S_xS_w\left[
\sum_i q_{x,i}q_{w,i}
-Z_w\sum_iq_{x,i}
-Z_x\sum_iq_{w,i}
+nZ_xZ_w
\right].
$$

这说明 zero-point 会引入 row sum、column sum 或等价补偿项；权重若采用 $Z_w=0$，可减少部分修正工作。真实 Kernel 可以预计算某些和、融合 correction 与 requantization，或使用硬件 dot-product 指令，但其收益取决于 layout、granularity、目标 ISA 与算子形状。数学上能在整数域表达，并不自动保证比反量化后计算更快。

若输出还要量化为 $S_y,Z_y$，则 accumulator 经过 bias、乘以 $S_xS_w/S_y$、舍入和 clipping 后才得到输出 code。整数-only inference 往往用定点乘数与 shift 近似这个 scale ratio。这一阶段称为 requantization，是新的有损 mapping；不能只分析输入权重的一次 quantize/dequantize 就认为误差路径结束。

## 9. Tensor 组织层的另一条分类轴：参数生命周期

本节讨论的 static、dynamic、delayed 与 learned 不描述 codebook 形状，也不描述存储 dtype；它们只描述 $\theta$ 在何时、由什么数据产生。把它们单列，是为了避免与 PTQ/QAT 或 symmetric/asymmetric 混为一谈。

统一记号 $\theta$ 包含 scale、zero-point、clipping range 或 codebook，但不规定这些参数何时产生。它们可以由离线 calibration 固定，可以在每次 inference 时从当前 Tensor 动态计算，可以在训练中学习，也可以采用 delayed scaling，用历史 amax 更新下一步参数。Static/dynamic 描述的是 parameter lifecycle；PTQ/QAT 描述的是模型在训练前后如何得到或适应量化方案。两者相关，但不是同一个分类轴。

训练或校准时常使用 fake quantization：前向执行

$$
X_{\mathrm{fq}}=D_\theta(E_\theta(X)),
$$

但把结果保存在较高精度 dtype 中，使后续普通浮点算子看到量化后的离散重建值。Fake quant 模拟数值误差，却不代表模型已经获得低 bit packed storage 或低精度 Kernel 加速。真正部署还需要 lowering、packing、量化算子和硬件 backend 共同满足 compute contract。

## 10. 综合检查：把各层重新接成一条数据合同

分析任何量化方案时，应至少填写下面的 contract：

| 阶段 | 必须回答的问题 |
| --- | --- |
| 原始 Tensor | dtype、shape、语义对象和分布特征是什么？ |
| Partition | 沿哪些轴分组，边界块如何处理？ |
| Statistics | range/codebook 如何估计，使用哪些数据，何时更新？ |
| Metadata | scale、zero-point 或 shared exponent 的语义、dtype、shape 是什么？ |
| Normalize / map | 是否 affine，如何 clipping，采用何种 rounding？ |
| Encode | element codebook、特殊值与饱和规则是什么？ |
| Pack / storage | 实际 bits/element、padding、alignment、metadata 排布是什么？ |
| Load / decode | 谁负责 unpack，何时应用 metadata，是否产生中间 Tensor？ |
| Compute | 是 weight-only、整数 dot、原生低精度 MMA 还是 fused decode？ |
| Accumulate / output | accumulator dtype、reduction 顺序和 requantization 是什么？ |
| Objective | 评价 reconstruction、layer output、task quality，还是端到端性能？ |

只有完整填写这条路径，`W4A16`、`INT8_BLOCK128` 或 `FP8` 之类标签才足以用于系统比较。否则，同名方案可能在 scale 方向、group axis、zero-point、packing 和 Kernel 上完全不同。

## 11. 最小实验：观察位宽、outlier 与 granularity 的联动

实验中的 `bits` 属于 element codebook，`group_size` 属于 Tensor 组织层，RMSE/cosine 属于评价层，而 `torch.int8` 容器属于存储层。把这四类变量同时标出，正是为了练习在一条数据路径中定位概念，而不是把它们视作同一级选项。

在进入 GPTQ、AWQ 等算法前，最有价值的 baseline 是自己实现 symmetric RTN。下面的 PyTorch 程序只模拟 quantize/dequantize 后的重建值，不进行真实 INT4 packing，也不调用低精度 GEMM。它依次比较 INT8/INT4、是否加入 outlier，以及 per-tensor/group128/group32 的 RMSE、cosine similarity 与逻辑 metadata 成本。

```python
import torch
import torch.nn.functional as F


def symmetric_rtn(x: torch.Tensor, bits: int, group_size: int):
    """按连续 group 做 symmetric RTN；本实验要求 numel 可被 group_size 整除。"""
    assert x.numel() % group_size == 0
    qmax = 2 ** (bits - 1) - 1

    groups = x.reshape(-1, group_size)
    scale = groups.abs().amax(dim=1, keepdim=True) / qmax
    scale = scale.clamp_min(torch.finfo(torch.float32).tiny)

    q = torch.round(groups / scale).clamp(-qmax, qmax).to(torch.int8)
    x_hat = (q.float() * scale).reshape_as(x)
    return q.reshape_as(x), x_hat, scale.squeeze(1)


def report(name: str, x: torch.Tensor, bits: int, group_size: int):
    _, x_hat, scales = symmetric_rtn(x, bits, group_size)
    rmse = (x - x_hat).square().mean().sqrt().item()
    cosine = F.cosine_similarity(x, x_hat, dim=0).item()

    # 假设每组一个 FP16 scale，无 zero-point；不计 padding 与容器开销。
    effective_bits = bits + 16 / group_size
    print(
        f"{name:24s} bits={bits} group={group_size:4d} "
        f"rmse={rmse:.6f} cosine={cosine:.8f} "
        f"scales={scales.numel():3d} effective_bits={effective_bits:.3f}"
    )


torch.manual_seed(0)
x = torch.randn(1024, dtype=torch.float32)
x_with_outlier = x.clone()
x_with_outlier[0] = 50.0

for tensor_name, tensor in [("normal", x), ("with_outlier", x_with_outlier)]:
    for bits, group_size in [
        (8, 1024),  # per-tensor INT8
        (4, 1024),  # per-tensor INT4
        (4, 128),
        (4, 32),
    ]:
        report(tensor_name, tensor, bits, group_size)
```

预期应观察到三条趋势，但应以实际输出而不是口号为准。相同 group 下从 8 bit 降到 4 bit，codebook 变稀，通常使误差增大；在 per-tensor 方案中加入幅值 50 的 outlier，会使 scale 被它主导并显著损害其他值；把 INT4 group 从整个 Tensor 缩小到 128 或 32，outlier 只影响局部组，通常降低全局 RMSE，但 scale 数量和 `effective_bits` 上升。

这个实验还刻意揭示 storage 与 fake quant 的差别：变量 `q` 使用 `torch.int8` 容器，所以即便 code 被限制在 INT4 范围，内存仍是 8 bit/element。只有进一步把两个 4-bit code pack 到一个 byte，并由对应 Kernel 正确 unpack，才获得真实 INT4 data storage。类似地，较低 RMSE 不保证模型任务质量更好，也不保证端到端运行更快；这些需要逐层输出、模型评测和 Kernel benchmark。

## 12. 小结

量化不是简单的 dtype cast，而是受参数 $\theta$ 控制的有限码字编码与重建过程。Affine INT 只是其中一个重要特例；其 scale 决定格点间距，zero-point 决定零如何对齐，rounding 处理范围内投影，clipping 处理范围外值。精度评价又必须区分局部重建误差、算子输出误差与任务损失。下一篇将固定这套符号，专门分析 symmetric/asymmetric、uniform/non-uniform、static/dynamic 与 granularity 等分类轴如何正交组合，以及 group/block 大小如何同时影响误差、metadata、layout 和 Kernel 效率。

- [PyTorch Quantization API Reference](https://docs.pytorch.org/docs/main/quantization-support.html)：用于核对 affine quantizer、scale/zero-point、granularity 与 observer/fake-quant 概念。PyTorch main 文档会随版本变化，具体部署应固定 PyTorch/torchao 版本和 backend。

本文的 affine UINT8 示例按所列公式手工推导；BF16 weight → INT4 与 BF16 activation → INT8 示例的 codes、FP16 scale、重建值、MSE 和 packed bytes 已用 Python 3.12.14、NumPy 2.3.5 复核。示例中的 nibble order 与 group size 8 是明确声明的教学合同，不代表通用文件格式。最小 PyTorch 实验用于读者本地验证 RTN 趋势；本文没有运行真实量化 Kernel、模型精度评测或性能 benchmark，部署性能、accumulator width、packing 与 requantization 指令将在对应 Kernel/Runtime 笔记中结合具体实现验证。
