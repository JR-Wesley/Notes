# 性能评估

## 性能基准测试工具

`llama.cpp` 包含用于对模型性能不同方面进行基准测试的专用工具。

### 1. `llama-bench`

**目的与功能：**

`llama-bench` 是一个命令行工具，旨在衡量 `llama.cpp` 在各种配置下的推理性能。它允许用户测试不同的模型、量化类型、提示长度、生成长度、批量大小、线程数和其他参数，以了解它们对速度和资源使用的影响。

该工具通过加载指定的 GGUF 模型并使用可配置的参数运行推理来工作。然后它会输出详细的性能指标。

**代码参考：**

- [llama-bench.cpp](https://github.com/ggml-org/llama.cpp/blob/master/tools/llama-bench/llama-bench.cpp)

**主要衡量指标：**

- 处理提示的时间（提示处理速度）
- 生成令牌的时间（令牌生成速度）
- 每秒令牌数
- 内存使用情况
- 不同量化方法的效果
- 线程和批量大小的可伸缩性

**使用示例：**

```bash
./llama-bench -m ./models/mymodel/ggml-model-Q4_K_M.gguf -p 512 -n 128 -t 8 -ngl 32
```

此命令将使用 512 个令牌的提示长度、生成 128 个令牌、使用 8 个线程并将 32 个层卸载到 GPU 来对模型 `ggml-model-Q4_K_M.gguf` 进行基准测试。

**输出解读：**

该工具以多种格式（CSV、JSON、Markdown、SQL）输出数据，其中包括推理不同阶段的时间、平均速度和标准差。这有助于识别瓶颈和最佳配置。

**源代码片段（说明性 - 参数解析）：** 有关详细的参数解析和基准测试循环，请参阅 `tools/llama-bench/llama-bench.cpp` 中的 `main` 函数。具体的解析逻辑由 `llama_bench_params_parse` 处理。

### 2. `batched-bench`

**目的与功能：**

`batched-bench` 是一个专门用于对 `llama.cpp` 的批量解码性能进行基准测试的工具。批量解码对于需要同时处理多个独立序列的场景至关重要，可以提高整体吞吐量。该工具有助于评估 `llama.cpp` 如何处理此类工作负载。

它支持两种主要操作模式：

- **提示不共享：** 批次中的每个序列都有其自己独特的提示。
- **提示共享：** 批次中的所有序列都使用一个共同的提示，只有后续的生成内容不同。

**代码参考：**

- [batched-bench.cpp](https://github.com/ggml-org/llama.cpp/blob/master/tools/batched-bench/batched-bench.cpp)

**主要衡量指标：**

- 批处理的提示处理时间 (T_PP)
- 批处理的提示处理速度 (S_PP, 令牌/秒)
- 批处理的令牌生成时间 (T_TG)
- 批处理的令牌生成速度 (S_TG, 令牌/秒)
- 整个批处理操作的总时间和速度。
- 基于并行序列数（`-npl` 参数）的性能特征。

**使用示例：**

```bash
./llama-batched-bench -m model.gguf -c 2048 -b 2048 -ub 512 -npp 128,256,512 -ntg 128,256 -npl 1,2,4,8,16,32
```

此命令测试模型 `model.gguf`，上下文大小为 2048，批量大小为 2048，ubatch 大小为 512，针对各种提示处理长度 (`-npp`)、令牌生成长度 (`-ntg`) 和并行序列数 (`-npl`)。

**输出解读：** 该工具输出一个表格，显示针对不同提示长度 (PP)、令牌生成长度 (TG)、批量大小 (B) 和 KV 缓存大小 (N_KV) 组合的性能指标。


**源代码片段（说明性 - 主循环）：** 请参阅 `tools/batched-bench/batched-bench.cpp` 的 `main` 函数（大约 100-150 行）中迭代 `n_pp`、`n_tg` 和 `n_pl` 的嵌套循环。核心解码逻辑位于 `decode_helper` lambda 函数（大约 56-76 行）内。

## 令牌生成性能技巧

优化令牌生成速度对于交互式应用程序至关重要。以下是一些关键考虑因素：

**代码参考：**

- [token_generation_performance_tips.md](https://github.com/ggml-org/llama.cpp/blob/master/docs/development/token_generation_performance_tips.md)

### 1. GPU 卸载 (CUDA)

- **验证：** 确保 `llama.cpp` 已编译并支持 CUDA。构建过程应能正确识别您的 CUDA 工具包。
- **用法：** 使用 `-ngl N` (或 `--n-gpu-layers N`) 标志将模型层卸载到 GPU。将 `N` 设置为一个较大的值（例如 `200000`）将卸载尽可能多的层。
- **诊断输出：** 在控制台输出中查找类似 `[cublas] offloading X layers to GPU` 的行以确认 GPU 使用情况。

**源代码片段（来自 `token_generation_performance_tips.md`）：**

```shell
./llama-cli -m "path/to/model.gguf" -ngl 200000 -p "Please sir, may I have some "
```

（见于 [token_generation_performance_tips.md](https://github.com/ggml-org/llama.cpp/blob/master/docs/development/token_generation_performance_tips.md)）

### 2. CPU 线程管理

- **过度饱和：** 使用过多的 CPU 线程可能会因上下文切换开销而降低性能。
- **参数：** 使用 `-t N` (或 `--threads N`) 标志来控制 CPU 线程的数量。
- **调优：**
    - 从 `-t 1` 开始。
    - 如果这显著提高了速度，则您的 CPU 可能已过度饱和。
    - 逐渐增加 `N`（例如，增加到物理 CPU核心数）。
    - 通过测试找到最佳的 `N`；如果性能下降，则减少 `N`。

### 3. Flash Attention

- **目的：** Flash Attention 是一种优化的注意力机制，可以通过减少内存 I/O 来显著加快推理速度，尤其对于长序列。
- **用法：** 如果 Flash Attention 已编译并启用，`batched-bench` 工具（以及其他示例）通常会包含 `params.flash_attn` 标志或类似机制。其可用性和用法取决于特定的后端（例如 CUDA、Metal）。
- **验证：** 检查构建选项和运行时日志以确认 Flash Attention 是否已激活。

**代码参考（说明性 - `batched-bench`）：** `tools/batched-bench/batched-bench.cpp` 中的 `params.flash_attn` 变量（例如，第 95 行）表明其在基准测试中的考虑。实际的 Flash Attention 实现位于 `ggml` 库和后端特定代码的更深层次。

### 4. 批处理和微批处理 (UBathing)

- **批处理 (`-b`)：** 在单个 `llama_decode` 调用中处理多个令牌或序列。这通常比一次处理一个令牌更有效。`ctx_params.n_batch` 控制此项。
- **微批处理 (`-ub` 或 `n_ubatch`)：** 为更细粒度的处理而对批次进行进一步细分，尤其适用于并行解码或管理非常大批次的内存。
- **调优：** 使用 `llama-bench` 或 `batched-bench` 试验不同的批处理和微批处理大小，以找到适合您的硬件和模型的最佳值。

**代码参考 (`batched-bench`)：** `tools/batched-bench/batched-bench.cpp` 中的 `decode_helper` lambda 函数（第 56-76 行）演示了如何处理批次。来自 `ctx_params` 的 `n_batch` 参数用于控制传递给 `llama_decode` 的数据块大小。

## 整体架构契合度

性能和优化是 `llama.cpp` 设计中不可或缺的一部分。


- **基准测试工具 (`llama-bench`, `batched-bench`)：** 这些工具直接利用 `llama.h` API 来模拟各种工作负载，并衡量核心库和底层 GGML 后端的性能。它们对于开发人员和用户理解性能特征和调整参数至关重要。
- **GPU 卸载与线程管理：** 这些是运行时配置，直接影响 `llama.cpp` 核心和 GGML 后端执行计算的方式。正确配置是利用硬件能力的关键。
- **Flash Attention 与量化：** 这些是在 GGML 后端层面实现的技术（并由 `llama.cpp` 使用），用于优化特定操作（注意力机制、权重的内存占用/带宽），以实现更快的推理。

通过提供这些工具和优化手段，`llama.cpp` 旨在在各种硬件上提供高性能推理。
